DESCRIPTION

t.rast.out.vtk writes each raster map of a space time raster dataset into a VTK legacy file, one file per map. The files are ASCII text; a program that reads VTK, such as ParaView, can show them one after the other as a time series. The tool runs r.out.vtk for every map. See the introduction to temporal data processing for space time datasets. The tool that writes a dataset into one archive for another GRASS project is t.rast.export.

The option input names the space time raster dataset, and directory the directory that receives the files. The directory must exist; the tool does not make it. A relative directory is taken from the current directory.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2026-03-02', and writes only the maps it selects. Without where, all maps are written. The maps are written in the order of their start time. where is ignored with the flag -g.

The flag -g writes the files for equidistant steps of the granularity of the dataset. A time step in which no map is registered, a gap, gets a file in which every cell has the null value. The files of a dataset without gaps are the same with and without -g. A dataset with gaps gets more files with -g, one for each missing step.

Names of the files

The files are numbered from 000000 in the order of the maps, and the number has six digits. The file name is the number, an underscore, the name of the dataset without its mapset and the suffix .vtk, such as 000002_temperature.vtk. The numbering starts at 000000 again for every call and counts only the written files, so a selection with where is numbered without holes. An existing file is refused unless the flag --overwrite is given.

Content of the files

r.out.vtk writes the cells of the current computational region, so the files of one call have the grid of the region at the time of the call. The first four lines of a file are # vtk DataFile Version 3.0, the title GRASS 8 Export, the word ASCII and the dataset type. The following lines give the number of points in each direction, the spacing, the origin and the number of values; the values follow in rows after the line LOOKUP_TABLE default. The name of the scalar in the line that starts with SCALARS is the name of the dataset and the number of the process that ran the tool, so it differs from call to call.
  • Without elevation the file holds the cells as a grid of cells (DATASET STRUCTURED_POINTS and CELL_DATA): the grid has one point more than cells in each direction and starts at the south-west corner of the region.
  • With the flag -p the file holds point data instead (POINT_DATA): one point at the centre of each cell, so the grid has as many points as the region has cells and starts at the centre of the south-west cell.
  • The option elevation names a raster map that gives the height of each cell. The file then holds a surface (DATASET POLYDATA): a list of points, one at the centre of each cell with the value of the elevation map as height, the quadrilaterals between four neighbouring points, and the values of the dataset map at the points. The flag -p changes nothing for a file with elevation.
  • The option null sets the value that is written for a cell without data. It is -99999.99 by default. The value applies to files with and without elevation.
  • The flag -c corrects the coordinates of the grid: the origin is moved by the centre of the default region of the project, which g.region -d shows, so that the coordinates of a project with large coordinate values become small numbers. Use -c for all files that are shown together, and only for data of one project, as the default region differs between projects.

NOTES

The tool copies every map under a temporary name to make the scalars of all files have the same name, and exports the copy. The copy and, with -g, the map without data are removed in every case, also if the export stops with an error.

The tool stops with "Export directory name not found." if directory does not exist or is a file. A where condition with a syntax error stops the tool with an error that contains "Invalid where condition", and no file is written. A file that exists already stops the tool with "Unable to export raster map" and leaves the file as it was (see the sixth example).

A dataset with relative time is written like one with absolute time, and a dataset of another mapset is named with its mapset. The last example shows both.

EXAMPLES

Write one VTK file per map

The dataset temperature has three maps of two rows and three columns. The cell value of temperature_1 is 10 * row + column, so it is 11, 12, 13 in the northern row and 21, 22, 23 in the southern one. temperature_2 is the same plus 100. temperature_4 has the value 1.5 in the first column and no data in the others. The first two maps are the days 1 and 2 of March 2026, and the third is the day 4, so there is no map for the day 3.

The first block creates the dataset. The second block makes the directory vtk and writes the files into it. The tool makes one file for each of the three maps, numbered in the order of time. The first eight lines of the first file are the version, the title, the format, the dataset type and the grid: 4 by 3 points around 3 by 2 cells with the spacing 1 and the origin in the south-west corner of the region. The last two lines hold the values, row by row, the southern row first. The line that starts with SCALARS is left out because it holds the number of the process.

Command line:

g.region n=2 s=0 e=3 w=0 res=1
r.mapcalc expression="temperature_1 = 10 * row() + col()"
r.mapcalc expression="temperature_2 = 10 * row() + col() + 100"
r.mapcalc expression="temperature_4 = if(col() == 1, 1.5, null())"
t.create output=temperature title="Air temperature" \
    description="Daily mean air temperature"
t.register -i input=temperature maps=temperature_1,temperature_2 \
    start=2026-03-01 increment="1 day"
t.register input=temperature maps=temperature_4 \
    start=2026-03-04 end=2026-03-05

mkdir vtk
t.rast.out.vtk input=temperature directory=vtk
ls vtk
head -n 8 vtk/000000_temperature.vtk
tail -n 2 vtk/000000_temperature.vtk | sed 's/ *$//'

Select maps and set the value of cells without data

where selects the maps temperature_2 and temperature_4, those that start on or after 2 March. They are written into the new directory selected and numbered 000000 and 000001, although they are the second and third map of the dataset. null sets -9999 for the cells without data, so the last two cells in each row of temperature_4 hold -9999 and the first one holds 1.5. The values are written with twelve decimal places.

mkdir selected
t.rast.out.vtk input=temperature directory=selected \

Draw the maps as a surface

The map elevation has the value 100 * row + column: 101, 102, 103 in the northern row and 201, 202, 203 in the southern one. With elevation the files hold a surface (DATASET POLYDATA) instead of a grid of cells: six points, one at the centre of each cell with the elevation as the third coordinate, listed from the southern row, and two quadrilaterals (POLYGONS 2 10) between them. Each quadrilateral lists four point numbers, counted from 0. The values follow with POINT_DATA. The example writes the first map only, the one with the values 11 to 23.

The second block repeats the call with -p into another directory and compares the files without the SCALARS line: they are the same, because -p changes nothing for a surface.

Command line:

r.mapcalc expression="elevation = 100 * row() + col()"
mkdir surface surface_p
t.rast.out.vtk input=temperature directory=surface elevation=elevation \
    where="name = 'temperature_1'" null=-9999
grep -v SCALARS surface/000000_temperature.vtk | sed 's/ *$//'

Point data and coordinates in a large coordinate system

The region moves to the coordinates 1000 to 1003 and 2000 to 2002, as in a project with a projected coordinate system, and the call writes the first map four times: without flag, with -p, with -c and with both. Each call prints the lines 5 to 8 of the first file, which hold the number of points, the spacing, the origin and the kind of data.

Without a flag the file holds cells: 4 by 3 points and the origin in the south-west corner, 1000 and 2000. With -p it holds points: 3 by 2 points and the origin at the centre of the south-west cell, 1000.5 and 2000.5. The default region of a new project is the square from 0 to 1, so its centre is 0.5; the values below depend on it (g.region -d -p shows the default region of another project). -c moves the origin by this value: 999.5 and 1999.5 for the cells, and 1000 and 2000 for the points. The last block sets the region back.

Command line:

g.region n=2002 s=2000 w=1000 e=1003 res=1
mkdir plain points corrected both
t.rast.out.vtk input=temperature directory=plain null=-9999 \
    where="name = 'temperature_1'"
t.rast.out.vtk -p input=temperature directory=points null=-9999 \
    where="name = 'temperature_1'"
t.rast.out.vtk -c input=temperature directory=corrected null=-9999 \
    where="name = 'temperature_1'"
t.rast.out.vtk -p -c input=temperature directory=both null=-9999 \
    where="name = 'temperature_1'"
for directory in plain points corrected both; do
    echo $directory
    sed -n 5,8p $directory/000000_temperature.vtk
done

Replace existing files

The directory vtk from the first example holds the files already. A second call without --overwrite is refused: the message names the file, and the tool stops with "Unable to export raster map" and a temporary name that differs from call to call, so only the line about the file is shown. The file is as it was. The call with --overwrite replaces the files.

Command line:

t.rast.out.vtk input=temperature directory=vtk 2>&1 | grep "exists" || true
t.rast.out.vtk --overwrite input=temperature directory=vtk
ls vtk

Write a dataset of another mapset with relative time

The dataset model has relative time and two maps in the mapset PERMANENT. The example switches to the mapset analysis, which has the default region, so it sets the region of the maps again. The call names the dataset with its mapset. The files are numbered as for absolute time.

Command line:

r.mapcalc expression="step_1 = 1"
r.mapcalc expression="step_2 = 2"
t.create output=model temporaltype=relative title="Model" \
    description="Model output per step"
t.register -i input=model maps=step_1,step_2 start=0 increment=1 unit=hours
g.mapset -c mapset=analysis
g.region n=2 s=0 e=3 w=0 res=1
mkdir model
t.rast.out.vtk input=model@PERMANENT directory=model
ls model
