DESCRIPTION

t.rast.out.vtk writes each raster map of a space time raster dataset into a VTK legacy file, one file per map. The files are ASCII text; a program that reads VTK, such as ParaView, can show them one after the other as a time series. The tool runs r.out.vtk for every map. See the introduction to temporal data processing for space time datasets. The tool that writes a dataset into one archive for another GRASS project is t.rast.export.

The option input names the space time raster dataset, and directory the directory that receives the files. The directory must exist; the tool does not make it. A relative directory is taken from the current directory.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2026-03-02', and writes only the maps it selects. Without where, all maps are written. The maps are written in the order of their start time. where is ignored with the flag -g.

The flag -g writes the files for equidistant steps of the granularity of the dataset. A time step in which no map is registered, a gap, gets a file in which every cell has the null value. The files of a dataset without gaps are the same with and without -g. A dataset with gaps gets more files with -g, one for each missing step. A monthly series from the last day of a month (January 31, February 28, March 31) has the granularity of one month, so -g writes a file per month.

Names of the files

The files are numbered from 000000 in the order of the maps, and the number has six digits. The file name is the number, an underscore, the name of the dataset without its mapset and the suffix .vtk, such as 000002_temperature_monthly.vtk. The numbering starts at 000000 again for every call and counts only the written files, so a selection with where is numbered without holes. An existing file is refused unless the flag --overwrite is given.

Content of the files

r.out.vtk writes the cells of the current computational region, so the files of one call have the grid of the region at the time of the call. The first four lines of a file are # vtk DataFile Version 3.0, the title GRASS 8 Export, the word ASCII and the dataset type. The following lines give the number of points in each direction, the spacing, the origin and the number of values; the values follow in rows after the line LOOKUP_TABLE default. The name of the scalar in the line that starts with SCALARS is the name of the dataset and the number of the process that ran the tool, so it differs from call to call.
  • Without elevation the file holds the cells as a grid of cells (DATASET STRUCTURED_POINTS and CELL_DATA): the grid has one point more than cells in each direction and starts at the south-west corner of the region.
  • With the flag -p the file holds point data instead (POINT_DATA): one point at the centre of each cell, so the grid has as many points as the region has cells and starts at the centre of the south-west cell.
  • The option elevation names a raster map that gives the height of each cell. The file then holds a surface (DATASET POLYDATA): a list of points, one at the centre of each cell with the value of the elevation map as height, the quadrilaterals between four neighbouring points, and the values of the dataset map at the points. The flag -p changes nothing for a file with elevation.
  • The option null sets the value that is written for a cell without data. It is -99999.99 by default. The value applies to files with and without elevation.
  • The flag -c corrects the coordinates of the grid: the origin is moved by the centre of the default region of the project, which g.region -d shows, so that the coordinates of a project with large coordinate values become small numbers. Use -c for all files that are shown together, and only for data of one project, as the default region differs between projects.

NOTES

The tool copies every map under a temporary name to make the scalars of all files have the same name, and exports the copy. The copy and, with -g, the map without data are removed in every case, also if the export stops with an error.

The tool stops with "Export directory name not found." if directory does not exist or is a file. A where condition with a syntax error stops the tool with an error that contains "Invalid where condition", and no file is written. A file that exists already stops the tool with "Unable to export raster map" and leaves the file as it was (see the sixth example).

A dataset with relative time is written like one with absolute time, and a dataset of another mapset is named with its mapset. The last example shows both.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_out_vtk and sets the computational region to North Carolina with cells of 1 km; it builds the dataset temperature_monthly with the mean air temperature of each month of 2020 in degree Celsius, generated from the elevation by a formula and not measured. A VTK file holds every cell of the region as text, and one file of the whole state would have more than 280,000 values. The examples therefore write a window of three by two cells of 1 km, set with g.region before each call: n=210000 s=208000 w=600000 e=603000 in the Piedmont and n=200000 s=198000 w=928000 e=931000 at the Atlantic coast, where the first column holds land and the two others lie outside the state and hold no data. The files then have six values each, and the shown lines are the same on every system.

Write one VTK file per map

The dataset temperature_monthly has the twelve monthly maps of 2020. The temperature falls by 0.65 degrees per 100 m of elevation of elev_state_500m, is rounded to 0.1 degrees and is highest in July. The window is the one in the Piedmont. The tool makes one file for each of the twelve maps, numbered in the order of time; the example lists the number of files and the first three names. The first eight lines of the first file are the version, the title, the format, the dataset type and the grid: 4 by 3 points around 3 by 2 cells with the spacing 1000 and the origin in the south-west corner of the window. The last two lines hold the values of the January map, row by row, the southern row first. The line that starts with SCALARS is left out because it holds the number of the process.

Command line:

g.mapset -c mapset=t_rast_out_vtk
g.region raster=elev_state_500m res=1000 -a
for month in $(seq 12); do
    echo "temperature_monthly_2020_$(printf %02d $month) = round((16.5" \
        "+ 10.5 * cos(30 * ($month - 7.2)) - 0.0065 * elev_state_500m" \
        "- 0.00001 * (y() - 160000)) * 10) / 10.0"
done | r.mapcalc file=-
t.create output=temperature_monthly title="Air temperature" \
    description="Monthly mean air temperature 2020 in degree Celsius"
t.register -i input=temperature_monthly \
    maps=$(g.list type=raster pattern="temperature_monthly_*" mapset=. separator=comma) \
    start=2020-01-01 increment="1 month"

Write a file for each time step with the granularity

Draw the maps as a surface

With elevation the files hold a surface (DATASET POLYDATA) instead of a grid of cells: six points, one at the centre of each cell with the elevation of elev_state_500m in meters as the third coordinate, listed from the southern row, and two quadrilaterals (POLYGONS 2 10) between them. Each quadrilateral lists four point numbers, counted from 0. The values follow with POINT_DATA. The example writes the January map only.

The second block repeats the call with -p into another directory and compares the files without the SCALARS line: they are the same, because -p changes nothing for a surface.

Point data and coordinates of the project

The coordinates of the window are large, as in every project with a projected coordinate system. The call writes the January map four times: without flag, with -p, with -c and with both. Each call prints the lines 5 to 8 of the first file, which hold the number of points, the spacing, the origin and the kind of data.

Without a flag the file holds cells: 4 by 3 points and the origin in the south-west corner of the window, 600000 and 208000. With -p it holds points: 3 by 2 points and the origin at the centre of the south-west cell, 600500 and 208500. The first command prints the default region of the project (g.region -d -u -g; -u leaves the current region as it is). Its centre is 527500 and 165000, the mean of the west and east and of the south and north values. -c moves the origin by this value: 72500 and 43000 for the cells, and 73000 and 43500 for the points. The values depend on the default region of the project, which is the same in the sample dataset and its full version.

Command line:

g.region -d -u -g | grep -E "^[nswe]="

Replace existing files

The directory vtk from the first example holds the files already. A second call without --overwrite is refused: the message names the file, and the tool stops with "Unable to export raster map" and a temporary name that differs from call to call, so only the line about the file is shown. The file is as it was. The call with --overwrite replaces the files.

Command line:

t.rast.out.vtk input=temperature_monthly directory=vtk 2>&1 | grep "exists" || true
t.rast.out.vtk --overwrite input=temperature_monthly directory=vtk
ls vtk | wc -l

Write a dataset of another mapset with relative time

The dataset runoff has relative time and two maps with the constant values 1 and 2 in the mapset t_rast_out_vtk: the simulated runoff in millimeters in model hours 0 to 1 and 1 to 2. The example switches to the mapset t_rast_out_vtk_2, which starts with the default region of the sample dataset, so it sets the region again. The mapset t_rast_out_vtk is not in the search path of the new mapset; the call names the dataset with its mapset, which is enough to read it. The files are numbered as for absolute time.

Command line:

for step in 1 2; do
    r.mapcalc expression="runoff_$step = $step"
done
t.create output=runoff temporaltype=relative title="Runoff" \
    description="Simulated runoff in mm per model hour"
t.register -i input=runoff maps=runoff_1,runoff_2 start=0 increment=1 unit=hours
g.mapset -c mapset=t_rast_out_vtk_2
g.region raster=elev_state_500m res=1000 -a
g.region n=210000 s=208000 w=600000 e=603000 res=1000
mkdir model
t.rast.out.vtk input=runoff@t_rast_out_vtk directory=model
ls model
