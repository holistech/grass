DESCRIPTION

t.rast3d.mapcalc computes new 3D raster maps from the maps of one or more space time 3D raster datasets and registers them in a new space time 3D raster dataset. It runs r3.mapcalc once for each time step and adds the temporal variables td(), start_time(), end_time() and, for absolute time, the calendar functions start_doy(), end_month() and others to the expression. Use it when the result of a time step depends on maps of several datasets, on the time of the step, or on both. See the introduction to temporal data processing for space time datasets. t.rast.mapcalc does the same for space time raster datasets, t.rast3d.algebra computes with the temporal algebra, and t.rast3d.list lists the maps of the result.

Datasets and time steps

The option inputs lists the datasets whose maps the expression uses. The first dataset of the list is the sampler: every map of it is one time step, which this manual calls a granule. Each of the other datasets is sampled by the granules: for each granule, the tool looks for the map of the dataset that is related to the granule in time, as the option method says. A granule for which one of the datasets has no related map is skipped. The order of the datasets in the expression does not matter, only their order in inputs. If the list names only one dataset, every map of it is a granule. The datasets may be in other mapsets (moisture@t_rast3d_mapcalc); the expression then uses the name without the mapset or, as in inputs, with it, and the mapset does not have to be in the search path (see Datasets of other mapsets).

The result dataset is the option output. It always belongs to the current mapset, and so do the new maps. It takes the temporal type and the semantic type of the first dataset of inputs. Each new map has the start and end time of its granule. An existing dataset output is refused unless the flag --overwrite is given; then it is replaced, and the tool warns that it unregisters all maps of the old dataset.

The tool computes in the current 3D region, as r3.mapcalc does. A map that lies outside the region reads as null.

The expression

The option expression is the right side of an r3.mapcalc expression, without the map = of a full one. In it, the name of each dataset of inputs stands for the related map of the current granule, so moisture * bias multiplies the map of moisture by the related map of bias, and bias * moisture does the same. Any other 3D raster map can be used by its name. The operators and functions of r3.mapcalc are available.

The tool puts the names of the maps into the text of the expression and numbers the results, so with the expression moisture / 2 a call with four granules runs four statements such as halved_1=moisture_1 / 2. A dataset name is replaced only where it stands as a whole name: not inside a longer name (moisture in moisture_deep), and not before an opening parenthesis, where it is the name of a function (day in start_day()); see the ninth example. After a map name, as in volume@moisture, the name is a mapset and stays. The rest of the expression goes to r3.mapcalc as written, blanks included. Two inputs with the same name, such as moisture,moisture, are refused before any map is computed, because the expression could not tell them apart.

The option basename is required. The new maps are named after it, followed by an underscore and the number of their granule, counted from 1 in the order of the sampler. The number has as many digits as the number of granules needs, filled up with zeros: halved_1 for four granules, halved_01 for eleven. A granule that is skipped, or whose result is empty, leaves a gap in the numbers.

Temporal variables

The following variables are replaced by a number for each granule before the expression goes to r3.mapcalc. They work with absolute and with relative time.
  • td(): the length of the granule, the end minus the start, in days and fractions of days for absolute time, in the unit of the dataset for relative time; null for a time instant.
  • start_time(): the start of the granule minus the start of the first granule, in days or in the unit.
  • end_time(): the end of the granule minus the start of the first granule, in days or in the unit; null for a time instant, which has no end.

For absolute time, the calendar functions give a part of the start or the end of the granule as a whole number. Each function exists for the start (start_doy()) and for the end (end_doy()) of the granule, and the end functions are null for a time instant.

  • start_doy(): the day of the year, 1 to 366.
  • start_dow(): the day of the week, 1 to 7; Monday is 1.
  • start_year(): the year.
  • start_month(): the month, 1 to 12.
  • start_week(): the ISO week of the year. Weeks start on Monday, and the first days of January can belong to week 52 or 53.
  • start_day(): the day of the month, 1 to 31.
  • start_hour(): the hour, 0 to 23.
  • start_minute(): the minute, 0 to 59.
  • start_second(): the second, 0 to 59.

With relative time, a calendar function stops the tool with an error.

Select the related maps

The option method is a list of the sampling methods. It names the relation between the granule and the map of another dataset. The default is during,overlap,contain,equal. A map is related to the granule if it has one of the listed relations. The third example shows the methods.
  • equal: the map has the start and the end time of the granule.
  • during: the granule lies inside the time interval of the map. The map may share the start or the end of the granule, but is not equal to it: for a granule from 10 to 20 the maps from 5 to 25, from 10 to 25 and from 5 to 20.
  • contain: the map lies inside the granule.
  • overlap: the map starts inside the granule and ends after it, or starts before it and ends inside it.
  • follows: the map ends when the granule starts.
  • precedes: the map starts when the granule ends.
  • start: the maps that lie inside the granule, the maps that start before it and end inside it, the maps that cover it while sharing its start or its end, and the equal map. It does not take a map that covers the granule strictly and a map that starts inside it and ends after it. The temporal topology names the relations of this group overlapped, starts, started, finishes, contains and equal.

If more than one map of a dataset is related to a granule, the tool warns on the standard error and uses only one of them. Which one, follows from the order in which it tries the relations. First come the methods equal, during, follows and precedes, in the order of the list method; then the group start, which tries the equal map last, then overlap and then contain, if they are in the list. Within one relation, the map with the earliest start time is taken, and for equal start times the map with the smaller id. So for the list contain,during a map found by during wins over a map found by contain. The fourth example shows this. Choose the first dataset of inputs so that its granules are the time steps you want, and use t.rast.aggregate.ds to make datasets with one map per step.

Empty results and spatial relation

A new map that has no valid cell, that is, no minimum and no maximum, is empty. By default it is not registered in output and is removed after the run. The flag -n registers the empty maps and keeps them. An expression such as if(moisture > 15, moisture, null()) selects time steps by values in this way. If all results are empty, output exists but holds no map.

The flag -s adds a spatial condition to the temporal one: a map is related to the granule only if its 2D extent, from west to east and from south to north, touches or overlaps that of the granule, so a shared edge counts. The vertical extent is not compared. A granule without a related map is skipped. The eighth example shows the difference.

Parallel processing

The option nprocs sets the number of r3.mapcalc processes that run at the same time. The default is 1. The result does not depend on it.

NOTES

t.rast3d.mapcalc has the same options as t.rast.mapcalc, except for where, and works on 3D rasters only. The maps of the datasets are not touched; the tool makes new maps.

If inputs names one dataset and it has no maps, the tool warns "No maps registered in input dataset ...", makes no dataset output and ends with status 0.

If a map of the base name exists as a registered map and --overwrite is not given, the tool stops before it computes any map, with "Map ... is already in temporal database, use overwrite flag to overwrite". If the dataset output exists, the tool stops with "Space time raster3d dataset ... is already in the database. Use the overwrite flag.".

With --overwrite, the maps of the old dataset are unregistered from it, not removed. A new run with fewer maps leaves the surplus old maps in the mapset; the tenth example shows it.

The tool stops with an error if an input dataset does not exist ("Space time dataset ... of type str3ds not found"), if method names a method that does not exist ("Value ... out of range for parameter method"), and if r3.mapcalc does not accept the expression ("Error while mapcalc computation"). A calendar function with relative time stops it with The temporal operators <start_*> support only absolute time. (<end_*> for an end function). The tool announces its steps on the standard error with "Starting temporal sampling..." (with -s: "Starting spatio-temporal sampling...") and "Starting mapcalc computation...".

If inputs names more than one dataset and the sampler has only time instants, or the datasets have different temporal types, the first dataset cannot sample the others: the tool stops before it computes any map, with "The temporal map type of the sample dataset must be interval" or "The space time datasets must be of the same temporal type". A call with one dataset needs no sampling, so time instants work there.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast3d_mapcalc and sets the computational region to North Carolina with cells of 1 km and three layers of 1000 m. The 3D resolution stays at the 500 m of the elevation model unless res3 is set, so the examples set it. The third example narrows the region to a square of two by two cells, where the maps of the later examples hold small constant values, so that the results can be checked by hand; the last example creates a second mapset with the full region again.

Apply an expression to every map

The dataset temperature_profile holds twelve 3D maps of the monthly mean air temperature in 2020, in degrees Celsius rounded to tenths. They are generated like the monthly maps of the other temporal manuals, but from the height of the layer instead of the elevation model: 16.5 degrees at sea level and the northing 160 km, an annual cycle of plus and minus 10.5 degrees with its maximum in July, 6.5 degrees less for every 1000 m of height, and 1 degree more for every 100 km to the south. The maps have three layers of 1000 m, from 0 to 3000 m, and each is an interval of one month.

The first block converts the maps to degrees Fahrenheit. The name temperature_profile in the expression stands for the map of each month. The new maps are named fahrenheit_01 to fahrenheit_12 after the granules, and each has the time of its source map. nprocs lets two r3.mapcalc processes run at the same time; the result is the same as with one. The result is rounded to tenths, as the source maps are. In July the warmest voxel has 25.4 degrees Celsius, which is 77.7 degrees Fahrenheit, and in January the coldest has -11.8 degrees Celsius, which is 10.8 degrees Fahrenheit. The second block shows what the new dataset takes from temperature_profile: the temporal type and the semantic type, and the granularity that follows from the maps it holds.

Command line:

g.mapset -c mapset=t_rast3d_mapcalc
g.region raster=elev_state_500m res=1000 res3=1000 t=3000 b=0 tbres=1000 -a
for month in $(seq 12); do
    echo "temperature_profile_2020_$(printf %02d $month) = round((16.5" \
        "+ 10.5 * cos(30 * ($month - 7.2)) - 0.0065 * z()" \
        "- 0.00001 * (y() - 160000)) * 10) / 10.0"
done | r3.mapcalc file=-
t.create type=str3ds output=temperature_profile title="Air temperature" \
    description="Monthly mean air temperature 2020 in degree Celsius, 0 to 3000 m"

Combine the maps of several datasets

The dataset bias has four maps, each for a quarter of 2020: bias_2020_q1 with the value 0.5, bias_2020_q2 with -0.5, bias_2020_q3 with 1 and bias_2020_q4 with -1, a correction in degrees Celsius that is the same in every voxel. The first block adds the correction to temperature_profile; the expression names bias second, which does not matter. The first dataset of inputs is the sampler, so the result has twelve maps of one month each, and each month of temperature_profile lies during a map of bias. The sum is rounded to tenths. The listing shows March, which is in the first quarter, and April and May, which are in the second: the values of March are 0.5 above those of the source map (the largest is 8.8 degrees there and 9.3 here), those of April and May are 0.5 below (the largest of April is 13.9 degrees and 13.4 here).

The second block swaps the order in inputs, so the sampler is bias and the result has four maps of three months each. Each granule of bias contains three maps of temperature_profile; the tool warns on the standard error and uses the first of them, the map of the first month of the quarter. The result is the value of bias plus that map, so the maps hold the temperature of January, April, July and October with the correction of their quarter: the largest value of July is 25.4 plus 1, which is 26.4 degrees.

Choose the sampling method

The next examples work on a small region: a square of two by two cells of 1 km with three layers of 1000 m. The maps of these examples hold constant values, and the time of the maps is the point.

The dataset dekads has nine granules of 10 days with relative time, from day 110 to 120, from 210 to 220 and so on up to 910 to 920. Its map dekad_k has the value k. The dataset probes has one map for each granule, probe_k with the value 10 * k, and each has a different position relative to the granule:

  1. probe_1 has the same times, 110 to 120.
  2. probe_2 lies inside the granule, 214 to 218.
  3. probe_3 covers the granule, 305 to 325.
  4. probe_4 starts inside the granule and ends after it, 415 to 425.
  5. probe_5 starts before the granule and ends inside it, 505 to 515.
  6. probe_6 ends when the granule starts, 600 to 610.
  7. probe_7 starts when the granule ends, 720 to 730.
  8. probe_8 starts with the granule and ends after it, 810 to 825.
  9. probe_9 starts before the granule and ends with it, 905 to 920.

The loop runs the tool once for each method and prints the maps of the result. The number at the end of a name is the number of the granule that found a related map: equal finds the map of granule 1, during the ones of the granules 3, 8 and 9, contain granule 2, overlap the granules 4 and 5, follows granule 6 and precedes granule 7. The method start finds the granules 1, 2, 5, 8 and 9. The last block uses no method, so the default during,overlap,contain,equal finds the granules 1 to 5, 8 and 9, and the listing shows that the maps have the times of the granules.

The time of the datasets is relative, in days, and the result takes it over. The files for t.register list one map per line with its start and end time.

The dataset window has one map of 10 days, from day 10 to 20, with the value 1. The dataset cands has four maps that are all related to it, in different ways: cand_a from 12 to 18 with the value 100 (inside the granule), cand_b from 5 to 25 with the value 200 (covers it), cand_c from 11 to 13 with the value 300 (inside, and starts before cand_a) and cand_d from 10 to 20 with the value 400 (equal).

Use the time of the granule

The dataset moisture has four maps for the days from 1 to 4 March 2026. The maps have three layers of two by two voxels, and their values are the layer number (1, 2 and 3) plus 0, 10, 20 and 30, so the smallest and largest values are 1 and 3, 11 and 13, 21 and 23, and 31 and 33. depth() counts the layers from 1. The expressions of the first four blocks need no map, only the time of the granule, so they name moisture only in inputs. The granules are the days from 1 to 4 March 2026; 1 March 2026 is a Sunday, the 60th day of the year.

The first block puts three variables into one number: start_time() counts the hundreds, td() the tens and end_time() the ones. The days start 0, 1, 2 and 3 days after the first, are 1 day long and end 1, 2, 3 and 4 days after the start of the first, so the results are 11, 112, 213 and 314. The second block combines the day of the year and the day of the week, tens and ones again: 60 and 7 (Sunday) for the first day, then 61 and 1 (Monday) and so on, so 607, 611, 622 and 633. The third block gives the month and the day at the end: the month is 3 and the end day is 2 to 5, so the results are 302 to 305. The fourth block uses the weeks, which start on Monday: the first day starts in week 9 and ends on Monday 2 March, in week 10, so 910, and 1010 for the other days.

The dataset gauge has two time instants, at 06:00 on 1 March and at 18:00 on 2 March, and its maps have the values 1 and 2. The last block shows what an instant gets: start_time() is the offset in days and fractions of days from the first instant, 0 and 1.5, and end_time() is null, so isnull() is true and the result is 100 and 101.5. The next block shows that td() of an instant is null as well: the result is 7.

The weeks are ISO weeks. The dataset newyear has one day, 1 January 2027, which is a Friday in week 53 of 2026, and the last block gives start_week() 53.

Names of datasets in the expression

A dataset name in the expression is replaced only where it stands as a whole name. The dataset day has one map with the value 4 on March 1. In day * start_day() the name day inside start_day() stays, so the result is 4 times the day of the month, 1. The dataset moisture_deep has one map with the value 3 on March 1. In moisture + moisture_deep the name moisture inside moisture_deep stays, so the first granule of moisture, whose map holds the layer number 1 to 3, gets 4 to 6; the other three granules of moisture have no map of moisture_deep and are skipped.

Two inputs with the same name cannot be told apart in the expression. The third block names day twice, and the tool stops before it computes anything.

Command line:

r3.mapcalc expression="day_1 = 4"
t.create type=str3ds output=day title="Day" description="One map"
t.register type=raster_3d input=day maps=day_1 \
    start=2026-03-01 end=2026-03-02
t.rast3d.mapcalc inputs=day output=day_of_month basename=day_of_month \
    expression="day * start_day()"
t.rast3d.list input=day_of_month columns=name,start_time,min,max

name|start_time|min|max
day_of_month_1|2026-03-01 00:00:00|4.0|4.0

r3.mapcalc expression="moisture_deep_1 = 3"

    description="One map"
t.register type=raster_3d input=moisture_deep maps=moisture_deep_1 \
    start=2026-03-01 end=2026-03-02
t.rast3d.mapcalc inputs=moisture,moisture_deep output=layers basename=layers \

Use a dataset of another mapset and replace a result

The mapset t_rast3d_mapcalc_2 is new and empty. The first block makes it the current mapset, sets the region of the first example there, and halves moisture@t_rast3d_mapcalc. The expression still uses the name moisture, and the mapset of the input does not have to be in the search path. See Datasets of other mapsets. The maps of moisture hold values only in the square where they were made, so the new maps read null in the rest of the region. The dataset halved and its maps belong to the current mapset; the listing shows the mapset of the maps.

The second block repeats the call without --overwrite. The tool stops because the dataset halved exists. The third block adds --overwrite and makes the dataset again, with the same four maps; the tool warns on the standard error that it unregisters all maps of the old dataset.

The fourth block replaces halved once more, now from the dataset gauge, which has two maps. The new dataset holds two maps, with the values 0.5 and 1. The maps halved_3 and halved_4 of the earlier run are no longer registered in it, but the tool does not remove them: g.list still finds all four.

g.mapset -c mapset=t_rast3d_mapcalc_2

t.rast3d.mapcalc inputs=moisture@t_rast3d_mapcalc output=halved basename=halved \
    expression="moisture / 2"
t.rast3d.list input=halved columns=name,mapset,min,max
