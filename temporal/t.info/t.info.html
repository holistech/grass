DESCRIPTION

t.info reports what the temporal database stores about a space time dataset or about a single map: its identifier and creator, its time, its spatial extent and metadata that depend on the type of the dataset. The report is made for reading, or, with the flag -g, in shell script style with one key=value pair per line. t.info only reads; it does not change the database. See the introduction to temporal data processing for space time datasets. Datasets are created with t.create, maps are registered in them with t.register, and t.list and t.rast.list list datasets and their maps.

t.info reports the values stored in the temporal database, it does not read the maps. For all values of a map, such as its category table or its history, use r.info, r3.info or v.info.

The option input names the dataset or the map. A name without a mapset refers to the current mapset; name@mapset selects another one. input is required, except together with -d.

The option type says what input is: a space time dataset of type strds (raster maps, the default), str3ds (3D raster maps) or stvds (vector maps), or a single map of type raster, raster_3d or vector.

The flag -g prints the report in shell script style instead of the framed box, as described below. The flag -h prints the history of a space time dataset instead of the report. The flag -d prints information about the database back end instead of a dataset. -g also changes the form of the output of -d. -h takes precedence over both: with -h, the output is the history, whether -g or -d is given or not.

The report of a space time dataset

The report is a box of sections. A line shows a label, dots, and a value.

The section Basic information starts with the lines Id (name and mapset, temperature@PERMANENT), Name and Mapset. Creator is the user who created the dataset, Temporal type is absolute or relative, Creation time and Modification time are the times at which the dataset was created and last changed in the database, and Semantic type is the label given with semantictype of t.create: mean unless set otherwise.

The next section is named Absolute time or Relative time, after the temporal type. Start time is the earliest start and End time the latest end of the registered maps; with absolute time they are dates and times, with relative time numbers, and the line Relative time unit names the unit of those numbers. Granularity is the step in which the time of the dataset can be counted: 1 day for maps that are one day long and follow each other without gap; with relative time it is a number of the unit, in the example 6 for maps that are 6 hours long. With maps of different lengths or gaps between them, it is the greatest common divisor of the lengths and gaps, as in the dataset uneven of the examples. How months and years count is explained in the introduction to temporal data processing. Temporal type of maps is interval if all maps have a start and an end, point if all are time instances, and mixed if both occur.

The section Spatial extent gives North, South, East, West, Top and Bottom of the dataset, the bounding box of its registered maps. Top and bottom are 0 for datasets of 2D maps.

The section Metadata information depends on the type:

  • A space time raster dataset (strds) shows the Raster register table, the name of the table of its maps in the temporal database. The lines North-South resolution min and max and East-west resolution min and max give the smallest and the largest resolution among the registered maps. Minimum value min is the smallest of the minima of the maps and Minimum value max the largest of them; Maximum value min and Maximum value max are the smallest and the largest of the maxima. Aggregation type is the aggregation type stored with the dataset, None for all datasets of the examples. Number of semantic labels and Semantic labels give the number and the names, separated by commas, of the different semantic labels of the registered maps, 0 and None if there are none.
  • A space time 3D raster dataset (str3ds) shows the 3D raster register table, Top-bottom resolution min and max in addition, and the same resolution and value lines as strds, except the semantic labels.
  • A space time vector dataset (stvds) shows the Vector register table and the number of points, lines, boundaries, centroids, faces, kernels, primitives, nodes, areas, islands, holes and volumes, added up over the registered maps.

All types end the section with Number of registered maps, followed by the Title, the Description and the Command history: the commands that created the dataset and registered maps in it, each with the time at which it ran. A dataset without maps shows None for the time, the extent, the granularity, the type of the maps, the values from the maps and the number of maps.

The report of a map

The report of a map (raster, raster_3d, vector) has the same sections. Its basic information has no modification time and no semantic type, its time has no granularity and no type of the maps, and End time is None for a time instance. Metadata information shows the values the temporal database stored when the map was registered:
  • a raster map: Datatype, Number of columns, Number of rows, Number of cells, the resolution, the Minimum value, the Maximum value and the Semantic label;
  • a 3D raster map: the same without the semantic label, and Number of depths and Top-Bottom resolution;
  • a vector map: Is map 3d and the numbers of points, lines, boundaries, centroids, faces, kernels, primitives, nodes, areas, islands, holes and volumes.

The last line, Registered datasets, lists the space time datasets the map is registered in, separated by commas.

Shell script style

With -g, each value of the report is printed as key=value, in the order of the box. Text values are not quoted, except the times, the granularity of a dataset with absolute time and the start and end of a dataset with relative time, which are put between single quotes: start_time='2026-03-01 00:00:00'. The keys follow the labels of the box: id, name, mapset, creator, temporal_type, creation_time, modification_time, semantic_type, start_time, end_time, unit, granularity, map_time, north, south, east, west, top, bottom, then the register table (raster_register, raster3d_register or vector_register) and the values of the type, such as nsres_min, min_min, number_of_semantic_labels, semantic_labels, points or, for maps, datatype, cols, rows, number_of_cells, nsres, min, max, depths and registered_datasets. A dataset ends with number_of_maps. Empty values are printed as None; the title, the description and the history are not part of this form, use -h for them.

The history of a space time dataset

With -h, t.info prints the title, the description and the command history of a space time dataset instead of the report. The lines # Title:, # Description: and # Command history: and the lines with the title and the description start with #. The commands are those that created the dataset and registered maps in it; before each command, a line starting with # gives its time. The lines of the commands themselves do not start with #. Long commands are broken into several lines, and every line of a command ends in a backslash, also the last line of a command that is followed by another one. Only the last line of the whole history has none. -h with a map prints the report of the map; only space time datasets have a history. -g has no effect together with -h.

The database back end

The flag -d prints information about the temporal database of the current mapset and ends; input and type are ignored. The lines are:
  • DBMI Python interface, the name of the Python module that talks to the database (sqlite3 for the default back end);
  • Temporal database string, the connection string; with SQLite the path of the database file, which lies in the directory tgis of the mapset;
  • SQL template path, the directory of the SQL templates of the installation;
  • tgis_version and tgis_db_version, the version of the temporal framework and of the database layout, and creation_time, the time at which the database was created.

With -g, the same values are printed as dbmi_python_interface, dbmi_string, sql_template_path, tgis_version, tgis_db_version and creation_time, each value between single quotes. -d together with -h asks for the history of a dataset and needs input.

NOTES

A dataset or a map that is not registered in the temporal database ends the module with the error "Dataset <name@mapset> of type <type> not found in temporal database". The error also appears when type does not fit: a map asked for with the default type strds, or a dataset asked for with type=raster. A name without a mapset refers to the current mapset: a dataset of another mapset is selected as input=name@mapset, and without the mapset the error names the current mapset. A map of another mapset that is registered in a dataset of the current mapset is found with name@mapset as well.

Without input and without -d, the parser stops with "Required parameter <input> not set". -d with -h and without input stops with "Please specify input=".

With absolute time, Start time, End time and the other times are printed as 2026-03-01 00:00:00. With relative time, Start time and End time are numbers without unit; the unit is the line Relative time unit of the box and the key unit of the shell form.

The Semantic label line of a map, and semantic_label in the shell form, show None even for a map that has a semantic label, as the last but one example shows. The dataset reports the labels of its maps correctly (Semantic labels). To read the label of a map, use t.rast.list columns=name,semantic_label.

Datasets with relative time, mixed time and no maps

The dataset model has relative time: two model steps of 6 hours, registered with the unit hours. Start time and End time are the numbers 0 and 12, the granularity is 6, and the unit has a line of its own (unit in the shell form).

The dataset mixed holds the map early as an interval of one day and the map late as a time instance four days later. The two maps lie in different parts of the region and have the resolutions 1 and 2. The map time of the dataset is mixed, its end is the start of the time instance, its extent is the bounding box of both maps, and the resolution lines give the smallest and the largest resolution. The region is set back afterwards.

The dataset uneven has three maps of 4, 6 and 4 days, with a gap of 4 days before the last one. Its granularity is the greatest common divisor, 2 days.

The dataset nothing has no maps. Its time, extent, values and number of maps are None, as the last command shows. The shell form quotes the times and the granularity, so they are 'None'.

Datasets of 3D raster and vector maps

type names the kind of the dataset. The 3D raster dataset soil holds two maps of three layers, each layer one unit high; the report shows the top and bottom of the region and the top-bottom resolution. The vector dataset gauges holds two maps with two and three points; the report counts the points and the primitives over both maps. The commands that follow select a few lines of the report of a 3D raster map and of a vector map, -g with the types raster_3d and vector. The region is set back afterwards.

Semantic labels

The dataset sentinel holds the red band (semantic label S2_B4) and the near infrared band (S2_B8) of two scenes, registered as time instances. The report of the dataset counts the two labels and names them. The second block shows what the notes say: the map nir_1 is a time instance, so its end is None, and the report gives None for its semantic label, although it has one, while t.rast.list gives it.

Information about the database back end

-d needs no dataset. The report names the Python interface and the connection string of the temporal database, which is the file sqlite.db in the directory tgis of the mapset. The commands select these and the two version lines; the SQL template path and the creation time of the database differ from installation to installation and are left out. With -g, the same values are key='value' lines.

Command line:

t.info -d | grep -E "interface|database string|version"

 | Temporal database string:... /home/user/grassdata/temporal_examples/PERMANENT/tgis/sqlite.db
 | tgis_version .......... 2
 | tgis_db_version .......... 3
