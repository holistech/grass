DESCRIPTION

t.rast.neighbors runs r.neighbors on each raster map of a space time raster dataset (STRDS), so a neighborhood analysis such as a smoothing filter, a local maximum or a local quantile is applied to every map of the dataset. The new raster maps are registered in a new space time raster dataset. Each new map gets the start and end time of the map it was computed from. The new dataset takes the temporal type, the semantic type, the title and the description of the input dataset. See the introduction to temporal data processing for space time datasets.

t.rast.neighbors passes the neighborhood options on to r.neighbors; what they mean in detail is described there. The options input and output name the input dataset and the new dataset, the option basename the names of the new maps.

Selection of the maps

  • where takes an SQL condition on the registered maps, for instance on their start_time or their name; only the maps that satisfy it are processed. Without it, all maps are processed.
  • region_relation selects the maps by the relation of their extent to the current computational region: overlaps takes the maps that share an area with the region (including those that contain the region and those that lie within it), contains the maps that contain the region and is_contained the maps that lie within the region. A map equal to the region contains it and is contained in it. Without the option, the extent is not considered. The selection uses the current region also with the flag -r.

If where and region_relation select no map, nothing is computed (see NOTES).

Neighborhood

  • size is the size of the window in cells, an odd number, 3 by default. r.neighbors refuses an even size.
  • method is the statistic computed over the cells of the window, average by default. The methods are average, median, mode, minimum, maximum, range, stddev, sum, count, variance, diversity, interspersion, quart1, quart3, perc90 and quantile; see r.neighbors. Cells without a value (also those outside the region) are left out. At the border of the region the window therefore holds fewer cells: with size 3, the cell in a corner is computed from four cells.
  • quantile (0.0 to 1.0) is the quantile that method quantile calculates; this method needs it. For one given quantile q and n sorted values, the result is the linear mix of the two sorted values around the position q * (n - 1) (counted from 0). Without method quantile the option is ignored. It takes one value, not a list.
  • -c uses a circular window: the cells in the corners of the square window are left out. In a window of 3 by 3 cells, five cells remain.
  • selection names a raster map. Only the cells where it has a value are computed; every other cell of the new map keeps the value of the input map.

Weights

By default all cells of the window count equally (weighting_function none). The other functions give each cell a weight that depends on its distance d from the center of the window, measured in cells:
  • gaussian weighs by exp(-d^2 / (2 * f^2)) / (2 * pi * f^2), with f the weighting_factor;
  • exponential weighs by exp(f * d), with f the weighting_factor; a negative factor lets the weights fall with the distance;
  • file takes the weights from a text file named by weight, a matrix of size rows with size numbers each, separated by spaces.

The functions gaussian and exponential need weighting_factor, the function file needs weight; without it, r.neighbors fails and t.rast.neighbors stops (see NOTES). The weighted average divides by the sum of the weights, so a common factor of the weights cancels; the weighted sum keeps it. A weighted median is the value at which the cumulative weight of the sorted values reaches half of the total weight.

Names of the new maps

The new maps are named after basename, followed by an underscore and a suffix that the option suffix chooses:
  • gran (the default) takes the start time of the map, cut to the granularity of the input dataset: 2020_07_01 in a dataset of days. A monthly series from the last day of a month (January 31, February 28) has the granularity of one month and gets year and month: 2026_01. A dataset of a single time instance has no granularity; gran then takes the full start time, as time does.
  • time takes the full start time: 2020_07_01T00_00_00.
  • num numbers the selected maps from 1, with five digits: 00001. num%03 gives three digits: 001.

In a dataset with relative time, gran and time give the number as num does, because a relative time has no calendar date. Maps with the same start time get the same name with gran and time; use num for them (see NOTES).

Semantic labels

The option semantic_labels sets the semantic label of each new map:
  • input (the default) copies the label of the input map; a map without a label gives a new map without a label.
  • method appends the name of the method to the label of the input map, as S2_B4_maximum; a map without a label gets the name of the method as its label.

The labels tell the new maps apart when several of them have the same time and extent, as the bands of an image do.

Result and region

  • -n registers the new maps that have no value in any cell. By default such an empty map is removed and not registered, which happens for a map that has no value in the region.
  • -r ignores the current region and computes each map in its own region; the new map has the region of its input map. By default all maps are computed in the current region and the new maps have it. The current region stays as it is.
  • -e adds the new maps to an existing output dataset instead of failing because it exists: the dataset keeps its maps and also gets the new ones. With -e and an output dataset that does not exist, a new dataset is made. --overwrite is needed with -e only if one of the new maps already exists; it replaces that map and keeps the others of the dataset. Without -e, --overwrite replaces the whole dataset.
  • nprocs is the number of r.neighbors processes that run at the same time, 1 by default. The maps are the same for any number.

NOTES

If where and region_relation select no map, t.rast.neighbors warns that the space time raster dataset is empty and creates no output dataset. A syntax error in where stops the tool with the error "Unable to get map ids from register table", followed by "Invalid where condition" and the message of the database.

An existing output dataset is refused with "Space time raster dataset <name> is already in the database" unless -e or --overwrite is given. A raster map of the name of a new map that exists in the mapset but is not registered in the output dataset stops the tool before anything is written, with "Raster map <name@mapset> exists. To overwrite, use the --overwrite flag."; --overwrite replaces it. With -e, a new map that is registered in the dataset already is refused before anything is written with "Map <name@mapset> is already in temporal database"; --overwrite replaces it.

r.neighbors can fail, for instance with an even size, with weighting_function gaussian and no weighting_factor, or with weighting_function file and no weight. t.rast.neighbors then stops with the message "Error running r.neighbors" and creates no dataset. The method quantile without quantile stops the tool at the start with "The method <quantile> requires input in the 'quantile' option."; a list of quantiles is refused by the parser. An unknown suffix is refused before anything is written, for instance with "Invalid suffix <gram>, use gran, time, num or num%NN" for suffix=gram.

Two maps with the same start time, such as the bands of a scene, get the same name with the suffixes gran and time. The tool refuses this before it writes anything, with the same message for every nprocs and with or without --overwrite: "The maps <first> and <second> are given the same name <name> by the suffix gran. Use the suffix num or select maps of different times." No raster map and no dataset are made. Use suffix num for such maps, as the fifth example shows.

The input dataset can be in another mapset of the project; the name with the mapset (input=model@t_rast_neighbors) selects it. The new maps and the new dataset are always created in the current mapset, as the last example shows. Relative time works as absolute time; the new maps have the time of the input maps.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_neighbors, sets the computational region to North Carolina with cells of 1 km, builds the dataset precipitation_daily and then narrows the region to a window of 5 by 5 cells, so that the cells of the results can be checked by hand; the later examples work in this mapset and change the region as they need. The last example creates a second mapset. The examples that show how maps are selected use small constant maps, so that the results can be checked by hand.

Smooth the maps of a dataset

The dataset precipitation_daily holds 31 maps of the daily precipitation sum in July 2020, in whole millimeters. They are generated, not measured: the July normal of the climate stations of precip_30ynormals (the column jul), interpolated with v.surf.idw and multiplied by an assumed factor of 1.1 for a wet July, is spread over the days with the weight max(0, sin(45 * day)). It rains on the days 1 to 3, 9 to 11, 17 to 19 and 25 to 27, with the weights 0.71, 1 and 0.71. Each map is an interval of one day.

The computational region is then narrowed to a window of 5 by 5 cells of 1 km in the mountains of the west, so that the cells can be checked by hand. With the default method average and a window of size 3, each cell takes the mean of the cells around it. The second block prints the cells of the map of 2 July and then the cells of the new map. The cell in the center, in the third row and the third column, sees all nine cells: the sum of 15, 15, 14, 16, 15, 15, 16, 16 and 16 is 138, and 138 / 9 is 15.33. A cell in a corner sees only the four cells that lie in the region: the upper left cell is (15 + 15 + 16 + 15) / 4, that is 15.25. The list shows the first three new maps with the names of their days and their smallest and largest value; on 1 and 3 July, with the weight 0.71, the rain is 10 to 12 mm. nprocs 2 computes two maps at the same time.

The third block shows with t.info that the new dataset takes the temporal type, the semantic type, the title and the description of precipitation_daily, that it holds 31 maps and that its extent is the window.

Command line:

g.mapset -c mapset=t_rast_neighbors
g.region raster=elev_state_500m res=1000 -a
v.surf.idw input=precip_30ynormals column=jul \
    output=precipitation_normal_07 npoints=12 power=2
r.mapcalc expression="precipitation_monthly_2020_07 = if(isnull(elev_state_500m), null(), round(1.1 * precipitation_normal_07))"
for day in $(seq 31); do
    echo "precipitation_daily_2020_07_$(printf %02d $day) =" \
        "round(precipitation_monthly_2020_07 * max(0, sin(45 * $day)) / 9.65685)"
done | r.mapcalc file=-
t.create output=precipitation_daily title="Precipitation" \
    description="Daily precipitation sum July 2020 in mm"
t.register -i input=precipitation_daily \
    maps=$(g.list type=raster pattern="precipitation_daily_*" mapset=. separator=comma) \
    start=2020-07-01 increment="1 day"
g.region w=366000 e=371000 s=270000 n=275000 res=1000
t.rast.neighbors input=precipitation_daily output=rain_smooth \
    basename=rain_smooth size=3 method=average nprocs=2
t.rast.list input=rain_smooth columns=name,start_time,end_time,min,max \
    where="start_time < '2020-07-04'"

Choose the statistic and the window

The three blocks use the map of 2 July only (where), so each result is a dataset of one map. The cells of that map are the input of the first example: the first row is 15 15 14 14 14, the third row 16 16 15 15 15.
  1. method maximum gives the largest value of the window: 16 in the upper left corner (of 15, 15, 16 and 15) and 16 in the center.
  2. method quantile with quantile 0.25 takes the position 0.25 * (n - 1) in the sorted values. In the center there are nine values and the position is 2, the third value, 15. At the right edge of the third row there are six values, 14, 14, 15, 15, 15 and 16; the position 1.25 gives 14 + 0.25 * (15 - 14) = 14.25.
  3. With -c, the window is circular. The center sees the five cells 15 above, 16 left, 15 itself, 15 right and 16 below, and method sum gives 77; the upper left corner sees the three cells 15, 15 and 16, which give 46.

Weight the cells of the window

The three blocks smooth the map of 2 July with weights. Without weights the center is 15.33 and the lower left corner 16.5, the mean of 17, 17, 16 and 16.
  1. weighting_function gaussian with weighting_factor 1. The weight falls with the distance from the center, so the cell itself counts more than in the plain average: the lower left corner is 16.62, nearer to its own value 17 than the plain 16.5.
  2. weighting_function exponential with weighting_factor -1 weights by exp(-d), which falls faster with the distance than the Gaussian weights of the first block: the corner is 16.69.
  3. weighting_function file with weight takes the matrix of a text file. The matrix 1 1 1 / 1 1 1 / 0 0 0 gives the row below the center the weight 0, so the center is the mean of the six cells above and beside it, (15 + 15 + 14 + 16 + 15 + 15) / 6 = 15.

Compute only some cells

The current region has 4 by 4 cells of 1 km. scene_around (6 by 6 cells) contains the region, scene_inside (2 by 2 cells) lies within it, scene_shifted (4 by 4 cells) overlaps it and scene_remote (2 by 2 cells) is far away.

Draw a map before and after the filter

The dataset rain_noisy has two maps of 40 by 40 cells, the rain of 2 and 3 July in a window in the mountains of the west with a checkerboard of plus and minus 3 mm added. The noise is assumed; it makes the effect of the filter visible. The figure shows rain_noisy_2020_07_02 on the left and its 3 by 3 average on the right. The same color table is used for both maps, so the colors mean the same values. The average smooths away most of the checkerboard, as every window inside the region holds five cells of one sign and four of the other, so that a flat field keeps a remainder of 3 / 9 mm; at the edge of the region the window holds fewer cells, 2 and 2 in a corner and 3 and 3 at an edge, and the noise cancels. The average leaves the trend of the rain; the range of the values shrinks from 9 to 20 mm in rain_noisy_2020_07_02 to 11.9 to 17.3 mm in the first new map, whose smallest value 107 / 9 and largest value 156 / 9 are sums of nine cells. The white cell in the upper left corner of the left map has no value in the input; the average fills it from its neighbors.
