DESCRIPTION

t.rast.accdetect finds, in a space time raster dataset of accumulated values, the maps and cells in which the accumulated value lies in a given range. The input is the result of a run of t.rast.accumulate, for instance the growing degree days of a crop, and the range is, for instance, the sum at which the crop germinates and the sum at which it is harvested. The tool writes two space time raster datasets. The occurrence dataset tells when the sum was in the range, and the optional indicator dataset marks the start, the course and the end of every stretch of time in which it was. See the introduction to temporal data processing for space time datasets.

Cycles

The tool works through the input dataset in cycles, as t.rast.accumulate does, and restarts at the beginning of every cycle.
  • start is the beginning of the first cycle and is required. With absolute time it is a date such as 2026-03-01; with relative time it is an integer in the unit of the dataset.
  • cycle is the length of a cycle, such as 12 months or 4 days, and is required. With relative time it is an integer.
  • offset is a time that is skipped between the end of a cycle and the beginning of the next one. Maps that start in the skipped time are not used. Without offset, a cycle begins where the cycle before ended. A negative offset is refused when a map would lie in two cycles, and when a cycle would not start after the one before it.
  • stop ends the last cycle. A cycle that reaches beyond stop ends at stop, and a map that starts at stop or later is not used. Without stop, the run ends with the input dataset; a map that is a time instant at the end of the dataset is processed as well.

A map belongs to the cycle in which it starts. A cycle in which no map starts is skipped. The cycle and the offset must be the ones that t.rast.accumulate used for the input dataset; start and stop need not be the same. Cycles and offsets in months or years are counted from start, as in t.rast.accumulate, and a month step that ends behind the last day of a month ends on that day, so monthly cycles from 2001-01-31 start on 2001-02-28 and 2001-03-31. If only one of cycle and offset is in months or years, such as a cycle in months with an offset in days, each cycle starts one offset after the end of the cycle before.

t.rast.accumulate moves its start to the beginning of its granularity, a month to its first day, and t.rast.accdetect does not. For the same cycles, give t.rast.accdetect the moved start.

The range

A cell is in the range when its value is above the minimum and below the maximum; the two bounds themselves are not in the range. The bounds come from the options minimum, maximum and range:
  • range takes two numbers, min,max, such as range=480,730. They are used for all cells and all maps for which no map of minimum or of maximum is found. A range with the bounds the wrong way round, such as 45,15, finds nothing.
  • minimum and maximum name space time raster datasets, which allow a different bound for each cell and each time. For example, to detect the germination (minimum) and the harvest (maximum) of different crops in Germany with growing degree days, the cells of the crops differ, and so do the bounds of one cell when the crops rotate. Both datasets must have the same temporal type as the input dataset.

The bound for a map of the input dataset is looked up by the temporal relation of the map to the maps of the dataset minimum or maximum. First the maps that have the time of the map are used. If there are none, the maps that cover the time of the map are used, then the maps that overlap it at its start or at its end, and last the maps that lie within it. The first map of the first relation that has any map gives the bound; the maps of different relations are never mixed. If no map is found, or the dataset is not given, the bound comes from range. The tool refuses to start without range unless both minimum and maximum are given, and it ends with a message when a map of the input dataset has no bound at all.

Output

The option occurrence names the new dataset and is required. For every input map it has a map that has the time of the input map and holds, in each cell in the range, the time from the beginning of the cycle to the start of the input map, and null elsewhere. With absolute time the unit is days; with relative time it is the unit of the dataset.

The option indicator names a second new dataset with the same maps. Its cells hold one of three integers: 1 where a stretch of time in the range starts, 2 while it goes on and 3 where it ends. The option staend changes the three values, for instance staend=10,20,30; the default is 1,2,3. A cell that is null in the occurrence map is null in the indicator. A stretch that is still going on at the last map of a cycle ends there, so that map gets the end value. A stretch of a single map has no map to end it after its start: it gets the start value only, never the end value. The same holds for a map that is alone in its cycle.

The flag -r works through every cycle from its last map back, for an input dataset that t.rast.accumulate made with its flag -r. The indicator then starts a stretch at its last map in time and ends it at an earlier map; a stretch that is still going on at the first map of the cycle ends there, so the first map gets the end value. The occurrence still counts the time from the beginning of the cycle, whatever the direction.

The maps in which no cell is in the range are empty. The flag -n registers the empty maps in the output datasets; without it, they are removed.

The option basename is the beginning of the names of the new maps and is required. The name of an occurrence map is the basename, an underscore and the suffix, such as occ_2026_03_02. An indicator map has the word indicator behind the basename, such as occ_indicator_2026_03_02. The option suffix selects the suffix:

  • gran (the default) takes, with absolute time, the start of the input map cut to the granularity of the input dataset, such as 2026_03_02. An input dataset that has only a time instant has no granularity, and gran then gives the full start time like time. This description is for absolute time only.
  • time takes the full start time, such as 2026_03_02T00_00_00.
  • num takes a number of five digits, from 1; num%NN takes NN digits, so num%02 gives 01. The numbers count the maps of each dataset in the order of the computation, over all cycles.

NOTES

The new datasets and maps are created in the current mapset. The last example reads an input dataset of another mapset, input=gdd@t_rast_accdetect. The input and the datasets of minimum and maximum are read from any mapset of the project that has a temporal database; a name without a mapset is searched in the current mapset first, then in the search path (see Datasets of other mapsets).

An existing occurrence or indicator dataset stops the run before any computation, unless --overwrite is set. A name with a dot is refused for a new dataset before any map is made, and so is a dataset of another mapset: "Space time datasets can only be created in the current mapset". A new map whose name is that of a map that is registered elsewhere is refused with the message "Map <name@mapset> is already registered in the temporal database, use overwrite flag to overwrite"; with --overwrite the new map replaces it and leaves the other dataset. A new map whose name is that of an existing raster map that no dataset holds is refused with "Raster map <name@mapset> exists. To overwrite, use the --overwrite flag."; with --overwrite the new map replaces it. All new names are checked before the first map is computed, so a refused run leaves no map behind. The names follow the granularity of the input dataset, and the tool has no option to change it. A map that lies in two overlapping cycles (a negative offset) is refused whatever the suffix is, because the tool writes one result for each input map and the first result of that map would stay behind in no dataset. The message is "The map <map> lies in overlapping cycles, but the tool writes one result for each input map. Use an offset that does not move the next cycle back into the one before." An offset that would give the same cycle start twice, such as a month with an offset of -29 days, ends with "The offset must not move the next cycle back to or before the start of this one". Two input maps that get one name, such as two maps of the same time with the suffix gran, are refused with "The maps <map1> and <map2> are given the same name <name> by the suffix gran. Use the suffix num or select maps of different times." Daily maps that overlap and start at different times of the same day, such as one from 10:30 and one from 14:30, have a granularity of one day, so gran gives them the same name as well; use the suffix num for them.

If no map with values is computed for an output, the tool warns, for example "No map with values was computed in any cycle. No space time dataset <name> was created.", and does not create that dataset. This happens when the cycles lie before or after the data or in a gap, when a stop is not after the start (such as a relative stop of 0), and when every map of the output is empty and -n is not set. With --overwrite, an output dataset that exists is removed in this case, and the tool warns again that it did so. The maps of the removed dataset stay as maps, except for maps that have the name of a new map, which the computation replaces and then removes. The first two examples leave out the empty maps and the third one registers them. An empty input dataset ends with a warning and creates no output.

Wrong input stops the tool with a message before anything is written:

  • An input, minimum or maximum dataset that does not exist: "Space time raster dataset <name@mapset> not found".
  • A minimum or maximum dataset of another temporal type than the input: "Temporal type of input strds and minimum strds must be equal".
  • No range and a missing minimum or maximum: "You need to set the range to compute the occurrence space time raster dataset". A map of the input dataset that has no bound from the datasets and no range gives "No minimum map found for <map> and no range given", or the same for maximum.
  • A start or stop that is not a date, such as "Invalid date <garbage> of the option <start>"; with relative time "The options start and stop must be integers". A cycle or offset that cannot be read: "Invalid cycle" or "Invalid offset".
  • A cycle that does not move time forward: "The cycle must be longer than zero". An offset that moves the next cycle back to or before the start of the cycle: "The offset must not move the next cycle back to or before the start of this one".
  • An unknown suffix: "Invalid suffix <gram>, use gran, time, num or num%NN".

With relative time, the unit of the dataset is the unit of start, stop, cycle and offset; they are integers without a unit.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_accdetect and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region, and the last one in a second mapset. The first example applies the tool to a heat sum; the others use small constant values, so that the sums and the stretches of time can be recomputed by hand.

Find the development stage of a crop

A crop or an insect develops through a stage while the heat sum lies between two values. The first block builds the monthly mean air temperature of 2020 in degree Celsius over North Carolina, 12 maps with a computed pattern: warmer in summer, colder with height and a little colder towards the north. The dataset is generated, not measured. The block then accumulates the heat sum above 10 degrees Celsius with t.rast.accumulate, with one cycle of 12 months. Its default granularity is one day, so the granularity of one month is given; every month then adds its mean minus 10, when that is positive, and the unit of the sum is degree months (about 30 degree days). The tool t.rast.what prints the temperature and the sum of every month for three cells: in the Mountains (1407 m), in the Piedmont near Raleigh (115 m) and on the coast (0 m), from left to right.

The second block detects the stage between 20 and 60 degree months, which is about 600 to 1800 degree days. The bounds themselves are not in the range. The maps of the occurrence dataset hold, in the cells in the range, the days from 1 January to the start of the map, such as 152 for 1 June; the maps of January to April have no cell in the range and are left out. The listing shows that every map has one value. The indicator marks the first month of the stage with 1, the months in between with 2 and the last month with 3. The Piedmont cell is in the range from June to August (27.1, 42.7 and 57.4 degree months) and has 1, 2 and 3. The coast cell passes the range in two months (33.9 and 51.4), has 1 and 3, and the cell in the Mountains never reaches 20.

Follow the sums cell by cell

The next examples are time logic. The dataset temperature_daily has eight daily maps from 1 to 8 March 2026 in degree Celsius. Each map holds the value base + 2 * (min(column, 3) - 1) in a cell, so the first three cells of the northern row, the ones that the listings show, differ by two, and all cells further east have the value of the third. The base is 12, 14, 16 and 18 on the days 1 to 4, and the same again on the days 5 to 8, so the data hold two cycles of four days.

The first block accumulates growing degree days above 10 with t.rast.accumulate, with one cycle of four days. The increment of a day is its value minus 10, so the sums of the first cell are 2, 6, 12 and 20, those of the second cell 4, 10, 18 and 28, and those of the third cell 6, 14, 24 and 36, in each cycle. The tool t.rast.what prints, for each map, the values of the three cells from west to east, given by the coordinates of their centers.

The second block detects the sums in the range from 8 to 25 with the same cycle. The occurrence dataset holds the days since the beginning of the cycle. The first cell reaches 12 on the third day, which is day 2 counted from 0, and 20 on the day 3, so it has 2 and 3. The second cell has 10 and 18 on the days 1 and 2, and the third cell 14 and 24. The sums 2, 4 and 6 of the first day, and the cells above 25, are not in the range. The map of the first day of each cycle is empty and not registered. The indicator marks the start with 1, the course with 2 and the end with 3: the second cell starts on day 1 and ends on day 2, because its sum 28 on day 3 is above the range; the first cell starts on day 2 and is still in the range on day 3, the last map of the cycle, so this map gets the end value 3.

Detect backwards in time

t.rast.accumulate with its flag -r accumulates every cycle from the last day to the first: the map of the last day holds the increment of one day and the map of the first day the sum of all. The first cell has 20 on the first day, 18 on the second, 14 on the third and 8 on the last. With the same range from 8 to 25 and the flag -r, t.rast.accdetect works through the cycle from the last map back. The first cell is not in the range on the last day (8 is not above 8), starts on the third day (14), goes on the second day (18) and ends on the first day (20), so its indicator is 1, 2 and 3 from the third to the first day. The third cell starts on the last day (12), and ends on the third day (22). The occurrence still counts the days from the beginning of the cycle: 0 for the first day of the cycle.

Take the bounds from datasets

The dataset lower has one map with the value 15 from 5 to 9 March, and the dataset upper one map with the value 20 from 1 to 9 March. Used as minimum and maximum, they replace the range where a map is found: every map of the input lies within the map of upper, so the upper bound is 20 for all of them, and the maps of the second cycle lie within the map of lower, so the lower bound is 15 there. The maps of the first cycle have no map of lower, and take the lower bound 8 from range; the upper bound 25 of range is not used. The bounds are not part of the range: the sum 20 of the first cell is not below 20 and does not count. Compared with the detection of the range from 8 to 25, the first cycle loses the sums 20 and 24, and the second cycle all sums but 18, which is above 15: only the second cell on 7 March is left there.

The second block shows a map within the time of an input map. The dataset upper_noon has one map with the value 20 from 6:00 to 18:00 on 3 March. It lies within the granule of 3 March and gives the upper bound there; all other maps take the upper bound 25 from range. The sum 24 of the third cell on 3 March is not below 20, but it is below 25 on 7 March.
