DESCRIPTION

t.remove removes space time datasets from the temporal database of the current mapset. A space time dataset (STRDS, STR3DS or STVDS) is a collection of time stamped maps; see the introduction to temporal data processing for an overview. t.remove is the counterpart of t.create. By default it removes only the dataset and leaves its maps alone: they stay in the mapset and, with their time stamps, in the temporal database, as t.list with type raster shows.

The datasets are named with inputs, a comma separated list, or with file, a text file that holds one name per line. Empty lines in the file are skipped and blanks around a name are ignored. A name may carry its mapset (rain@PERMANENT). The options inputs and file exclude each other, and one of them is required.

The option type gives the type of all datasets of the call: strds (the default), str3ds or stvds. A dataset is found by its type and name, so the call refuses a name that belongs to a dataset of another type.

Nothing is removed without the flag -f (force). Without it, t.remove only reports, as messages on the standard error, which datasets it would remove and, with -r or -d, the names of their maps, and ends with the message "Nothing removed. You must use the force flag (-f) to actually remove them." With -f, the flags choose how far the removal goes:

  • no further flag: the datasets are removed and their maps are left as they are;
  • -r (recursive): the datasets are removed and their maps are unregistered from the temporal database. The maps stay in the mapset, but are no longer known to the temporal database and belong to no dataset;
  • -d (delete): as -r, and the maps are also deleted from the mapset, with g.remove: raster maps for strds, 3D raster maps for str3ds and vector maps for stvds. -d alone does what -r and -d together do. A vector map with several layers is deleted once.

Only maps of the current mapset are deleted, because GRASS writes to the current mapset only. For each registered map of another mapset, t.remove with -d warns that the map is not removed, and still removes the dataset.

A map can be registered in several datasets. With -r or -d, a map is taken out of every dataset that holds it. A dataset that is not removed and loses maps this way gets its number of maps, time and spatial extent and the other metadata computed again from the maps that are left; t.info shows the new values.

NOTES

All datasets of a call are opened before the first one is removed. A name that does not exist stops the run with an error before anything has changed, so that a call with an unknown name after valid ones removes none of them. The same holds for a call with both or neither of inputs and file, for which the errors are "inputs= and file= are mutually exclusive" and "inputs= or file= must be specified". A missing file is reported as an error with the file name.

Removing a dataset twice fails the second time with the error that the dataset does not exist, because the first call removed it.

A dataset is found by its type. A call with the wrong type for the name, such as the default strds for a space time 3D raster dataset, stops with an error like Space time dataset <soil> of type <strds> not found; give type=str3ds.

A dataset of an earlier release can have a dot in its name. It is found by its whole name and removed like any other dataset; only for a name that no dataset has, the text after the dot is read as a semantic label.

A dataset of another mapset is refused with Unable to delete dataset <name@mapset> of type strds from the temporal database. The mapset of the database does not match the current mapset. The refusal comes before the listing of a call without -f and before the first removal of a call with it, so the listing never names a dataset that the same call with -f would refuse.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_remove and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region. t.remove removes datasets and, with -d, maps of the current mapset only, so no map of the sample dataset is touched. The maps of the examples hold small constant values.

Remove a dataset and keep its maps

Two space time raster datasets hold five maps in all: rain has three daily maps of precipitation in mm, 4, 2 and 6 mm in every cell, snow two maps of snow depth in cm, 5 and 7 cm. t.list shows both datasets of the current mapset and, with type raster, all five maps with their time stamps. After t.remove -f inputs=rain, the second command lists three results: first the datasets, where only snow is left, then the registered maps, where all five are still found, and last the maps named rain_* in the mapset, found with g.list.

Command line:

g.mapset -c mapset=t_remove
g.region raster=elev_state_500m res=1000 -a
r.mapcalc expression="rain_1 = 4"
r.mapcalc expression="rain_2 = 2"
r.mapcalc expression="rain_3 = 6"
r.mapcalc expression="snow_1 = 5"
r.mapcalc expression="snow_2 = 7"
t.create output=rain title="Rain" description="Daily precipitation in mm"
t.register -i input=rain maps=rain_1,rain_2,rain_3 \
    start=2026-06-01 increment="1 day"
t.create output=snow title="Snow" description="Daily snow depth in cm"
t.register -i input=snow maps=snow_1,snow_2 \
    start=2026-06-01 increment="1 day"
t.list type=strds columns=name,number_of_maps mapset=.
t.list type=raster columns=name,start_time mapset=.

Maps that belong to two datasets

The map shared_2 is registered in first and in second. Removing first with -r unregisters its maps from second too. second stays, and t.info shows that it has only one map left, shared_3, with its start and end time computed from that map.

Command line:

r.mapcalc expression="shared_1 = 3"
r.mapcalc expression="shared_2 = 5"
r.mapcalc expression="shared_3 = 8"
t.create output=first title="First" description="Maps 1 and 2"
t.register -i input=first maps=shared_1,shared_2 \
    start=2026-08-01 increment="1 day"
t.create output=second title="Second" description="Maps 2 and 3"
t.register -i input=second maps=shared_2,shared_3 \
    start=2026-08-02 increment="1 day"
t.remove -rf inputs=first
t.info -g input=second | grep -E "^(number_of_maps|start_time|end_time)="
t.rast.list input=second

start_time='2026-08-03 00:00:00'
end_time='2026-08-04 00:00:00'
number_of_maps=1

Remove datasets of other types

With type, t.remove works on space time 3D raster datasets and on space time vector datasets. -d then deletes 3D raster maps or vector maps. Here, a dataset of each type is created and removed with its maps. A copy of each map, registered in no dataset, shows that g.list lists the maps before the removal and only the copies after it.

Command line:

g.region raster=elev_state_500m res=1000 -a
g.region t=3 b=0 res3=1000 tbres=1
r3.mapcalc expression="soil_1 = depth()"
t.create type=str3ds output=soil title="Soil" description="Soil layers"
t.register -i type=raster_3d input=soil maps=soil_1 \
    start=2026-03-01 increment="1 day"
v.in.ascii input=- output=gauges_1 separator=comma \
    columns="x double precision, y double precision, speed double precision" <<EOF
400000,100000,3.0
700000,200000,5.0
EOF
t.create type=stvds output=gauges title="Gauges" description="Wind speed"
t.register -i type=vector input=gauges maps=gauges_1 \
    start=2026-03-01 increment="1 day"
g.copy raster_3d=soil_1,soil_copy
g.copy vector=gauges_1,gauges_copy
g.list type=raster_3d mapset=.
