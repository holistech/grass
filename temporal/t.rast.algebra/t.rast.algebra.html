DESCRIPTION

t.rast.algebra performs temporal and spatial map algebra operations on space time raster datasets (STRDS) by using the temporal raster algebra. It reads an expression of the form result = expression, relates the maps of the datasets in the expression by their time (and, with -s, by their place), computes each result map with r.mapcalc and registers the result maps in a new space time raster dataset in the current mapset. Use it when the maps to combine are not simply paired by equal time stamps, or when a result depends on how the time intervals of the maps lie to each other. To compute with the maps of the datasets for each time step with a single r.mapcalc expression, see t.rast.mapcalc. The counterparts for 3D raster and vector datasets are t.rast3d.algebra and t.vect.algebra, and t.select selects maps without computing. See the introduction to temporal data processing for space time datasets.

The algebra provides methods for map selection based on their temporal relations. It is also possible to temporally shift maps, to create temporal buffer and to snap time instances to create a valid temporal topology. Furthermore, expressions can be nested and evaluated in conditional statements (if, else statements). Within if-statements, the algebra provides temporal variables like start time, end time, day of year, time differences or number of maps per time interval to build up conditions. In addition the algebra provides a subset of the spatial operations from r.mapcalc. All these operations can be assigned to STRDS or to the map lists resulting of operations between STRDS.

Expression, result and maps

The statement structure of the option expression is similar to that of r.mapcalc: 
"result = expression"

The name left of the equal sign is the new STRDS that will contain the result of the calculation on the right side. The expression can be any valid or nested combination of temporal operations and spatial overlay or buffer functions that are provided by the temporal algebra, as described below. The option must be passed as quoted expression, for example: 

t.rast.algebra expression="C = A + B" basename=result

Here C is the new space time raster dataset that will contain maps with the basename "result" and a numerical suffix separated by an underscore that represent the sum of maps from the STRDS A and temporally equal maps (i.e., maps with equal temporal topology relation) from the STRDS B.

The result dataset is created in the current mapset, and an existing dataset of that name is replaced only with --overwrite; without it the tool stops with the error Space time dataset <C@t_rast_algebra> exists. Use the overwrite flag. The name of the result must not contain a dot or a mapset. The parser stops at the dot with the error "Unexpected character '.'". No dataset is created. A dataset of another mapset is named name@mapset in the expression. A name without mapset is searched in the current mapset first, then in the mapsets of the search path (see the example "Use datasets of another mapset").

The option basename is required. The result maps are named basename_0, basename_1 and so on, numbered in the order in which the algebra computes them. This is not always the order of their time. The number is padded with zeros to the digits of the count of computed maps: ten maps are named basename_00 to basename_09 (see the example "Catalog: merge, single maps and the neighbourhood modifier"). A map that is null everywhere is not registered unless -n is given. The algebra numbers only the registered maps, so such a map leaves no gap: the next registered map takes its number (see the example "Spatially related maps and empty maps"). A neighbourhood modifier that reaches before the first map makes such a map, see the last example of "Catalog: the expressions of the original manual". The dry run with -d shows the names of a run that registers every computed map. An expression that leaves no map to register ends with the warning "The expression produced no map, the result is empty", and the result is an empty dataset.

The option suffix changes the part of the names after the basename. num, the default, is the number described above. For absolute time, gran takes the start time of the map cut to the granularity of the result and time the full start time, see the example "Name the result maps and plan a run". A monthly result from the last day of a month (January 31, February 28) has the granularity of one month, so gran gives year and month (2026_01), see the introduction. num%NN pads the number with zeros to NN digits: suffix=num%03 names the maps basename_000, basename_001 and so on, as in t.rast.extract.

The option nprocs is the number of r.mapcalc processes that run at the same time. The default is 1. The result is the same for any number.

Flags

-s also checks the spatial topology of temporally related maps and processes only maps that are related in space too. -n registers maps that are null everywhere, which are left out by default. -g uses the granularity algebra instead of the temporal topology of the maps, see "Granularity algebra" below. -d performs a dry run: it plans the maps and prints the process chain, but computes no map and creates no dataset.

TEMPORAL RASTER ALGEBRA

The temporal algebra provides a wide range of temporal operators and functions that will be presented in the following section.

TEMPORAL RELATIONS

Several temporal topology relations are supported between maps registered in space time datasets: 
equal             A ------
                  B ------

during            A  ----
                  B ------

contains          A ------
                  B  ----

starts            A ----
                  B ------

started           A ------
                  B ----

finishes          A   ----
                  B ------

finished          A ------
                  B   ----

precedes          A ----
                  B     ----

follows           A     ----
                  B ----

overlapped        A   ------
                  B ------

overlaps          A ------
                  B   ------

over              both overlaps and overlapped

The relations must be read as: A is related to B, like - A is equal to B - A is during B - A contains B.

Gebbert, Leppelt and Pebesma (2019) write the relation equal as equals; the algebra reads both names. The releases before GRASS 8.6 refused equals with a syntax error.

Topological relations must be specified with curly brackets {}.

The relations during and contains are inclusive: during also selects maps that start or finish together with the related map (the relations starts and finishes), and contains also selects maps with the relations started and finished. The relations precedes and follows only apply to maps that touch each other, that is the end of one map is the start of the other. Maps that are separated by a gap have no relation.

TEMPORAL OPERATORS

The temporal algebra defines temporal operators that can be combined with other operators to perform spatio-temporal operations. The temporal operators process the time instances and intervals of two temporally related maps and calculate the resulting temporal extent in five possible different ways. 
LEFT REFERENCE     l       Use the time stamp of the left space time dataset
INTERSECTION       i       Intersection
DISJOINT UNION     d       Disjoint union
UNION              u       Union
RIGHT REFERENCE    r       Use the time stamp of the right space time dataset

TEMPORAL SELECTION

The temporal selection simply selects parts of a space time dataset without processing any raster or vector data. The algebra provides a selection operator : that by default selects parts of a space time dataset that are temporally equal to parts of a second space time dataset. The following expression 
C = A : B

means: select all parts of space time dataset A that are equal to B and store them in space time dataset C. These parts are time stamped maps.

In addition, the inverse selection operator !: is defined as the complement of the selection operator, hence the following expression 

C = A !: B

means: select all parts of space time time dataset A that are not equal to B and store them in space time dataset C.

To select parts of a STRDS using different topological relations regarding to other STRDS, the temporal topology selection operator can be used. This operator consists of the temporal selection operator, the topological relations that must be separated by the logical OR operator | and, the temporal extent operator. All three parts are separated by comma and surrounded by curly brackets as follows: {"temporal selection operator", "topological relations", "temporal operator"}.

Examples: 

C = A {:,equal} B
C = A {!:,equal} B

We can now define arbitrary topological relations using the OR operator "|" to connect them: 

C = A {:,equal|during|overlaps} B

Select all parts of A that are equal to B, during B or overlaps B.
In addition, we can define the temporal extent of the resulting STRDS by adding the temporal operator. 

C = A {:,during,r} B

Select all parts of A that are during B and use the temporal extents from B for C.

The selection operator is implicitly contained in the temporal topology selection operator, so that the following statements are exactly the same: 

C = A : B
C = A {:} B
C = A {:,equal} B
C = A {:,equal,l} B

Same for the complementary selection: 

C = A !: B
C = A {!:} B
C = A {!:,equal} B
C = A {!:,equal,l} B

CONDITIONAL STATEMENTS

Selection operations can be evaluated within conditional statements as showed below. Note that A and B can be either space time datasets or expressions. The temporal relationship between the conditions and the conclusions can be defined at the beginning of the if statement (third and fourth examples below). The relationship between then and else conclusion must be always equal. 
if statement                        decision option                        temporal relations
  if(if, then, else)
  if(conditions, A)                   A if conditions are True;              temporal topological relation between if and then is equal.
  if(conditions, A, B)                A if conditions are True, B otherwise; temporal topological relation between if, then and else is equal.
  if(topologies, conditions, A)       A if conditions are True;              temporal topological relation between if and then is explicitly specified by topologies.
  if(topologies, conditions, A, B)    A if conditions are True, B otherwise; temporal topological relation between if, then and else is explicitly specified by topologies.

An if without else gives 0 where a condition on map values is false, like the if() of r.mapcalc with two arguments, so a map that is false everywhere is registered with the value 0.

The conditions are comparison expressions that are used to evaluate space time datasets. Specific values of temporal variables are compared by logical operators and evaluated for each map of the STRDS.
Important: && binds stronger than ||, as in r.mapcalc, and conditions can be grouped with parentheses. GRASS 8.5 evaluated conditions on temporal variables from left to right instead (see NOTES).

The relation reads from the condition to the conclusion: if({contains}, condition, A) takes the maps of A that lie within a map of the condition. A map of the then part gets a result only if it has a condition map in the given temporal relation. For a condition on temporal variables and a temporal relation beyond equal, the else part is also taken for the maps that no condition map is related to, while the then part leaves them out. if({equal}, ...) and if(...) take no such maps, because the condition speaks of maps with equal time only, and neither does a condition on map values. In this expression each map of B that contains two maps of A becomes the sum of these three maps, and the maps of A outside of B are kept unchanged by the else part: 

C = merge(if({equal|contains}, B {#,contains} A == 2, B {+,contains,l} A, A), A {!:,during} B)

The result stays the same without the merge() and the inverse select operator, because the else part takes the maps without condition map.

Several maps with equal time stamps cannot be told apart by their time. An arithmetic operator aggregates them (E + E adds all maps of a time to each map of E), a conditional pairs them: a single condition map applies to all conclusion maps of its time, n condition maps of a time are paired with n conclusion maps of that time in the order of the datasets. Different numbers of several maps of one time are an error.

In order to use the numbers returned by the functions in the last block above, an offset value needs to be added. For example, start_doy(A, 0) would return the DOY of the current map in STDS A. end_hour(A, -1) would return the end hour of the previous map in STDS A.

A function whose value a map does not have stops the algebra with an error that names the map: td() and the end functions of a time instance, and on relative time every function but td().

Comparison operator

As mentioned above, the conditions are comparison expressions that are used to evaluate space time datasets. Specific values of temporal variables are compared by logical operators and evaluated for each map of the STDS and (optionally) related maps. For complex relations, the comparison operator can be used to combine conditions.
The structure is similar to the select operator with the addition of an aggregation operator: {"comparison operator", "topological relations", aggregation operator, "temporal operator"}
This aggregation operator (| or &) defines the behaviour when a map is related to more than one map, e.g. for the topological relation 'contains'. Should all (&) conditions for the related maps be true or is it sufficient to have any (|) condition that is true. The resulting boolean value is then compared to the first condition by the comparison operator (|| or &&). By default, the aggregation operator is related to the comparison operator:
comparison operator -> aggregation operator: 
|| -> | and && -> &

Examples: 

Condition 1 {||, equal, r} Condition 2
Condition 1 {&&, equal|during, l} Condition 2
Condition 1 {&&, equal|contains, |, l} Condition 2
Condition 1 {&&, equal|during, l} Condition 2 && Condition 3
Condition 1 {&&, equal|during, l} Condition 2 {&&,contains, |, r} Condition 3

Comparison of related maps

Inside if(), the values of two space time datasets can be compared with the comparison operators ==, !=, >, >=, < and <=. Each map of the first dataset is compared with every map of the second dataset that has one of the given topological relations to it. The result for a map is true if all comparisons are true (aggregation &) or if any is true (aggregation |). The operator in braces has the form {"comparison operator", "topological relations", aggregation operator, "temporal operator"}; the aggregation operator and the temporal operator are optional, the aggregation operator is & and the temporal operator l by default, and the relations default to equal if the braces are left out. The short form A >= F is the operator {>=, equal, &, l}. A map of the first dataset without a related map gives a null map: 
if(A {>=, contains, |} E, A, 0)
if(A {<, equal|during, &, r} F, F, 0)
if(A >= F, A, F)

The first expression is true for a map of A if it is greater than or equal to any related map of E; the last one gives, for each map of A, the value of A where it is not smaller than the map of F with the same time, and the value of F otherwise. The short form compares maps of equal time stamps cell by cell, as A + F does, and stops with an error if the time stamps differ. With the temporal reference r, the algebra compares each pair on its own, as it does for && and ||. Earlier GRASS releases did not read the comparison of two datasets, neither in braces nor as A >= F. The granularity mode (-g) reads the short form; it refuses the operator in braces, as it refuses every operator in braces.

Hash operator

Additionally, the number of maps in intervals can be computed and used in conditional statements with the hash (#) operator. 
A {#, contains} B

The hash operator is mostly used in the condition of an if statement, but it can also stand alone or in arithmetic, where it has the precedence of + and -: B {#,contains} A + B adds the count to each map of B.

This expression computes the number of maps from space time dataset B which are during the time intervals of maps from space time dataset A.
A list of integers (scalars) corresponding to the maps of A that contain maps from B will be returned.

The result keeps the time stamps of the maps of A. The temporal operators r, u, i and d have no meaning for the count and are rejected with a syntax error; l is the default. 

C = if({equal}, A {#, contains} B > 2, A {:, contains} B)

This expression selects all maps from A that temporally contain more than 2 maps from B and stores them in space time dataset C. The leading equal statement in the if condition specifies the temporal relation between the if and then part of the if expression. This is very important, so we do not need to specify a global time reference (a space time dataset) for temporal processing.

Furthermore, the temporal algebra allows temporal buffering, shifting and snapping with the functions buff_t(), tshift() and tsnap(), respectively. 

buff_t(A, size)         Buffer STDS A with granule ("1 month" or 5)
tshift(A, size)         Shift STDS A with granule ("1 month" or 5)
tsnap(A)                Snap time instances and intervals of STDS A

A negative size shrinks the maps; the algebra stops with an error where a map would keep no time, see "Differences from GRASS 8.5".

tsnap() ends a last map that is a time instance one granularity of the maps after its start. A granularity of months counts from the first map, with the cut to the end of a shorter month: the time instances January 31, February 28 and March 31 have the granularity of one month, and the last one ends on April 30; after an instance on April 30 in the same series it ends on May 31. GRASS 8.5 computed the granularity of one day here and ended the instance of March 31 on April 1.

Merge function

The function merge() returns the union of the maps of two space time datasets or of two expressions. The datatype of both operands must be the same. 
C = merge(A, B)

A map that occurs in both operands identically, that is with the same map name, the same time stamps and the same computation, is kept once in the result and the algebra prints a warning. This happens, for example, if two selections of one dataset overlap. Maps of equal time stamps that were computed differently are both kept: 

C = merge(A + 1, A + 2)

Single map with temporal extent

The temporal algebra can also handle single maps with time stamps in the tmap() function. 
tmap()

For example: 

C = A {:, during} tmap(event)

This statement selects all maps from space time data set A that are during the temporal extent of the single map 'event'

Single raster map

The temporal raster algebra features also a function to integrate single raster maps without time stamps into the expressions. 
map()

For example: 

C = A * map(constant_value)

This statement multiplies all raster maps from space time raster data set A with the raster map 'constant_value'

Combinations of temporal, raster and select operators

The user can combine the temporal topology relations, the temporal operators and the spatial/select operators to create spatio-temporal operators as follows: 
{"spatial or select operator", "list of temporal relations", "temporal operator"}

For multiple topological relations or several related maps the spatio-temporal operators feature implicit aggregation. The algebra evaluates the stated STDS by their temporal topologies and apply the given spatio-temporal operators in a aggregated form. If we have two STDS A and B, B has three maps: b1, b2, b3 that are all during the temporal extent of the single map a1 of A, then the following arithmetic calculations would implicitly aggregate all maps of B into one result map for a1 of A: 

 C = A {+, contains} B --> c1 = a1 + b1 + b2 + b3

Important: the aggregation behaviour is not symmetric 

 C = B {+, during} A --> c1 = b1 + a1
                         c2 = b2 + a1
                         c3 = b3 + a1

Temporal neighbourhood modifier

The neighbourhood modifier of r.mapcalc is extended for the temporal raster algebra with the temporal dimension. The format is strds[r,c,t], where r is the row offset, c is the column offset and t is the temporal offset. A single neighborhood modifier is interpreted as temporal offset [t], while two neighborhood modifiers are interpreted as row and column offsets [r,c]. 
strds[2]

refers to the second successor of the current map. 

strds[1,2]

refers to the cell one row below and two columns to the right of the current cell in the current map. 

strds[-2,-1,1]

refers to the cell two rows above and one column to the left of the current cell of the first successor map. 

strds[0,1,-2]

refers to the cell one column to the right of the current cell in the second predecessor map.

NOTES

By default, only temporal topological relations among space time datasets (STDS) are evaluated. The -s flag additionally activates the evaluation of the spatial topology of the maps. It applies wherever the algebra evaluates the topology of maps: in selections, in the hash operator, in the conditions of if statements, in comparison operators and in the spatial operators. Two temporally related maps are then only used together if they are also spatially related, that is the spatial extents of the maps are equivalent, one covers or is covered by the other, they overlap, one lies in the other, one contains the other, or they meet (the spatial relations equivalent, cover, covered, overlap, in, contain and meet). The relations equivalent, cover, overlap, in, contain and meet can also be named in the curly brackets of a spatial operator, for example {+,equal|overlap}; the maps then need this spatial relation in addition to the temporal one. Such a name builds the spatial topology for its operator also without -s.

Maps are computed in the current region. A map that the result takes over unchanged, for example one that a selection stamps with a new time, is copied there as well; with -s, r.mapcalc computes such a copy in the union of the regions of its input maps instead. A copy of a map that lies outside the region has no data. Like any map without data it is not registered unless -n is given, and a warning names it and the map it copies. Set the region with g.region so that it covers the maps.

Datasets of absolute and of relative time work in the same way, and the result has the temporal type of the datasets in the expression. The steps of tshift() and buff_t() are numbers in the unit of a dataset of relative time and texts such as "1 day" for absolute time. Datasets of both temporal types cannot be related in one expression: the tool stops with an error and creates no dataset (see the example "Catalog: select and combine maps by temporal relations").

An existing result dataset without --overwrite stops a dry run with -d as it stops a real run.

Differences from GRASS 8.5

Since GRASS 8.6, t.rast.algebra computes its expressions with the functions of the Python package grass.temporal.algebra. The implementation of the releases up to GRASS 8.5 is no longer part of GRASS; it is available in those releases and in the history of the source code (tag classic-reference-corpus). The expressions of the publication cited under REFERENCES compute in GRASS 8.6, see "Catalog: expressions of the publication". Some expressions give other results than in GRASS 8.5, as the following points describe; where such an expression also meets one of the cases under "Results corrected since GRASS 8.5" below, GRASS 8.5 behaved as described there for the earlier versions. The examples use four daily maps in A with the values 1 to 4, two maps of two days in B that start with A, and time instances in I.
  1. One result per conclusion map. If a map of the conclusion of an if has several related condition maps, their conditions are joined with and; written as {during,|}, the relation joins them with or. GRASS 8.5 gave one result for each pair of condition map and conclusion map, so that a conclusion map could occur several times. The first expression keeps the cells of B where both maps of A within the map of B are greater than 1, the second where one of them is: 
    C = if({during}, A > 1, B, 0)
C = if({during,|}, A > 1, B, 0)
  2. Equal time stamps for then and else. With a condition on map values, the then and the else part need equal time stamps; otherwise the algebra stops with an error. GRASS 8.5 computed only the maps whose time stamp occurs in both parts and left out the others without notice. This expression is therefore an error, where GRASS 8.5 gave an empty result: 
    C = if(A > 2, A, B)
  3. Precedence. && binds stronger than ||, and conditions can be grouped with parentheses. GRASS 8.5 evaluated conditions on temporal variables from left to right and did not accept parentheses around conditions. The first expression takes all maps of A, because td(A) == 1 is true for each of them; GRASS 8.5 read it as the second expression and took none: 
    C = if(td(A) == 1 || td(A) == 2 && td(A) == 3, A)
C = if((td(A) == 1 || td(A) == 2) && td(A) == 3, A)
  4. Right reference. A {:,R,r} B and A {op,R,r} B give one map per related pair, with the time stamp of the right map and, for an operator, the value of this pair. GRASS 8.5 kept only the last pair of a selection, and an operator combined the left map with all of its related right maps in every result. The first expression gives four maps, the time stamps of A with the values of B; GRASS 8.5 gave one map per map of B. If a map b1 contains the maps a1 and a2, the second expression gives b1 + a1 and b1 + a2, GRASS 8.5 gave b1 + a1 + a2 for both: 
    C = B {:,contains,r} A
C = B {+,contains,r} A

    The inverse selection A {!:,R,t} B takes only the temporal operator l, because its maps have no related map to combine with; GRASS 8.5 accepted the other operators.

  5. More syntax. Comparisons, temporal functions and the minus sign may stand anywhere in an expression, and a dataset may have the name of a function. GRASS 8.5 reported a syntax error for each of these expressions; the last one adds 1 to a dataset named td: 
    C = A
C = -A + 10
C = A > 2
C = A + start_doy(A)
C = isnull(A)
C = td + 1
  6. Intersection with several related maps. With the temporal operator i, a map whose related maps have no common intersection is left out. GRASS 8.5 intersected the map with its related maps until the first one that had no common time with the result so far, so that its result depended on the order of the related maps. If a dataset H has a map from day 2 to day 4, this map follows the map of A of day 1 and precedes the one of day 4; the intersections are the time instances of day 2 and day 4, and the map is left out: 
    C = H {:,follows|precedes,i} A
  7. Negative buffer. A negative size in buff_t() shrinks the maps by that size at both ends. The algebra stops with an error if a map would keep no time, that is if its end would fall on or before its start, and for a time instance, which has no duration to shrink. GRASS 8.5 went on instead: for a map whose end would fall before its start it printed an error message and kept the old time stamp, and it made a time instance of a map whose end equals its start. For maps of two days, the first expression shrinks them to one day and the second is an error: 
    C = buff_t(B, "-12 hours")
C = buff_t(B, "-1 day")
  8. merge() of maps read at an offset. Two maps with equal content and time stamps are one map. GRASS 8.5 made a new map for each map read with a temporal neighbourhood modifier and for each value of a temporal function with an offset, and merge() kept such a map next to an equal one. The first two expressions give four maps, where GRASS 8.5 gave eight, the third three, where GRASS 8.5 gave six: 
    C = merge(A[0], A[0])
C = merge(A + 1, A[0] + 1)
C = merge(start_day(A, 1), start_day(A, 1))
  9. tsnap() of maps that start together. Of maps with the same start, tsnap() snaps only one to the start of the next later map; the others keep their own ends. The algebra takes the map that ends last, so its result does not depend on the order of the maps. If C has a map from day 2 to day 4, it starts with the map of A on days 2 to 3. Both expressions give the same maps, the map of C ends on day 3. GRASS 8.5 snapped such maps differently, see item 12 under "Results corrected since GRASS 8.5": 
    D = tsnap(merge(A, C))
D = tsnap(merge(C, A))
  10. Integers beyond 32 bits. The algebra keeps an integer constant beyond 32 bits and writes it as a floating point number, so the result map is of type DCELL. GRASS 8.5 read it as r.mapcalc does, which keeps only its lower 32 bits: 3000000000 becomes -1294967296, and 2147483648 becomes null. Each map of A lasts one day, so this expression gives 3000000001, where GRASS 8.5 gave -1294967295: 
    C = if(td(A) <= 0.5, A, 3000000000) + td(A)

    GRASS 8.5 also computed arithmetic on time function values as r.mapcalc does, in 32 bits, also in a condition; the algebra computes with all digits. If the two maps of RS last 3000000000 seconds each, td(RS) * td(RS) wrapped around to -494665728 in GRASS 8.5, so this expression gave the value 1 for both maps there, and it gives the maps of RS now. A time function on its own, as in if(td(RS) > 2000000000, RS, 1), kept all its digits in GRASS 8.5 as well. 

    C = if(td(RS) * td(RS) > 5, RS, 1)
  11. A number beside a temporal operator. An operator in braces or the hash operator # needs a space time dataset on both sides. GRASS 8.5 read the number with the expression behind it as the right operand, so that the first expression was the second; the algebra reports a syntax error for the first and computes the second: 
    C = A {*,equal} 2 - B
C = A {*,equal} (2 - B)
C = A # 2 - B
C = A # (2 - B)

    With an operator in braces, the same holds for a number with an expression in front of it as the left operand. GRASS 8.5 read this expression, the algebra reports a syntax error: 

    C = A - 1.5 {%,starts} A
  12. Maps without a related map under -n. With -n, the algebra registers a null map for each map of the left side of {&&,...} that has no related map; GRASS 8.5 never registered one. In this expression the maps of A that contain no map of E give a null map each, where GRASS 8.5 gave no map: 
    C = if(A > 1 {&&,contains,&,l} E > 1, A)
  13. Maps that touch under -s. Under -s, a selection with the temporal operator r or u takes the time of the maps that are related in time and in space. GRASS 8.5 chose the maps with the spatial test but took the time from the maps related in time, also from one whose box only touches the map at a corner, which is no spatial relation.

In Python, the algebra raises SyntaxError for an expression it cannot read. For one it cannot compute, it raises ValueError or TypeError, where GRASS 8.5 raised FatalError. It raises FatalError for a missing dataset or map and, without overwrite, for an existing result dataset or map. The tool stops with the error message.

Two more differences concern conditions on temporal variables. if({R}, condition, conclusion) reads "condition R conclusion" also for conditions on temporal variables, as it always did for conditions on map values. With a temporal relation beyond equal, the else part of a condition on temporal variables also takes the maps that no condition map is related to (see CONDITIONAL STATEMENTS). Figure A3 of Gebbert, Leppelt and Pebesma (2019) needs both: A has maps from day 1 to 3, 3 to 5 and 5 to 7 of January 2001, B has daily maps from day 1 to 10, and this expression gives the first two maps of A and the maps of B from day 5 on, as the figure shows, while GRASS 8.5 gives only the two maps of A: 

C = if({equal|contains}, start_date(A) <= "2001-01-03", A, B)

Results that rely on the previous reading direction or else rule need the GRASS version they were computed with.

Results corrected since GRASS 8.5

In the following cases GRASS 8.5 computed wrongly, ended in an error that had no reason, or reported the wrong error; GRASS 8.6 gives the result described here. Results of earlier GRASS versions that used one of these forms need a new run. The examples use the datasets of the list above and, in addition, N with daily maps of the values 11 to 14 and RT with maps of relative time.
  1. td() of an expression on the right of an operator used the value of the expression instead of the duration of its maps. With daily maps in N and A, the expression gave N - A * 2 where it now gives N - 1: 
    C = N - td(A * 2)
  2. tsnap() and tshift() of no maps. If the expression inside has no maps, the result is empty, like any other empty result: an empty dataset is created, and an enclosing expression goes on with no maps. Earlier versions ended in an error. No map of A is equal to a map of B, so both expressions give an empty dataset: 
    C = tsnap(A {:,equal} B)
C = A + tshift(A {:,equal} B, "1 day")
  3. Increments that the library refuses. An increment of tshift() or buff_t() that does not fit the temporal type is an error and leaves no result dataset: a text with a time unit on relative time, a number without unit on absolute time, or a text that is not a time step. Earlier versions raised a TypeError for buff_t() on relative time, and for tshift() they did not report the increment as the cause: the result was missing, or an enclosing operator complained about its input. Each of these expressions is an error. A number with a fraction, such as buff_t(RT, 1.5), is a syntax error on relative time: 
    C = tshift(A, "1 DAY")
C = tshift(RT, "1 month")
C = buff_t(RT, "3 hours")
C = buff_t(A, 3)
  4. merge() with a single map. The releases before GRASS 8.6 refused merge() of a dataset with a single map from tmap() with the error "Space time datasets to merge must have the same temporal type", also when both had the same temporal type. The data types of the maps are not compared, so a dataset may hold integer and floating point maps. The first expression gives the four maps of A and the single map. The second gives the maps of A and the floating point maps computed from them; it ran in those releases as well. merge() with map(), as in merge(A, map(a1)), is refused, because a map without time stamp forms a series of its own. 
    C = merge(A, tmap(singletmap))
C = merge(A, A * 1.5)
  5. Time constants with offset. A temporal function with an offset needs a map with the time value it returns. On a map without it, such as end_month() of a time instance or start_month() of relative time, the expression stops with an error, as the same function in a condition does. The releases before GRASS 8.6 ended with a Python traceback (AttributeError) while they read the expression: 
    C = A + end_month(I, 0)
C = A + start_month(RT, 1)
  6. Intersection with a time instance. With the temporal operator i, the time stamp of the result is the time instance, for a selection and for an operator, on absolute and on relative time. Earlier versions kept the time stamp of the left map for an operator and failed with a TypeError for a selection on relative time. If sinst is an instance on day 1, both expressions give one map with the instance as time: 
    C = A {:,contains,i} tmap(sinst)
C = A {+,contains,i} tmap(sinst)
  7. Infinite values. A map with infinite values, such as the result of exp(A * 1000), is registered with null as its minimum and maximum. Earlier versions failed when they wrote the map statistics ("no such column: inf") and could leave the temporal database locked. 
    C = exp(A * 1000)
  8. td() of a counted map. td() of a map counted by the hash operator gave the count instead of the duration, as an operand and in a comparison. The datasets A and N have daily maps and A # merge(A, N) counts 2 for each map of A. The expression added 2 to the maps of N where it now adds the one day of their duration; a condition such as td(A # merge(A, N)) > 1.5 was true and is false now. The duration of a map that is not counted did not change: 
    C = N + td(A # merge(A, N))
  9. Chains that start with a number or map(). A chain of operators whose first operand is a number or a map without time stamp, such as map(L) - 1 - A, was grouped from the right, as map(L) - (1 - A). It is grouped from the left now, as in mathematics. With 0.5 in L and the values 1 to 4 in A, the expression gave 0.5, 1.5, 2.5 and 3.5 and now gives -1.5, -2.5, -3.5 and -4.5, the result of (map(L) - 1) - A. The same holds for 2 * map(L) + A, 1 - 2 - 3 - A and chains inside if(). Chains after a dataset, such as A + (map(L) - 1 - 1), which ended in a syntax error, are read now. A chain of numbers or maps alone, as in map(L) - 1 - 1, has no dataset to compute and ends with an error: 
    C = map(L) - 1 - A
  10. td() as left operand of a stronger operator. An expression such as A + td(A) / A was computed as (A + td(A)) / A, because td() could only stand right of an operator. The operators *, / and %, also with a temporal operator in braces, bind stronger than + and - now, as in mathematics. With daily maps and the values 1 to 4 in A, td(A) is one day. The expression gave 2, 1.5, 1.3333 and 1.25 and now gives 2, 2.5, 3.3333 and 4.25. A td() at the start of a product, such as td(A) * 2, was a syntax error and is read now: 
    C = A + td(A) / A
  11. A spatial relation without a temporal one. An operator with spatial relation names only, such as A {+,equivalent,l} N, related no map, because maps are related by their temporal relations, and gave an empty result without a message. It stops now with the error "equivalent is a spatial relation and needs a temporal one, as in equal|overlap". Write a temporal relation beside the spatial one: 
    C = A {+,equal|equivalent,l} N
  12. A map that starts with the next map in tsnap(). tsnap() sets the end of each map to the start of the next map. A map that starts at the same time as the next map keeps its own end instead. Earlier versions gave it the end of the next map, so the two maps swapped their ends. In the datasets above, the map of A on days 2 to 3 and the map of C on days 2 to 4 start together; of such maps the one that ends last is snapped, see item 9 of the differences above: 
    D = tsnap(merge(A, C))
  13. Month and year steps from the end of a month. tshift() and buff_t() by months or years ended in an error ("day is out of range for month") when a time stamp moved to a day that the target month lacks. Such a step now ends on the last day of that month. With a dataset M whose map lasts from 31 January to 31 March 2001, the first expression gives a map from 28 February to 30 April 2001, the second one a map from 31 December 2000 to 30 April 2001. A year step from 29 February 2004 ends on 28 February 2005: 
    C = tshift(M, "1 months")
C = buff_t(M, "1 months")

    A month step back that ends in December of the year before last or earlier, for example buff_t(A, "24 months") on a map that starts on 1 December or tshift(A, "-13 months") on one that starts in January, ended in the error "bad month number 0" and now gives a result. Years and months of one step count as one step of 12 * years + months months, so "1 years, 11 months" and "23 months" end on the same day.

  14. A date beyond the year 9999. A step that ends behind the year 9999 or before the year 1, for example buff_t(A, "365 days") on a map that ends on 1 December 9999, ended with a traceback ("date value out of range"). It now ends with the error "... is beyond the year 9999" or "... is before the year 1"; no map and no dataset is created.
  15. A failed module. If a module fails while the maps are computed, for example r.mapcalc on a floating point map as an operand of &&, the tool ended with a Python traceback. It now ends with the error Module <r.mapcalc> failed with return code 1, see the error output above; the cause is in the error output of the module above it. No dataset is created.
  16. The relation equals. The releases before GRASS 8.6 refused the spelling equals of the paper with a syntax error. It is read as equal, so this expression gives the same maps as C = A {+,equal,l} B: 
    C = A {+,equals,l} B
  17. Comparison of related maps. The releases before GRASS 8.6 refused the comparison of two space time datasets, in braces and as A >= F, with a syntax error. It is read as described in the comparison of related maps above: 
    C = if(A {<, contains, |, r} B, B, 0)
  18. The granularity of steps over a year and of a time of the day. The granularity of a dataset, which the time suffix gran, tsnap() and the granularity mode -g use, counted a step between the first days of two months more than a year apart by the difference of the months only: 1 January 2024 to 1 March 2025 gave 2 months and now gives 14 months. A step whose two ends lie at the same time of the day other than midnight counted in hours or minutes: time instances at 10:30 ten days apart had the granularity 14400 minutes and now have 10 days. A time of the day that differs between the two ends still counts: from 10:30 to 11:30 ten days later the granularity is 241 hours.

Granularity algebra

With the flag -g, each space time dataset of the expression is first sampled with the common granularity of all datasets of the expression. A monthly series from the last day of a month (January 31, February 28 and March 31) has the granularity of one month and gets a granule per month; GRASS 8.5 computed one day here and got a granule per day. If the start times of the datasets differ in a finer unit than their common granularity, the granules are one unit long, in the finest unit in which the start times differ, so that the maps of every dataset start with a granule: a monthly series from the first of a month and one from the fifteenth are sampled per day, a daily series from midnight and one from noon per hour. The granules of a dataset follow each other from the start of its first map until they cover the end of its last map, so the last granule may reach past it, for example a granule of two days over a map of three days. If the dataset has time instances, one more granule follows. Each granule takes one map of the dataset, with the time stamp of the granule:
  1. the first map that is equal to the granule;
  2. otherwise the first map that contains the granule;
  3. otherwise the first map that starts within the granule and ends after it;
  4. otherwise the first map that starts before the granule and ends within it;
  5. otherwise the first map that lies within the granule.

A granule without such a map is left out. Then the expression is computed as without the flag, so that maps of equal time are combined. Operators with temporal relations in curly brackets cannot be used in this mode, and all datasets need a valid temporal topology and the same temporal type.

Single maps given with map() or tmap() are not sampled; an expression without any space time dataset is computed as without the flag, with a warning. The differences listed under "Differences from GRASS 8.5" apply with -g as well, for example item 4, the right reference.

See the example "Sample the maps with a common granularity" below.

Compute the NDVI of satellite scenes

The red and the near infrared band of three scenes are stored in two datasets, S2_b4 and S2_b8, as time instances five days apart. The bands are generated, not measured: integer reflectances scaled by 10000, as in Sentinel-2 products, over North Carolina. From scene to scene the red band decreases by 150 and the near infrared band increases by 400, and with the elevation the red band rises and the near infrared band falls. The scenes of the two datasets have equal time, so the expression pairs them and computes the NDVI (nir - red) / (nir + red) of each scene; its smallest and largest values grow from scene to scene. float() turns the integer maps into floating point maps before the division, because the division of two integers is an integer division. t.rast.colors sets the color table ndvi for the maps of the result.

Use datasets of another mapset

A dataset of another mapset is named name@mapset in the expression. A name without mapset is searched in the current mapset first, then in the mapsets of the search path. The example creates the mapset t_rast_algebra_2, switches to it and sets the region of the first example. The first call names A without mapset and fails: t_rast_algebra_2 has no dataset A, and t_rast_algebra, where A exists, is not in its search path. The second call names A@t_rast_algebra. The result dataset halved is always created in the current mapset: its maps are new maps in t_rast_algebra_2, as the column mapset shows, and the maps of A stay as they were.

The second block adds t_rast_algebra to the search path with g.mapsets, and A without mapset is found there. The last command returns to t_rast_algebra for the following examples.

Figures A2 and A3 compare start_time() with a date and set the date in typographic quotes, as Appendix C.3 sets the size of the temporal buffer.
