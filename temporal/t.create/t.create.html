DESCRIPTION

t.create creates a new, empty space time dataset in the temporal database of the current mapset. A space time dataset collects time stamped maps of one type and is the input and output of most temporal tools. t.create is usually the first step of a temporal workflow: the dataset is created here, maps are added with t.register, and the other tools work on the dataset from then on. See the introduction to temporal data processing for an overview.

The option type chooses what the dataset collects:

  • strds, a space time raster dataset, holds raster maps (the default);
  • str3ds, a space time 3D raster dataset, holds 3D raster maps;
  • stvds, a space time vector dataset, holds vector maps.

The option temporaltype sets how the maps of the dataset are placed in time. No tool changes it later; the only way is to replace the dataset with --overwrite:

  • absolute (the default) means calendar time: a map has a date and time, such as 2026-06-01 00:00:00, as a time instance or as the start and end of an interval;
  • relative means a number of time units counted from an arbitrary start, such as model step 3. The unit (years, months, days, hours, minutes or seconds) is not set by t.create, but by the first registration of maps with t.register: from its option unit, or, without it, from the relative time the maps carry already, such as a time stamp date="5 days" set with r.timestamp or the time of an earlier registration. If neither gives a unit, t.register stops with an error.

A dataset holds maps of its own temporal type: t.register refuses, for instance, to add a map with relative time to a dataset with absolute time.

The option semantictype states how the values of the maps are to be understood: sum for amounts, such as precipitation sums, mean for mean values (the default), min or max for extremes. The temporal tools store this label, print it with t.info and t.list, and tools that derive a new dataset from an existing one, such as t.copy and t.rast.aggregate, take it over. No tool computes with it; it is information for the user. t.support changes it later.

The options title and description are required. The title is a short name for the dataset, the description can say what the maps show, where they come from and how they were made. t.info prints both, together with the command history, which starts with the t.create command.

The option output names the new dataset. If a dataset of this type with this name exists already, t.create stops with an error unless --overwrite is given (see NOTES).

NOTES

The name of a space time dataset follows the rules for map names: it must not be empty or start with a dot, and it must not contain a space, a slash, a quotation mark, an apostrophe, @, a comma, =, * or ~. t.create stops with an error for such a name. For a raster dataset (STRDS) the part of the name after the first dot is read as a semantic label, as in the input of other temporal tools, and the part before it must be legal as well. t.create creates the dataset under the part before the dot and stores no label: output=prec.label creates the dataset prec. A dot in the name of a space time raster dataset is therefore best avoided.

A space time dataset is always created in the current mapset. The name may carry the current mapset (output=precipitation@PERMANENT in the mapset PERMANENT); with any other mapset t.create stops with the error "Space time datasets can only be created in the current mapset".

If a dataset of the same type and name exists, t.create stops with an error that points to the overwrite flag and leaves the dataset as it is. With --overwrite, t.create warns that it overwrites the dataset and unregisters all its maps, removes the old dataset and creates a new, empty one with the given options. The maps of the old dataset are not removed: they stay in the mapset and in the temporal database with their time stamps, but no longer belong to the dataset. To remove a dataset together with its maps, use t.remove with the flags -d and -f.

A new dataset has no start and end time, no spatial extent and no map count; t.info prints None for them. They follow from the maps once maps are registered.

EXAMPLES

Create a space time raster dataset

A space time raster dataset for daily precipitation sums. The values of the maps are amounts, so the semantic type is sum.

Command line:

t.create output=precipitation type=strds temporaltype=absolute \
    semantictype=sum title="Daily precipitation" \
    description="Daily precipitation sums in millimeters"

Python (grass.tools):

from grass.tools import Tools

tools = Tools()
tools.t_create(
    output="precipitation",
    type="strds",
    temporaltype="absolute",
    semantictype="sum",
    title="Daily precipitation",
    description="Daily precipitation sums in millimeters",
)

Rely on the default values

Without type, temporaltype and semantictype, t.create creates a space time raster dataset with absolute time and the semantic type mean. The flag -g of t.info prints key=value lines; in Python, the attribute keyval of the result turns them into a dictionary.

Command line:

t.create output=temperature title="Air temperature" \
    description="Daily mean air temperature at 2 m above ground"
t.info -g input=temperature | grep -E "^(temporal_type|semantic_type)="

temporal_type=absolute
semantic_type=mean

Python (grass.tools):

tools.t_create(
    output="temperature",
    title="Air temperature",
    description="Daily mean air temperature at 2 m above ground",
)
info = tools.t_info(input="temperature", flags="g").keyval
for key in ("temporal_type", "semantic_type"):
    print(f"{key}={info[key]}")

temporal_type=absolute
semantic_type=mean

tools.t_create(

    semantictype="min",
    title="Soil temperature",
    description="Daily minimum soil temperature in 3D layers",
)

Create a space time vector dataset with relative time

Model results counted in steps rather than in calendar time get a dataset with relative time. Here, the points of a vector map hold the maximum wind speed of each step. The time unit of the dataset stays unset (None) until the first maps are registered.

Command line:

t.create output=wind_gauges type=stvds temporaltype=relative \
    semantictype=max title="Simulated wind gauges" \
    description="Maximum wind speed per model step at the gauge points"
t.info -g type=stvds input=wind_gauges | grep -E "^(temporal_type|unit)="

temporal_type=relative
unit=None

Python (grass.tools):

tools.t_create(
    output="wind_gauges",
    type="stvds",
    temporaltype="relative",
    semantictype="max",
    title="Simulated wind gauges",
    description="Maximum wind speed per model step at the gauge points",
)
info = tools.t_info(type="stvds", input="wind_gauges", flags="g").keyval
for key in ("temporal_type", "unit"):
    print(f"{key}={info[key]}")

temporal_type=relative
unit=None

Replace a dataset with --overwrite

Two small raster maps are registered as daily intervals in the dataset precipitation of the first example. t.create with --overwrite then replaces the dataset with a new, empty one. The maps are no longer part of it, but they stay in the temporal database with their time stamps, as t.list with type raster shows.

Command line:

g.region n=2 s=0 e=2 w=0 res=1
r.mapcalc expression="rain_1 = 4.5"
r.mapcalc expression="rain_2 = 0.5"
t.register -i input=precipitation maps=rain_1,rain_2 \
    start=2026-06-01 increment="1 day"
t.rast.list input=precipitation

name|mapset|start_time|end_time
rain_1|PERMANENT|2026-06-01 00:00:00|2026-06-02 00:00:00
rain_2|PERMANENT|2026-06-02 00:00:00|2026-06-03 00:00:00

t.create --overwrite output=precipitation semantictype=sum \
    title="Daily precipitation" \
    description="Daily precipitation sums in millimeters, second run"
t.info -g input=precipitation | grep number_of_maps
t.list -c type=raster columns=name,start_time,end_time

number_of_maps=None
name|start_time|end_time
rain_1|2026-06-01 00:00:00|2026-06-02 00:00:00
rain_2|2026-06-02 00:00:00|2026-06-03 00:00:00

Python (grass.tools):

tools.g_region(n=2, s=0, e=2, w=0, res=1)
tools.r_mapcalc(expression="rain_1 = 4.5")
tools.r_mapcalc(expression="rain_2 = 0.5")
tools.t_register(
    input="precipitation",
    maps="rain_1,rain_2",
    start="2026-06-01",
    increment="1 day",
    flags="i",
)
print(tools.t_rast_list(input="precipitation").text)
