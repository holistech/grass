DESCRIPTION

t.select selects maps from space time datasets with the temporal algebra and registers them in a new space time dataset. It only selects and retimes maps, it computes none: use t.rast.algebra, t.rast3d.algebra or t.vect.algebra to compute with them. A selection answers questions such as "which maps of A lie in the time of a map of B?", "which maps of A have no map of B at the same time?" or "which maps of A start before a date?". See the introduction to temporal data processing for space time datasets and their temporal relations.

PROGRAM USE

The module expects an expression as input parameter in the following form:

"result = expression"

The statement structure is similar to r.mapcalc. result is the name of the space time dataset (STDS) that will contain the maps selected by the expression on the right side of the equality sign. The expression can be any valid or nested combination of the temporal operations and functions that the temporal algebra provides. The temporal algebra works with space time datasets of any type (STRDS, STR3DS and STVDS). The algebra provides methods for map selection from STDS based on their temporal relations. It is also possible to temporally shift maps, to create temporal buffers and to snap time instances to create a valid temporal topology. Furthermore expressions can be nested and evaluated in conditional statements (if, else statements). Within if-statements the algebra provides temporal variables like start time, end time, day of year, time differences or number of maps per time interval to build up conditions. These operations can be assigned to space time datasets or to the results of operations between space time datasets.

The result dataset is created in the current mapset, with the temporal type (absolute or relative) of the datasets in the expression. Maps whose temporal extent is changed by a temporal operator (for example {:,during,r}) cannot stay the maps of the input dataset. They are copied to new maps that are named after the result dataset: the dataset C in C = A {:,during,r} B contains the maps C_1, C_2 and so on. Existing maps with these names are only overwritten with the --overwrite flag. Maps whose extent is not changed are registered in the result dataset without being copied; a map of another mapset keeps its mapset in the result (a2@t_select). An expression that selects no map creates an empty space time dataset.

Options

The option expression takes the statement result = expression. It must be passed as quoted expression, for example: 
t.select expression="C = A : B"

Here C is the new space time raster dataset that will contain the maps from A that are selected by equal temporal relationships to the existing dataset B. An existing dataset C is only replaced with the --overwrite flag. Datasets of other mapsets are written as name@mapset. A name without mapset is searched in the current mapset first, then in the mapsets of the search path.

The option type gives the type of the datasets named in the expression: strds (default), stvds or str3ds. The result has this type as a rule. Maps of a dataset of another type are pulled into a selection with the functions strds(), str3ds() and stvds(); a result whose maps come from such a function can have the type of that function, see the NOTES.

As default, topological relationships between space time datasets will be evaluated only temporal. The -s flag additionally activates the evaluation of the spatial topology of the maps. It applies wherever the algebra evaluates the topology of maps: in selections, in the hash operator, in the conditions of if statements and in comparison operators. Two temporally related maps are then only used together if they are also spatially related, that is the spatial extents of the maps are equivalent, one covers or is covered by the other, they overlap, one lies in the other, one contains the other, or they meet (the spatial relations equivalent, cover, covered, overlap, in, contain and meet).

The -d flag performs a dry run. The tool computes the plan and prints it as a Python dictionary to standard output, and creates no dataset and no map. The entry STDS holds the name, the type and the temporal type of the result, processes the modules that would copy maps, register the maps that would be registered in the result with their start and end time, and remove the removals, which are empty in the plans shown here.

TEMPORAL ALGEBRA

The temporal algebra provides a wide range of temporal operators and functions that will be presented in the following section. The catalog under EXAMPLES runs the expressions of this section on small datasets and shows the maps they select.

TEMPORAL RELATIONS

Several temporal topology relations between registered maps of space time datasets are supported: 
equal             A ------
                  B ------

during            A  ----
                  B ------

contains          A ------
                  B  ----

starts            A ----
                  B ------

started           A ------
                  B ----

finishes          A   ----
                  B ------

finished          A ------
                  B   ----

precedes          A ----
                  B     ----

follows           A     ----
                  B ----

overlapped        A   ------
                  B ------

overlaps          A ------
                  B   ------

over              both overlaps and overlapped

The relations must be read as: A is related to B, like - A is equal to B - A is during B - A contains B

Gebbert, Leppelt and Pebesma (2019) write the relation equal as equals; the algebra reads both names. The releases before GRASS 8.6 refused equals with a syntax error.

Topological relations must be specified in {} parentheses.

The relations during and contains are inclusive: during also selects maps that start or finish together with the related map (the relations starts and finishes), and contains also selects maps with the relations started and finished. The relations precedes and follows only apply to maps that touch each other, that is the end of one map is the start of the other. Maps that are separated by a gap have no relation.

TEMPORAL OPERATORS

The temporal algebra defines temporal operators that can be combined with other operators to perform spatio-temporal operations. The temporal operators process the time instances and intervals of two temporal related maps and calculate the result temporal extent by five different possibilities. 
LEFT REFERENCE     l       Use the time stamp of the left space time dataset
INTERSECTION       i       Intersection
DISJOINT UNION     d       Disjoint union
UNION              u       Union
RIGHT REFERENCE    r       Use the time stamp of the right space time dataset

Each operator can also be written as a word: left, intersect, disjoint, union and right.

TEMPORAL SELECTION

The temporal selection simply selects parts of a space time dataset without processing raster or vector data. The algebra provides a selection operator : that selects parts of a space time dataset that are temporally equal to parts of a second one by default. The following expression 
C = A : B

means: Select all parts of space time dataset A that are equal to B and store it in space time dataset C. The parts are time stamped maps.

In addition the inverse selection operator !: is defined as the complement of the selection operator, hence the following expression 

C = A !: B

means: select all parts of space time time dataset A that are not equal to B and store it in space time dataset (STDS) C.

To select parts of a STDS by different topological relations to other STDS, the temporal topology selection operator can be used. The operator consists of the temporal selection operator, the topological relations, that must be separated by the logical OR operator | and the temporal extent operator. All three parts are separated by comma and surrounded by curly braces: 

{"temporal selection operator", "topological relations", "temporal operator"}

Examples: 

C = A {:, equal} B
C = A {!:, equal} B

We can now define arbitrary topological relations using the OR operator "|" to connect them: 

C = A {:,equal|during|overlaps} B

Select all parts of A that are equal to B, during B or overlaps B.
In addition we can define the temporal extent of the result STDS by adding the temporal operator. 

C = A {:, during,r} B

Select all parts of A that are during B and use the temporal extents from B for C.

The selection operator is implicitly contained in the temporal topology selection operator, so that the following statements are exactly the same: 

C = A : B
C = A {:} B
C = A {:,equal} B
C = A {:,equal,l} B

Same for the complementary selection: 

C = A !: B
C = A {!:} B
C = A {!:,equal} B
C = A {!:,equal,l} B

CONDITIONAL STATEMENTS

Selection operations can be evaluated within conditional statements. 
Note A and B can either be space time datasets or expressions. The temporal
relationship between the conditions and the conclusions can be defined at the
beginning of the if statement. The relationship between then and else conclusion
must be always equal.

if statement                           decision option                        temporal relations
  if(if, then, else)
  if(conditions, A)                    A if conditions are True;              temporal topological relation between if and then is equal.
  if(conditions, A, B)                 A if conditions are True, B otherwise; temporal topological relation between if, then and else is equal.
  if(topologies, conditions, A)        A if conditions are True;              temporal topological relation between if and then is explicit specified by topologies.
  if(topologies, conditions, A, B)     A if conditions are True, B otherwise; temporal topological relation between if, then and else is explicit specified by topologies.

The conditions are comparison expressions that are used to evaluate space time datasets. Specific values of temporal variables are compared by logical operators and evaluated for each map of the STDS.
Important: The conditions are evaluated from left to right.

Comparison operator

The conditions are comparison expressions that are used to evaluate space time datasets. Specific values of temporal variables are compared by logical operators and evaluated for each map of the STDS and the related maps. For complex relations the comparison operator can be used to combine conditions:
The structure is similar to the select operator with the extension of an aggregation operator: {"comparison operator", "topological relations", aggregation operator, "temporal operator"}
This aggregation operator (| or &) define the behaviour if a map is related the more than one map, e.g for the topological relations 'contains'. Should all (&) conditions for the related maps be true or is it sufficient to have any (|) condition that is true. The resulting boolean value is then compared to the first condition by the comparison operator (|| or &&). As default the aggregation operator is related to the comparison operator:
Comparison operator -> aggregation operator: 
|| -> | and && -> &

Examples: 

Condition 1 {||, equal, r} Condition 2
Condition 1 {&&, equal|during, l} Condition 2
Condition 1 {&&, equal|contains, |, l} Condition 2
Condition 1 {&&, equal|during, l} Condition 2 && Condition 3
Condition 1 {&&, equal|during, l} Condition 2 {&&,contains, |, r} Condition 3

Hash operator

Additionally the number of maps in intervals can be computed and used in conditional statements with the hash (#) operator. 
A{#, contains}B

The hash operator can only be used in the condition of an if statement.

This expression computes the number of maps from space time dataset B which are during the time intervals of maps from space time dataset A.
A list of integers (scalars) corresponding to the maps of A that contain maps from B will be returned.

The result keeps the time stamps of the maps of A. The temporal operators r, u, i and d have no meaning for the count and are rejected with a syntax error; l is the default. 

C = if({equal}, A {#, contains} B > 2, A {:, contains} B)

This expression selects all maps from A that temporally contains more than 2 maps from B and stores them in space time dataset C. The leading equal statement in the if condition specifies the temporal relation between the if and then part of the if expression. This is very important, so we do not need to specify a global time reference (a space time dataset) for temporal processing.

Furthermore the temporal algebra allows temporal buffering, shifting and snapping with the functions buff_t(), tshift() and tsnap() respectively. 

buff_t(A, size)         Buffer STDS A with granule ("1 month" or 5)
tshift(A, size)         Shift STDS A with granule ("1 month" or 5)
tsnap(A)                Snap time instances and intervals of STDS A

A negative size shrinks the maps; the algebra stops with an error where a map would keep no time, see "Differences from GRASS 8.5".

tsnap() ends a last map that is a time instance one granularity of the maps after its start. A granularity of months counts from the first map, with the cut to the end of a shorter month: the time instances January 31, February 28 and March 31 have the granularity of one month, and the last one ends on April 30; after an instance on April 30 in the same series it ends on May 31. GRASS 8.5 computed a granularity of one day here and ended the instance of March 31 on April 1.

Single map with temporal extent

The temporal algebra can also handle single maps with time stamps in the map function. 
tmap()

For example: 

 C = A {:,during} tmap(event)

This statement select all maps from space time data set A that are during the temporal extent of single map 'event'

NOTES

Results, empty selections and mapsets

The result dataset and the copies of retimed maps are always created in the current mapset. A selected map that keeps its time is registered as it is, also when it belongs to another mapset: the result of the example with the mapset t_select_2 holds a2@t_select, and no map of that name exists in t_select_2. A name without a mapset in the expression finds a dataset X of another mapset only if that mapset is in the search path; X@mapset finds it in any mapset of the project that has a temporal database.

An expression that selects no map creates an empty space time dataset, for vector maps also. The empty dataset has the map count 0 in t.info, as the example with the mapset t_select_2 shows.

Datasets of relative time are selected like those of absolute time, with the same relations and operators. The result has the temporal type of the input (see the example on relative time). The calendar functions, such as start_month() or start_doy(), need absolute time: on a dataset of relative time the algebra stops with the error "Temporal function start_month() is not available for map ...", and no dataset is created.

Differences from GRASS 8.5

Since GRASS 8.6, t.select selects with the functions of the Python package grass.temporal.algebra, as t.rast.algebra and t.vect.algebra do. The implementation of the releases up to GRASS 8.5 is no longer part of GRASS; it is available in those releases and in the history of the source code (tag classic-reference-corpus).

The functions strds(), str3ds() and stvds() pull maps of another dataset type into a selection; the type of the function need not equal the parameter type, which gives the type of the result. The algebra also relates a vector dataset on the left to a raster or 3D raster dataset, as in if({contains}, stvds(B) {#,contains} A == 2, A), which GRASS 8.5 did not. Besides the lower case spelling, str3ds(A), the algebra reads the capitals of the paper, STRDS(A), STR3DS(A) and STVDS(A). A capital name is a function only before an opening parenthesis, so that a dataset may be named STRDS. Other spellings, such as Str3ds(A), are a syntax error.

t.select only selects and retimes maps, it computes none, so most differences that t.rast.algebra lists do not reach it. Some expressions give other results than in GRASS 8.5, as the following points describe; where such an expression also meets one of the cases under "Results corrected since GRASS 8.5" below, GRASS 8.5 behaved as described there for the earlier versions.

  1. Spatial relations. A spatial relation in an operator, such as {:,equal|overlap}, is read with and without the flag -s, and needs a temporal relation to go with it. GRASS 8.5 reports a syntax error for the name of a spatial relation, with and without -s.
  2. Right reference. A {:,R,r} B gives one map per related pair, with the time stamp of the right map: a map of A that contains two maps of B gives two maps. GRASS 8.5 keeps only the last pair of each map of A. A {!:,R,t} B with a temporal reference other than l is a syntax error, because the inverse selection has no related map to combine with; GRASS 8.5 accepts it.
  3. More syntax. The neighbourhood modifier A[1] and A[-1], and comparisons and temporal functions anywhere in a condition (also with the number on the left, as in 20 < start_doy(A), and in arithmetic, as in start_doy(A) - 1 > 20), and the hash operator in arithmetic within a condition are read. So is an expression that is only a dataset, C = A. GRASS 8.5 reports a syntax error for each.
  4. Arithmetic on datasets. An expression such as A + B is read, and the tool stops with a message that names the tools that compute maps, because it is no selection. GRASS 8.5 cannot read it and reports a syntax error.
  5. Copy names in a mixed result. When a result mixes maps registered unchanged with retimed maps, the copied maps are named <result>_1, <result>_2, ... in the time order of the result. GRASS 8.5 numbers them by their position among all result maps, so the suffixes can differ; the maps and their time stamps are the same. If three maps are registered unchanged before three copies, the copies are C_1 to C_3 in GRASS 8.6 and C_4 to C_6 in GRASS 8.5: 
    C = merge(A {:,during,l} D, A {:,during,r} D)
  6. Negative buffer. A negative size in buff_t() shrinks the maps by that size at both ends. GRASS 8.6 stops with an error if a map would keep no time, that is if its end would fall on or before its start, and for a time instance, which has no duration to shrink. GRASS 8.5 goes on instead: for a map whose end would fall before its start it prints an error message and keeps the old time stamp, and it makes a time instance of a map whose end equals its start. For maps of two days, the first expression shrinks them to one day and the second is an error: 
    C = buff_t(B, "-12 hours")
C = buff_t(B, "-1 day")
  7. tsnap() of maps that start together. Of maps with the same start, tsnap() snaps only one to the start of the next later map; the others keep their own ends. GRASS 8.6 takes the map that ends last, so its result does not depend on the order of the maps. GRASS 8.5 takes the map listed last, so that the order of the arguments of merge() matters. If a map from day 2 to day 4 is in C and a map from day 2 to day 3 in A, GRASS 8.6 gives both expressions the same maps; GRASS 8.5 lets the map of C keep its end in the second: 
    D = tsnap(merge(A, C))
D = tsnap(merge(C, A))
  8. Time functions as the conclusion of if(). A time function such as start_doy() gives numbers, not maps, so GRASS 8.6 stops with the error "A time function such as start_doy() cannot be the result of a selection" whenever it is the conclusion of if() beside maps. A time function belongs in the condition. GRASS 8.5 stops with this error only where a value of the time function would be among the selected maps (see the corrections below). If the first map of A starts on 1 January, only that map meets the condition, and it has no predecessor: GRASS 8.5 selects the other maps of A with the first expression and stops with the second: 
    C = if(start_doy(A) < 3, start_doy(A, -1), A)
C = if(start_doy(A) < 3, start_doy(A, 1), A)
  9. Maps that touch under -s. Under -s, a selection with the temporal operator r or u takes the time of the maps that are related in time and in space. GRASS 8.5 chose the maps with the spatial test but took the time from the maps related in time, also from one whose box only touches the map at a corner, which is no spatial relation.

In Python, the algebra raises SyntaxError for an expression it cannot read, and FatalError for a missing dataset and, without overwrite, for an existing result. It raises ValueError for an expression it reads but cannot select, such as A + B, where GRASS 8.5 raises SyntaxError. The tool stops with the error message.

Two more differences concern conditions on temporal variables, in t.rast.algebra, t.rast3d.algebra and t.vect.algebra as well. First, if({R}, condition, conclusion) reads "condition R conclusion": if({contains}, start_doy(A) > 0, B) gives the maps of B that lie within a map of A. Second, with a temporal relation beyond equal, the else part of a condition on temporal variables also takes the maps that no condition map is related to. Figure A3 of Gebbert, Leppelt and Pebesma (2019) needs both: A has maps from day 1 to 3, 3 to 5 and 5 to 7 of January 2001, B has daily maps from day 1 to 10, and this expression gives the first two maps of A and the maps of B from day 5 on, as the figure shows: 

C = if({equal|contains}, start_date(A) <= "2001-01-03", A, B)

Results that rely on the previous reading direction or else rule need the GRASS version they were computed with. The section "Differences from GRASS 8.5" in the NOTES of t.rast.algebra describes both.

Results corrected since GRASS 8.5

In the following cases GRASS 8.5 ended in an error that had no reason, reported the wrong error, or did not do what this manual describes; GRASS 8.6 gives the result described here. Results of earlier GRASS versions that used one of these forms need a new run.
  1. tsnap() and tshift() of no maps. If the expression inside selects no map, the result is an empty dataset, like any other selection of no map, and an enclosing expression goes on with no maps. Earlier versions ended in an error. No map of A is equal to a map of D, so both expressions give an empty dataset: 
    C = tsnap(A {:,equal} D)
C = tshift(A {:,equal} D, "1 day")
  2. Increments that the library refuses. An increment of tshift() or buff_t() that does not fit the temporal type, such as a text that is not a time step or a number without unit on absolute time, is an error and leaves no result dataset: 
    C = tshift(A, "1 DAY")
C = buff_t(A, 3)
  3. Selection with a time instance on relative time. With the temporal operator i, the time stamp of the result is the time instance. Earlier versions failed with a TypeError for a selection on relative time. If A has maps of relative time that contain the time instances of I, this expression gives maps with the instances as time: 
    C = A {:,contains,i} I
  4. Spatial relation names alone. A selection in braces refuses spatial relation names with a syntax error. With spatial names only, such as A {:,equivalent} B, it stops now with the error "equivalent is a spatial relation and needs a temporal one, as in equal|overlap", as every operator of the algebra does. Selections read temporal relations only: 
    C = A {:,equal} B
  5. Empty selection of vector maps. An expression that selects no map creates an empty space time vector dataset, as it does for raster maps. GRASS 8.5 created no dataset for vector maps and gave no warning. With type=stvds, if no map of A is equal to a map of D, this expression gives an empty dataset: 
    C = A {:,equal} D
  6. Planned type of a mixed selection. The dry run (-d) plans the type of the dataset that the run creates. If the maps of the result come from a function of another type, the run creates a dataset of that type: with type=strds, this expression creates a space time 3D raster dataset, and the dry run plans one. GRASS 8.5 planned the type given by type and created the other: 
    C = if({contains}, (stvds(B) {#,contains} str3ds(A)) == 2, str3ds(A))
  7. A map that starts with the next map in tsnap(). tsnap() sets the end of each map to the start of the next map. A map that starts at the same time as the next map keeps its own end instead. Earlier versions gave it the end of the next map, so the two maps swapped their ends. Of maps that start together, the one that ends last is snapped, see item 7 of the differences above: 
    D = tsnap(merge(A, C))
  8. Month and year steps from the end of a month. tshift() and buff_t() by months or years ended in an error ("day is out of range for month") when a time stamp moved to a day that the target month lacks. Such a step now ends on the last day of that month. With a dataset M whose map lasts from 31 January to 31 March 2001, the first expression gives a map from 28 February to 30 April 2001, the second one a map from 31 December 2000 to 30 April 2001. A year step from 29 February 2004 ends on 28 February 2005: 
    C = tshift(M, "1 months")
C = buff_t(M, "1 months")

    A month step back that ends in December of the year before last or earlier, for example buff_t(A, "24 months") on a map that starts on 1 December or tshift(A, "-13 months") on one that starts in January, ended in the error "bad month number 0" and now gives a result. Years and months of one step count as one step of 12 * years + months months, so "1 years, 11 months" and "23 months" end on the same day.

  9. Time functions as the selected maps. In a selection, a time function at an offset such as start_doy(A, 1) stands for the map it reads, whose value GRASS 8.5 never computed. Where such a value was among the selected maps, a dry run listed it and the real run failed when it copied that map. The tool now stops with the error "A time function such as start_doy() cannot be the result of a selection" before it creates a dataset or a map, see item 8 of the differences above. A time function belongs in the condition: 
    C = if(start_doy(A) < 3, start_doy(A, 1), A)
C = tshift(start_doy(A, 1), "1 day")
  10. A date beyond the year 9999. A step that ends behind the year 9999 or before the year 1, for example buff_t(A, "365 days") on a map that ends on 1 December 9999, ended with a traceback ("date value out of range"). It now ends with the error "... is beyond the year 9999" or "... is before the year 1"; no map and no dataset is created.
  11. A failed module. If a module fails while the maps are computed or copied, the tool ended with a Python traceback. It now ends with an error that names the module and its return code, such as Module <g.copy> failed with return code 1, see the error output above; the cause is in the error output of the module above it. No dataset is created.
  12. The relation equals and capital function names. The releases before GRASS 8.6 refused the relation name equals and the capital function names STRDS(A), STR3DS(A) and STVDS(A) of the paper with a syntax error. They are now read as equal and as the functions in lower case.
  13. The granularity of steps over a year and of a time of the day. The granularity of a dataset, which tsnap() uses for the end of a last time instance, counted a step between the first days of two months more than a year apart by the difference of the months only: 1 January 2024 to 1 March 2025 gave 2 months and now gives 14 months. A step whose two ends lie at the same time of the day other than midnight counted in hours or minutes: time instances at 10:30 ten days apart had the granularity 14400 minutes and now have 10 days. A time of the day that differs between the two ends still counts: from 10:30 to 11:30 ten days later the granularity is 241 hours.

EXAMPLES

The examples run in the order of this section in one project, and each one builds on the datasets of the first. The first five show the options of the tool with both interfaces; the ones after them are a catalog of expressions, which run on the command line only and show the maps each expression selects.

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_select and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region unless they say otherwise. t.select works with the times of the maps, so the maps hold small constant values.

Select the maps of a dataset by their time

The first example creates four datasets of constant maps over North Carolina. Every time below is a day of January 2001: a map from day 6 to 11 starts at 00:00 of 6 January and ends at 00:00 of 11 January, so a1 from day 1 to 6 ends where a2 starts. The value of each map is the number in its name.
DatasetMaps from day to day
Aa1 1 to 6, a2 6 to 11, a3 11 to 16, a4 16 to 21
Bb1 1 to 11, b2 6 to 11, b3 11 to 13, b4 12 to 14, b5 14 to 18, b6 18 to 21, b7 21 to 24
Cc1 6 to 11, c2 16 to 21
Ww1 3 to 19

The operator : selects the maps of A that are equal in time to a map of B; the operator !: selects the ones that are not. Only a2 and b2 have the same time, so the first selection holds a2 and the second the other three maps. The maps are registered in the result datasets, not copied.

Command line:

g.mapset -c mapset=t_select
g.region raster=elev_state_500m res=1000 -a
for dataset in A B C W; do
    t.create output=$dataset title="Dataset $dataset" \
        description="Maps of dataset $dataset"
done
while read -r dataset map first last; do

Select with conditions on time

An if selects the maps for which a condition on temporal variables holds. Without an else part, the other maps are dropped; with one, each map for which the condition is false is replaced by the map of the else dataset that is equal to it in time. The first block is the chain of relations from above, the second takes the else maps c2 for a4.

Count related maps and compare them

The hash operator # counts, for each map of the left dataset, the maps of the right dataset in the given relation. A map without any related map has no count: it is neither selected nor used for the else part. a1 and a2 contain no map of B, a3 contains b3 and b4, a4 contains b6. A comparison operator in braces combines the conditions on two datasets.

Command line:
