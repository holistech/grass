DESCRIPTION

t.rast3d.algebra performs temporal and spatial map algebra operations on space time 3D raster datasets (STR3DS) by using the temporal 3D raster algebra.

NOTES

The module expects an expression as input parameter in the following form:

"result = expression"

The statement structure is exact the same as of t.rast.algebra, see t.rast.algebra but allows four-dimensional indexing: a neighbourhood modifier with four offsets is written str3ds[row,column,depth,time].

By default, only temporal topological relations are evaluated. The -s flag additionally activates the evaluation of the spatial topology of the maps. It applies wherever the algebra evaluates the topology of maps: in selections, in the hash operator, in the conditions of if statements, in comparison operators and in the spatial operators. Two temporally related maps are then only used together if they are also spatially related, that is the spatial extents of the maps are equivalent, one covers or is covered by the other, they overlap, one lies in the other, one contains the other, or they meet (the spatial relations equivalent, cover, covered, overlap, in, contain and meet). The relations equivalent, cover, overlap, in, contain and meet can also be named in the curly brackets of a spatial operator, for example {+,equal|overlap}; the maps then need this spatial relation in addition to the temporal one. The relation is evaluated in three dimensions: two maps with the same depth range are not related as overlap, even if they overlap in the horizontal plane.

Maps that are related in space are computed in the current 3D region, in both algebras: r3.mapcalc cannot compute in the union of the regions of its input maps.

Core and classic algebra

Since GRASS 8.6, t.rast3d.algebra computes its expressions with the functions of the Python package grass.temporal.algebra, as t.rast.algebra does. The previous implementation stays available as the classic algebra, so that published results remain reproducible. The classic algebra is a set of rules of the same functions: it reads the syntax of the previous implementation and applies its rules for relations, order and results. The flag -c selects it for one call, the environment variable GRASS_TEMPORAL_ALGEBRA=classic for a whole session or script; GRASS_TEMPORAL_ALGEBRA=core or an unset or empty variable selects the new algebra, and the flag takes precedence over the variable. In Python, TemporalRaster3DAlgebraParser takes the keyword classic=True for the same purpose. Both algebras compute the granularity mode (-g), see below.

The two algebras differ in the following points. The examples use four daily 3D raster maps in A with the values 1 to 4, two maps of two days in B that start with A, and time instances in I.

  1. One result per conclusion map. If a map of the conclusion of an if has several related condition maps, their conditions are joined with and; written as {during,|}, the relation joins them with or. The classic algebra gives one result for each pair of condition map and conclusion map, so that a conclusion map can occur several times, and does not read the form {during,|}. The first expression keeps the cells of B where both maps of A within the map of B are greater than 1, the second where one of them is: 
    C = if({during}, A > 1, B, 0)
C = if({during,|}, A > 1, B, 0)
  2. Equal time stamps for then and else. With a condition on map values, the then and the else part need equal time stamps; otherwise the algebra stops with an error. The classic algebra computes only the maps whose time stamp occurs in both parts and leaves out the others without notice. This expression is therefore an error, where the classic algebra gives an empty result: 
    C = if(A > 2, A, B)
  3. Precedence. && binds stronger than ||, and conditions can be grouped with parentheses. The classic algebra evaluates conditions on temporal variables from left to right and does not accept parentheses around conditions. The first expression takes all maps of A, because td(A) == 1 is true for each of them; the classic algebra reads it as the second expression and takes none: 
    C = if(td(A) == 1 || td(A) == 2 && td(A) == 3, A)
C = if((td(A) == 1 || td(A) == 2) && td(A) == 3, A)
  4. Right reference. A {:,R,r} B and A {op,R,r} B give one map per related pair, with the time stamp of the right map and, for an operator, the value of this pair. The classic algebra keeps only the last pair of a selection, and an operator combines the left map with all of its related right maps in every result. The first expression gives four maps, the time stamps of A with the values of B; the classic algebra gives one map per map of B. If a map b1 contains the maps a1 and a2, the second expression gives b1 + a1 and b1 + a2, the classic algebra b1 + a1 + a2 for both: 
    C = B {:,contains,r} A
C = B {+,contains,r} A

    The inverse selection A {!:,R,t} B takes only the temporal operator l, because its maps have no related map to combine with; the classic algebra accepts the other operators.

  5. if without else. An if without else gives null where a condition on map values is false; the classic algebra gives 0 there, like the if() of r3.mapcalc with two arguments. A map that is false everywhere is not registered unless -n is set. This expression registers the maps of value 3 and 4, with -n also the first two maps as null maps; the classic algebra registers four maps, the first two with the value 0: 
    C = if(A > 2, A)
  6. td() of a time instance is null instead of an error, so a condition on it is neither true nor false. This expression gives no map; the classic algebra stops with an error: 
    C = if(td(I) > 0, I)

    A temporal variable that a map does not have, such as end_doy() of a time instance or the calendar values of relative time, is an error in both algebras.

  7. Spatial relations need -s. A spatial relation in an operator, such as {+,equal|overlap}, needs the flag -s; without it, the algebra stops with an error. The classic algebra gives an empty result.
  8. More syntax. Comparisons, temporal functions and the minus sign may stand anywhere in an expression, and a dataset may have the name of a function. The classic algebra reports a syntax error for each of these expressions; the last one adds 1 to a dataset named td: 
    C = A
C = -A + 10
C = A > 2
C = A + start_doy(A)
C = isnull(A)
C = td + 1
  9. Maps without time stamp in arithmetic. An expression of maps without time stamp, such as map(L) + 1, can be combined with space time datasets. This expression is a syntax error in the classic algebra: 
    C = A * (map(L) + 1)
  10. Intersection with several related maps. With the temporal operator i, a map whose related maps have no common intersection is left out. The classic algebra intersects the map with its related maps until the first one that has no common time with the result so far, so that its result depends on the order of the related maps. If a dataset H has a map from day 2 to day 4, this map follows the map of A of day 1 and precedes the one of day 4; the intersections are the time instances of day 2 and day 4, and the map is left out: 
    C = H {:,follows|precedes,i} A
  11. Negative buffer. A negative size in buff_t() shrinks the maps by that size at both ends. The new algebra stops with an error if a map would keep no time, that is if its end would fall on or before its start, and for a time instance, which has no duration to shrink. The classic algebra goes on instead: for a map whose end would fall before its start it prints an error message and keeps the old time stamp, and it makes a time instance of a map whose end equals its start. For maps of two days, the first expression shrinks them to one day and the second is an error: 
    C = buff_t(B, "-12 hours")
C = buff_t(B, "-1 day")
In Python, both algebras raise SyntaxError for an expression they cannot read. For one they cannot compute, such as if(end_doy(I) > 0, I), the new algebra raises ValueError or TypeError, where the classic algebra raises FatalError. Both raise FatalError for a missing dataset and, without overwrite, for an existing result. The tool stops with the error message in both algebras.

Two corrections apply to both algebras, and to t.rast.algebra, t.select and t.vect.algebra as well, so -c gives the rules of the previous algebra, not the results of a particular release. First, if({R}, condition, conclusion) reads "condition R conclusion": if({contains}, start_doy(A) > 0, B) gives the maps of B that lie within a map of A, where earlier versions gave the maps of B that contain a map of A. Second, with a temporal relation beyond equal, the else part of a condition on temporal variables also takes the maps that no condition map is related to. Figure A3 of Gebbert, Leppelt and Pebesma (2019) needs both: A has maps from day 1 to 3, 3 to 5 and 5 to 7 of January 2001, B has daily maps from day 1 to 10, and this expression gives the first two maps of A and the maps of B from day 5 on, as the figure shows: 

C = if({equal|contains}, start_date(A) <= "2001-01-03", A, B)

Results that rely on the previous reading direction or else rule need the GRASS version they were computed with. The section "Core and classic algebra" in the NOTES of t.rast.algebra describes both corrections.

Corrections to the classic algebra

The classic algebra gives the results of the previous implementation, with the exceptions below. In these cases the previous implementation computed wrongly or reported the wrong error. -c now gives the result described here; the new algebra never computed these cases wrongly. Results of earlier GRASS versions that used one of these forms need a new run. The examples use the datasets of the list above and, in addition, N with daily maps.
  1. td() of an expression on the right of an operator used the value of the expression instead of the duration of its maps. With daily maps in N and A, the expression gave N - A * 2 where it now gives N - 1: 
    C = N - td(A * 2)
  2. tsnap() and tshift() of no maps. If the expression inside has no maps, the result is an empty dataset, and an enclosing expression goes on with no maps. Earlier versions ended in an error. No map of A is equal to a map of B, so both expressions give an empty dataset: 
    C = tsnap(A {:,equal} B)
C = A + tshift(A {:,equal} B, "1 day")
  3. Increments that the library refuses. An increment of tshift() or buff_t() that does not fit the temporal type, such as a text that is not a time step or a number without unit on absolute time, is a syntax error and leaves no result dataset. The new algebra refuses the same increments with a ValueError: 
    C = tshift(A, "1 DAY")
C = buff_t(A, 3)
  4. merge() and the data type. The data types of the maps are not compared, so a dataset may hold integer and floating point maps. Earlier versions refused merge() of a dataset with a single map from map() or tmap() with the error that the datasets must have the same data type: 
    C = merge(A, A * 1.5)
  5. Time constants with offset. A temporal function with an offset needs a map with the time value it returns. On a map without it, such as end_month() of a time instance or start_month() of relative time, the expression stops with an error that says the function requires absolute time, as the same function in a condition does. Earlier versions wrote None into the r3.mapcalc expression, which failed when the maps were computed: 
    C = A + end_month(I, 0)
  6. Intersection with a time instance. With the temporal operator i, the time stamp of the result is the time instance, for a selection and for an operator, on absolute and on relative time. Earlier versions kept the time stamp of the left map for an operator and failed with a TypeError for a selection on relative time. Both expressions give maps with the instances of I as time: 
    C = A {:,contains,i} I
C = A {+,contains,i} I

Differences from the previous implementation

The differences in message texts, in the debug output of the Python parser, in the order of errors and in the error for an existing result that t.rast.algebra lists apply here likewise, as do the items on lists of absolute and relative time and on the relation equals, the two that change the outcome of an expression. The relation equal may be written equals here too, as in t.rast.algebra; the previous implementation refuses that spelling with a syntax error.

Granularity algebra

With the flag -g, each space time dataset of the expression is first sampled with the common granularity of all datasets of the expression. The granules of a dataset follow each other from the start of its first map until they cover the end of its last map, so the last granule may reach past it, for example a granule of two days over a map of three days. If the dataset has time instances, one more granule follows. Each granule takes one map of the dataset, with the time stamp of the granule:
  1. the first map that is equal to the granule;
  2. otherwise the first map that contains the granule;
  3. otherwise the first map that starts within the granule and ends after it;
  4. otherwise the first map that starts before the granule and ends within it;
  5. otherwise the first map that lies within the granule.

A granule without such a map is left out. Then the expression is computed as without the flag, so that maps of equal time are combined. Operators with temporal relations in curly brackets cannot be used in this mode, and all datasets need a valid temporal topology and the same temporal type.

Single maps given with map() or tmap() are not sampled. The differences between the two algebras listed under "Core and classic algebra" apply with -g as well, for example item 5, an if without else.

See the manual of t.rast.algebra for an example.
