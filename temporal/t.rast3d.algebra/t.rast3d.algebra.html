DESCRIPTION

t.rast3d.algebra performs temporal and spatial map algebra operations on space time 3D raster datasets (STR3DS) by using the temporal 3D raster algebra. It reads an expression of the form result = expression, relates the maps of the datasets in the expression by their time (and, with -s, by their place), computes each result map with r3.mapcalc and registers the result maps in a new space time 3D raster dataset in the current mapset. Use it when the maps to combine are not simply paired by equal time stamps, or when a result depends on how the time intervals of the maps lie to each other. The 2D counterpart is t.rast.algebra; to compute with the maps of the datasets for each time step with a single r3.mapcalc expression, see t.rast3d.mapcalc. See the introduction to temporal data processing for space time datasets.

Expression, result and maps

The option expression holds the statement result = expression. The name left of the equal sign is the new space time 3D raster dataset; it is created in the current mapset, and an existing dataset of that name is replaced only with --overwrite. A dataset of another mapset is named name@mapset in the expression; a name without mapset is searched only in the current mapset. The right side may contain space time 3D raster datasets, single maps (map() and tmap()), temporal and raster operators and functions, as described below and in t.rast.algebra.

The option basename is required. The result maps are named basename_0, basename_1 and so on, counted from 0 in the order in which the algebra computes them. This is not always the order of their time, and in the new algebra a number can be missing: a map that is null everywhere is not registered unless -n is given, but it keeps its number (see the example "Spatially related maps and empty maps"). The classic algebra (-c) does not compute a pair of maps that do not overlap in space at all, so it registers no empty map for it, even with -n, and its numbers have no gap. An expression that leaves no map to register ends with the warning "The expression produced no map, the result is empty", and the result is an empty dataset.

The option nprocs is the number of r3.mapcalc processes that run at the same time. The default is 1. The result is the same for any number.

Flags

-s also checks the spatial topology of temporally related maps and processes only maps that are related in space too. -n registers maps that are null everywhere, which are left out by default; this concerns the new algebra, see above for -c. -g uses the granularity algebra instead of the temporal topology of the maps, see "Granularity algebra" below. -c selects the classic algebra, which gives the results of the releases before GRASS 8.6; see "Core and classic algebra" below. The environment variable GRASS_TEMPORAL_ALGEBRA selects it for a whole session.

NOTES

The module expects an expression as input parameter in the following form:

"result = expression"

The statement structure is exact the same as of t.rast.algebra, see t.rast.algebra but allows four-dimensional indexing: a neighbourhood modifier with four offsets is written str3ds[row,column,depth,time].

By default, only temporal topological relations are evaluated. The -s flag additionally activates the evaluation of the spatial topology of the maps. It applies wherever the algebra evaluates the topology of maps: in selections, in the hash operator, in the conditions of if statements, in comparison operators and in the spatial operators. Two temporally related maps are then only used together if they are also spatially related, that is the spatial extents of the maps are equivalent, one covers or is covered by the other, they overlap, one lies in the other, one contains the other, or they meet (the spatial relations equivalent, cover, covered, overlap, in, contain and meet). The relations equivalent, cover, overlap, in, contain and meet can also be named in the curly brackets of a spatial operator, for example {+,equal|overlap}; the maps then need this spatial relation in addition to the temporal one. Such a name builds the spatial topology for its operator also without -s, as in the classic algebra (since 17 October 2026; before, the new algebra stopped with an error). The relation is evaluated in three dimensions: two maps with the same depth range are not related as overlap, even if they overlap in the horizontal plane.

Maps that are related in space are computed in the current 3D region, in both algebras: r3.mapcalc cannot compute in the union of the regions of its input maps.

A map that the result takes over unchanged, for example one that a selection stamps with a new time, is copied in the current 3D region as well, with or without -s. A copy of a map that lies outside the region has no data. Like any map without data it is not registered unless -n is given, and since 24 October 2026 a warning names it and the map it copies. Set the region with g.region so that it covers the maps.

Core and classic algebra

Since GRASS 8.6, t.rast3d.algebra computes its expressions with the functions of the Python package grass.temporal.algebra, as t.rast.algebra does. The implementation used before, the reference implementation in grass.temporal.classic, stays in the source code, and its rules stay available as the classic algebra, so that published results remain reproducible. The classic algebra is a set of rules of the same functions: it reads the syntax of the reference implementation and applies its rules for relations, order and results. The flag -c selects it for one call, the environment variable GRASS_TEMPORAL_ALGEBRA=classic for a whole session or script; GRASS_TEMPORAL_ALGEBRA=core or an unset or empty variable selects the new algebra, and the flag takes precedence over the variable. In Python, TemporalRaster3DAlgebraParser takes the keyword classic=True for the same purpose. Both algebras compute the granularity mode (-g), see below.

An if without else gives 0 where a condition on map values is false, in both algebras, like the if() of r3.mapcalc with two arguments. The new algebra does so since 17 October 2026; before, it gave null there and registered a map that is false everywhere only with -n.

The two algebras differ in the following points. The examples use four daily 3D raster maps in A with the values 1 to 4, two maps of two days in B that start with A, and time instances in I.

  1. One result per conclusion map. If a map of the conclusion of an if has several related condition maps, their conditions are joined with and; written as {during,|}, the relation joins them with or. The classic algebra gives one result for each pair of condition map and conclusion map, so that a conclusion map can occur several times, and does not read the form {during,|}. The first expression keeps the cells of B where both maps of A within the map of B are greater than 1, the second where one of them is: 
    C = if({during}, A > 1, B, 0)
C = if({during,|}, A > 1, B, 0)
  2. Equal time stamps for then and else. With a condition on map values, the then and the else part need equal time stamps; otherwise the algebra stops with an error. The classic algebra computes only the maps whose time stamp occurs in both parts and leaves out the others without notice. This expression is therefore an error, where the classic algebra gives an empty result: 
    C = if(A > 2, A, B)
  3. Precedence. && binds stronger than ||, and conditions can be grouped with parentheses. The classic algebra evaluates conditions on temporal variables from left to right and does not accept parentheses around conditions. The first expression takes all maps of A, because td(A) == 1 is true for each of them; the classic algebra reads it as the second expression and takes none: 
    C = if(td(A) == 1 || td(A) == 2 && td(A) == 3, A)
C = if((td(A) == 1 || td(A) == 2) && td(A) == 3, A)
  4. Right reference. A {:,R,r} B and A {op,R,r} B give one map per related pair, with the time stamp of the right map and, for an operator, the value of this pair. The classic algebra keeps only the last pair of a selection, and an operator combines the left map with all of its related right maps in every result. The first expression gives four maps, the time stamps of A with the values of B; the classic algebra gives one map per map of B. If a map b1 contains the maps a1 and a2, the second expression gives b1 + a1 and b1 + a2, the classic algebra b1 + a1 + a2 for both: 
    C = B {:,contains,r} A
C = B {+,contains,r} A

    The inverse selection A {!:,R,t} B takes only the temporal operator l, because its maps have no related map to combine with; the classic algebra accepts the other operators.

  5. td() of a time instance is null instead of an error, so a condition on it is neither true nor false. This expression gives no map; the classic algebra stops with an error: 
    C = if(td(I) > 0, I)

    A temporal variable that a map does not have, such as end_doy() of a time instance or the calendar values of relative time, is an error in both algebras.

  6. More syntax. Comparisons, temporal functions and the minus sign may stand anywhere in an expression, and a dataset may have the name of a function. The classic algebra reports a syntax error for each of these expressions; the last one adds 1 to a dataset named td: 
    C = A
C = -A + 10
C = A > 2
C = A + start_doy(A)
C = isnull(A)
C = td + 1
  7. Intersection with several related maps. With the temporal operator i, a map whose related maps have no common intersection is left out. The classic algebra intersects the map with its related maps until the first one that has no common time with the result so far, so that its result depends on the order of the related maps. If a dataset H has a map from day 2 to day 4, this map follows the map of A of day 1 and precedes the one of day 4; the intersections are the time instances of day 2 and day 4, and the map is left out: 
    C = H {:,follows|precedes,i} A
  8. Negative buffer. A negative size in buff_t() shrinks the maps by that size at both ends. The new algebra stops with an error if a map would keep no time, that is if its end would fall on or before its start, and for a time instance, which has no duration to shrink. The classic algebra goes on instead: for a map whose end would fall before its start it prints an error message and keeps the old time stamp, and it makes a time instance of a map whose end equals its start. For maps of two days, the first expression shrinks them to one day and the second is an error: 
    C = buff_t(B, "-12 hours")
C = buff_t(B, "-1 day")
  9. merge() of maps read at an offset. The new algebra takes two maps with equal content and time stamps as one map. The classic algebra, as the reference implementation, makes a new map for each map read with a temporal neighbourhood modifier, and merge() keeps such a map next to an equal one. For four maps in A, this expression gives four maps in the new algebra and eight in the classic algebra: 
    C = merge(A[0], A[0])
  10. Integers beyond 32 bits. The new algebra keeps an integer constant beyond 32 bits and writes it as a floating point number, so the result map is of type DCELL. The classic algebra reads it as r3.mapcalc does, which keeps only its lower 32 bits: 3000000000 becomes -1294967296, and 2147483648 becomes null. Each map of A lasts one day, so this expression gives 3000000001 in the new algebra and -1294967295 in the classic algebra: 
    C = if(td(A) <= 0.5, A, 3000000000) + td(A)
    The classic algebra also computes arithmetic on time function values as r3.mapcalc does, in 32 bits, also in a condition; the new algebra computes with all digits. If the two maps of RS last 3000000000 seconds each, td(RS) * td(RS) wraps around to -494665728 in the classic algebra, so this expression gives the value 1 for both maps there and the maps of RS in the new algebra. A time function on its own, as in if(td(RS) > 2000000000, RS, 1), keeps all its digits in both algebras. 
    C = if(td(RS) * td(RS) > 5, RS, 1)
In Python, both algebras raise SyntaxError for an expression they cannot read. For one they cannot compute, such as if(end_doy(I) > 0, I), the new algebra raises ValueError or TypeError, where the classic algebra raises FatalError. Both raise FatalError for a missing dataset and, without overwrite, for an existing result. The tool stops with the error message in both algebras.

Two corrections apply to both algebras, and to t.rast.algebra, t.select and t.vect.algebra as well, so -c gives the rules of the classic algebra, not the results of a particular release. First, if({R}, condition, conclusion) reads "condition R conclusion": if({contains}, start_doy(A) > 0, B) gives the maps of B that lie within a map of A, where earlier versions gave the maps of B that contain a map of A. Second, with a temporal relation beyond equal, the else part of a condition on temporal variables also takes the maps that no condition map is related to. Figure A3 of Gebbert, Leppelt and Pebesma (2019) needs both: A has maps from day 1 to 3, 3 to 5 and 5 to 7 of January 2001, B has daily maps from day 1 to 10, and this expression gives the first two maps of A and the maps of B from day 5 on, as the figure shows: 

C = if({equal|contains}, start_date(A) <= "2001-01-03", A, B)

Results that rely on the previous reading direction or else rule need the GRASS version they were computed with. The section "Core and classic algebra" in the NOTES of t.rast.algebra describes both corrections.

Corrections to the classic algebra

The classic algebra gives the results of the releases before GRASS 8.6, with the exceptions below. In these cases those releases computed wrongly, ended in an error that had no reason, or reported the wrong error. -c now gives the result described here. The reference implementation was corrected in the same way, except in items 14 and 15: it still takes the time of a partner whose box only touches, and it still raises the CalledModuleError of a failed module. The new algebra never computed these cases wrongly; only the items on month steps, on dates beyond the year 9999 and on a failed module concerned the library and with it both algebras. Results of earlier GRASS versions that used one of these forms need a new run. The examples use the datasets of the list above and, in addition, N with daily maps.
  1. td() of an expression on the right of an operator used the value of the expression instead of the duration of its maps. With daily maps in N and A, the expression gave N - A * 2 where it now gives N - 1: 
    C = N - td(A * 2)
  2. tsnap() and tshift() of no maps. If the expression inside has no maps, the result is an empty dataset, and an enclosing expression goes on with no maps. Earlier versions ended in an error. No map of A is equal to a map of B, so both expressions give an empty dataset: 
    C = tsnap(A {:,equal} B)
C = A + tshift(A {:,equal} B, "1 day")
  3. Increments that the library refuses. An increment of tshift() or buff_t() that does not fit the temporal type, such as a text that is not a time step or a number without unit on absolute time, is a syntax error and leaves no result dataset. The new algebra refuses the same increments with a ValueError: 
    C = tshift(A, "1 DAY")
C = buff_t(A, 3)
  4. merge() and the data type. The data types of the maps are not compared, so a dataset may hold integer and floating point maps. Earlier versions refused merge() of a dataset with a single map from map() or tmap() with the error that the datasets must have the same data type: 
    C = merge(A, A * 1.5)
  5. Time constants with offset. A temporal function with an offset needs a map with the time value it returns. On a map without it, such as end_month() of a time instance or start_month() of relative time, the expression stops with an error that says the function requires absolute time, as the same function in a condition does. Earlier versions wrote None into the r3.mapcalc expression, which failed when the maps were computed: 
    C = A + end_month(I, 0)
  6. Intersection with a time instance. With the temporal operator i, the time stamp of the result is the time instance, for a selection and for an operator, on absolute and on relative time. Earlier versions kept the time stamp of the left map for an operator and failed with a TypeError for a selection on relative time. Both expressions give maps with the instances of I as time: 
    C = A {:,contains,i} I
C = A {+,contains,i} I
  7. td() of a counted map. td() of a map counted by the hash operator gave the count instead of the duration, as an operand and in a comparison (corrected 17 October 2026). The datasets A and N have daily maps and A # merge(A, N) counts 2 for each map of A. The expression added 2 to the maps of N where it now adds the one day of their duration; a condition such as td(A # merge(A, N)) > 1.5 was true and is false now. The duration of a map that is not counted did not change: 
    C = N + td(A # merge(A, N))
  8. A map read at an offset as a truth value. A time function of a map read at an offset in time or in cells, such as end_year(A[1]), joined with && or || to a condition on cells is a truth value, like the time function of any map (corrected 17 October 2026). The releases before GRASS 8.6 wrote the map itself as the operand, so that a map with a value other than 0 counted as true whatever the time function said. The same holds where the time condition follows further time conditions, as in td(A[1]) > 0.5 && td(B) > 0.5 && B > 0. Where the maps are floating point, r3.mapcalc refused the map as an operand and the expression ended in an error; it now runs. The cell value of a map read at an offset, as in B[1] > 0.5 && B, did not change: 
    C = if(B > 0.5 && td(A[1]) > 0.5, A)
  9. Chains that start with a number or map(). A chain of operators whose first operand is a number or a map without time stamp, such as map(L) - 1 - A, was grouped from the right, as map(L) - (1 - A) (corrected 17 October 2026). It is grouped from the left now, as in mathematics and in the new algebra. With 0.5 in L and the values 1 to 4 in A, the expression gave 0.5, 1.5, 2.5 and 3.5 and now gives -1.5, -2.5, -3.5 and -4.5, the result of (map(L) - 1) - A. Chains after a dataset, such as A + (map(L) - 1 - 1), which ended in a syntax error, are read now: 
    C = map(L) - 1 - A
  10. td() as left operand of a stronger operator. An expression such as A + td(A) / A was computed as (A + td(A)) / A, because td() could only stand right of an operator (corrected 17 October 2026). The operators *, / and %, also with a temporal operator in braces, bind stronger than + and - now, as in mathematics and in the new algebra. With daily maps and the values 1 to 4 in A, td(A) is one day. The expression gave 2, 1.5, 1.3333 and 1.25 and now gives 2, 2.5, 3.3333 and 4.25. A td() at the start of a product, such as td(A) * 2, was a syntax error and is read now: 
    C = A + td(A) / A
  11. A spatial relation without a temporal one. An operator with spatial relation names only, such as A {+,equivalent,l} N, related no map, because maps are related by their temporal relations, and gave an empty result without a message (corrected 17 October 2026). It stops now with the error "equivalent is a spatial relation and needs a temporal one, as in equal|overlap", as in the new algebra. Write a temporal relation beside the spatial one: 
    C = A {+,equal|equivalent,l} N
  12. Month and year steps from the end of a month. tshift() and buff_t() by months or years ended in an error ("day is out of range for month") when a time stamp moved to a day that the target month lacks, in both algebras. Such a step now ends on the last day of that month (corrected 23 October 2026). With a dataset M whose map lasts from 31 January to 31 March 2001, the first expression gives a map from 28 February to 30 April 2001, the second one a map from 31 December 2000 to 30 April 2001. A year step from 29 February 2004 ends on 28 February 2005: 
    C = tshift(M, "1 months")
C = buff_t(M, "1 months")

    A month step back that ends in December of the year before last or earlier, for example buff_t(A, "24 months") on a map that starts on 1 December or tshift(A, "-13 months") on one that starts in January, ended in the error "bad month number 0" and now gives a result (corrected 23 October 2026). Years and months of one step count as one step of 12 * years + months months, so "1 years, 11 months" and "23 months" end on the same day.

  13. A date beyond the year 9999. A step that ends behind the year 9999 or before the year 1, for example buff_t(A, "365 days") on a map that ends on 1 December 9999, ended with a traceback ("date value out of range") in both algebras. It now ends with the error "... is beyond the year 9999" or "... is before the year 1" (corrected 23 October 2026); no map and no dataset is created.
  14. A selection with r or u under -s and maps whose boxes only touch. With -s two maps are related when they are related in time and in space; boxes that meet at an edge or a corner only are not related in space. A selection such as A {:,precedes,r} B took the time of every map that was related in time, also of one whose box only touches the box of the map of A, and the last such map won. An inverse selection such as A {!:,precedes,r} B kept a map without a related partner, as it should, but gave it the time of a partner that only touches it. The time is now taken only from maps that are related in time and in space, and !: keeps a map without such a partner with its own time (corrected 23 October 2026). For example, a map of A from 1 to 2 January whose box meets at a corner the box of a map of B from 2 to 3 January keeps the time 1 to 2 January in the inverse selection above, where it took 2 to 3 January. Without -s nothing changes.
  15. A failed module. If a module fails while the maps are computed, for example r3.mapcalc on a floating point map as an operand of &&, both algebras ended with a Python traceback. They now end with the error Module <r3.mapcalc> failed with return code 1, see the error output above (corrected 24 October 2026); the cause is in the error output of the module above it. No dataset is created.
  16. The relation equals. The relation equal may be written equals here too, as in t.rast.algebra; the releases before GRASS 8.6 refused that spelling with a syntax error (corrected 17 October 2026).
  17. Comparison of related maps. The comparison of related maps inside if(), such as C = if(A {>=, contains, |} B, A, 0) or C = if(A >= B, A, B), described in t.rast.algebra, works for 3D raster maps in the same way. The releases before GRASS 8.6 refused it with a syntax error (corrected 17 October 2026).

Differences from the reference implementation

The differences in message texts, in the debug output of the Python parser, in the order of errors and in the error for an existing result that t.rast.algebra lists apply here likewise, as does the item on lists of absolute and relative time, the one that changes the outcome of an expression.

Granularity algebra

With the flag -g, each space time dataset of the expression is first sampled with the common granularity of all datasets of the expression. The granules of a dataset follow each other from the start of its first map until they cover the end of its last map, so the last granule may reach past it, for example a granule of two days over a map of three days. If the dataset has time instances, one more granule follows. Each granule takes one map of the dataset, with the time stamp of the granule:
  1. the first map that is equal to the granule;
  2. otherwise the first map that contains the granule;
  3. otherwise the first map that starts within the granule and ends after it;
  4. otherwise the first map that starts before the granule and ends within it;
  5. otherwise the first map that lies within the granule.

A granule without such a map is left out. Then the expression is computed as without the flag, so that maps of equal time are combined. Operators with temporal relations in curly brackets cannot be used in this mode, and all datasets need a valid temporal topology and the same temporal type.

Single maps given with map() or tmap() are not sampled. The differences between the two algebras listed under "Core and classic algebra" apply with -g as well, for example item 4, the right reference.

See the example "Sample the maps with a common granularity" below and the manual of t.rast.algebra.

Relate the maps of two datasets by their time

The dataset B has two maps of two days each: b_1 with the value 10 for 1 and 2 March and b_2 with the value 20 for 3 and 4 March. Each map of B contains two maps of A, and each map of A lies during a map of B. The relation is written in curly brackets after the operator.

The first block adds to each map of B all the maps of A that it contains: b_1 + a_1 + a_2 is 13 and b_2 + a_3 + a_4 is 27. The result has two maps and takes the time of B. The second block adds to each map of A the map of B that it lies in: 11, 12, 23 and 24, with the times of A. The two expressions differ because the operator combines a map with all of its related maps of the right dataset, and does so for each map of the left one.

Command line:

r3.mapcalc expression="b_1 = 10"
r3.mapcalc expression="b_2 = 20"
t.create type=str3ds output=B title="Two-day maps" \
    description="Two maps of two days each"
t.register -i type=raster_3d input=B maps=b_1,b_2 \

Catalog: temporal functions, shifts and buffers

The temporal functions give the duration or a part of the date of each map as a number. start_day(A) is the day of the month, 1 to 4, so the sum is 2, 4, 6 and 8. td(A) is the duration of a map in days, here 1. The neighbourhood modifier has four offsets for a 3D raster dataset: Z[row,column,depth,time]. The maps of Z have the values 1 and 2 in their two layers (plus 0, 10, 20 and 30 for the four days). The offset 1 in depth reads the next layer: the first layer sees the value of the second one, and the second layer has no next layer, so it is null. The only value of the result is 2 for the first day, 12 for the second, and so on. The fourth offset reads another map in time: Z[0,0,0,1] has the cells of the next map with the time of the current one, and the last map has no successor, so the result has three maps. The offsets combine: Z[0,0,1,-1] reads the next layer of the previous map, which leaves out the first map.

Catalog: where the classic algebra differs

Each pair of blocks computes one expression of the list "Core and classic algebra" in the NOTES, first with the new algebra and then with -c. The first pair is item 1: the conditions of the two maps of A within a map of B are joined with and, so the new algebra gives 0 and 20; the classic algebra gives one result for each pair of a condition map and a conclusion map, and four maps in total.
