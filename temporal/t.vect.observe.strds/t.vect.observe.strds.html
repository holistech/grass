DESCRIPTION

t.vect.observe.strds observes the values of one or several space time raster datasets (STRDS) at the positions of the points of a vector map. For every raster map of the dataset it reads the value under each point and stores it in a column. The result is a new space time vector dataset (STVDS) with one vector map and as many layers as the raster dataset has maps: layer 1 holds the values of the first map, layer 2 those of the second map, and so on. Every layer is registered in the new dataset with the time of its raster map. See the introduction to temporal data processing for space time datasets. t.vect.what.strds does the opposite: it samples at the positions of the maps of a vector dataset and writes the values into the table of each vector map. t.rast.what prints the values at points instead of storing them. The values are read with v.what.rast.

The option input is the vector map with the points; it can be in another mapset. The option strds names one or several space time raster datasets, separated by commas. The option columns names the columns that get the sampled values, one name for each dataset in the order of strds; the numbers of names and datasets must be equal. A column of a CELL (integer) raster map is of type INTEGER, the column of any other raster map of type DOUBLE PRECISION.

The option type names the feature types that v.what.rast reads, point (the default), centroid or both. With type=centroid a map of areas is observed at the centroids of its areas, one value for each area: the value of the cell below the centroid. The output map is a copy of the whole input with its boundaries and centroids, so the areas arrive intact. Without it a map without points gets columns that stay empty. The last example observes counties.

The output is made of two parts, both in the current mapset:

  • the option vector_output names the new vector map. It is a copy of the input in which every point has the same category in each layer. Layer 1 is linked to a copy of the table of the input, which gets the new columns in addition to the columns that it has; it keeps the layer name of the input. Every further layer has a new table <vector_output>_<layer> with the columns cat and the new columns;
  • the option output names the new space time vector dataset. It takes the temporal type (absolute or relative time, with its unit) and the semantic type of the first dataset of strds. Its maps are the layers <vector_output>:<layer>, each with the start and end time of its granule.

With one dataset, a granule is a map of the dataset. With several datasets, the granules are the maps of the first dataset, and the run observes a granule only if every other dataset has a map with the same time; a granule for which one dataset has no map is left out. If a dataset has several maps with that time, the module warns, naming the granule and the dataset, and uses the first of them. The datasets must have the same temporal type, and the first dataset needs maps with intervals. All datasets are sampled as they are, over their whole temporal extent.

Points are sampled in the current computational region (see g.region): a point outside the region, or on a cell without a value, gets a NULL in the column.

The option where takes an SQL condition on the table of layer 1 of the input and selects the points to observe. The points that it does not select are not in the output map, in none of its layers.

Use t.vect.db.select or v.db.select to print the values of the new layers.

NOTES

The condition where works on the table of layer 1, so the module stops with an error before it writes anything if the input map has other layers besides layer 1, with categories or with a table. A condition that v.extract refuses stops the module with the message Unable to select the points of <name> with where, again before anything is written.

If a column named in columns exists in the table of a layer of the input map, the module stops with an error that names the column and advises the overwrite flag. With --overwrite it keeps the column, sets it to NULL in every row of the output map first and then writes the sampled values, so a point that is not sampled, outside the region or on a cell without a value, gets a NULL as well. The input map keeps its values. A name that differs from such a column only in upper and lower case (Altitude for altitude) is refused, with and without --overwrite, before the output map is made, with a message that names both spellings.

If a run fails with an error message, the module removes the vector map and the space time vector dataset that it made, so nothing is left behind. With --overwrite the previous output map and dataset of the same names have already been replaced when the run fails, so they are gone as well and are not restored. Without --overwrite an existing output is refused before anything is made and stays as it was. To keep a result, give the new run another name.

If where selects no point, the module stops with the message The where option selects no point of vector map <name>. It makes no output vector map and no space time vector dataset. The second block of the example "Observe a selection of the points" shows it.

If several datasets are given and no map of the first dataset has a map with the same time in every other dataset, the module ends with the return code 0 and a warning that no granule has a map in each of the datasets. It writes nothing: no space time vector dataset and no vector map are made, and an output of the same names that exists stays as it is. The third block of the example "Observe several raster datasets" shows it.

The names in columns must differ, whatever the case of the letters. A name that is given twice stops the module with the message The column names must be different before anything is written.

The module stops with an error, among others, for these reasons:

  • the numbers of columns and datasets differ: The number of columns must be equal to the number of space time raster datasets;
  • a dataset has no maps: Space time raster dataset <name@mapset> is empty;
  • the datasets have different temporal types: Temporal type of space time raster datasets must be equal;
  • with several datasets, the first dataset has maps that are time instances: The temporal map type of the sample dataset must be interval;
  • a raster map of a dataset does not exist any more.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_vect_observe_strds and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region. The raster series are generated, they are not measurements. The points are the places of real climate stations of the dataset, rounded to the meter, but the values at them come from a formula and say nothing about the climate there. The datasets shifted, twin and runoff hold maps with small constant values.

Observe a raster dataset at points

The dataset temperature_monthly holds the three maps of the monthly mean air temperature from January to March 2020, in degrees Celsius rounded to tenths. They are generated from the elevation model elev_state_500m: 16.5 degrees at sea level and the northing 160 km, an annual cycle of plus and minus 10.5 degrees with its maximum in July, 6.5 degrees less for every 1000 m of elevation, and 1 degree more for every 100 km to the south. Each map is an interval of one month.

The input map stations has five points; the column altitude is their only attribute besides the coordinates, and their categories are 1 to 5. The first three lie at the climate stations 310090, 310184 and 310241, the fourth at the station 311458 on the Outer Banks, whose cell has no value in the elevation model, and the fifth west of the computational region. The altitudes are those of the stations in meters, rounded, the altitude of the fifth point is chosen.

The run observes the dataset temperature_monthly, so the output has three layers with one month each. The first block runs the module and shows the temporal properties of the new dataset, which holds 15 points (five in each of the three layers), and its maps. The layers have the column temp and, in layer 1, the columns of stations in addition. The fourth and the fifth point have no value. The second block shows the tables of the layers. The third block shows how the layers are linked to their tables: layer 1 keeps the layer name stations of the input and uses the table obs_points, the others have the table obs_points_<layer>.

Observe several raster datasets

The second input is the dataset precipitation_monthly with the maps of February and March 2020, in whole millimeters. They are generated too: the monthly normal of the climate stations (the columns feb and mar of precip_30ynormals) is interpolated with v.surf.idw and multiplied by an assumed factor for a wet year, 1.7 for February and 0.9 for March. The run needs one column for each dataset, so columns=temp,precip gives the values of temperature_monthly to temp and those of precipitation_monthly to precip. The granules are the maps of temperature_monthly for which precipitation_monthly has a map with the same time: January has no precipitation, so it is left out and the output has two layers, February and March. The fourth and the fifth point read NULL in both columns: the cell of the fourth point has no value in either series, and the fifth point lies outside the region. The second block shows the column types: temp follows the floating point maps of temperature_monthly, precip the integer maps of precipitation_monthly.

The third block adds the dataset shifted with one map from noon of 15 January to noon of 15 February 2020. No map of shifted has the time of a map of temperature_monthly, so no granule is left: the module warns and writes nothing, neither the dataset none nor the vector map none_points. The fourth block adds the dataset twin with the two maps twin_a (the value 1) and twin_b (the value 2) for January. The module warns that twin has two maps for the granule and uses the first one, twin_a. The column two gets its value 1 for the points in the region, also for the fourth point on the Outer Banks, where the temperature is null: the constant maps have a value in every cell of the region.

Observe a dataset with relative time

The dataset runoff has relative time with the unit hours: runoff_1 from 0 to 1 and runoff_2 from 1 to 2, with the constant values 100 and 200. In layer 2 the points 1 to 4 read 200, the fifth point outside the region has no value. The output dataset has relative time with the same unit, and its layers have the times of the maps as numbers.

Command line:

for step in 1 2; do
    r.mapcalc expression="runoff_$step = 100 * $step"
done
t.create output=runoff temporaltype=relative title="Runoff" \
    description="Simulated runoff in mm per model hour"
t.register -i input=runoff maps=runoff_1,runoff_2 start=0 increment=1 unit=hours
t.vect.observe.strds input=stations strds=runoff output=obs_runoff \
    vector_output=obs_runoff_points columns=runoff_mm
t.vect.list input=obs_runoff columns=name,layer,start_time,end_time
t.info -g type=stvds input=obs_runoff | grep -E "^(temporal_type|unit)="
v.db.select map=obs_runoff_points layer=2

Observe data of another mapset

The input map and the raster dataset may be in another mapset: the names with the mapset, stations@t_vect_observe_strds and temperature_monthly@t_vect_observe_strds, select them. The output map and dataset are made in the current mapset, here the new mapset t_vect_observe_strds_2. A new mapset has its own region, so the example sets the region again before the points are sampled. The mapset t_vect_observe_strds does not have to be in the search path.

Command line:

g.mapset -c mapset=t_vect_observe_strds_2
g.region raster=elev_state_500m res=1000 -a
t.vect.observe.strds input=stations@t_vect_observe_strds \
    strds=temperature_monthly@t_vect_observe_strds output=remote \
    vector_output=remote_points columns=temp
t.vect.list input=remote columns=name,layer,mapset

Observe areas at their centroids

The example works in the mapset t_vect_observe_strds_2 of the previous example. The map counties holds the areas of three counties, extracted from boundary_county with v.extract. With type=centroid the module reads the value under the centroid of each county. Layer 1 holds the January map and layer 2 the February map; the output map still has three areas with their centroids, which v.info -t shows.

Command line:

v.extract input=boundary_county output=counties \
    where="NAME IN ('WAKE', 'DURHAM', 'ORANGE')"
t.vect.observe.strds input=counties strds=temperature_monthly@t_vect_observe_strds \
    output=county_obs vector_output=county_points columns=temp type=centroid
v.db.select map=county_points layer=1 columns=cat,NAME,temp
v.db.select map=county_points layer=2
v.info -t map=county_points | grep -E "^(boundaries|centroids|areas)="
