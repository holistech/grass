DESCRIPTION

t.vect.observe.strds observes the values of one or several space time raster datasets (STRDS) at the positions of the points of a vector map. For every raster map of the dataset it reads the value under each point and stores it in a column. The result is a new space time vector dataset (STVDS) with one vector map and as many layers as the raster dataset has maps: layer 1 holds the values of the first map, layer 2 those of the second map, and so on. Every layer is registered in the new dataset with the time of its raster map. See the introduction to temporal data processing for space time datasets. t.vect.what.strds does the opposite: it samples at the positions of the maps of a vector dataset and writes the values into the table of each vector map. t.rast.what prints the values at points instead of storing them. The values are read with v.what.rast.

The option input is the vector map with the points; it can be in another mapset. The option strds names one or several space time raster datasets, separated by commas. The option columns names the columns that get the sampled values, one name for each dataset in the order of strds; the numbers of names and datasets must be equal. A column of a CELL (integer) raster map is of type INTEGER, the column of any other raster map of type DOUBLE PRECISION.

The output is made of two parts, both in the current mapset:

  • the option vector_output names the new vector map. It is a copy of the input in which every point has the same category in each layer. Layer 1 is linked to a copy of the table of the input, which gets the new columns in addition to the columns that it has; it keeps the layer name of the input. Every further layer has a new table <vector_output>_<layer> with the columns cat and the new columns;
  • the option output names the new space time vector dataset. It takes the temporal type (absolute or relative time, with its unit) and the semantic type of the first dataset of strds. Its maps are the layers <vector_output>:<layer>, each with the start and end time of its granule.

With one dataset, a granule is a map of the dataset. With several datasets, the granules are the maps of the first dataset, and the run observes a granule only if every other dataset has a map with the same time; a granule for which one dataset has no map is left out. If a dataset has several maps with that time, only one of them is used. The datasets must have the same temporal type, and the first dataset needs maps with intervals. All datasets are sampled as they are, over their whole temporal extent.

Points are sampled in the current computational region (see g.region): a point outside the region, or on a cell without a value, gets a NULL in the column.

The option where takes an SQL condition on the table of layer 1 of the input and selects the points to observe. The points that it does not select are not in the output map, in none of its layers.

Use t.vect.db.select or v.db.select to print the values of the new layers.

NOTES

The condition where works on the table of layer 1, so the module stops with an error before it writes anything if the input map has other layers besides layer 1, with categories or with a table. A condition that v.extract refuses stops the module with the message Unable to select the points of <name> with where, again before anything is written.

If a column named in columns exists in the table of a layer of the input map, the module stops with an error that names the column and advises the overwrite flag. With --overwrite it keeps the column and replaces its values with the sampled ones, but a point that is not sampled (a point outside the region) keeps its old value; a point on a cell without a value gets a NULL. A name that differs from such a column only in upper and lower case (Altitude for altitude) is refused, with and without --overwrite, before the output map is made, with a message that names both spellings.

If a run fails with an error message, the module removes the vector map and the space time vector dataset that it made, so nothing is left behind. The exception is a where that selects no point, see below. With --overwrite the previous output map and dataset of the same names have already been replaced when the run fails, so they are gone as well and are not restored. Without --overwrite an existing output is refused before anything is made and stays as it was. To keep a result, give the new run another name.

If where selects no point, the module ends with a Python error (KeyError: 1) and leaves the empty output vector map behind; it makes no space time vector dataset. Remove the map with g.remove, or check the condition on the table of the input with v.db.select first. The second block of the example "Observe a selection of the points" shows it.

If several datasets are given and no map of the first dataset has a map with the same time in every other dataset, the module ends without a message and with the return code 0. It makes an empty space time vector dataset and a vector map that has only layer 1. Check the result with t.info if the datasets may not share a granule. The third block of the example "Observe several raster datasets" shows it.

The module stops with an error, among others, for these reasons:

  • the numbers of columns and datasets differ: The number of columns must be equal to the number of space time raster datasets;
  • a dataset has no maps: Space time raster dataset <name@mapset> is empty;
  • the datasets have different temporal types: Temporal type of space time raster datasets must be equal;
  • with several datasets, the first dataset has maps that are time instances: The temporal map type of the sample dataset must be interval;
  • a raster map of a dataset does not exist any more.

EXAMPLES

Observe a raster dataset at points

The region has 3 by 3 cells. The raster map temperature_k (k from 1 to 3, one map for each day from 1 March 2026) holds 10 * k plus the number of the cell, counted from 1 in the upper left corner row by row: 11 to 19 in the first map, 21 to 29 in the second, 31 to 39 in the third. The input map stations has five points; the column altitude is their only attribute, and their categories are 1 to 5. The first four lie in the middle of the cells 1, 3, 5 and 7, the fifth outside the region.

The run observes the dataset temperature, so the output has three layers with one day each. The first block runs the module and shows the temporal properties of the new dataset, which holds 15 points (five in each of the three layers), and its maps. The layers have the column temp and, in layer 1, the columns of stations in addition: the points in the cells 1, 3, 5 and 7 read 11, 13, 15 and 17 in the first layer, 21, 23, 25 and 27 in the second, 31, 33, 35 and 37 in the third. The fifth point has no value. The second block shows the tables of the layers. The third block shows how the layers are linked to their tables: layer 1 keeps the layer name stations of the input and uses the table obs_points, the others have the table obs_points_<layer>.

Observe several raster datasets

The second input is the dataset humidity from the maps humidity_2 and humidity_3, which are valid on the second and the third day. Their values are k + 0.5 * n for humidity_k and the cell number n, except that the cell number 7 is NULL. The granules are the maps of temperature for which humidity has a map with the same time: the first day has no humidity, so it is left out and the output has two layers, the second and the third day. The point in the cell 7 reads a NULL in hum, and the fifth point outside the region a NULL in both columns. The second block shows the column types: temp follows the integer maps of temperature, hum the floating point maps of humidity.

The third block adds the dataset late with one map from noon of the first day to noon of the second day. No map of late has the time of a map of temperature, so no granule is left: the module ends without a message and the new dataset none has no map (number_of_maps=0); the vector map none_points exists, with layer 1 only. The fourth block adds the dataset twice with the two maps twice_a (the value 1) and twice_b (the value 2) for the first day. Observe data of another mapset

The input map and the raster dataset may be in another mapset: the names with the mapset, stations@PERMANENT and temperature@PERMANENT, select them. The output map and dataset are made in the current mapset, here the new mapset analysis. A new mapset has its own region, so the example sets the region again before the points are sampled.

Command line:

g.mapset -c mapset=analysis
g.region n=3 s=0 e=3 w=0 res=1
t.vect.observe.strds input=stations@PERMANENT \
    strds=temperature@PERMANENT output=remote \
    vector_output=remote_points columns=temp
t.vect.list input=remote columns=name,layer,mapset
v.db.select map=remote_points layer=1 columns=cat,temp
