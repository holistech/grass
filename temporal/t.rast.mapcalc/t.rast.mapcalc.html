DESCRIPTION

t.rast.mapcalc computes new raster maps from the maps of one or more space time raster datasets (STRDS) and registers them in a new STRDS. It runs r.mapcalc once for each time step and adds the temporal variables td(), start_time(), end_time() and, for absolute time, the calendar functions start_doy(), end_month() and others to the expression. Use it when the result of a time step depends on maps of several datasets, on the time of the step, or on both. See the introduction to temporal data processing for space time datasets. t.rast3d.mapcalc does the same for space time 3D raster datasets, t.rast.algebra computes with the temporal algebra, and t.rast.list lists the maps of the result.

Datasets and time steps

The option inputs lists the datasets whose maps the expression uses. The first dataset of the list is the sampler: every map of it is one time step, which this manual calls a granule. Each of the other datasets is sampled by the granules: for each granule, the tool looks for the map of the dataset that is related to the granule in time, as the option method says. A granule for which one of the datasets has no related map is skipped. The order of the datasets in the expression does not matter, only their order in inputs. If the list names only one dataset, every map of it is a granule. The datasets may be in other mapsets (precipitation_monthly@t_rast_mapcalc); the expression then uses the name without the mapset or, as in inputs, with it, and the mapset does not have to be in the search path (see Datasets of other mapsets).

A name with a dot, such as bands.S2_8, is a dataset name and a semantic label. It selects the maps of the dataset that have this label, and the expression uses the same name. The new maps take the semantic label of the map of the sampler. The eighth example shows it; see i.band.library for the concept of semantic labels. A dataset of an earlier release can have a dot in its name. It is found by its whole name: the mapsets are searched in turn, the current one first, and in each the whole name is tried before the text after the dot is read as a semantic label.

The result dataset is the option output. It always belongs to the current mapset, and so do the new maps. It takes the temporal type and the semantic type of the first dataset of inputs. Each new map has the start and end time of its granule. An existing dataset output is refused unless the flag --overwrite is given; then it is replaced, and the tool warns that it unregisters all maps of the old dataset. A name with a dot is refused as output.

The option where is an SQL condition on the registered maps, for example start_time >= '2026-06-11'. It applies to every dataset in inputs, the sampler too, so only the remaining maps are granules and partners. The new maps are numbered from 1 among the remaining granules. The eighth example uses it.

The tool computes in the current region, as r.mapcalc does. A map that lies outside the region reads as null.

The expression

The option expression is the right side of an r.mapcalc expression, without the map = of a full one. In it, the name of each dataset of inputs stands for the related map of the current granule, so precipitation_monthly * temperature_monthly multiplies the map of precipitation_monthly by the related map of temperature_monthly, and temperature_monthly * precipitation_monthly does the same. Any other raster map can be used by its name. The operators and functions of r.mapcalc are available.

The tool puts the names of the maps into the text of the expression and numbers the results, so with the expression soil * 2 a call with four granules runs four statements such as doubled_1=soil_1 * 2. A dataset name is replaced only where it stands as a whole name: not inside a longer name (soil in soil_deep), and not before an opening parenthesis, where it is the name of a function (day in start_day()); see the ninth example. A modifier of r.mapcalc in front of the name applies to the map of the granule, so @soil reads the category labels of soil_1; after a map name, as in elevation@soil, the name is a mapset and stays. The rest of the expression goes to r.mapcalc as written, blanks included. Two inputs with the same name, such as soil,soil, are refused before any map is computed, because the expression could not tell them apart.

The option basename is required. The new maps are named after it, followed by an underscore and the number of their granule, counted from 1 in the order of the sampler. The number has as many digits as the number of granules needs, filled up with zeros: doubled_1 for four granules, doubled_01 for eleven. A granule that is skipped, or whose result is empty, leaves a gap in the numbers.

Temporal variables

The following variables are replaced by a number for each granule before the expression goes to r.mapcalc. They work with absolute and with relative time.
  • td(): the length of the granule, the end minus the start, in days and fractions of days for absolute time, in the unit of the dataset for relative time; null for a time instant.
  • start_time(): the start of the granule minus the start of the first granule, in days or in the unit.
  • end_time(): the end of the granule minus the start of the first granule, in days or in the unit; null for a time instant, which has no end.

For absolute time, the calendar functions give a part of the start or the end of the granule as a whole number. Each function exists for the start (start_doy()) and for the end (end_doy()) of the granule, and the end functions are null for a time instant.

  • start_doy(): the day of the year, 1 to 366.
  • start_dow(): the day of the week, 1 to 7; Monday is 1.
  • start_year(): the year.
  • start_month(): the month, 1 to 12.
  • start_week(): the ISO week of the year. Weeks start on Monday, and the first days of January can belong to week 52 or 53.
  • start_day(): the day of the month, 1 to 31.
  • start_hour(): the hour, 0 to 23.
  • start_minute(): the minute, 0 to 59.
  • start_second(): the second, 0 to 59.

With relative time, a calendar function stops the tool with an error. The fifth example shows the variables for both kinds of time.

Select the related maps

The option method is a list of the sampling methods. It names the relation between the granule and the map of another dataset. The default is equal. A map is related to the granule if it has one of the listed relations. The third example shows the methods.
  • equal: the map has the start and the end time of the granule.
  • during: the granule lies inside the time interval of the map. The map may share the start or the end of the granule, but is not equal to it: for a granule from 10 to 20 the maps from 5 to 25, from 10 to 25 and from 5 to 20.
  • contain: the map lies inside the granule. It may share the start or the end of the granule, but is not equal to it.
  • overlap: the map starts inside the granule and ends after it, or starts before it and ends inside it.
  • follows: the map ends when the granule starts.
  • precedes: the map starts when the granule ends.
  • start: the maps that lie inside the granule, the maps that start before it and end inside it, the maps that cover it while sharing its start or its end, and the equal map. It does not take a map that covers the granule strictly and a map that starts inside it and ends after it.

If more than one map of a dataset is related to a granule, the tool warns on the standard error and uses only one of them. Which one, follows from the order in which it tries the relations. First come the methods equal, during, follows and precedes, in the order of the list method; then the group start, which tries the equal map last, then overlap and then contain, if they are in the list. Within one relation, the map with the earliest start time is taken, and for equal start times the map with the smaller id. So for the list contain,during a map found by during wins over a map found by contain. The fourth example shows this. Choose the first dataset of inputs so that its granules are the time steps you want, and use t.rast.aggregate.ds to make datasets with one map per step.

Empty results and spatial relation

A new map that has no valid cell, that is, no minimum and no maximum, is empty. By default it is not registered in output and is removed after the run. The flag -n registers the empty maps and keeps them. An expression such as if(soil > 15, soil, null()) selects time steps by values in this way. If all results are empty, output exists but holds no map.

The flag -s adds a spatial condition to the temporal one: a map is related to the granule only if its extent, from west to east and from south to north, touches or overlaps that of the granule, so a shared edge counts. A granule without a related map is skipped. The seventh example shows the difference.

Parallel processing

The option nprocs sets the number of r.mapcalc processes that run at the same time. The default is 1. The result does not depend on it.

NOTES

t.rast.mapcalc has the same options as t.rast3d.mapcalc, plus where, and works on raster maps only. The maps of the datasets are not touched; the tool makes new maps.

If a map of the base name exists as a registered map and --overwrite is not given, the tool stops before it computes any map, with "Map ... is already in temporal database, use overwrite flag to overwrite". If the dataset output exists, the tool stops with "Space time raster dataset ... is already in the database. Use the overwrite flag.".

With --overwrite, the maps of the old dataset are unregistered from it, not removed. A new run with fewer maps leaves the surplus old maps in the mapset; the tenth example shows it.

The tool stops with an error if an input dataset does not exist ("Space time dataset ... of type strds not found"), if method names a method that does not exist ("Value ... out of range for parameter method"), if where is not valid SQL ("Invalid where condition ...") and if r.mapcalc does not accept the expression ("Error while mapcalc computation"). A calendar function with relative time stops it with The temporal operators <start_*> support only absolute time. (<end_*> for an end function). The tool announces its steps on the standard error with "Starting temporal sampling..." (with -s: "Starting spatio-temporal sampling...") and "Starting mapcalc computation...".

If inputs names more than one dataset and the sampler has only time instants, or the datasets have different temporal types, the first dataset cannot sample the others: the tool stops before it computes any map, with "The temporal map type of the sample dataset must be interval" or "The space time datasets must be of the same temporal type". If where leaves no map in the sampler, the tool warns "The where condition selects no map of space time raster dataset ...". A call with one dataset needs no sampling: time instants work as in the fifth example; if where leaves no map, the tool gives the same warning, and if the dataset has no maps and no where is given, it warns "No maps registered in input dataset ...". Labels of one dataset, as in bands.S2_8,bands.S2_4, are not sampled either: if a later label has no map, the tool warns in the same way and names that label. If a sampler without maps (a label without maps, or a dataset without maps) samples another dataset of the same temporal type and no where is given, the tool warns "No samples found for map calculation". In these cases it makes no dataset output and ends with status 0. If where leaves no map in another dataset that the sampler samples, no granule has a partner, and the tool makes an output without maps.

The first example creates the mapset t_rast_mapcalc and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region, except the last, which creates a second mapset with the same region. Apply an expression to every map

The dataset temperature_monthly holds twelve maps of the monthly mean air temperature in 2020, in degrees Celsius rounded to tenths. They are generated from the elevation model elev_state_500m: 16.5 degrees at sea level and the northing 160 km, an annual cycle of plus and minus 10.5 degrees with its maximum in July, 6.5 degrees less for every 1000 m of elevation, and 1 degree more for every 100 km to the south. Each map is an interval of one month.

The first block makes the mapset, the region and the dataset, and converts the maps to degrees Fahrenheit. The name temperature_monthly in the expression stands for the map of each month. The new maps are named fahrenheit_01 to fahrenheit_12 after the granules, and each has the time of its source map. nprocs lets two r.mapcalc processes run at the same time; the result is the same as with one. The result is rounded to tenths, as the source maps are. In July the warmest cell has 28.4 degrees Celsius, which is 83.1 degrees Fahrenheit, and in January the coldest has -7.0 degrees Celsius, which is 19.4 degrees Fahrenheit. The second block shows what the new dataset takes from temperature_monthly: the temporal type and the semantic type, and the granularity that follows from the maps it holds.

Combine the maps of several datasets

The dataset precipitation_monthly holds twelve maps of the monthly precipitation sum in 2020, in whole millimeters. They are generated, not measured: the monthly normals of the climate stations in precip_30ynormals are interpolated for each month with v.surf.idw from 12 neighbours and multiplied by an assumed factor for a wet year, between 0.8 and 1.7. The maps are null outside North Carolina. The twelve interpolated normals stay in the mapset as precipitation_normal_01 to precipitation_normal_12. t.rast.aggregate adds the dataset precipitation_quarterly with four maps, the sums of three months each, so each map of it is an interval of one quarter.

The first block calculates the share of a month in the precipitation of its quarter. The first dataset of inputs is the sampler, so the result has twelve maps of one month each, and each month of precipitation_monthly lies during a map of precipitation_quarterly. The expression divides the two and gives percent rounded to tenths. In January a cell has between 28.0 and 38.6 percent of the precipitation of the first quarter; before the rounding, the three shares of a cell add up to 100 percent.

The second block swaps the order in inputs, so the sampler is precipitation_quarterly and the result has four maps of three months each. With method contain, each granule contains three monthly maps; the tool warns on the standard error and uses the first of them, the map of the first month of the quarter. The result is the sum of the quarter minus that map, so the precipitation of the other two months: 222 to 521 mm for February and March.

The third block leaves out method. The default is equal, and no month has the time of a quarter, so every granule is skipped. The tool does not fail; the new dataset exists and holds no map.

The fourth block names the default method equal and gives it partners. The sampler is temperature_monthly, and every month has a map of precipitation_monthly with the same time. The expression names precipitation_monthly first, which does not matter. It chooses the calculation by the time of the granule, a simple climatic water balance: from April to September it subtracts an assumed evaporation of 4 mm for every degree Celsius, rounded to whole millimeters, from the precipitation; in the other months it keeps the precipitation. So the maps from October to March have the values of precipitation_monthly, for example 94 to 249 mm in January, and in July the balance is between -14 and 136 mm, negative where the evaporation exceeds the precipitation.

The dataset slots has nine granules of 10 days with relative time, from day 110 to 120, from 210 to 220 and so on up to 910 to 920. Its map slot_k has the value k. The dataset probes has one map for each granule, probe_k with the value 10 * k, and each has a different position relative to the granule:
  1. probe_1 has the same times, 110 to 120.
  2. probe_2 lies inside the granule, 214 to 218.
  3. probe_3 covers the granule, 305 to 325.
  4. probe_4 starts inside the granule and ends after it, 415 to 425.
  5. probe_5 starts before the granule and ends inside it, 505 to 515.
  6. probe_6 ends when the granule starts, 600 to 610.
  7. probe_7 starts when the granule ends, 720 to 730.
  8. probe_8 starts with the granule and ends after it, 810 to 825.
  9. probe_9 starts before the granule and ends with it, 905 to 920.

The loop runs the tool once for each method and prints the maps of the result. The number at the end of a name is the number of the granule that found a related map: equal finds the map of granule 1, during the ones of the granules 3, 8 and 9, contain granule 2, overlap the granules 4 and 5, follows granule 6 and precedes granule 7. The method start finds the granules 1, 2, 5, 8 and 9. The last two blocks show that method takes a list. Without method the default equal finds only the granule 1. With the list during,overlap,contain,equal the tool collects the granules 1 to 5, 8 and 9, and the listing shows that the maps have the times of the granules.

The time of the datasets is relative, in days, and the result takes it over. The files for t.register list one map per line with its start and end time.

The first block makes the dataset soil with four maps for the days from 1 to 4 March 2026. Each map has the same value in every cell: 2, 12, 22 and 32 degrees Celsius. The expressions of the first four blocks need no map, only the time of the granule, so they name soil only in inputs. The granules are the days; 1 March 2026 is a Sunday, the 60th day of the year. Each block prints the smallest and largest value of every new map; all cells of a map have the same value.
  • Block 1: start_time() counts the hundreds, td() the tens and end_time() the ones. The days start 0, 1, 2 and 3 days after the first, are 1 day long and end 1, 2, 3 and 4 days after the start of the first, so the results are 11, 112, 213 and 314.

  • Block 3: the month and the end day. The month is 3 and the end day is 2 to 5, so the results are 302 to 305.
  • Block 4: the weeks, which start on Monday. The first day starts in week 9 and ends on Monday 2 March, in week 10, so 910, and 1010 for the other days.

The next three blocks show time instants and the ISO weeks.

  • Block 5: the dataset gauge has two time instants, at 06:00 on 1 March and at 18:00 on 2 March, and its maps have the values 1 and 2. start_time() is the offset in days and fractions of days from the first instant, 0 and 1.5, and end_time() is null, so isnull() is true and the result is 100 and 101.5. The dataset model has three steps of 5 hours with relative time. start_time(), td() and end_time() give numbers in the unit of the dataset, hours.
