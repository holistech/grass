DESCRIPTION

t.rast.mapcalc computes new raster maps from the maps of one or more space time raster datasets (STRDS) and registers them in a new STRDS. It runs r.mapcalc once for each time step and adds the temporal variables td(), start_time(), end_time() and, for absolute time, the calendar functions start_doy(), end_month() and others to the expression. Use it when the result of a time step depends on maps of several datasets, on the time of the step, or on both. See the introduction to temporal data processing for space time datasets. t.rast3d.mapcalc does the same for space time 3D raster datasets, t.rast.algebra computes with the temporal algebra, and t.rast.list lists the maps of the result.

Datasets and time steps

The option inputs lists the datasets whose maps the expression uses. The first dataset of the list is the sampler: every map of it is one time step, which this manual calls a granule. Each of the other datasets is sampled by the granules: for each granule, the tool looks for the map of the dataset that is related to the granule in time, as the option method says. A granule for which one of the datasets has no related map is skipped. The order of the datasets in the expression does not matter, only their order in inputs. If the list names only one dataset, every map of it is a granule. The datasets may be in other mapsets (soil@PERMANENT); the expression then still uses the name without the mapset.

A name with a dot, such as bands.S2_8, is a dataset name and a semantic label. It selects the maps of the dataset that have this label, and the expression uses the same name. The new maps take the semantic label of the map of the sampler. The eighth example shows it; see i.band.library for the concept of semantic labels.

The result dataset is the option output. It always belongs to the current mapset, and so do the new maps. It takes the temporal type and the semantic type of the first dataset of inputs. Each new map has the start and end time of its granule. An existing dataset output is refused unless the flag --overwrite is given; then it is replaced, and the tool warns that it unregisters all maps of the old dataset. A name with a dot is refused as output.

The option where is an SQL condition on the registered maps, for example start_time >= '2026-06-11'. It applies to every dataset in inputs, the sampler too, so only the remaining maps are granules and partners. The new maps are numbered from 1 among the remaining granules. The eighth example uses it.

The tool computes in the current region, as r.mapcalc does. A map that lies outside the region reads as null.

The expression

The option expression is the right side of an r.mapcalc expression, without the map = of a full one. In it, the name of each dataset of inputs stands for the related map of the current granule, so soil * weight multiplies the map of soil by the related map of weight, and weight * soil does the same. Any other raster map can be used by its name. The operators and functions of r.mapcalc are available.

The tool puts the names of the maps into the text of the expression and numbers the results, so a call with four granules runs four statements such as doubled_1=soil_1*2. Because the replacement works on the text, a dataset name must not occur anywhere else in the expression, neither in a function name (a dataset day breaks start_day()) nor in another dataset name (soil breaks soil_deep); see the ninth example.

The option basename is required. The new maps are named after it, followed by an underscore and the number of their granule, counted from 1 in the order of the sampler. The number has as many digits as the number of granules needs, filled up with zeros: doubled_1 for four granules, doubled_01 for eleven. A granule that is skipped, or whose result is empty, leaves a gap in the numbers.

Temporal variables

The following variables are replaced by a number for each granule before the expression goes to r.mapcalc. They work with absolute and with relative time.
  • td(): the length of the granule, the end minus the start, in days and fractions of days for absolute time, in the unit of the dataset for relative time; null for a time instant.
  • start_time(): the start of the granule minus the start of the first granule, in days or in the unit.
  • end_time(): the end of the granule minus the start of the first granule, in days or in the unit; null for a time instant, which has no end.

For absolute time, the calendar functions give a part of the start or the end of the granule as a whole number. Each function exists for the start (start_doy()) and for the end (end_doy()) of the granule, and the end functions are null for a time instant.

  • start_doy(): the day of the year, 1 to 366.
  • start_dow(): the day of the week, 1 to 7; Monday is 1.
  • start_year(): the year.
  • start_month(): the month, 1 to 12.
  • start_week(): the ISO week of the year. Weeks start on Monday, and the first days of January can belong to week 52 or 53.
  • start_day(): the day of the month, 1 to 31.
  • start_hour(): the hour, 0 to 23.
  • start_minute(): the minute, 0 to 59.
  • start_second(): the second, 0 to 59.

With relative time, a calendar function stops the tool with an error. The fifth example shows the variables for both kinds of time.

Select the related maps

The option method is a list of the sampling methods. It names the relation between the granule and the map of another dataset. The default is equal. A map is related to the granule if it has one of the listed relations. The third example shows the methods.
  • equal: the map has the start and the end time of the granule.
  • during: the granule lies inside the time interval of the map. The map may share the start or the end of the granule, but is not equal to it: for a granule from 10 to 20 the maps from 5 to 25, from 10 to 25 and from 5 to 20.
  • contain: the map lies inside the granule. It may share the start or the end of the granule, but is not equal to it.
  • overlap: the map starts inside the granule and ends after it, or starts before it and ends inside it.
  • follows: the map ends when the granule starts.
  • precedes: the map starts when the granule ends.
  • start: the maps that lie inside the granule, the maps that start before it and end inside it, and the maps that cover it while sharing its start or its end. It does not take the equal map, a map that covers the granule strictly and a map that starts inside it and ends after it.

If more than one map of a dataset is related to a granule, the tool warns on the standard error and uses only one of them. Which one, follows from the order in which it tries the relations. First come the methods equal, during, follows and precedes, in the order of the list method; then the group start, then overlap and then contain, if they are in the list. Within one relation, the map with the earliest start time is taken, and for equal start times the map with the smaller id. So for the list contain,during a map found by during wins over a map found by contain. The fourth example shows this. Choose the first dataset of inputs so that its granules are the time steps you want, and use t.rast.aggregate.ds to make datasets with one map per step.

Empty results and spatial relation

A new map that has no valid cell, that is, no minimum and no maximum, is empty. By default it is not registered in output and is removed after the run. The flag -n registers the empty maps and keeps them. An expression such as if(soil > 15, soil, null()) selects time steps by values in this way. If all results are empty, output exists but holds no map.

The flag -s adds a spatial condition to the temporal one: a map is related to the granule only if its extent, from west to east and from south to north, touches or overlaps that of the granule, so a shared edge counts. A granule without a related map is skipped. The seventh example shows the difference.

Parallel processing

The option nprocs sets the number of r.mapcalc processes that run at the same time. The default is 1. The result does not depend on it.

NOTES

t.rast.mapcalc has the same options as t.rast3d.mapcalc, plus where, and works on raster maps only. The maps of the datasets are not touched; the tool makes new maps.

If a map of the base name exists as a registered map and --overwrite is not given, the tool stops before it computes any map, with "Map ... is already in temporal database, use overwrite flag to overwrite". If the dataset output exists, the tool stops with "Space time raster dataset ... is already in the database. Use the overwrite flag.".

With --overwrite, the maps of the old dataset are unregistered from it, not removed. A new run with fewer maps leaves the surplus old maps in the mapset; the tenth example shows it.

The tool stops with an error if an input dataset does not exist ("Space time dataset ... of type strds not found"), if method names a method that does not exist ("Value ... out of range for parameter method"), if where is not valid SQL ("Invalid where condition ...") and if r.mapcalc does not accept the expression ("Error while mapcalc computation"). A calendar function with relative time stops it with The temporal operators <start_*> support only absolute time. (<end_*> for an end function). The tool announces its steps on the standard error with "Starting temporal sampling..." (with -s: "Starting spatio-temporal sampling...") and "Starting mapcalc computation...".

Some inputs give no samples. If inputs names more than one dataset and the sampler has only time instants, or the datasets have different temporal types, the tool prints a message that names the reason and "No samples found for map calculation". It also prints that last message if where leaves no map in the sampler. A call with one dataset needs no sampling: time instants work as in the fifth example, and if where leaves no map, the tool prints "No maps registered in input dataset ...". In all these cases it makes no dataset output and ends with status 0. If where leaves no map in another dataset, no granule has a partner, and the tool makes an output without maps.

Because the tool replaces the names as text, two datasets whose names share a start, such as soil and soil_deep, cannot be used together in one call, in whatever order they are listed. Copy one of them with t.copy under another name, as the ninth example shows.

Apply an expression to every map

The dataset soil has four maps for the days from 1 to 4 March 2026. The region from g.region is two by two cells wide, and col() counts the columns from 1. So the maps have two columns of two cells each, and their values are the column number (1 and 2) plus 0, 10, 20 and 30, so the smallest and largest values are 1 and 2, 11 and 12, 21 and 22, and 31 and 32.

The first block doubles the maps. The name soil in the expression stands for the map of each day. The new maps are named doubled_1 to doubled_4 after the granules, and each has the time of its source map. nprocs lets two r.mapcalc processes run at the same time; the result is the same as with one. The values are twice those of the source maps. The second block shows what the new dataset takes from soil: the temporal type and the semantic type, and the granularity that follows from the maps it holds.

Combine the maps of several datasets

The dataset weight has two maps, each for two days: weight_1 with the value 2 for 1 and 2 March, weight_2 with the value 3 for 3 and 4 March. The first block multiplies soil by weight with method during. The expression names weight first, which does not matter. The first dataset of inputs is the sampler, so the result has four maps of one day each, and each day of soil lies during a map of weight. The values are twice those of soil for the first two days and three times for the last two: 2 and 4, 22 and 24, 63 and 66, 93 and 96.

The second block swaps the order in inputs, so the sampler is weight and the result has two maps of two days each. With method contain, each granule of weight contains two maps of soil; the tool warns on the standard error and uses the first of them. The result is the value of weight plus the first map of soil: 3 and 4 for the first two days (2 plus 1 and 2), 24 and 25 for the last two (3 plus 21 and 22).

The third block leaves out method. The default is equal, and no map of weight has the time of a day of soil, so every granule is skipped. The tool does not fail; the new dataset exists and holds no map.

The fourth block names the default method equal and gives it partners. The dataset offset has one map for each day of soil, offset_k with the value k, so every day has a map with the same time. The expression chooses the calculation by the time of the granule: on the 2nd and 3rd of the month it adds the maps, on the other days it multiplies them. The results are 1 and 2 (1 times 1 and 2), 13 and 14 (11 plus 2 and 12 plus 2), 24 and 25 (21 plus 3 and 22 plus 3), and 124 and 128 (31 and 32 times 4).

Choose the sampling method

The dataset slots has nine granules of 10 days with relative time, from day 110 to 120, from 210 to 220 and so on up to 910 to 920. Its map slot_k has the value k. The dataset probes has one map for each granule, probe_k with the value 10 * k, and each has a different position relative to the granule:
  1. probe_1 has the same times, 110 to 120.
  2. probe_2 lies inside the granule, 214 to 218.
  3. probe_3 covers the granule, 305 to 325.
  4. probe_4 starts inside the granule and ends after it, 415 to 425.
  5. probe_5 starts before the granule and ends inside it, 505 to 515.
  6. probe_6 ends when the granule starts, 600 to 610.
  7. probe_7 starts when the granule ends, 720 to 730.
  8. probe_8 starts with the granule and ends after it, 810 to 825.
  9. probe_9 starts before the granule and ends with it, 905 to 920.

The loop runs the tool once for each method and prints the maps of the result. The number at the end of a name is the number of the granule that found a related map: equal finds the map of granule 1, during the ones of the granules 3, 8 and 9, contain granule 2, overlap the granules 4 and 5, follows granule 6 and precedes granule 7. The method start finds the granules 2, 5, 8 and 9. The last two blocks show that method takes a list. Without method the default equal finds only the granule 1. With the list during,overlap,contain,equal the tool collects the granules 1 to 5, 8 and 9, and the listing shows that the maps have the times of the granules.

The time of the datasets is relative, in days, and the result takes it over. The files for t.register list one map per line with its start and end time.

The option where is an SQL condition on the registered maps of all datasets in inputs. The second block repeats the call for the maps that start on or after 11 June. Only the second period is left, and the one new map has the number 1.

Names of datasets in the expression

The tool replaces the name of a dataset in the text of the expression, so the name must not appear elsewhere in it. The dataset day has one map. In day * start_day() the replacement also changes start_day(), and r.mapcalc stops with the message that the function start_day_1 is not defined.

Two datasets whose names share a start have the same problem. The dataset soil_deep has one map; soil + soil_deep becomes soil_1+soil_1_deep, and r.mapcalc does not know the map soil_1_deep.

Use a dataset of another mapset and replace a result

The mapset analysis is new and empty. The first block makes it the current mapset, sets the region there, and halves soil@PERMANENT. The expression still uses the name soil. The dataset halved and its maps belong to the current mapset; the listing shows the mapset of the maps.

The second block repeats the call without --overwrite. The tool stops because the dataset halved exists. The third block adds --overwrite and makes the dataset again, with the same four maps; the tool warns on the standard error that it unregisters all maps of the old dataset.

The fourth block replaces halved once more, now from the dataset weight, which has two maps. The new dataset holds two maps, with the values 1 and 1.5. The maps halved_3 and halved_4 of the earlier run are no longer registered in it, but the tool does not remove them: g.list still finds all four.
