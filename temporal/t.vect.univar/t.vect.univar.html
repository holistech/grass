DESCRIPTION

t.vect.univar calculates univariate statistics of an attribute column for each vector map registered in a space time vector dataset and prints one line of statistics per map, ordered by start time. It runs v.univar for every map, so the statistics are those of v.univar: they are taken from the values of the column in the attribute table of the map, which are read through the categories of the features. See the introduction to temporal data processing for space time datasets. Space time raster datasets have their own tool, t.rast.univar, space time 3D raster datasets t.rast3d.univar.

The option input names the space time vector dataset, and the option column the numeric attribute column, which has to exist in the table of every selected map. Each line of the output starts with three columns that name the map:

  • id, the name of the map with its mapset, such as gauges_1@t_vect_univar;
  • start and end, the start and end time of the map; the end of a map registered as a time instance is None.

Three columns count the features:

  • n, the number of values the statistics are taken from;
  • nmissing, the number of features without a selected row in the attribute table. The condition where leaves rows out, so the features whose row it does not select are counted here;
  • nnull, the number of features whose value in the column is NULL. A NULL is not a value: it takes no part in the statistics and not in n.

The statistics follow. They are empty if the map has no value to take them from (n is 0):

  • min, max and range, the smallest and the largest value and their difference;
  • mean and mean_abs, the mean of the values and the mean of their absolute values;
  • population_stddev and population_variance: the variance is the sum of the squared deviations from the mean divided by n (the population variance), the standard deviation is its square root;
  • population_coeff_variation, the population standard deviation divided by the absolute value of the mean, so that it stays positive for a negative mean (the values -1 and -3 have the mean -2, the standard deviation 1 and the coefficient 0.5). Unlike coeff_var of t.rast.univar it is not given in percent;
  • sample_stddev and sample_variance: the sum of the squared deviations divided by n - 1, and its square root;
  • kurtosis, the mean of the fourth powers of the deviations divided by the fourth power of sample_stddev, minus 3, so that it is 0 for a normal distribution;
  • skewness, the mean of the third powers of the deviations divided by the third power of sample_stddev. It is 0 for values that are symmetric around the mean.

The flag -e adds the extended statistics first_quartile, median, third_quartile and the 90th percentile percentile_90; the percentile cannot be changed. v.univar finds a percentile p in the sorted values: it takes the value at position n * p / 100 - 0.5 with the fractional part dropped, counting from 0, so with four values the 90th percentile is the largest. The quartiles follow the same rule with p = 25 and p = 75. The median is the middle value, or the mean of the two middle values when n is even. The extended statistics need values: for a map without values they are empty, too.

The option type chooses the features that are read: point (the default), line, boundary, centroid or area. A feature has to have a category in the layer, and its category links it to a row of the table. With point and centroid, the statistics are all those above. With the other types, the output has the columns up to range and no more, also with -e (see NOTES). The type area reads the categories of the centroids of the areas, which is the way to get the attribute of an area. A type that the map has no features of gives a line with n 0 and no statistics, as a map of lines does with the default point.

The option layer is the layer of the vector map whose table holds the column. It applies to the maps that are registered without a layer; a map registered with a layer, as mast_1:2 for layer 2, is always read from that layer. The default is layer 1.

Two options select what is counted, and they can be combined:

  • the option twhere takes an SQL condition on the registered maps of the dataset and selects the maps, for instance on start_time or name;
  • the option where takes an SQL condition on the table of each map and selects the rows whose features are counted.

The option output writes the statistics to a file instead of the standard output; output=- is the standard output. An existing file is replaced only with --overwrite. The option separator sets the character between the columns, the vertical bar | by default; it takes a single character or a name such as comma. The flag -u leaves out the line with the column names.

NOTES

A NULL value is counted in nnull and is not part of the statistics, neither of the extended ones. With where, a feature whose row the condition does not select is counted in nmissing, a NULL included: the condition discharge > 2 is not true for a NULL.

In a dataset with relative time, start and end are numbers of the time unit of the dataset, printed without the unit: a map registered from 0 to 6 hours shows 0 and 6, as the first example shows.

t.vect.univar only reads, so it works on a dataset of another mapset as well. The name with the mapset (input=gauges@t_vect_univar) selects it. A name without a mapset means the current mapset: the mapsets of the search path (see g.mapsets) are not searched, unlike in t.rast.univar, and the dataset is reported as not found. The last example shows this.

If twhere selects no map, or the dataset has no map, t.vect.univar stops with the message that the space time vector dataset is empty. A dataset that does not exist stops it with the message that it was not found.

If v.univar fails on a map, for instance because the column does not exist in the table of the map, because the layer does not exist, or because where is no valid condition, t.vect.univar stops with the message Error running v.univar on followed by the map and the message of v.univar. A twhere that the database cannot parse stops the tool with the message Invalid twhere condition followed by the condition and the message of the database.

-e is accepted for the types line, boundary and area, and v.univar warns that the extended statistics exist only for points and centroids, as the example of the type area shows.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_vect_univar and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region. t.vect.univar reads the attribute tables, so the maps are copies of the stream gauges usgsgages of the dataset with integer columns of generated values, which the examples set to numbers that can be recomputed by hand.

Statistics of each map of a dataset

The points of the maps are stream gauges. Three maps with two integer columns: discharge, a generated discharge in cubic meters per second, and peak, which is discharge + 1. The values are plausible for small streams, a few cubic meters per second, with a flood of 40 in the third map, but they are not measured.
  • gauges_1 has the discharges 1, 2, 3 and 4, those of the gauges with the categories 1 to 4;
  • gauges_2 has 2, 4, 6 and 8, and a fifth gauge without a discharge: its columns stay NULL;
  • gauges_3 has 10, 10, 10 and 40.

The maps are registered as daily intervals starting on 1 March 2026. The statistics follow by hand from the values. For gauges_1 the mean is 10 / 4 = 2.5, and the deviations from the mean are -1.5, -0.5, 0.5 and 1.5, whose squares add up to 5. The population variance is 5 / 4 = 1.25, the sample variance 5 / 3 = 1.6667, and the population coefficient of variation sqrt(1.25) / 2.5 = 0.4472. The values are symmetric, so the skewness is 0; the kurtosis is 10.25 / 4 / (5 / 3)^2 - 3 = -2.0775. gauges_2 has twice the values, so four times the variances, and the same coefficient of variation, skewness and kurtosis; its fifth point is counted in nnull, not in n. gauges_3 is skewed: the mean is 17.5, the deviations are -7.5, -7.5, -7.5 and 22.5, the sample variance 225, and the skewness (10125 / 4) / 15^3 = 0.75.

The second block makes the dataset steps with relative time: two maps of 6 hours each. Their start and end are numbers of hours. It shows the columns id, n to range only.

The third block makes the region smaller, so that it holds only the first gauge of each map, and runs the command of the first block again: the numbers are the same as there. The region does not change the statistics of t.vect.univar. The block sets the region back afterwards.

Choose the attribute and calculate extended statistics

The option column chooses the attribute. peak is discharge + 1, so every value is 1 larger: the minimum, the maximum, the mean and the quartiles move by 1, while the range, the variances, the kurtosis and the skewness stay the same; the coefficient of variation falls, because the mean grows. The flag -e adds the quartiles and the 90th percentile. For gauges_1 the sorted values are 2, 3, 4 and 5. The first quartile is at position 4 * 25 / 100 - 0.5 = 0.5, which becomes 0 (the value 2), the third quartile at position 2.5, which becomes 2 (the value 4), and the 90th percentile at position 3.1, which becomes 3 (the value 5). The median is the mean of the two middle values 3 and 4. The NULL of gauges_2 is left out: its sorted values are 3, 5, 7 and 9.

Select maps and features

The option twhere selects maps by their registered times, and the option where the features of each map by their attributes. The columns id, n to range are shown.
  1. where="discharge > 2" counts only the points with a discharge above 2 in every map. In gauges_1 these are 3 and 4, so n is 2 and the 2 other points are counted in nmissing. gauges_2 keeps 4, 6 and 8; the points with the discharges 2 and NULL are missing, because the row of a NULL is not selected by the condition, so nnull is 0 here. gauges_3 keeps all of its points.
  2. twhere="start_time >= '2026-03-02'" selects the maps gauges_2 and gauges_3 and counts all their points.
  3. Both options work together: of the maps that start on 2 March or later, only the points above 2 are counted.

Read the table of another layer

A vector map can have several layers, each with its own table. The maps mast_1 and mast_2 are copies of the first three stream gauges with the categories 1 to 3 in the layers 1 and 2. The column speed of the layer 1 holds 1, 2 and 3, the column of the layer 2 (the wind speed higher up) 11, 12 and 13. The dataset masts registers mast_1 as mast_1:2, for layer 2, and mast_2 without a layer.
  1. With the default layer 1, mast_1 is read from its registered layer 2 (11 to 13), and mast_2 from layer 1 (1 to 3).
  2. With layer=2, both maps are read from layer 2.
  3. With layer=1, the registered layer of mast_1 still wins.

Command line:

for mast in mast_1 mast_2; do
    v.extract input=usgsgages output=${mast}_points where="cat <= 3"
    v.db.addcolumn map=${mast}_points columns="speed integer"
    v.db.update map=${mast}_points column=speed query_column=cat
    v.category input=${mast}_points output=$mast option=transfer layer=1,2
    db.copy from_table=$mast to_table=${mast}_2
    v.db.connect map=$mast table=${mast}_2 layer=2 key=cat
    db.execute sql="UPDATE ${mast}_2 SET speed = speed + 10"
done
t.create type=stvds output=masts title="Masts" \
    description="Wind speed in two layers"

Choose the output format

The option separator sets another separator between the columns, and the flag -u leaves out the line with the column names, for instance to append the lines to a table that has them already. With separator=comma and the option output, the statistics go to a file instead of the standard output; the second block of each tab prints the file.

t.vect.univar -u input=gauges column=discharge separator=";" |

Use a dataset of another mapset

t.vect.univar reads a dataset of another mapset. The example creates the mapset t_vect_univar_2, switches to it, sets the region and adds the mapset t_vect_univar to the search path with g.mapsets. The dataset gauges stays in the mapset t_vect_univar and is named with its mapset. A name without a mapset means the current mapset, whatever the search path of g.mapsets holds: in the second block, t_vect_univar is in the search path of t_vect_univar_2, but input=gauges is refused. The second block prints the line of the error message.

Command line:

g.mapset -c mapset=t_vect_univar_2
g.region raster=elev_state_500m res=1000 -a
g.mapsets mapset=t_vect_univar operation=add
t.vect.univar input=gauges@t_vect_univar column=discharge \
    twhere="start_time < '2026-03-02'" | cut -d"|" -f1,4-9
