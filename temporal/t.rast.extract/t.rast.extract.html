DESCRIPTION

t.rast.extract selects maps of a space time raster dataset and registers them in a new space time raster dataset. On the way, it can compute a new map from each selected map with a r.mapcalc expression. Use it to cut a time window out of a dataset, to drop the maps whose values do not matter, or to derive a dataset by map algebra when the same expression applies to every map. See the introduction to temporal data processing for space time datasets. t.rast.mapcalc computes from more than one dataset, and t.rast.list lists the maps of the result.

The option input names the space time raster dataset, the option output the new one. The new dataset takes the temporal type and the semantic type of the input dataset. The output always belongs to the current mapset. An existing output dataset is refused unless the flag --overwrite is given; then it is replaced.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2020-06-01', which selects the maps that start on 1 June 2020 or later. Without where, all maps are selected.

Register or compute

Without expression, t.rast.extract creates no map. It registers the selected maps themselves in the new dataset, so a map is then part of two datasets and the data are not duplicated.

With expression, the tool runs r.mapcalc once for each selected map and registers the new maps, with the start and end time of the map they come from, in the new dataset. The expression is the right side of an r.mapcalc expression, without the map = of a full one. The name of the input dataset stands for the selected map of each step, so 2 * temperature doubles the map of every step of the dataset temperature. Any other raster map can be used in the expression by name. The new maps belong to the current mapset. The expression needs the option basename.

The new maps are named after basename, followed by an underscore and a suffix that the option suffix chooses. A map with a semantic label gets the label between the base name and the suffix: basename_label_suffix. The new map keeps the semantic label.

  • gran (the default) takes the start time of the map, cut to the unit of the granularity of the input dataset: year and month for a granularity of three months, year, month and day for a granularity of one day (2026_03_01). A monthly series from the last day of a month (January 31, February 28) has the granularity of one month and gets year and month (2026_01). A dataset of a single time instant has no granularity; gran then takes the full start time, as time does.
  • time takes the full start time: 2026_03_01T00_00_00.
  • num numbers the selected maps from 1 in the order of their start time and map id, with five digits (00001); the number counts also the maps that come out empty. num%03 gives three digits (001).
  • With relative time, a start time is a number without a calendar date. Every suffix then gives the number, as num does.

Two different maps of one time, such as two maps of January 2001, get the same name from the suffix. The first of them, in the order of start time and map id, keeps the name; the second and every further map get the number _2, _3 and so on after it. A number that another new map has as its name is skipped.

A new map that has no valid cell, that is, no minimum and no maximum, is empty. By default it is not registered in the new dataset and the map is removed after the run. The flag -n registers the empty maps and keeps them. An expression such as if(temperature > 6, temperature, null()) therefore selects maps by their values as well.

The option nprocs sets the number of r.mapcalc processes that run at the same time. The default is 1. The result does not depend on it.

NOTES

The expression is the right side of an r.mapcalc expression only. A call with expression="if(temperature_monthly < 0, null(), temperature_monthly)", for instance, sets the negative values of a dataset temperature_monthly to null.

If where selects no map, or the input dataset has none, t.rast.extract warns "Nothing found in the database for space time dataset" and makes no output dataset; for a where that selects nothing, the message adds that "Dataset is empty or where clause is too constrained or incorrect". A condition with a syntax error stops with the error "Invalid where condition".

The tool stops with an error if expression is given without basename ("You need to specify the base name of new created maps"), if the input dataset does not exist, if the output dataset exists and --overwrite is not given, and if suffix is not gran, time, num or num%NN ("Invalid suffix"). A dot in the name of the output dataset is refused: "a dot is not allowed". An expression that r.mapcalc does not accept stops with "Error in computation process". If a new map is already in the temporal database and --overwrite is not given, the tool stops before it computes anything, with "Map ... is already in temporal database, use overwrite flag to overwrite", and makes no dataset.

A dataset of another mapset works as input. With an expression the new maps belong to the current mapset. Without one the new dataset registers the maps of the input, which stay in their mapset: the tool inserts them into the temporal database of the current mapset, as t.copy does without -c. The last example shows both.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_extract and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region, except the last, which creates a second mapset with the same region. The examples that show how names and times work use maps with small constant values, so that the results can be checked by hand.

Select maps by time

The dataset temperature_monthly holds twelve maps of the monthly mean air temperature in 2020, in degrees Celsius rounded to tenths. They are generated from the elevation model elev_state_500m: 16.5 degrees at sea level and the northing 160 km, an annual cycle of plus and minus 10.5 degrees with its maximum in July, 6.5 degrees less for every 1000 m of elevation, and 1 degree more for every 100 km to the south. Each map is an interval of one month.

The first block extracts the summer months, June to August, into the dataset summer. There is no expression, so no map is made: the second block lists the raster maps of the mapset, and they are still the twelve maps of temperature_monthly. The dataset summer lists three of them. The third block shows what the new dataset takes from the input: the temporal type and the semantic type, and the start and end time that follow from the maps it holds.

Command line:

g.mapset -c mapset=t_rast_extract
g.region raster=elev_state_500m res=1000 -a
for month in $(seq 12); do
    echo "temperature_monthly_2020_$(printf %02d $month) = round((16.5" \
        "+ 10.5 * cos(30 * ($month - 7.2)) - 0.0065 * elev_state_500m" \
        "- 0.00001 * (y() - 160000)) * 10) / 10.0"
done | r.mapcalc file=-
t.create output=temperature_monthly title="Air temperature" \
    description="Monthly mean air temperature 2020 in degree Celsius"
t.register -i input=temperature_monthly \
    maps=$(g.list type=raster pattern="temperature_monthly_*" mapset=. separator=comma) \
    start=2020-01-01 increment="1 month"
t.rast.extract input=temperature_monthly output=summer \
    where="start_time >= '2020-06-01' and start_time < '2020-09-01'"

Compute new maps from the selected maps

The first block converts the summer months to degrees Fahrenheit. The expression names the input dataset temperature_monthly, which stands for the map of each step, multiplies it by 1.8, adds 32 and rounds to tenths, as the input is. The new maps are named fahrenheit, an underscore and the month of the map (the granularity of temperature_monthly is one month), and each has the time of its source map. nprocs lets two r.mapcalc processes run at the same time; the result is the same as with one process. The values follow from the ones of the previous example: the coolest cell of June, 12.0 degrees, is 53.6 degrees Fahrenheit, and the warmest cell of July, 28.4 degrees, is 83.1.

The second block shows that the expression may use any raster map. The cells of the elevation model elev_state_500m that lie 600 m or higher are the mountains; where selects January and February, and the new maps hold the temperature of these cells and null elsewhere. The coldest cell of the whole year, -7.0 degrees in January, lies there.

    where="start_time >= '2020-06-01' and start_time < '2020-09-01'" \
    expression="round((temperature_monthly * 1.8 + 32) * 10) / 10.0"

Extract maps with semantic labels

The dataset sentinel has two scenes, on 1 and 11 June 2026, each with a red band (S2_B4) and a near infrared band (S2_B8). The red maps hold 10 and 20, the near infrared maps 30 and 40. The call takes the second scene and doubles its values. The name of each new map has the semantic label between the base name and the suffix, and the maps keep their labels. With suffix=num, the maps are numbered in the order of start time and map id, so the near infrared map nir_2 is number 1 and the red map red_2 is number 2. The block lists the maps sorted by name.

Command line:

for scene in 1 2; do
    r.mapcalc expression="red_$scene = $scene * 10"
    r.mapcalc expression="nir_$scene = $scene * 10 + 20"
    r.support map=red_$scene semantic_label=S2_B4
    r.support map=nir_$scene semantic_label=S2_B8
done
t.create output=sentinel title="Reflectance" \
    description="Red and near infrared"
t.register input=sentinel maps=red_1,nir_1 start="2026-06-01 10:30:00"
t.register input=sentinel maps=red_2,nir_2 start="2026-06-11 10:30:00"
t.rast.extract input=sentinel output=sentinel_twice basename=twice \
    where="start_time >= '2026-06-10'" expression="2 * sentinel" \

t.rast.list input=sentinel_twice columns=name,semantic_label,min order=name

Extract from a dataset with relative time

The dataset model has two maps of six hours each, from 0 to 6 and from 6 to 12 hours, with the values 1 and 2. In a dataset with relative time a start time is a number, so the names of the new maps carry the number of the map instead of a date. The first block keeps the values above 1. The number counts all selected maps, also the empty one: the first map is empty and left out, so the remaining map is m_00002. The new dataset has the times and the unit of the input. The second block takes time as the suffix; with relative time it gives the number as well.

Extract from a dataset of another mapset

The dataset model stays in the mapset t_rast_extract. The first block creates the mapset t_rast_extract_2, sets the same region, and extracts with an expression from model@t_rast_extract, which the name with its mapset selects. The name model in the expression stands for the maps of the dataset, though it has no mapset, and the output dataset model_copy and its maps copy_00001 and copy_00002 belong to t_rast_extract_2. The id column shows the mapset.

The second block extracts without an expression. The new dataset model_shared belongs to t_rast_extract_2 and registers the maps of model@t_rast_extract themselves. The id column shows that they stay in t_rast_extract, and g.list shows that t_rast_extract_2 holds only the two copies of the first block.

g.mapset -c mapset=t_rast_extract_2
