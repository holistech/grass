DESCRIPTION

t.rast.to.vect converts each raster map of a space time raster dataset into a vector map and registers the vector maps in a new space time vector dataset. It runs r.to.vect for every map, so the points, lines and areas are those of r.to.vect; see its manual for the details of the conversion. Each new vector map gets the start and end time of the raster map it was computed from. See the introduction to temporal data processing for space time datasets.

The option input names the space time raster dataset, the option output the new space time vector dataset. The new dataset takes the temporal type, the semantic type, the title and the description of the input dataset. The option where takes an SQL condition on the registered maps and selects the maps to convert, for instance by their start_time or their name; without it, all maps are converted.

The option type is required and sets the kind of feature:

  • point writes one point at the centre of each cell that has a value.
  • area writes one area for each group of cells with the same value that touch along an edge, with a boundary and a centroid; the areas follow the cell borders.
  • line writes the lines between the centres of the cells. It needs a raster map of lines that are one cell wide; r.to.vect stops at a map that is not thinned and asks for r.thin.

The option column names the column of the attribute table that stores the value of the cell, value by default. Each vector map gets an attribute table with the columns cat, the column named by column and label. Null cells give no feature. Three flags change the table and the categories:

  • -t creates the vector maps without attribute tables.
  • -v uses the values of the raster map as categories instead of a sequence of numbers. The table then has no column for the value, only cat and label, and one row for each value. This works for integer raster maps only: for a map with floating point values, r.to.vect ignores -v, warns, and writes the values to the column named by column, as the third example shows.
  • -z writes the values of the cells as the z coordinate of the points and creates no table. It works for type=point only: with type=area or type=line, r.to.vect fails.

Two more flags are passed to r.to.vect:

  • -s smooths the corners of the areas of type=area.
  • -b does not build the topology of the vector maps. Such a map has no topological counts, such as the number of areas, and no spatial index.

The option nprocs sets the number of r.to.vect runs at the same time, 1 by default. More than one run at a time works only with -t: without it, t.rast.to.vect sets nprocs to 1 and warns, because the attribute tables cannot be created in parallel.

The new vector maps are named after the option basename, followed by an underscore and a suffix that the option suffix chooses:

  • gran (the default) takes the start time of the raster map, cut to the granularity of the input dataset: 2020_05 in a dataset of months, also in a monthly series from the last day of a month (May 31, June 30), which has the granularity of one month. A dataset of a single time instance has no granularity; gran then takes the full start time, as time does.
  • time takes the full start time: 2020_05_01T00_00_00.
  • num numbers the selected maps from 1, with five digits: 00001. num%03 gives three digits: 001.

In a dataset with relative time, each suffix gives the number, because a relative time has no calendar date.

A raster map can give a vector map without features, for instance when all its cells are null. Such an empty vector map is removed and not registered, unless the flag -n is given; then it is registered as well.

NOTES

r.to.vect converts each map in the current computational region, so the region decides which cells are converted and where the features end, as the last example shows.

If where selects no map, t.rast.to.vect warns that the space time raster dataset is empty and creates no output dataset.

An unknown suffix is refused before anything is written, for instance with "Invalid suffix <gram>, use gran, time, num or num%NN" for suffix=gram. An SQL error in where stops the tool with a message that begins with "Invalid where condition". If r.to.vect fails for a map, for instance for type=line on a map that is not thinned, as in the fourth example, or for -z with type=area or type=line, or for a column that is no valid SQL name, t.rast.to.vect stops with a message that begins with "Error running r.to.vect" and creates no dataset.

An existing output dataset is replaced only with --overwrite; without it, the tool stops with the message that the dataset is already in the database. With --overwrite, the vector maps of the same names are replaced as well.

The input dataset can be in another mapset of the project; the name with the mapset (input=precipitation_heavy@t_rast_to_vect) selects it. The new vector maps and the new dataset are always created in the current mapset, as the last example shows.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_to_vect and sets the computational region to North Carolina with cells of 1 km; the first two examples work in this region. The later examples work in a window of 8 by 8 cells, 8 km by 8 km, in the west of the state, so that the vector maps stay small and their features can be counted by hand. The last example creates a second mapset. The shapes in the examples about lines and corners are made up, with dates in July 2026, so that the results can be checked by hand.

Convert the classes of heavy rain to areas

The dataset precipitation_monthly holds twelve maps of the monthly precipitation sum in 2020 in whole millimeters. The maps are generated, not measured: the monthly normals of the 136 climate stations in precip_30ynormals are interpolated with v.surf.idw and multiplied by an assumed factor for each month, so the pattern changes from month to month. Each map is an interval of one month. The list at the end of the first block shows the largest value of each month.

The dataset precipitation_heavy classifies them: a cell with 200 mm or more gets the class int(mm / 100), so 2 stands for 200 to 299 mm and 3 for 300 mm and more. All other cells are null and give no area. The semantic type max is the one that t.info shows for the new dataset later.

In the second block, t.rast.to.vect converts all twelve maps with type=area. Four months have no cell of 200 mm or more: June, September, October and December. Their vector maps are empty and t.rast.to.vect removes them, so eight vector maps are registered, as g.list shows. The default suffix gran names the maps after the month. The columns areas and centroids of t.vect.list differ, because areas counts every closed ring of boundaries, also a ring that encloses only null cells and carries no class, while centroids counts the areas that carry a class. The third block prints the classes of the first two months, selected with t_where, from the attribute tables with t.vect.db.select: one row for each area with a class, in the default column value. January has one area of class 2, February five areas of class 2 and three of class 3. The fourth block shows with t.info that the new dataset rain_areas has the time, the semantic type max, the title and the description of the input dataset. Its counts are the sums over the eight maps, so the number of areas (46) again exceeds the number of centroids (36) for the same reason.

In the last block, the flag -n keeps the four empty maps, and --overwrite replaces the dataset rain_areas of the second block together with its vector maps.

g.mapset -c mapset=t_rast_to_vect

month=1

Convert the cells to points

With type=point, each cell with a value becomes a point at the centre of the cell. The example sets the region to the window of 8 by 8 cells. The condition in where selects the map of February, which has 64 cells with values and so gives 64 points. column names the column that holds the class of each cell, class instead of value. The second block groups the table by the class: 32 cells in each class. The third block prints the first two rows of the table, with the columns cat, class and label.

The flag -v takes the class of each cell as the category of the point instead of a sequence of numbers. The fourth block shows the table of that map: only the categories 2 and 3, one for each class, and no column for the value.

The flag -z writes the class as the z coordinate of the points and makes no table. v.out.ascii prints the first three points, the cells of the top row, with class 2 as z coordinate, and the z coordinates of all points, 2 and 3. v.info shows that the map has no attribute table.

The last block shows the limit of -v. The dataset precipitation_cm holds the map of February in centimeters, with floating point values. With -v, t.rast.to.vect warns that the raster is not CELL and that the flag is ignored; the table has the column value with the values of the cells, as without the flag, not one category for each value.

Convert thin lines to lines

With type=line, r.to.vect needs lines that are one cell wide. The dataset roads has two maps in the window: the diagonal from the north-west to the south-east cell on the first day, and the fourth row on the second day. Each map gives one line with two nodes, one at the centre of its first and one at the centre of its last cell. The bounding box of the first line runs from 225500 to 232500 in x and from 150500 to 157500 in y, the second line lies at y = 154500.

The second block shows what happens with a map that is not thinned. The map of February fills the whole window, so r.to.vect finds no thin lines in it; t.rast.to.vect ends with the message of r.to.vect and creates no dataset thick.

Smooth the corners and skip the topology

The map stairs_triangle is a triangle in the south-west of the window: the cells with row() >= col(). Its outline is a staircase. The first block converts it to an area twice, without and with the flag -s. v.out.ascii starts the boundary of each area with B and the number of its points: 19 points for the staircase, 22 for the smoothed outline, because -s cuts the corners.

The flag -b builds no topology. The second block converts the map with -b: the topological counts of the map, such as the number of areas, are not known, and t.vect.list shows None for them. ls lists the files of the vector maps: the map made with -b has none of the topology files topo, sidx and cidx.

Command line:

r.mapcalc expression="stairs_triangle = if(row() >= col(), 1, null())"

Choose the names of the new maps and convert in parallel

The option suffix chooses how the new maps are named after basename. The condition in where selects the first two months, and the numbers count the selected maps from 1:
  1. time takes the full start time of each raster map.
  2. num%03 numbers the maps with three digits.
  3. In a dataset with relative time, the suffix is always a number. The dataset model holds the maps of January and February as the steps 1 and 2 of a model run, six hours apart; the default suffix gran numbers the maps, and the new dataset has relative time as well.

The last block uses the flag -t: the vector maps get no attribute table, and nprocs can run several r.to.vect processes at the same time; here three, one for each of the months January to March. The map of January and that of February have a value in all 64 cells of the window and give 64 points. In March, 25 cells are below 200 mm and null, so the map gives 39 points. v.info shows that the map of January is linked to no attribute table.

Command line:

t.rast.to.vect input=precipitation_heavy output=timed basename=timed type=area \
    suffix=time where="start_time < '2020-03-01'"
t.vect.list input=timed columns=name
t.rast.to.vect input=precipitation_heavy output=numbered basename=zone type=area \
    suffix=num%03 where="start_time < '2020-03-01'"

Use a dataset of another mapset

The example creates the mapset t_rast_to_vect_2, sets the region of North Carolina as in the first example. The dataset precipitation_heavy stays in the mapset t_rast_to_vect and is named with its mapset, which does not have to be in the search path; the new dataset west and its vector maps are created in t_rast_to_vect_2, as the column id shows.

The region of the new mapset is then set to the western half of the window, so r.to.vect converts only the cells of the western half: the east edge of the vector maps lies at x = 229000. The map of January has one area, class 2; the map of February has two, the classes 2 and 3.

Command line:

g.mapset -c mapset=t_rast_to_vect_2
g.region raster=elev_state_500m res=1000 -a
g.region n=158000 s=150000 e=229000 w=225000 res=1000
t.rast.to.vect input=precipitation_heavy@t_rast_to_vect output=west basename=west \
    type=area where="start_time < '2020-03-01'"
t.vect.list input=west columns=id,areas,east
