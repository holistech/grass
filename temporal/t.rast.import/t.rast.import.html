DESCRIPTION

t.rast.import imports an archive that t.rast.export wrote: it unpacks the archive, imports the raster maps and registers them in a new space time raster dataset with the times of the archive. The archive moves a dataset from another project or computer into the current project. See the introduction to temporal data processing for space time datasets. The tool for space time vector datasets is t.vect.import; t.rast.import refuses the archive of a vector dataset.

The option input names the archive, and output the new space time raster dataset, which is made in the current mapset. The compression of the archive (bzip2, gzip or none) and the format of the maps in it (GTiff, AAIGrid or pack) are found out from the archive. The maps of a GTiff or AAIGrid archive are imported with r.in.gdal, those of a pack archive with r.unpack. The temporal type, the unit of relative time, the semantic type of the dataset, the times of the maps and their semantic labels come from the archive, too. The options title and description set the title and the description of the new dataset.

Names of the maps

Without basename, each map keeps the name it has in the archive. The option basename names the maps basename_1, basename_2 and so on, with a numerical suffix in the order of the maps in the archive. The suffix has as many digits as the number of maps, padded with zeros: a dataset of ten maps gets basename_01 to basename_10 (see the first example). This is the way to import a dataset into the project it was exported from, where the names of the archive are taken. A map of the same name in the current mapset is refused (see the notes).

Projection and new projects

The option project makes a new project with the coordinate reference system of the archive in the GRASS database of the session and imports into it. The project must not exist yet. When the import is over, the session is in the project and mapset it was in before. The flag -c makes the project and imports nothing; the archive is needed even then, because the new project takes its coordinate reference system from it. An archive made in a project without a coordinate reference system (the project XY) makes a project without one.

Without project, the maps are imported into the current project. The import compares the coordinate reference system of the archive with that of the project and refuses a difference. The flag -o assumes that the archive has the coordinate reference system of the current project and skips this check. In a project without a coordinate reference system, -o is needed for GeoTIFF archives as well, because a GeoTIFF file made there holds none. An archive of AAIGrid files holds no coordinate reference system either and needs no -o, as the example with the ASCII grid shows, and neither does the pack format. An import with project needs no -o.

The flag -e extends the extent of the project to the maps of a GTiff or AAIGrid archive: it makes the default region and the current region of the project cover the imported maps. With project, the flag is always on for these formats. Without project it changes the default region of the current project, so use it with care in a project that you share. The maps of a pack archive do not change the region, with or without -e (see the notes); a new project then keeps its default region.

Files and region

The option directory names the directory that the archive is extracted to. It must exist, and the extracted files stay in it. By default, the tool uses a temporary directory. The flag -l links the raster maps to the GeoTIFF or ASCII grid files with r.external instead of importing the cells with r.in.gdal. The maps then read their cells from the extracted files, so with -l choose a directory that you keep. The option memory is the cache size in MB for raster rows (default 300) that r.in.gdal uses; r.external has none, so -l ignores it.

The flag -r sets the current computational region to the region of the last map that was imported. Without it, the region stays as it is.

An existing dataset output is refused unless --overwrite is given. With --overwrite, the dataset is made again from the archive and maps of the same names are replaced.

NOTES

The maps of a pack archive are unpacked with r.unpack, which does not extend the region: -e has no effect, the region stays as it is, and with project the new project keeps its default region, one cell from (0, 0) to (1, 1). Use -r to set the region from the maps of a pack archive, or g.region afterwards. The example with the semantic labels shows the missing extension.

A map that the archive names name@mapset, which t.rast.export writes for maps of one name from several mapsets, is imported as name_mapset; every character of the mapset other than a letter, a digit or an underscore becomes an underscore, so dup@my.set is imported as dup_my_set. If two maps of the archive would get one name this way, for example dup@other and a map dup_other, the import stops before the first map is imported; with basename the maps are numbered instead. An archive that lists a map more than once, as older exports wrote it for maps of one name from several mapsets, is refused before the first map is imported; a new export of the dataset names the maps with their mapset.

The name of the new dataset may not contain a dot. The tool checks this before it makes anything, so a refused name leaves no new project behind.

The dataset and the maps are made in the current mapset. A map of the same name in another mapset is no clash, as the example with the semantic labels shows. In a dataset with relative time, the unit of the archive is kept.

The tool checks the archive and the names before it imports the first map, so a refusal does not leave part of the maps behind:

  • Space time strds dataset ... is already in the database. Use the overwrite flag. for an existing dataset;
  • ... exists. To overwrite, use the --overwrite flag for an existing map of the current mapset;
  • Space time raster dataset archive ... not found and Extraction directory ... not found for a missing archive or directory;
  • The archive file is of wrong space time dataset type for an archive of vector maps;
  • Number of maps mismatch in init and list file. if number_of_maps in "init.txt" differs from the number of maps in "list.txt";
  • Unable to create location ... for a project that exists.

An archive whose coordinate reference system differs from that of the project is refused with Projection information does not match. Aborting.. A GeoTIFF archive in a project without a coordinate reference system is refused with Unable to import/link raster map .... -o cures both, if the coordinate reference systems are the same.

Blank lines in "list.txt" and "init.txt" are skipped, so an archive edited by hand may contain them. A line of "init.txt" without an equals sign stops the import with an error; a value is everything after the first equals sign.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_import, sets the computational region to North Carolina with cells of 1 km, generates a dataset of twelve monthly precipitation maps and imports the archive that t.rast.export wrote from it; the later examples work in this mapset and with this archive. The example with the semantic labels creates a second mapset with the same region. The new projects of two examples are made in the GRASS database of the session, next to the dataset, and the dataset itself stays as it is. Where a command names the project nc_spm_08_grass7, use the name of the project you opened.

Import an archive under new names

The dataset precipitation_monthly holds twelve maps of the monthly precipitation sum in 2020, in millimeters. They are generated, not measured: the monthly normals of the 136 climate stations of the dataset are interpolated with v.surf.idw and multiplied by an assumed factor for a wet year, which is different for every month. Each map is an interval of one month. The first block creates the dataset.

The second block writes the archive precipitation.tar.bz2 with t.rast.export and imports it into the same project. The maps of the archive carry the names of the maps that exist already, so basename names the new maps imported_01 to imported_12: the suffix has two digits because there are twelve maps, and a dataset of fewer than ten maps gets a single digit. The archive holds GeoTIFF files with the coordinate reference system of the project, so the import needs no -o. title and description are set, and memory limits the cache of r.in.gdal to 100 MB. The commands print the new dataset with the minimum and the maximum of each map, the range of both datasets, which is the same, and the title and the description of the new dataset from t.info.

Command line:

g.mapset -c mapset=t_rast_import
g.region raster=elev_state_500m res=1000 -a
month=1
for entry in jan:1.2 feb:1.7 mar:0.9 apr:1.3 may:1.6 jun:0.9 \
    jul:1.1 aug:1.5 sep:0.8 oct:1.0 nov:1.6 dec:0.9; do
    name=$(printf %02d $month)
    v.surf.idw input=precip_30ynormals column=${entry%:*} \
        output=precipitation_normal_$name npoints=12 power=2
    r.mapcalc expression="precipitation_monthly_2020_$name = if(isnull(elev_state_500m), null(), round(${entry#*:} * precipitation_normal_$name))"
    month=$((month + 1))
done
t.create output=precipitation_monthly title="Precipitation" \
    description="Monthly precipitation sum 2020 in mm"
t.register -i input=precipitation_monthly \
    maps=$(g.list type=raster pattern="precipitation_monthly_*" mapset=. separator=comma) \
    start=2020-01-01 increment="1 month"

t.rast.export input=precipitation_monthly output=precipitation.tar.bz2
t.rast.import input=precipitation.tar.bz2 output=precipitation_copy \
    basename=imported title="Copy of precipitation" \
    description="Imported from the archive" memory=100
t.rast.list input=precipitation_copy columns=name,start_time,end_time,min,max
for name in precipitation_monthly precipitation_copy; do
    t.info -g input=$name | grep -E "^(min_min|max_max)="
done
t.info input=precipitation_copy | grep -A3 "Title:"

Link the files instead of importing the cells

With -l, the maps are linked to the GeoTIFF files with r.external: the cells stay in the files, which directory names and the tool leaves there. The directory files has to exist. The commands count the GeoTIFF files in it, print the type of the first map, GDAL-link for a linked map, and the range of the linked dataset, which is that of the exported maps. The maps read their cells from the files, so the files must stay where they are.

Command line:

mkdir files
t.rast.import -l input=precipitation.tar.bz2 output=linked \
    basename=linked directory=files
ls files | grep -c tif
r.info -e map=linked_01 | grep maptype
t.info -g input=linked | grep -E "^(min_min|max_max)="

The new project is made in the GRASS database of the session, so it lies next to the project nc_spm_08_grass7; it must not exist yet. The archive is in the pack format and needs no GDAL driver. The import goes to the new mapset t_rast_import_2; the maps keep their names, because the mapset has none of them, although the maps of the same names exist in the first mapset.
