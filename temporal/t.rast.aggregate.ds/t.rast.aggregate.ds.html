DESCRIPTION

t.rast.aggregate.ds aggregates the maps of a space time raster dataset over the time intervals of a second space time dataset, the sampler. Each map of the sampler is an interval. For every interval the tool collects the raster maps of the input dataset that stand in a chosen temporal relation to it, computes one map from them with an aggregation method, and registers the result in a new space time raster dataset. The new map has the start and the end time of the interval. t.rast.aggregate instead cuts the time into granules of one given length; here the intervals can differ in length and leave gaps between them. The maps are computed by r.series. See the introduction to temporal data processing for space time datasets.

Datasets

The option input names the space time raster dataset to aggregate, the option sample the sampler. The option type gives the type of the sampler: strds (the default), stvds or str3ds. Only the time stamps of the sampler are used; the aggregated maps are always the raster maps of input. A dataset of another mapset is named with its mapset, name@mapset, and the new dataset is created in the current mapset, as the last example shows. A name without a mapset is searched in the current mapset first, then in the search path, for the input and for the sampler.

The input and the sampler must have the same temporal type, absolute or relative, and all maps of the sampler must be time intervals, not time instances. With relative time they must have the same unit. The sampler intervals can overlap: each interval collects its maps, so a map can go into several results. The intervals are not required to touch; the time between two of them is not aggregated. Two intervals with the same start and the same end are refused, see the NOTES.

The option output names the new space time raster dataset. It takes the temporal type, the unit of relative time and the semantic type of the input, and the method as its aggregation type, as the first example shows. An existing dataset is replaced only with --overwrite.

Choosing the maps of an interval

The option sampling lists the temporal relations that select the maps of an interval. It is always formulated from the point of view of the sampler interval, so the default contains takes the maps that lie inside the interval. The values describe maps that have a start and an end, that is intervals. The values are:
  • equal: the map has the start and the end of the interval
  • contains: the map lies inside the interval; a map that shares the start or the end of the interval counts as well, but a map that has both is equal
  • started: the map has the start of the interval and ends inside it
  • finished: the map has the end of the interval and starts inside it
  • during: the interval lies inside the map; a map that shares the start or the end of the interval counts as well, but a map that has both is equal
  • starts: the map has the start of the interval and reaches over its end
  • finishes: the map has the end of the interval and starts before it
  • overlaps: the interval starts before the map and ends inside it
  • overlapped: the map starts before the interval and ends inside it

An interval includes its start and excludes its end. A time instance at the start of an interval or inside it is selected by contains; a time instance at the end of an interval stands in none of these relations to it, and belongs to the interval that starts there, if there is one.

Several values are separated by commas. A map that stands in more than one of the listed relations goes into the result once: contains,started selects what contains selects, and during,starts what during selects. The selected maps are read in the order of their start times. The third example runs every value.

The option where takes an SQL condition on the registered maps, for instance on start_time or name. It applies to the maps of the input and to the maps of the sampler: a condition on start_time removes intervals as well as input maps.

Names of the new maps

The option basename is required. Each new map is named basename_suffix. The option suffix sets the form of the suffix:
  • gran (the default), for absolute time: the start of the interval, cut to the granularity of the sampler, with underscores. For a sampler with a granularity of one day this is 2020_07_01. A monthly sampler from the last day of a month (January 31, February 28) has the granularity of one month and gives year and month, 2026_01;
  • time: the full start time, 2020_07_01T00_00_00;
  • num: the number of the interval with five digits, 00001; num%03 sets the number of digits to 3.

With relative time the default gran gives the number of the interval with five digits, as num does, as the example with relative time shows.

The intervals are numbered from 1 in the order of their start times, and an interval that gets no map keeps its number, so the numbers can have gaps. The option offset (default 0) is added to the number in the suffixes num and num%NN; the suffixes gran and time ignore it.

Computing the maps

The option method is one of the aggregates of r.series; its default is average. See the manual of r.series for their definitions. Cells without a value are passed over: a result cell is null only if the cell is null in every map of the interval. An interval without any related map produces no map. If all maps of an interval are null, the result is a map without a valid cell; by default it is not registered, and the flag -n keeps it. The option nprocs sets how many aggregations run at the same time (default 1); the result does not depend on it.

t.rast.aggregate.ds computes in the current computational region, as r.series does, as the fourth example shows.

NOTES

The tool checks its input before it computes anything and refuses the following with an error.
  • A dataset that does not exist, or the sampler with another type than type: Space time dataset <name> of type <strds> not found, with the name and the type that were looked for.
  • An input and a sampler of different temporal types: Input and aggregation dataset must have the same temporal type.
  • With relative time, a sampler with another unit than the input: The unit <years> of the aggregation dataset <sampler> differs from the unit <days> of the input dataset <input>, here for a sampler in years and an input in days. Releases before GRASS 8.6 related no map of a sampler in another unit to the input and ended without a result and with exit code 0.
  • A sampler with a time instance: All registered maps of the aggregation dataset must have time intervals.
  • An input or a sampler that where leaves without a map: Space time raster dataset <name> is empty for the input, Space time dataset <name> is empty for the sampler.
  • A where with an SQL syntax error: Invalid where condition <condition> followed by the message of the database, without a traceback.
  • Two sampler intervals with the same start and end, which would give two maps one name: Several maps would get the same name.
  • A suffix other than gran, time, num or num%NN: Invalid suffix <name>, use gran, time, num or num%NN.
  • A dot in the name of the new dataset: <name> is not a valid name for a new space time dataset: a dot is not allowed.
  • A new map that would get the name of a map of the input in the current mapset, also with --overwrite: The result map <name> has the name of an input map. The input map stays as it is.
  • An existing output dataset without --overwrite: one error message that names the dataset.

If no map is related to any interval, the tool warns, names the granularity of the sampler and the sampling, and creates no space time dataset; it ends without an error. With monthly intervals and maps that do not start on the first day of a month, for example a series from 31 January, the default sampling contains finds nothing; sampling=overlaps relates each map to the interval in which it starts and which it outlasts.

Since GRASS 8.6 the flag -n works as documented and as in t.rast.aggregate: by default an aggregated map without any valid cell is not registered, and -n keeps it. Earlier versions did the opposite. Since GRASS 8.6 a map that stands in several of the listed relations counts once, and the maps of an interval are read as one list in time order. Earlier versions read them relation by relation, in the order equal, contains, during, starts, started, finishes, finished, overlaps, overlapped. This matters only when sampling lists more than one relation and the method depends on the order of the maps, that is min_raster, max_raster, slope, offset and detcoeff; the other methods give the same result.

r.series keeps every map of an interval open once per thread and needs two files per map and thread. The tool therefore runs r.series with the flag -z, which reads the maps row by row, when the maps of an interval exceed 1000 (this tool has no file_limit option) or when 2 x threads x maps + 64 exceeds the limit of open files of the process (ulimit -n). The threads are counted from NPROCS of the GRASS session (see g.gisenv), else OMP_NUM_THREADS, else the usable processors. With a raster mask (see r.mask), r.series runs one thread, and so does the count. In a GRASS built without OpenMP, r.series runs one thread; the count does not know this and may set -z earlier than needed. The tool warns whenever it sets the flag. Without a limit on open files, or without the Python module resource (for example on Windows), the limit of 1000 maps counts. The flag does not change the result but is slower: for 100 maps of 1000 x 1000 cells, r.series took 5.2 s with -z instead of 0.25 s (measured 31.10.2026 with method sum, three runs).

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_aggregate_ds and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region, except the last, which creates a second mapset with the same region. The first four examples aggregate the precipitation of July 2020. It is generated from the 30-year normals of the climate stations in precip_30ynormals, not measured. The examples that show how the sampling works use maps with small constant values, so that the results can be checked by hand.

Aggregate by the intervals of another dataset

The dataset precipitation_daily holds the precipitation sums of the 31 days of July 2020 in whole millimeters, with the semantic type sum. The monthly sum of July is interpolated from the normals of the stations with v.surf.idw, times 1.1 for an assumed wet year; the daily sums distribute it over the days 1 to 3, 9 to 11, 17 to 19 and 25 to 27, the days with rain, and all other days are dry.

The sampler dekads has three intervals, the dekads of the month: 1 to 10 July, 11 to 20 July and 21 to 31 July. A dekad is ten days long, the last one of a month up to eleven, so the intervals differ in length, which t.rast.aggregate cannot do. The default sampling=contains takes the daily maps of each interval, and the method sum gives the precipitation of the dekad in millimeters. The first dekad has five days with rain, the days 1 to 3, 9 and 10, the second four, the days 11 and 17 to 19, and the third three, the days 25 to 27. The sums of the cells range from 36 to 94 mm in the first dekad, from 27 to 71 mm in the second and from 21 to 55 mm in the third. In the wettest cell the five days of the first dekad have 16, 23, 16, 16 and 23 mm, which is 94 mm.

The first block creates the daily dataset, the second block the sampler and aggregates with nprocs 2, and lists the result with t.rast.list. The third block reads the semantic type and the aggregation type of the new dataset.

Command line:

g.mapset -c mapset=t_rast_aggregate_ds
g.region raster=elev_state_500m res=1000 -a
v.surf.idw input=precip_30ynormals column=jul \
    output=precipitation_normal_07 npoints=12 power=2
r.mapcalc expression="precipitation_monthly_2020_07 = if(isnull(elev_state_500m), null(), round(1.1 * precipitation_normal_07))"
for day in $(seq 31); do
    echo "precipitation_daily_2020_07_$(printf %02d $day) =" \
        "round(precipitation_monthly_2020_07 * max(0, sin(45 * $day)) / 9.65685)"
done | r.mapcalc file=-
t.create output=precipitation_daily semantictype=sum title="Precipitation" \
    description="Daily precipitation sum July 2020 in mm"
t.register -i input=precipitation_daily \
    maps=$(g.list type=raster pattern="precipitation_daily_*" mapset=. separator=comma) \
    start=2020-07-01 increment="1 day"

t.create output=dekads title="Dekads" \
    description="The three dekads of July 2020"
for dekad in "1 2020-07-01 2020-07-11" "2 2020-07-11 2020-07-21" \
    "3 2020-07-21 2020-08-01"; do
    set -- $dekad
    r.mapcalc expression="dekad_$1 = $1"
    t.register input=dekads maps=dekad_$1 start=$2 end=$3
done
t.rast.aggregate.ds input=precipitation_daily sample=dekads \
    output=precipitation_dekads basename=precipitation_dekad method=sum \
    nprocs=2
t.rast.list input=precipitation_dekads columns=name,start_time,end_time,min,max

Choose the temporal relation

The sampler window has one interval, 10 to 20 June 2026. The dataset shapes has nine maps in different positions to it, with the values 1, 2, 4 and so on, so the sum of a result shows which maps were selected:
  • wide, 5 to 25 June, value 1: the interval lies inside it;
  • early, 8 to 12 June, value 2: it starts before the interval and ends inside it;
  • late, 18 to 25 June, value 4: it starts inside the interval and ends after it;
  • inside, 12 to 15 June, value 8: it lies inside the interval;
  • same, 10 to 20 June, value 16: it has the start and the end of the interval;
  • first_part, 10 to 15 June, value 32: it has the start of the interval and ends inside it;
  • last_part, 15 to 20 June, value 64: it has the end of the interval and starts inside it;
  • long_start, 10 to 25 June, value 128: it has the start of the interval and ends after it;
  • long_end, 5 to 20 June, value 256: it has the end of the interval and starts before it.

The loop runs every value of sampling and prints the value with the sum. contains selects inside and the two maps that share a border, 8 + 32 + 64 = 104, but not same. during selects wide and the two maps that share a border, 1 + 128 + 256 = 385. contains,started and during,starts give the same sums, as the maps of started and starts are selected by both. Each run replaces the previous result with --overwrite.

Command line:

r.mapcalc expression="window = 1"
t.create output=window title="Window" description="One interval"
t.register input=window maps=window start=2026-06-10 end=2026-06-20
t.create output=shapes title="Shapes" \
    description="Maps in different positions to the interval"
for shape in "wide 1 2026-06-05 2026-06-25" "early 2 2026-06-08 2026-06-12" \
    "late 4 2026-06-18 2026-06-25" "inside 8 2026-06-12 2026-06-15" \
    "same 16 2026-06-10 2026-06-20" "first_part 32 2026-06-10 2026-06-15" \
    "last_part 64 2026-06-15 2026-06-20" \
    "long_start 128 2026-06-10 2026-06-25" \
    "long_end 256 2026-06-05 2026-06-20"; do
    set -- $shape
    r.mapcalc expression="$1 = $2"
    t.register input=shapes maps=$1 start=$3 end=$4
done
for relation in equal overlaps overlapped starts started finishes finished \
    during contains contains,started during,starts; do
    t.rast.aggregate.ds --overwrite input=shapes sample=window \
        output=by_relation basename=by_relation method=sum sampling=$relation
    printf "%s " $relation
    t.rast.list -u input=by_relation columns=min
done

Null cells and empty intervals

The dataset rain holds the rain of eight days from 1 June 2026 as maps with constant values 1 to 8. The gauge failed on 4 and 5 June, so rain_4 and rain_5 have no value at all, and rain_3 has no value in its western column. The sampler periods has four intervals: 1 to 4 June, 4 to 6 June, 6 to 8 June and 8 to 9 June, one day long. The default sampling=contains and the method sum give:
  • 1 to 4 June: rain_1, rain_2 and rain_3 lie in the interval, the sum is 1 + 2 + 3 = 6 in the eastern columns, and 1 + 2 = 3 in the western column, where rain_3 has no value and is passed over. The map has the minimum 3 and the maximum 6;
  • 4 to 6 June: both maps have no value, so there is no map with data. Without -n the tool does not register the result;
  • 6 to 8 June: 6 + 7 = 13;
  • 8 June: rain_8 has the start and the end of the interval, so it is equal and not related by contains. The interval gets no map.

The first block uses suffix=num: the maps carry the numbers 1 and 3 of their intervals, and the number 2 of the interval without data is missing. The second block runs the same aggregation with -n. The map for 4 to 6 June, number 2, is then registered, and its minimum and maximum are None; the interval of 8 June, number 4, has no related map and still gets none.

Command line:

for day in 1 2 6 7 8; do
    r.mapcalc expression="rain_$day = $day"
done
r.mapcalc expression="rain_3 = if(col() == 1, null(), 3)"
r.mapcalc expression="rain_4 = null()"
r.mapcalc expression="rain_5 = null()"
t.create output=rain title="Daily rain" \
    description="Rain on eight days, the gauge failed on days 4 and 5"

    maps=rain_1,rain_2,rain_3,rain_4,rain_5,rain_6,rain_7,rain_8 \
    start=2026-06-01 increment="1 day"
t.create output=periods title="Periods" \
    description="Four intervals of different length"
for period in "1 2026-06-01 2026-06-04" "2 2026-06-04 2026-06-06" \
    "3 2026-06-06 2026-06-08" "4 2026-06-08 2026-06-09"; do
    set -- $period
    r.mapcalc expression="period_$1 = $1"
    t.register input=periods maps=period_$1 start=$2 end=$3
done

Select the relations and the maps

The default contains leaves out the map of 8 June, which is equal to the last interval of periods. With sampling=contains,equal the interval gets its map, 8. The second block adds a where condition: only the maps of rain and the intervals of periods that start on 6 June or later remain, and the result has the two last maps of the first one, 13 and 8. The interval of 1 to 4 June is removed from the sampler as well as the maps of the first days from the input.

t.rast.aggregate.ds input=rain sample=periods output=rain_equal \
    basename=rain_equal method=sum sampling=contains,equal

Take the intervals from a vector or 3D raster dataset

The sampler can be a space time vector dataset or a space time 3D raster dataset; type names its type. Only its time stamps count. The vector dataset gauges has two maps, one point each, for 1 to 3 June and 5 to 9 June. The days between are in no interval, so rain_3 is not used: the sums are 1 + 2 = 3 and, for the second interval, 6 + 7 + 8 = 21, as rain_5 has no value. The 3D raster dataset slabs has three intervals, 1 to 3 June, 3 to 6 June and 6 to 9 June; the sums are 3, then 3 for rain_3 alone, as rain_4 and rain_5 have no value, and 21. The 3D maps are one layer thick: the first block of the example sets a 3D region of one layer of 1000 m.

Command line:

g.region raster=elev_state_500m res=1000 res3=1000 t=1000 b=0 tbres=1000 -a
t.create type=stvds output=gauges title="Gauges" \
    description="Two gauge periods with a gap between them"
t.create type=str3ds output=slabs title="Slabs" \
    description="Three periods without a gap"
for gauge in "1 2026-06-01 2026-06-03" "2 2026-06-05 2026-06-09"; do
    set -- $gauge
    echo "640000,220000" | v.in.ascii input=- output=gauge_$1 separator=comma \
        columns="x double precision, y double precision"
    t.register type=vector input=gauges maps=gauge_$1 start=$2 end=$3
done
for slab in "1 2026-06-01 2026-06-03" "2 2026-06-03 2026-06-06" \
    "3 2026-06-06 2026-06-09"; do
    set -- $slab
    r3.mapcalc expression="slab_$1 = $1"
    t.register type=raster_3d input=slabs maps=slab_$1 start=$2 end=$3
done

t.rast.aggregate.ds type=stvds input=rain sample=gauges \
    output=rain_gauges basename=rain_gauge method=sum
t.rast.list input=rain_gauges columns=name,start_time,end_time,min

Aggregate a dataset with relative time

A model writes one map per hour for six hours, with the values 1 to 6. The dataset runoff has relative time in the unit hours, and so has the sampler blocks with the intervals 0 to 3 and 3 to 6. The method maximum gives 3 and 6. Start and end of the new maps are numbers of the unit of the input, printed without it. The sampler needs the same unit as the input. The last two blocks register a sampler in years and try to aggregate the dataset in hours with it. The tool refuses and prints the error; the block goes on after it.

Command line:

for hour in 1 2 3 4 5 6; do
    r.mapcalc expression="runoff_$hour = $hour"
done
t.create output=runoff temporaltype=relative title="Runoff" \
    description="Simulated runoff in mm per model hour"
t.register -i input=runoff maps=runoff_1,runoff_2,runoff_3,runoff_4,runoff_5,runoff_6 \
    start=0 increment=1 unit=hours
t.create output=blocks temporaltype=relative title="Blocks" \
    description="Two blocks of three hours"
for block in "1 0 3" "2 3 6"; do
    set -- $block
    r.mapcalc expression="block_$1 = $1"
    t.register input=blocks maps=block_$1 start=$2 end=$3 unit=hours
done
t.rast.aggregate.ds input=runoff sample=blocks output=runoff_blocks \
    basename=runoff_block method=maximum
t.rast.list input=runoff_blocks columns=name,start_time,end_time,min

Aggregate to intervals that restart every year

Satellite products such as MODIS cut each year into intervals of equal length that start again on 1 January, so the last interval of a year is shorter. The example scales this down: eight daily maps from 28 December 2026 to 4 January 2027 with the values 1 to 8, and a sampler with the intervals 28 to 31 December, the single day of 31 December, 1 to 4 January and 4 to 7 January. The map of 31 December has the start and the end of the second interval, so the sampling is contains,equal. The sums are 1 + 2 + 3 = 6, 4, 5 + 6 + 7 = 18 and 8. The names carry the start of each interval.

Command line:

for day in 1 2 3 4 5 6 7 8; do
    r.mapcalc expression="year_change_$day = $day"
done
t.create output=year_change title="Year change" \
    description="Eight daily maps over the end of a year"
t.register -i input=year_change \
    maps=year_change_1,year_change_2,year_change_3,year_change_4,year_change_5,year_change_6,year_change_7,year_change_8 \
    start=2026-12-28 increment="1 day"
t.create output=year_intervals title="Year intervals" \
    description="Intervals that restart on 1 January"
for interval in "1 2026-12-28 2026-12-31" "2 2026-12-31 2027-01-01" \
    "3 2027-01-01 2027-01-04" "4 2027-01-04 2027-01-07"; do
    set -- $interval
    r.mapcalc expression="interval_$1 = $1"
    t.register input=year_intervals maps=interval_$1 start=$2 end=$3
done
t.rast.aggregate.ds input=year_change sample=year_intervals output=year_sums \
    basename=year_sum method=sum sampling=contains,equal
t.rast.list input=year_sums columns=name,start_time,end_time,min
