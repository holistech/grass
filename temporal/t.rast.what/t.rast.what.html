DESCRIPTION

t.rast.what samples the maps of a space time raster dataset at point locations: it reads the cell value of each selected map at each location and writes the values, together with the start and end time of each map, as a text table. A temperature series sampled at a few stations gives one time series per station, for instance. The tool runs r.what on the maps, so the values are those of r.what, and it brings the output of r.what into one of three layouts, with the time stamps of the maps instead of their names. It can run several r.what processes in parallel. See the introduction to temporal data processing for space time datasets, and v.what.strds for sampling that stores the values in the attribute table of a vector map.

Locations

The locations come from one of three sources. The option points names a vector map; each point of it is a location. The option coordinates lists the locations as east,north pairs, for instance 0.5,2.5,2.5,0.5 for the two locations 0.5,2.5 and 2.5,0.5; the tool stops with the message Option <coordinates> must be provided in multiples of 2 if a coordinate lacks its partner. The flag -i reads the locations from stdin, one location per line, and ignores coordinates and points. A line has the east and the north coordinate, separated by blanks. If the first line has a third column, it is the name of the location (a site name or an identifier), and the tool shows it in every layout. The sixth example uses -i.

The tool stops with an error message if no source is given, with a request to give the coordinates, the points option or the flag -i, and if points and coordinates are given together, also with -i: "Options coordinates and points are mutually exclusive". A location outside the current region is no error; it gets a null value in every map.

The flag -v adds the category of each point of the vector map. It needs points; with coordinates or with -i the tool stops with the message "Flag 'v' required option 'points'". The third example uses -v.

Selection of maps

The option strds names the space time raster dataset. The option where takes an SQL condition on the registered maps and selects the maps to sample; without it, all maps are sampled. If the condition selects no map, the tool stops with the message that the space time raster dataset is empty; a condition with a syntax error stops it with the message "Invalid where condition" and the error of the database. The option order sorts the selected maps by one or several columns, separated by commas; the output lists the maps in this order. The columns are id, name, creator, mapset, creation_time, modification_time, start_time (the default), end_time, north, south, west, east, min and max. The fourth example shows both options.

Layouts

The option layout chooses how the table is arranged. With the flag -n the table has a header line. Without -n the table has no header line and the lines of the data are the same.
  • row (the default) writes one line for each location and map, location after location, in the order of the maps. A line holds the coordinates, the start time, the end time and the value: x, y, start, end and value in the header. The coordinates have ten decimals.
  • col writes one line for each map and one column for each location. A line holds the start time, the end time and the value of every location. The title of a location column in the header is its coordinates, east and north, separated by a comma. If the output separator is a comma, a semicolon separates the parts of the title instead, so that the title stays one column. Coordinates have ten decimals.
  • timerow writes one line for each location and one column for each map. A line holds the coordinates followed by the values of all maps, and the title of a map column is its start and end time, separated by a semicolon. The coordinates are written in the shortest form (0.5, not 0.5000000000). This is the layout of r.what with the time stamps as column titles.

With -v, the category of the point comes first in the row and timerow layouts (cat in the header) and in front of the coordinates in the title of a location column in the col layout, separated from them by the same character as the coordinates. With a site name from stdin, the name follows the coordinates: in the column site of the row and timerow layouts, and as a third part of the title of a location column in the col layout.

Output

The option output names a text file for the table; with -, the default, the table goes to stdout. The tool does not overwrite an existing file unless the flag --overwrite is given. The option separator sets the character between the columns of the table: a character, or one of the names pipe (the default), comma, space, tab and newline. It also tells r.what which character to write; it does not change how the locations on stdin are separated. The option null_value sets the text that stands for a null cell; the default is *. The fifth example shows these options.

Computation

The option nprocs sets the number of r.what processes that run at the same time (default 1). Each process samples a share of the maps and writes a temporary file; the tool puts the files together in the order of the maps. The table does not depend on the number of processes. The first example uses nprocs.

NOTES

If r.what reads none of the locations, for example because a line of the locations on stdin has the coordinates separated by | or , instead of blanks, the tool ends with the message "No location was sampled: r.what returned no line. Check the locations and the separator." and writes no output. It leaves an existing output file as it is. The same happens with an empty vector map in points.

A map that is registered in the dataset but no longer exists stops the tool with the message "Error running r.what".

A dataset with relative time works in the same way; the tables show the start and end time of a map as the numbers stored in the temporal database, without the unit. The seventh example shows it.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_what and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region. The series are generated from the elevation model, they are not measurements: the locations are real climate stations of the dataset, but the values at them come from a formula and say nothing about the climate there. The last example uses maps with small constant values.

Sample a dataset at coordinates

The dataset temperature_monthly holds twelve maps of the monthly mean air temperature in 2020, in degrees Celsius rounded to tenths. They are generated from the elevation model elev_state_500m: 16.5 degrees at sea level and the northing 160 km, an annual cycle of plus and minus 10.5 degrees with its maximum in July, 6.5 degrees less for every 1000 m of elevation, and 1 degree more for every 100 km to the south. Each map is an interval of one month.

The tool samples it at two locations given as coordinates, in the coordinates of the dataset (meters): 500657,183601 is the position of the climate station 310090, rounded to the meter, and 169208,171737 that of the station 310184. The formula uses the elevation of the 1 km cell, about 170 m at the first and 547 m at the second location. The option where keeps the table short, it selects the first three months. The tool writes the default layout row, a line for each location and map, with a header from -n. The option nprocs lets two processes sample the maps; the table is the same as with one. In these months the second location is colder than the first one, because the formula lowers the temperature with the elevation.

Command line:

g.mapset -c mapset=t_rast_what
g.region raster=elev_state_500m res=1000 -a
for month in $(seq 12); do
    echo "temperature_monthly_2020_$(printf %02d $month) = round((16.5" \
        "+ 10.5 * cos(30 * ($month - 7.2)) - 0.0065 * elev_state_500m" \
        "- 0.00001 * (y() - 160000)) * 10) / 10.0"
done | r.mapcalc file=-
t.create output=temperature_monthly title="Air temperature" \
    description="Monthly mean air temperature 2020 in degree Celsius"
t.register -i input=temperature_monthly \
    maps=$(g.list type=raster pattern="temperature_monthly_*" mapset=. separator=comma) \
    start=2020-01-01 increment="1 month"

t.rast.what strds=temperature_monthly coordinates=500657,183601,169208,171737 \
    where="start_time < '2020-04-01'" -n nprocs=2
