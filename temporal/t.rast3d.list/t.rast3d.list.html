DESCRIPTION

t.rast3d.list lists the 3D raster maps that are registered in a space time 3D raster dataset, with the metadata that the temporal database holds for each map. It reads the temporal database; the maps themselves are not opened. The listing is the usual step after t.info has shown the dataset as a whole and before a tool such as the map algebra works on its maps. See the introduction to temporal data processing for space time datasets. The tool is the counterpart of t.rast.list for 3D raster maps, with the same options, formats and methods; the differences are the columns of the volume (see below), the flag -s instead of -u, and the method cols instead of list. Space time vector datasets have their own tool, t.vect.list, and t.list lists the datasets themselves.

Select the maps

The option input names the space time 3D raster dataset. The option where takes an SQL condition on the columns of the registered maps, such as max > 5, name = 'soil_1' or start_time >= '2026-03-02'. Times are compared as text, so a time with a clock part needs the whole text: start_time = '2026-03-02' selects nothing, because the stored value is 2026-03-02 00:00:00. Use >= and < for a day, or name for a single map. The function strftime() of SQLite selects recurring times, such as one day of the month or one month of the year. With the methods delta, deltagaps and gran, the condition selects the maps before the lengths and distances are counted, so the distances start at 0 with the first selected map.

Columns and order

The option columns chooses the columns that are printed for each map, separated by commas. The columns are:
  • id, the name of the map with its mapset, such as soil_1@PERMANENT; name and mapset, the two parts of it;
  • temporal_type, absolute or relative;
  • start_time and end_time, the time of the map. The end time of a map registered as a time instant is None. With relative time, they are numbers in the unit of the dataset, printed without the unit;
  • creator and creation_time, the user who created the entry of the map in the temporal database and the time of its creation;
  • north, south, west and east, the horizontal extent of the map; nsres and ewres, its horizontal cell sizes;
  • tbres, the vertical resolution, which is the thickness of one layer; depths, the number of layers; cols and rows, the number of columns and rows of one layer; number_of_cells, the number of cells of the whole map, which is cols * rows * depths. The vertical extent of the map is the number of layers times their thickness;
  • min and max, the smallest and the largest value of the map, as stored in the temporal database;
  • interval_length and distance_from_begin, the length of the time interval of the map and the distance of its start from the start of the first listed map. They exist for the methods delta, deltagaps and gran only (see below). With absolute time they are numbers of days, with relative time numbers of the time unit of the dataset.

The option order sorts the maps by one or more columns, separated by commas; the possible columns are those of the list above up to max. The default is start_time. The order is ascending, and the option takes names of columns only, no sort direction. The option works with the methods cols and comma only.

Methods

The option method chooses what is listed. The default is cols.
  • cols prints one line per registered map with the columns of columns. Without columns, these are name, mapset, start_time and end_time; with format=line, the column id. It supports all columns except interval_length and distance_from_begin, and order applies to it.
  • delta prints the maps ordered by start time with the length of their intervals and their distance from the first map. Without columns, the columns are id, name, mapset, start_time, end_time, interval_length and distance_from_begin. The length of a time instant is None. delta supports only these columns.
  • deltagaps is delta with a line for every temporal gap between two maps. A gap line has None as id, name and mapset; its times are the end of the map before and the start of the map after the gap, and its length is the length of the gap. Maps that follow each other directly leave no gap.
  • gran samples the maps by a granule and prints one line per granule, with the columns of delta. The times and the length are those of the granule, not of the map, so a map that is longer than the granule is listed once for each granule it covers. A granule without a map has None as id, name and mapset. When more than one map meets a granule, the line names one of them: a map that covers or overlaps the granule names it before a map that lies inside it.
  • comma is the old name of cols with format=line: it prints the ids in one line. Prefer the option format.

The option granule is the granule of the method gran. For absolute time it is a text with a number and a time unit, such as "2 months". For relative time, leave it out (see the notes). Without it, the granularity of the dataset is used. The first granule starts with the first map; each later start is counted in whole granules from this start. A step of months or years that ends behind the last day of a shorter month ends on that day: with a granule of one month and a first map from 31 January, the granules start on 31 January, 28 February, 31 March and 30 April. The other methods ignore granule.

Output

The option format chooses the form of the output:
  • plain (the default) prints one line per map with the columns separated by a vertical bar |, and the column names as the first line;
  • line prints the values of one column in one line, separated by commas. It takes one column only; the default column is id, so the line is a list of maps that other tools accept as input;
  • csv prints comma separated values, with the column names as the first line. Text is enclosed in double quotes and numbers are not. A missing value (None) is an empty text;
  • json prints an object with the key data, a list with one object per map, and the key metadata with the list column_names. A missing value is null, numbers are numbers, and times with absolute time are text;
  • yaml prints the same structure as YAML. It needs the PyYAML package.

The flag -s suppresses the line with the column names in the formats plain and csv. The formats json and yaml always name the columns and refuse -s.

The option separator replaces the separator of the formats plain, csv and line. It is a single character or a name such as pipe, comma or tab. The format csv accepts one character only, and json and yaml refuse separator. The option output writes the listing to a file instead of the standard output.

NOTES

A column name that is not in the list above is refused by the parser, which names the column.

If no map is listed, the result depends on the method and the format. The methods cols and comma stop with the error "Nothing found in the database for space time dataset <name@mapset> (type: str3ds)", followed by "Dataset is empty" for a dataset without maps and by "Dataset is empty or where clause is too constrained or incorrect" when where selects nothing. With the format json, data is an empty list. The methods delta and deltagaps print the line with the column names only, both for a dataset without maps and when where selects nothing. The method gran does the same when where selects nothing in a dataset that has a granularity, but stops for a dataset without maps with the error "Nothing found in the database for space time dataset <name@mapset> (type: str3ds)", followed by "Dataset is empty". A dataset with a single map that is a time instant has no granularity, and gran without granule stops for it with the error "Wrong granularity: "None"", whatever where selects. Give a granule, such as "1 day", or use delta.

With relative time, the times are numbers of the time unit of the dataset, printed without the unit, as the model in the fourth example shows. The method gran works with relative time without granule. Given a granule for a dataset with relative time, it fails: a number ends with a Python error (TypeError) and a text with a unit such as "6 hours" with the error "Wrong granularity". Leave granule out; the granularity of the dataset is used.

The option output takes the name of a file. The name - is not the standard output here: it writes a file with this name, as the last block of the "Choose the output format" example shows. To print the listing, leave out output; to keep it in a file, give a file name other than -.

t.rast3d.list only reads, so it works on a dataset of another mapset as well. The name with the mapset (input=soil@PERMANENT) selects it; a name without a mapset is searched in the mapsets of the search path (see g.mapsets). The last example shows this.

Combinations that cannot work are refused with a message that names the options. order is refused with delta, deltagaps and gran. These three methods list only the columns of delta, so a column of the temporal database is refused with them, and interval_length and distance_from_begin are refused with cols. More than one column is refused with format=line, -s and separator with json and yaml, and a separator of more than one character with csv. A granule of absolute time without a time unit ("2") or with an unknown unit ("3 foo") is refused with the error "Wrong granularity".

List the maps of a dataset

The dataset soil has four 3D raster maps of the soil temperature on the days from 1 to 4 March 2026. The region of the maps has 3 columns, 2 rows and 4 layers of a thickness of 2, from the bottom 0 to the top 8, so each map has 24 cells. The value of a cell is the number of its layer plus an offset, so the smallest and largest value of soil_1 are 1 and 4. The offsets 0, 6, 3 and 9 make the third map colder than the second one. A space time 3D raster dataset has the type str3ds, and its maps are registered with the type raster_3d.

The first block lists the maps with the default columns. The second block adds the flag -s, which suppresses the line with the column names, and names the default method cols. The third block names the columns, among them the smallest and largest value of each map. Select and sort the maps

The maps of soil are sorted by start time. The option order sorts by another column; the first block sorts by max, so the colder third map comes before the second one.

The option where selects the maps. The second block selects the maps that start from 2 March on and before 4 March, so the second and the third map. The third block combines a condition on the smallest value with order. The fourth block uses strftime() to select the maps that start on the 1st or the 4th day of the month, a recurring selection that works the same way for one month of every year.

The last block shows a trap: a time compared with = must be the whole text 2026-03-02 00:00:00, and the short form selects no map. The format json shows the empty result, data is an empty list; the formats plain and line stop with an error here.

Intervals, distances and gaps

The dataset rain has two daily maps, registered with a start and an end: rain_1 for 1 June 2026 and rain_3 for 3 June, so 2 June is a gap. The method delta prints the length of each map and its distance from the first map in days; it skips the gap. The method deltagaps adds a line for the gap with None as id, name and mapset, and its length. The CSV form of this table shows None as an empty text.

The dataset model has relative time: three model steps of 6 hours. Its times, lengths and distances are numbers of hours, printed without the unit.

Sample the maps by a granule

The dataset monthly has four maps that start on the last day of a month and end on the last day of the next one, from 31 January. The first block lists them. The method gran with a granule of one month prints one line per month granule: the granules start on 31 January, 28 February, 31 March and 30 April, as each start is counted in months from 31 January and cut to the last day of a shorter month. With a granule of two months, each line covers two maps and names the first of them. The last block samples the relative dataset model of the previous example without a granule, so it uses the granularity of the dataset, 6 hours.

Command line:

for month in 1 2 3 4; do
    r3.mapcalc expression="month_$month = $month"
done
t.create type=str3ds output=monthly title="Monthly" \
    description="Monthly maps"
t.register -i type=raster_3d input=monthly \
    maps=month_1,month_2,month_3,month_4 \
    start=2026-01-31 increment="1 month"
t.rast3d.list input=monthly

Use a dataset of another mapset

t.rast3d.list reads a dataset of another mapset. The example creates the mapset other and switches to it; the dataset soil stays in the mapset PERMANENT and is named with its mapset. In the second block, g.mapsets shows that PERMANENT is in the search path of the new mapset, so the name soil without a mapset finds the same dataset.

Command line:

g.mapset -c mapset=other
t.rast3d.list input=soil@PERMANENT columns=id,start_time
