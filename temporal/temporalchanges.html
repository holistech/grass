DESCRIPTION

This page lists what changed in the temporal framework since GRASS 8.5: in the results and the output of the temporal tools, in the options they take and the errors they report, and in the Python library grass.temporal. It is written for users who move from GRASS 8.5 or an earlier release, for authors of scripts and addons, and for reviewers. Each entry says what happened before, what happens now and, where a user has to act, what to do. It links the section of a manual that describes the behavior of today.

Most entries come from a rework of the temporal framework for GRASS 8.6: a new implementation of the temporal algebra, a review of every temporal tool with new tests and new manuals, and the errors that this review found and fixed. Entries marked (upstream) come from the development of GRASS after the creation of the release branch of GRASS 8.5, both before the start of the rework and, where the rework took them over later, after it; GRASS 8.5 does not have them either. Where the rework later changed such an entry, the entry describes the behavior of GRASS 8.6.

The algebra tools compute with one implementation, new in GRASS 8.6; the implementation of the releases up to GRASS 8.5 is no longer part of GRASS (see Temporal algebra). Corrections of results that GRASS 8.5 computed wrongly are listed in Corrected results of the algebra. Errors that were fixed without a change of the result of a valid call are only grouped, in Fixed errors. The EXAMPLES show two of the changes in the North Carolina sample dataset.

Temporal algebra

Since GRASS 8.6, t.rast.algebra, t.rast3d.algebra, t.vect.algebra and t.select compute their expressions with a new implementation, the Python package grass.temporal.algebra. The implementation of the releases up to GRASS 8.5 is removed, with the flag -c and the environment variable GRASS_TEMPORAL_ALGEBRA that selected it while GRASS 8.6 was developed: a call with -c is refused like any unknown flag, before anything is written, and the variable has no effect. The formulas of the publication cited in t.rast.algebra compute with the new implementation, see the catalog "Catalog: expressions of the publication" there. The old implementation is in those releases and in the history of the source code (tag classic-reference-corpus). The section Differences from GRASS 8.5 of t.rast.algebra describes the differences.

The new algebra differs from the releases up to GRASS 8.5 in the points below. The example Read a condition as the releases before GRASS 8.6 shows the first point on precedence.

  • One result per conclusion map. An if() whose conclusion map had several related condition maps gave one result for each pair, so a conclusion map could occur several times. Now there is one result per conclusion map: the conditions are joined with and, and a relation written as {during,|} joins them with or (t.rast.algebra).
  • Equal time stamps for then and else. With a condition on map values, only the maps whose time stamp occurred in both the then and the else part were computed, and the others were left out without notice; the result could be empty. Now the then and the else part need equal time stamps, or the tool stops with an error. Write both parts with equal times (t.rast.algebra).
  • Precedence of && and ||. Conditions on temporal variables were read from left to right, and parentheses around conditions were not accepted. Now && binds stronger than ||, and conditions can be grouped with parentheses (t.rast.algebra).
  • Selection with the time of the right map. A {:,R,r} B kept only the last pair of a selection, an operator with r joined the left map with all related right maps in each result, and !: took every temporal operator. Now there is one map for each related pair, with the time of the right map and the value of the pair, and !: takes only the temporal operator l (t.rast.algebra).
  • td() of a time instance. td() of a time instance stopped the tool with an error. Now it is null, and a condition on it is neither true nor false (t.rast.algebra).
  • More forms of expressions. Comparisons, temporal functions and minus signs were syntax errors outside a few places, and a dataset could not have the name of a function, so that C = A, C = -A + 10, C = A > 2, C = isnull(A) and C = td + 1 were syntax errors. Now these forms are read (t.rast.algebra).
  • Intersection with several related maps. The temporal operator i with several related maps intersected them up to the first map without common time, so the result depended on their order. Now a map whose related maps have no common intersection is left out (t.rast.algebra).
  • Negative buffers. buff_t() with a negative buffer reported an error when the end came before the start but kept the old time, and an end equal to the start gave a time instance. Now the tool stops with an error if a map would keep no time, and for time instances (t.rast.algebra).
  • merge() of equal maps. merge() kept a map read with the neighbourhood modifier or a temporal function with an offset next to an equal map, so merge(A[0], A[0]) gave eight maps instead of four. Now two maps with equal content and time are one map (t.rast.algebra).
  • tsnap() of maps that start together. The times that tsnap() gave two maps with the same start depended on the order of the arguments of merge(). Now they do not: of a map from 2 to 3 January and a map from 2 to 4 January, both end on 3 January in either order (t.rast.algebra).
  • Integers beyond 32 bits. An integer constant beyond 32 bits was read by r.mapcalc with its lower 32 bits only (3000000000 became -1294967296, 2147483648 became null), and the values of temporal functions were computed with 32 bits. Now the new algebra keeps the constant and writes it as a floating point value, and the values of temporal functions keep all digits (t.rast.algebra).
  • A number next to an operator in brackets. A number next to an operator in curly brackets or the hash operator was read together with the expression behind it: A {*,equal} 2 - B meant A {*,equal} (2 - B). Now such an operator needs a dataset on both sides, and the form without parentheses is a syntax error. Add the parentheses (t.rast.algebra).
  • Null maps with -n. With -n, no null map was registered for a map on the left of {&&,...} without a related map. Now -n registers a null map for each such map (t.rast.algebra).
  • Errors in Python and dry runs. In Python, an expression that cannot be computed raised FatalError, and a dry run checked existing results only at the maps. Now the new algebra raises ValueError or TypeError (an expression that cannot be read stays a SyntaxError), and a dry run with -d without --overwrite stops at an existing result dataset as the real run does. Python code that catches FatalError has to catch ValueError and TypeError too (t.rast.algebra).
  • Errors without traceback. The algebra tools printed a Python traceback with an error. Now they report the error with a message only (t.rast.algebra).
  • Copies outside the region. A map that the result takes over unchanged, for example with a new time, was copied only where needed, and a copy outside the region came out empty without notice. Now such copies are computed in the current region, with -s in the union of the regions of the input maps; an empty copy is registered only with -n, and a warning names it and the map it copies. Set the region with g.region so that it covers the maps (t.rast.algebra).
  • Datasets in the search path. t.rast.algebra and t.rast3d.algebra looked for a dataset name without mapset in the current mapset only. Now the new algebra looks in the current mapset and then in the search path (t.rast.algebra).
  • Digits of the map numbers. With suffix=num%NN, t.rast.algebra ignored NN and took the number of digits from the number of maps. Now NN sets the number of digits as in t.rast.extract (t.rast.algebra).
  • Granularity mode with more expressions. With -g, the algebra looked for the names of datasets in the text of the expression, and a word that is no dataset name could stop the tool: the unit in tshift(A, "1 day") or buff_t(A, "3 days") was searched as a dataset day, a comparison with !=, as in if(N != 1.5, B, A), was a syntax error, and an expression without any dataset, such as map(M) / 0 or tmap(M) : tmap(M), ended with reduce() of empty iterable with no initial value. Now -g reads the names from the syntax tree, so text in a function and != cause no error, and an expression that names no dataset prints a warning and computes as without -g, because there is nothing to sample. Of 333 recorded expressions, 26 gave another answer; the others are unchanged (t.rast.algebra).

Corrected results of the algebra

In the cases below, GRASS 8.5 and the releases before it computed a wrong result, refused an expression that they should compute, or computed one that they should refuse, with a few exceptions that the entries name. GRASS 8.6 gives the result described. Results of an earlier release that used one of these forms need a new run. The manuals of the algebra tools describe many of these corrections with examples, in their sections "Results corrected since GRASS 8.5".
  • Unknown relations. Unknown relations, such as {:,bogus} or {+,nonsense}, and operators of the wrong type gave no result without notice. Now they are a syntax error with a message. Correct the expression (t.rast.algebra).
  • The default relation of a selection. {:} and {!:} gave no result, and the default relation included the spatial relation equivalent. Now the default relation is equal, {:} selects the maps of equal time and {!:} gives an empty result (t.rast.algebra).
  • The simple operator + with maps of equal time. Of several maps of equal time, the simple operator + aggregated only the last. Now it aggregates all of them. Results that rely on this need a new run (t.rast.algebra).
  • Hash operator with several relations. The hash operator with several relations counted the maps of the last relation only. Now it counts the maps of all relations. Results that rely on this need a new run (t.rast.algebra).
  • Relative time. Result datasets always had absolute time, and inputs with relative time failed, also in td(), buff_t() and tshift(). Now the result dataset has the temporal type of the inputs, and relative time is computed (t.rast.algebra).
  • Temporal functions in conditions. Conditions with start_datetime() or end_datetime() failed for every literal, start_time() and end_time() raised a TypeError or selected nothing, and all temporal functions raised an AttributeError for time instances and relative time. Now the literal is converted into the type of the value of the function, and a function that a map does not have stops the tool with an error that names the map (t.rast.algebra).
  • Vector overlays. t.vect.algebra removed the results of an overlay from the mapset after it had registered them, if() crashed, the operators |, ^, ~ and + dropped pairs with separate extents, the overlay operator + could not be read and merge() always failed. Now the results stay, if() computes, all pairs are overlaid, + is read and merge() joins vector datasets (t.vect.algebra).
  • Spatial topology with -s. The flag -s had no effect, and the relation covered was missing from the spatial relations. Now -s evaluates the spatial topology (equivalent, cover, covered, overlap, in, contain, meet) in selections, the hash operator, conditions and comparisons. Results computed with -s need a new run (t.rast.algebra).
  • Blanks in overlay operators. In t.vect.algebra, a blank after the second comma of an overlay operator, as in aa {&,equal, l} ab, was a syntax error. Now it is read; in the operators of the raster algebras it stays a syntax error (t.vect.algebra).
  • Null maps of 3D rasters. t.rast3d.algebra could not remove its null maps, and in Python, run=False crashed in the raster algebras. Now null maps are removed, and run=False only checks the syntax.
  • Conditions over maps of equal time. With several maps of equal time, if() combined every condition map with every conclusion map of that time and gave one result for each pair. Now maps of equal time are paired like the arrays of numpy: a single map goes with all maps of its time, n maps with n maps in their order, and unequal numbers are an error. Results that rely on this need a new run (t.rast.algebra).
  • Selected maps of another mapset. t.select could not register a selected map of another mapset. Now the map is registered in the temporal database of the current mapset; the map itself is not copied (t.select).
  • Result maps of the other temporal type. Result maps that were registered with the other temporal type lost their time when they were overwritten, so the result was empty or incomplete. Now they are replaced completely (t.rast.algebra).
  • Temporal operators at the hash operator. The hash operator took the temporal operators r, u, i and d and ignored them, so that {#,contains,r} meant {#,contains}. Now they are a syntax error, and the result keeps the time of the left maps. Change {#,R,r} and the like into {#,R}, which gives the same result (t.rast.algebra).
  • merge() is a union. merge() appended its operands to each other, so a map in both operands was there twice and was counted twice later: N {+,equal} merge(A {:,during} B, A {:,during} C) gave 12, 16, 19 and 18. Now merge() keeps a map with equal identifier, time and command once and warns about it; the expression gives 12, 14, 16 and 18. Results of merge() with overlapping operands need a new run (t.rast.algebra).
  • Reading direction and else in conditions. In if({R}, condition, conclusion), the relation R was read from the conclusion to the condition for conditions on temporal variables, and the else part took no map without a related condition map. Now R goes from the condition to the conclusion, also for temporal variables, and with a relation beyond equal the else part also takes the maps without a related condition map; figure A3 of Gebbert, Leppelt and Pebesma (2019) comes out as published. Results that rely on the old reading direction or else rule need the GRASS version they were computed with (t.rast.algebra).
  • td() of an expression. td() of an expression on the right of an operator gave the value of the expression instead of the duration of its maps: N - td(A * 2) was N - A * 2. Now it is N - 1 for daily maps. Results with this form need a new run (t.rast.algebra).
  • tsnap() and tshift() of no maps. tshift() of an expression without maps ended with an IndexError, and tsnap() of such an expression created no dataset. Now the result is empty like any other empty result: an empty dataset, and an enclosing expression goes on without maps (t.rast.algebra).
  • Increments of tshift() and buff_t(). tshift() with a number on absolute time ended without result and with exit code 0, and buff_t() on relative time ended with a TypeError, also with a number such as 1.5. Now an increment that does not fit the temporal type is an error, and no dataset is created; buff_t(RT, 1.5) computes on relative time with the whole number 1. Correct the increment (t.rast.algebra).
  • merge() with a single map. merge() of a dataset with a single map from tmap() ended with the error "Space time datasets to merge must have the same temporal type", also when both had the same temporal type. Now the map is taken (t.rast.algebra).
  • Intersection with a time instance. An operator with i and a time instance, such as A {+,contains,i} I, kept the time of the left map, and such a selection on relative time ended with a TypeError. Now the time of the result is the time instance, for selections and operators, in absolute and in relative time. Results with this form need a new run (t.rast.algebra).
  • Infinite values. A map with infinite values, as made by exp(A * 1000), could not be registered, because writing its range failed, and the temporal database could stay locked. Now its minimum and maximum are stored as NULL, and a failed transaction is rolled back. This concerned the library and with it the algebra (t.rast.algebra).
  • td() of a counted map. td() of a map counted by the hash operator gave the count instead of the duration, as an operand and in a comparison. Now it gives the duration. Results with this form need a new run (t.rast.algebra).
  • Chains that start with a number. A chain that starts with a number or map(), such as map(L) - 1 - A, was grouped from the right, as map(L) - (1 - A), and A + (map(L) - 1 - 1) was a syntax error. Now chains are grouped from the left, and chains after a dataset are read; a chain of numbers and map() only stays a syntax error. Results with such chains need a new run (t.rast.algebra).
  • Precedence of td(). A + td(A) / A was computed as (A + td(A)) / A, because td() could only stand on the right of an operator, and td(A) * 2 was a syntax error. Now *, / and %, also with a temporal operator, bind stronger than + and -, and td() at the start of a product is read. Results with this form need a new run (t.rast.algebra).
  • A spatial relation without a temporal one. An operator with spatial relation names only, such as A {+,equivalent,l} N, related no map and gave an empty result without notice, and in t.select {:,equivalent} selected nothing. Now this is an error that says that equivalent is a spatial relation and needs a temporal one. Write a temporal relation next to it, as in equal|equivalent (t.rast.algebra).
  • tsnap() of a map that starts with the next map. tsnap() gave a map that starts at the same time as the next map the end of that map, so the two maps exchanged their ends; t.snap did the same. Now such a map keeps its own end (t.rast.algebra, t.snap).
  • Steps of months and years. tshift() and buff_t() by months or years ended with the error "day is out of range for month" when the target month is too short for the day, and a step of 24 months back from December ended with "month must be in 1..12"; years and months of a step were added one after the other. Now such a step ends on the last day of the target month, and years and months are one step of 12 times the years plus the months (t.rast.algebra).
  • equals and dataset functions in capitals. The name equals, which the publication of the algebra uses, gave no result without notice, and t.select refused STRDS(A), STR3DS(A) and STVDS(A) as syntax errors. Now equals is another name of equal, and t.select reads the dataset functions in capitals in front of a parenthesis (t.rast.algebra, t.select).
  • Comparison of two datasets. A comparison of two datasets in curly brackets, such as {<,equal,|,r}, and a comparison of two datasets in if(), such as if(A >= B, A, 0), were syntax errors. Now both are read (t.rast.algebra).
  • Granularity in calendar steps. The granularity counted a step between the first days of two months more than a year apart by the difference of the months only (from 1 January 2024 to 1 March 2025: 2 months), and maps at the same time of day other than midnight in hours or minutes (ten days at 10:30: 14400 minutes). Now these are 14 months and 10 days; a time of day that differs still counts (10:30 to 11:30 ten days later: 241 hours). This holds for the suffix gran, for tsnap() and for the granularity mode -g. Results with -g, gran or tsnap() over such series need a new run; t.support -m computes the stored granularity of a dataset again (t.rast.algebra).
  • Dry run of a selection of mixed types. The dry run (-d) of t.select with an expression of mixed types planned the type given with type, while the real run created another one, a str3ds. Now the dry run plans the type that the run creates (t.select).
  • Empty buffers in overlays. In t.vect.algebra, an intermediate map that buff_p() leaves empty went to v.overlay, which failed. Now it counts as a map without areas: v.overlay does not run, a warning is printed, and the result is left out (t.vect.algebra).
  • Datasets of a mapset outside the search path. A dataset name@mapset of a mapset outside the search path was refused. Now it is read if the mapset has a temporal database, so an algebra expression that GRASS 8.5 refused computes; see Datasets of other mapsets (temporal data processing).
  • Range of maps in full. The temporal database stored the minimum and the maximum of a map in SQLite with six decimals, so a value such as 1.5e-8 became 0. Now the full value is stored. Values printed with fewer digits can differ in the last digit, such as 3.31662 instead of 3.31663 (t.info).
  • merge() of absolute and relative time. merge() of a map of absolute time from tmap() with a dataset of relative time ended with the error "Space time datasets to merge must have the same temporal type", so a relation over such a list never computed. Now maps of the two temporal types are not related to each other: C = merge(tmap(sinst), RT) : RT selects the maps of RT as RT : RT does (t.rast.algebra).
  • Selection of a relative time instance. A selection on relative time with a time instance on the right and the temporal operator r, such as RT {:,contains,r} tmap(rinst), ended with a TypeError. Now it gives the selected map with the time of the instance (t.rast.algebra).

Granularity, gaps and lists

  • Monthly series that do not start on the first day. A series of months that starts on another day, such as 31 January, the last day of February, 31 March and 30 April, or the 15th of each month, had the granularity 1 day. Now steps of whole months, also those that end on the last day of a shorter month, count as months, and the granularity is 1 month. The granularity mode -g of the algebra makes one granule per month, and t.rast.to.rast3 one layer per month. Compute the stored granularity of older datasets again with t.support -m. The example Register a series of month ends shows such a series (t.register, temporal data processing).
  • Gaps under longer maps. A gap between two maps counted also when a longer map covered it. Now a gap is only time that no map covers; this holds for the gaps of t.rast.list method=deltagaps, t.info, t.topology, t.sample, t.rast.mapcalc and t.rast3d.mapcalc. t.rast.gapfill fills no covered gap and counts the granules of a gap from the start of the dataset (temporal data processing, t.rast.list).
  • Granularity over a year and at a time of day. Between the first days of two months more than a year apart, the granularity counted the difference of the months only (2 months instead of 14), and maps at the same time of day other than midnight counted in hours or minutes (ten days at 10:30: 14400 minutes instead of 10 days). Now the steps are counted in the calendar, and the names of maps with suffix=gran follow (names of days instead of names of minutes). Daily maps that overlap at different times of day have the granularity 1 day and get the same name with suffix=gran: t.rast.accdetect refuses this, t.rast.extract numbers the maps. Compute the stored granularity again with t.support -m, and use suffix=num for daily maps that overlap (temporal data processing, t.support).
  • Month steps from the end of a month. A step of a month from the 29th, 30th or 31st ended with the error "day is out of range for month", and series were built step by step from the previous time. Now a step of months or years ends on the last day of the target month, and a series counts from its first time: 31 January, the last day of February, 31 March. Steps that combine units are still added one after the other. This holds for t.register -i, t.shift, t.rast.accumulate, t.rast.accdetect, the granules of the new algebra and the list of gaps (t.register, t.shift).
  • Years and months as one step. Years and months of a step were added one after the other: 31 March 2003 plus "1 years, 11 months" ended with "day is out of range for month", 1 February 2003 plus "1 years, 1 months" gave 29 February 2004, and a step of 24 months back from December ended with "month must be in 1..12". Now years and months are one step of 12 times the years plus the months, which ends on the last day of a shorter month: 28 February 2005, 1 March 2004, and the step back is computed. This holds for increment of t.register, for t.shift and for the library (t.shift).
  • Weeks start on Monday. A granule of a week in t.rast.aggregate began at the first map, on its day of the week, and so did the weekly cycles of t.rast.accumulate. Now weeks begin on the Monday on or before the first map (t.rast.aggregate).
  • Granules of the list tools. In t.rast.list, t.rast3d.list and t.vect.list, method=gran with a granule on relative time ended with a TypeError, and a granule of 0 or less, such as 0 days, never ended. Now a number, or a number with the unit of the dataset, counts in the unit of the dataset, another unit is refused, and a granule smaller than 1 is refused before the query, with the message of t.rast.aggregate (t.rast.list).
  • output=- of the list tools. output=- of t.rast.list, t.rast3d.list and t.vect.list wrote a file named - into the working directory. Now it is the standard output (t.rast.list).
  • Granules of t.vect.list. t.vect.list had no option granule, and method=gran ended at the end of the map sorted last. Now it has the option granule with the rules of t.rast.list, and the granules reach the end of the dataset (t.vect.list).
  • format=line with every method. format=line printed the identifiers with some methods only, and method=delta with format=line ended with a traceback. Now every method prints the identifiers with format=line (t.rast.list).
  • method=comma of t.rast.list. method=comma printed the table of method=list with commas instead of the identifiers in one line. Now it prints the identifiers in one line, separated by separator (t.rast.list).
  • Delta methods of t.vect.list. The delta methods of t.vect.list printed no lengths, ignored order without notice, method=comma changed nothing, and format=line required columns. Now the delta columns are there, order with a delta method is refused, and method=comma prints the identifiers (t.vect.list).
  • where with method=gran of t.rast3d.list. t.rast3d.list refused where with method=gran. Now it takes it, as t.rast.list does (t.rast3d.list).
  • method=gran without granularity. method=gran on an empty dataset or on a single time instance reported "Wrong granularity: None" or, on relative time with a single time instance, printed the header only and ended with exit code 0. Now the message says that the dataset is empty, or that the granularity is missing and a granule or another method is needed (t.rast.list).
  • Maps without start time in t.rast.list. A map without start time ended method=delta and method=deltagaps of t.rast.list with a TypeError. Now it is listed with None in the time columns and a warning, and the distances count from the first map with a start time (t.rast.list).

Sampling and topology

  • method=start keeps maps of equal time. The sampling method start lost the maps of equal time, so a sampler map with a map of the same time got none. Now start includes equal; this holds for t.sample, t.rast.mapcalc and t.rast3d.mapcalc (t.sample, temporal data processing).
  • Samplers of time instances. A sampler of time instances or of the other temporal type made t.sample, t.rast.mapcalc and t.rast3d.mapcalc print an error and end with exit code 0. Now they end with an error and a non-zero exit code. Scripts that check the exit code see the difference (t.sample).
  • Samplers without maps and labels in t.sample. A sampler without registered maps made t.sample report that the sampler must have intervals and end with exit code 0, a dataset with a semantic label in inputs, such as ds.B4, was not found, and a name without mapset was looked for in the current mapset only. Now a sampler without maps prints nothing, also with -c no header, and ends with exit code 0; a label selects its maps only, and the header names ds.B4@mapset; the search path is searched. Samplers of the other temporal type and of time instances are still refused (t.sample).
  • Sampling and aggregation on the new algebra. t.sample, t.rast.mapcalc, t.rast3d.mapcalc, t.rast.aggregate and t.rast.aggregate.ds computed sampling and aggregation with code of their own. Now they use the functions of the new algebra; their results are those of before, and tests that record them keep them (t.rast.mapcalc).
  • Samplers and empty maps in t.rast.aggregate.ds. A sampler in another relative unit gave no result and exit code 0, and -n worked the wrong way round: without -n empty maps were registered, with -n they were not. Now a sampler in another relative unit is refused, and -n registers the empty maps, which are left out without it (t.rast.aggregate.ds).
  • Maps without start time or with a reversed interval. A map without start time, or with its end before its start, crashed the topology, the count of gaps and the granularity, or came into the chain of next and previous maps. Now such maps stand outside the chain and are left out with a warning, and t.topology ends with exit code 0 (t.topology).
  • Empty selections in t.topology. An empty selection on absolute time ended t.topology with a traceback, and an empty selection counted as an invalid topology. Now an empty selection is a valid topology without granularity (t.topology).
  • Spatial relations of 3D datasets. A space time 3D raster dataset computed overlap and relations with a 3D raster map in 2D, but intersection and union in 3D. Now space time 3D raster datasets compute all spatial relations in 3D; this concerns -s of t.select and t.rast3d.algebra (t.rast3d.algebra).

Registration and time stamps

  • A label after the dataset name (upstream). t.rast.extract and the other tools that open a dataset together with its map type did not find a dataset given as name.label, such as input=sat.S2_1: the run stopped with "not found". Now the label selects the maps with this semantic label in these tools too, as in the others. The tools that change a dataset refuse a name with a label, before they write anything: t.register, t.unregister, t.remove, t.support, t.shift, t.snap and t.rast.gapfill. Give the dataset without the label to change it. t.rast.colors still colors only the maps of the label (temporal data processing).
  • Intervals with -i. With an increment of several units, such as 1 months, 15 days, and with monthly intervals from the 31st, each map of t.register -i ended one step after its start, which left gaps or overlaps. Now each map ends at the start of the next map, also for lists of units and for the ends of months (t.register).
  • Times in whole seconds. Time stamps were stored with microseconds, and an interval within one second stayed an interval. Now times are stored in whole seconds, with their time zone, and an interval within one second becomes a time instance (t.register).
  • Relative intervals within one unit. Relative times were cut to whole numbers before they were compared: an interval within one unit, such as 1.2 to 1.7 days, was stored as the interval of length 0 from 1 to 1, and an end before the start within one unit was not seen. Now start and end are compared exactly before they are cut; an interval within one unit becomes a time instance, and an end before the start is refused (t.register).
  • Reversed intervals. An interval with its end before its start, and a start and an end that cannot be compared, were taken or raised an error without a message of their own. Now they raise a ValueError with a message, and a reversed interval that is already stored reads as a map without time (t.register).

Now type is point (the default), centroid or both, as in v.what.rast, and type=centroid reads the cell below the centroid of each area. The option was asked for in OSGeo/grass issue 4168 (t.vect.what.strds).

Other tools and libraries

  • r.contour. Levels of step had no anchor in the step grid, regions with one or two rows or columns hung the tool, lines ran over null cells, levels on the minimum or maximum gave no line, rings through border cells and lines through saddle cells at the border were lost, minlevel > maxlevel gave an empty map, cut worked before snapping, lines of one point crashed the tool, and step on a map without values crashed it. Now levels come from the step grid (anchored at minlevel, else at 0) within the limits and the range of the map, step <= 0 and more levels than an integer holds are errors, lines end open at null cells, extreme levels, border rings and saddles are traced, minlevel > maxlevel is an error, cut works after snapping, no line has one point, and a map without values gives an empty map (r.contour).
  • r.series with weights and method=kurtosis. The weighted kurtosis summed the third power of the deviations instead of the fourth and gave a wrong value, for example -2.7279 instead of -1.2381 for the values 7 and 14 with the weights 0.7 and 0.3. Now it uses the fourth power, and t.rast.aggregate -w takes kurtosis (r.series, t.rast.aggregate).
  • r.univar and r3.univar. Without a valid cell, r.univar printed -1.79769e+308 as maximum and -nan; r3.univar counted cells masked by the 3D mask and rounded floating point zones without notice. Now nan is printed without sign, and r3.univar respects the 3D mask and refuses zones that are not integers (r.univar, r3.univar).
  • r3.support. raster= ended with "Raster map <layers> not found", so categories could not be set. Now the categories are taken from the raster map (r3.support).
  • r3.mapcalc and the 3D mask. r3.mapcalc did not respect the 3D mask, @map gave null, the mask of tiles hid wrong cells with another region, and a mask on another grid was applied differently by each tool. Now the 3D mask applies when existing maps are read (a constant stays unmasked, a 2D mask has no effect), @map gives the number of the label, and a value is masked exactly when the mask is null at its location; with the region of the map the result is the same byte for byte (r3.mask).
  • 3D rasters of reduced precision. A 3D mask, and any 3D raster map of reduced precision with tiles that compress, could not be read, and on little-endian machines every 3D raster map of reduced precision stored wrong values since 2012; only 0 and null were right. Now these maps are read, writing and reading exchange the bytes around the packing on little-endian machines, and new maps are written as version 3, whose bytes are exchanged when they are read. Old maps read as before, with their wrong values; r3.null on an old map writes 0; older releases read new maps of reduced precision wrongly, with values near 0. Make maps of reduced precision of older releases again where the values are needed (3D raster data).
  • v.unpack. In a project without projection information (XY), v.unpack ended with a FileNotFoundError. Now the missing file counts as another coordinate system, and -o allows the import (v.unpack).
  • v.univar. -e sorted NULL rows as 0 and took the quartiles from the rows of the table instead of the features. Now NULL is left out, and the values come from the features; a category of two features counts twice (v.univar).
  • Integer and floating point options. An integer or floating point option took text behind the number, such as 5abc or 2.5abc. Now such text is refused (blanks are allowed, an underflow is valid, an overflow refused), and each value of a tuple is checked. Correct such values (g.parser).
  • The temporal database. The PostgreSQL back end did not work throughout, new SQLite databases had 27 indices that repeat the primary key, and the C library set up a new environment in each call. Now PostgreSQL works and is tested, new databases have no repeated indices (8,859,648 instead of 10,215,424 bytes for 20,000 maps; the index of the register stays), and the C library reads the variables of the mapset without a new environment (about 70 kB instead of 48,444 kB of memory over 40,000 calls). The schema is unchanged (t.connect).
  • SQLite 3.33 or newer (upstream). The templates for SQLite before 3.33 were removed; with an older SQLite, the update of a dataset ends with a message to update SQLite or to use PostgreSQL with t.connect (t.connect).
  • The region of r.mapcalc. With region=union or region=intersect, r.mapcalc wrote the computed region into the region file of the mapset, so after t.rast.algebra -s the region of the session was that of the last maps. Now that region holds for the process only (r.mapcalc).

Python API and addons

The public interface of grass.temporal that the repository and the addons of grass-addons use is recorded in a contract of the tests (python/grass/temporal/tests/data/public_contract.json), and a test keeps it. Every name of the contract that the addons use was there before GRASS 8.6 and is kept: the package names such as open_old_stds, open_new_stds, init, SpaceTimeRasterDataset and register_maps_in_space_time_dataset, the modules core, datetime_math, list_stds and space_time_datasets, and the methods and members of the dataset classes, such as SpaceTimeRasterDataset.metadata.get_number_of_maps() and RasterDataset.absolute_time.start_time. Code that uses only these names needs no change. Names of the contract that only the repository uses can be new in GRASS 8.6, such as the steps that the temporal tools share, and code that has to run with GRASS 8.5 cannot use them. The reference documentation of the temporal framework (temporal framework) describes every module.
  • The names of the package. grass.temporal imported all names of its modules with star imports. Now it exports the names that the repository and the addons use, among them all package names of the contract, and the steps that the temporal tools share. Code that imports another name from grass.temporal has to import it from the module that defines it today; the table below names this module for each name that grass.temporal exported in GRASS 8.5 and no longer exports.
  • New modules. The package grass.temporal.algebra holds the new implementation of the temporal algebra, with series, relations, operations, the back ends for raster, 3D raster and vector maps, the plan of a computation and its parser; a reduction with nulls="skip" passes the maps to r.series in a file and uses -z above the limit of open files. The module grass.temporal.tool_steps holds the steps that the temporal tools share, and grass.temporal.testing the helpers of their tests (writing a temporal tool, extending the algebra core).
  • The classic algebra is removed. The modules of the algebra of the releases up to GRASS 8.5, temporal_algebra, temporal_raster_base_algebra, temporal_operator and their siblings, are no longer part of GRASS, and neither are their lexers and parsers. The parser classes TemporalRasterAlgebraParser, TemporalRaster3DAlgebraParser and TemporalVectorAlgebraParser that grass.temporal exports compute with the new implementation, and the argument lexer of setup_common_granularity() of the parser classes is gone with the lexers. Code that imports one of the removed names has to use the parser classes or the package grass.temporal.algebra; the tables below list the names. The old implementation is in GRASS 8.5 and in the history of the source code (tag classic-reference-corpus).
  • Comparisons without eval (upstream). The algebra of the releases before compared values with eval of strings. Now it uses compare_values(), eval_datetime_str() is deprecated, and a value in a list of conditions that is not a Boolean raises a TypeError; both methods are removed with the classic algebra. The results are the same.
  • Parser tables. The parser of GRASS 8.5 built its tables in each call of parse(). Now they are built once for each parser class.
  • Directory of the SQL templates (upstream). get_sql_template_path() took the directory of the SQL files that create and update the temporal database from GISBASE, below which it assumed etc. Now it takes GRASS_ETCDIR, which grass sets, so an installation that keeps etc elsewhere works. Outside a GRASS session without this variable, the function raises a KeyError.
  • Maps of other mapsets (partly upstream). BaseRow.get_readonly(), the property readonly and AbstractMapDataset.get_readonly() are new. They tell whether a map belongs to another mapset than the current one, and the library writes the time stamp and label files only for maps that are not read-only. There is no set_readonly(): the answer is computed at each call, so it cannot become wrong when the current mapset changes.
  • Initialization (upstream). init() always created the temporal database. Now init(skip_db_init=True) creates none and checks no version, dataset objects work without a temporal database, the default back end is SQLite before the initialization, the message and C library servers start again after a change of the session, and SQLite waits up to 30 s for a locked database. Mapsets with a connection but without a database file are skipped, and "Creating temporal database" is a verbose message: scripts that read it have to set --verbose.
  • Switches and sessions of init(). The switches TGIS_DISABLE_* had no effect, and a second session in one process kept the error mode and the servers of the first. Now the switches work, and init() sets the error mode and the servers in each call.
  • Connections to mapsets (upstream). SQLDatabaseInterfaceConnection and get_available_temporal_mapsets() take the argument mapsets, and get_dataset_list() takes the mapsets of the connection; with a list of types, it returns a dictionary for each row with the key type. Read the rows as dictionaries when you pass a list.
  • Registering maps (upstream). register_maps_in_space_time_dataset() took dbif as a positional argument and used it. Now it opens its own connection to the current mapset, dbif is a keyword argument only, deprecated and ignored with a warning, and name is optional. Remove dbif from calls; a transaction of the caller is not used.
  • Opening a dataset for writing. open_old_stds() takes the keyword argument for_writing. With for_writing=True, a name with a semantic label ends with a message instead of opening the dataset name; register_maps_in_space_time_dataset() opens its dataset this way.
  • Identifiers in SQL. Identifiers went into SQL statements unbound, so SQL could be injected, set_id() with a layer split the identifier wrongly, and a where with OR together with a label or an extent was not put into parentheses. Now identifiers are bound or checked, set_id() splits name, layer and mapset, and conditions are put into parentheses.
  • Granules with where (upstream). get_registered_maps_as_objects_by_granularity() takes where before dbif. Calls that pass dbif as the third positional argument have to change.
  • nprocs of aggregate_raster_maps() (upstream). aggregate_raster_maps() passes the keyword argument nprocs to r.series (0 for all cores).
  • Dates beyond the year 9999. A step of days beyond the year 9999 raised an OverflowError. Now it raises a ValueError with a message, as steps of months and years did already.
  • Relations of no maps. count_temporal_relations() of an empty list of maps returned None. Now it returns a dictionary with zeros; check_temporal_topology([]) stays False.
  • ctime and mtime. BaseRow.set_ctime() and set_mtime() kept microseconds in memory, while the database held whole seconds. Now they keep whole seconds too, with their time zone.
  • Intersections of relative extents. RelativeTemporalExtent.intersect() of two extents in different units gave a result, also for separate numbers. Now it returns None when both units are set and differ.
  • Failed SQL statements on PostgreSQL. A failed PostgreSQL statement in DBConnection.mogrify_sql_statement() was printed to the standard output. Now nothing is printed.
  • Invalid spatial relations (upstream). The selection by an invalid spatial relation reported an error and then raised a RuntimeError. Now it raises a ValueError with the message.
  • shift() (upstream). AbstractSpaceTimeDataset.shift() returned None. Now it returns True, and False for a dataset without maps.
  • Messages (upstream). The fatal messages of shift() and snap() raised a TypeError instead of the message, and the messages for a failed removal of a time stamp showed <%s> or spoke of a raster map for a 3D raster map. Now they name the map.
  • Catalog of the GUI (upstream). registered_maps_grouped() returns the registered maps by type and dataset, ordered by start time, and is exported by grass.temporal; tlist() takes the mapsets of the connection; the data catalog of the GUI shows the space time datasets.
  • Python 3.14 (upstream). From Python 3.14 on, the servers of the library started without a GRASS session. Now they start with the method fork, also in t.rast.extract and t.rast.mapcalc, and stopping them no longer releases a lock twice.
  • unit_tests (upstream). The module grass.temporal.unit_tests was removed; its tests are pytest tests. Remove imports of it.
  • pygrass modules. MultiModule could hang on a failing module, the child process printed tracebacks, ParallelModuleQueue.wait() did not wait for all processes, and Messenger warned about a restart after fatal(). Now the parent process checks the child, wait() waits for all processes and reports the first error with a note, and the warning is gone.
  • ParallelModuleQueue with more than one process. The put() that took the last free slot waited for all processes of the queue, so no module started before the slowest one had ended. Now put() starts the next module as soon as a slot is free; a failure is raised by the next put() that finds it while waiting for a slot, after the running processes ended and without starting its module, or by wait(); and get_num_run_procs() counts the occupied slots.
  • grass.script under LC_ALL=C. Every Python tool failed for an argument with a non-ASCII character under LC_ALL=C. Now UTF-8 holds in the UTF-8 mode of Python.
  • Pack archives in grass.tools. tools.v_unpack(input="a.pack") called r.unpack, and v.pack got the name of the map instead of the path of the archive. Now r.pack, r.unpack, v.pack and v.unpack get their archive argument as it is.

Register a series of month ends

The dataset inflow holds four maps of the inflow into a reservoir, one for each period from the end of a month to the end of the next month; the values 1 to 4 number the periods. t.register with the flag -i, start=2020-01-31 and increment="1 month" registers them as consecutive intervals. Each step of a month ends on the last day of the month: 29 February, 31 March, 30 April and 31 May. The releases before GRASS 8.6 could not add one month to 31 January and ended with the error "day is out of range for month". t.info with -g shows the granularity of the dataset, 1 month, where the releases before GRASS 8.6 gave a series of month ends the granularity 1 day.

Command line:

g.mapset -c mapset=temporalchanges
g.region raster=elev_state_500m res=1000 -a
for period in 1 2 3 4; do
    r.mapcalc expression="inflow_2020_0$period = $period"
done
t.create output=inflow title="Inflow" \
    description="Inflow of periods that start at the end of a month"
t.register -i input=inflow \
    maps=inflow_2020_01,inflow_2020_02,inflow_2020_03,inflow_2020_04 \
    start=2020-01-31 increment="1 month"
t.rast.list input=inflow columns=name,start_time,end_time
t.info -g input=inflow | grep "^granularity="

Read a condition as the releases before GRASS 8.6

t.rast.algebra selects maps of inflow by a condition on the month and the day of their start. The algebra reads && before ||: it selects the period that starts in April and, of the periods that start in January or February, the one that starts on day 31, which is the period of January. The releases before GRASS 8.6 read conditions on temporal variables from left to right. The second call writes that reading with parentheses, (start_month(inflow) == 4 || start_month(inflow) <= 2) && start_day(inflow) == 31, and selects the period of January only.

Command line:

t.rast.algebra basename=selected expression="selected = if(start_month(inflow) == 4 || start_month(inflow) <= 2 && start_day(inflow) == 31, inflow)"
t.rast.list input=selected columns=name,start_time,min
