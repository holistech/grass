DESCRIPTION

t.rast.univar calculates univariate statistics of each raster map registered in a space time raster dataset and prints one line of statistics per map, ordered by start time. It runs r.univar for every map, so the statistics are those of r.univar: they are taken from the cells of the current computational region and count only cells with a value (non-null cells). See the introduction to temporal data processing for space time datasets. Space time 3D raster datasets have their own tool, t.rast3d.univar, space time vector datasets t.vect.univar.

The option input names the space time raster dataset. Each line of the output starts with four columns that name the map:

  • id, the name of the map with its mapset, such as temperature_1@PERMANENT;
  • semantic_label, the semantic label of the map, empty if it has none;
  • start and end, the start and end time of the map; the end of a map registered as a time instance is None.

The statistics follow:

  • non_null_cells and null_cells: the number of cells with and without a value;
  • min, max and range, the smallest and the largest value and their difference;
  • mean and mean_of_abs, the mean of the values and the mean of their absolute values;
  • stddev and variance: the variance is the sum of the squared deviations from the mean divided by the number of non-null cells (the population variance), the standard deviation is its square root;
  • coeff_var, the coefficient of variation in percent, 100 times the standard deviation divided by the mean. It grows without bound when the mean approaches 0, and it is negative for a negative mean;
  • sum and sum_abs, the sum of the values and of their absolute values.

The flag -e adds the extended statistics first_quartile, median, third_quartile and the 90th percentile percentile_90. r.univar finds a percentile p in the sorted values of the n non-null cells: it takes the value at position n * p / 100 - 0.5 with the fractional part dropped, counting from 0, so the percentile 0 is the minimum. The quartiles follow the same rule with p = 25 and p = 75. The median is the middle value, or the mean of the two middle values when n is even, so it can differ from the 50th percentile. The option percentile replaces the 90th percentile by one or more percentiles from 0 to 100, separated by commas; it requires -e. Each percentile gets a column of its own, named after it, with an underscore for a decimal point: percentile=97.5 gives percentile_97_5.

Three ways select the maps of the dataset, and they can be combined:

  • the option where takes an SQL condition on the registered maps, for instance on start_time or name;
  • a semantic label after the name of the dataset, input=name.label, keeps only the maps with this label;
  • the option region_relation keeps the maps that have a spatial relation with the current computational region: overlaps keeps the maps that share at least a part of the region, contains the maps that cover the whole region, and is_contained the maps that lie inside the region. A map with the extent of the region both contains it and is contained in it. The option only selects maps; it does not change the cells the statistics are taken from.

Without the flag -r, the statistics of every map are taken in the current computational region: cells of the map outside the region are not counted, and cells of the region outside the map are null cells. With -r, the statistics of each map are taken in the region of that map, so every cell of the map is counted, whatever the current region. In this version, -r has no effect together with zones: the statistics per zone are taken in the current region.

The option zones names an integer (CELL) raster map whose categories divide the region into zones. t.rast.univar then prints one line per map and zone, with the columns zone (the category) and label (the category label) after the four columns of the map. zones takes a single raster map, not a space time dataset; the same zones apply to every map.

The option nprocs sets the number of maps that are processed at the same time. Its default is the variable NPROCS of the session, if it is set with g.gisenv, and 0 otherwise. 0 uses all CPU cores, a negative number leaves that many cores unused. The output is the same, in the same order, for any value.

The option format chooses the form of the output:

  • plain (the default) separates the columns with a vertical bar |;
  • csv separates them with a comma, or with another single character given in separator;
  • json prints a list with one object per map, or with zones one per map and zone, the category label under the name zone_label. The objects use the names of r.univar: n for the number of non-null cells, cells for the number of all cells, and the list percentiles for the percentiles. They have no sum_abs. A value that does not exist, such as the semantic label of a map without one, is null.

The option separator sets the separator of the formats plain and csv. The flag -u leaves out the line with the column names. The format json always names the values and accepts neither separator nor -u.

The option output writes the statistics to a file instead of the standard output; output=- is the standard output. An existing file is replaced only with --overwrite.

NOTES

The current computational region decides which cells are counted, unless -r is given. A map that does not reach into the region has only null cells there; its min and max are nan in the formats plain and csv and null in the format json. The raster mask is respected: cells outside the mask are null cells. Region and mask are the same for all maps, so maps with different extents can have different numbers of non-null cells, as the example with the scenes below shows.

In a dataset with relative time, start and end are numbers of the time unit of the dataset, printed without the unit: a map registered from 0 to 6 hours shows 0 and 6, as the first example shows.

t.rast.univar only reads, so it works on a dataset of another mapset as well. The name with the mapset (input=temperature@PERMANENT) selects it; a name without a mapset is searched in the mapsets of the search path (see g.mapsets). The example at the end shows this.

If no map is selected, for instance because the condition in where matches none, t.rast.univar prints nothing, not even the line with the column names, in all formats. With the format json, the output is then empty, not an empty list [].

The option zones takes a map of type CELL; t.rast.univar stops with the error "Zoning raster must be of type CELL" for a floating point map.

The format csv refuses a separator of more than one character, the format json refuses separator and -u. percentile without -e is refused by the parser.

EXAMPLES

Statistics of each map of a dataset

Three maps of daily mean air temperature on a small region of two rows and three columns make up the dataset temperature. The helper map cell_number numbers the cells from 1 to 6, row by row, so each map is simple to follow:
  • temperature_1 holds -2, -1, 0 in the northern row and 1, 2, 3 in the southern row;
  • temperature_2 holds 1, 2, 3 and 4, 5, 6;
  • temperature_3 holds 4, 5 and 7, 8, and nothing in the eastern column, as if a sensor had failed there.

The maps are registered as daily intervals starting on 1 March 2026. t.rast.univar processes two maps at the same time here (nprocs); the output does not depend on it.

The second block makes the dataset model with relative time: two model steps of 6 hours each, with the constant values 1 and 2. Their start and end are numbers of hours, printed without the unit.

Command line:

g.region n=2 s=0 e=3 w=0 res=1
r.mapcalc expression="cell_number = 3 * (row() - 1) + col()"
r.mapcalc expression="temperature_1 = cell_number - 3"
r.mapcalc expression="temperature_2 = cell_number"
r.mapcalc expression="temperature_3 = if(col() == 3, null(), cell_number + 3)"
t.create output=temperature title="Air temperature" \
    description="Daily mean air temperature in degrees Celsius"
t.register -i input=temperature \
    maps=temperature_1,temperature_2,temperature_3 \
    start=2026-03-01 increment="1 day"
t.rast.univar input=temperature nprocs=2

Calculate extended statistics and percentiles

The flag -e adds the quartiles, the median and the 90th percentile. The six values 1 to 6 of temperature_2 give the first quartile at position 6 * 25 / 100 - 0.5 = 1 (the value 2), the third quartile at position 4 (the value 5), and the 90th percentile at position 4.9, which becomes 4 (the value 5). The median is the mean of the two middle values 3 and 4.

The option percentile replaces the 90th percentile by the listed ones. For temperature_2, the 10th percentile is at position 0.1 (the value 1), the 50th at position 2.5 (the value 3) and the 95th at position 5.2 (the value 6). The 50th percentile 3 is not the median 3.5: the median takes the mean of the two middle values, the percentile one value.

Choose the output format

The option separator sets another separator, and the flag -u leaves out the line with the column names, for instance to append the lines to a table that has them already. With format csv, the columns are separated by commas, and the option output writes the statistics to a file. With format json, t.rast.univar prints a list with one object per map; here for temperature_2 with the extended statistics and two percentiles. In Python, the attribute json of the result holds this list, and the example prints the mean, the median and the percentiles from it.

Maps with extents of their own

Satellite scenes rarely share one extent. The dataset scenes holds four maps with constant values on extents of their own; the current region is the square from (0, 0) to (4, 4) with 16 cells:
  • scene_1 covers the square from (-1, -1) to (5, 5) and so the whole region;
  • scene_2 lies inside the region, from (1, 1) to (3, 3);
  • scene_3 reaches from (2, 2) to (6, 6) and shares 4 cells with the region;
  • scene_4 lies outside, from (10, 10) to (12, 12).

The commands print the columns id, non_null_cells and null_cells only: on the command line, cut keeps the first, fifth and sixth column; in Python, the function print_cells() reads them from the JSON output, where n is the number of non-null cells.

  1. By default, the cells are counted in the current region: scene_1 has 16 non-null cells there, scene_2 and scene_3 have 4, and scene_4 none.
  2. With -r, each map is counted in its own region: scene_1 has 36 cells, scene_3 16, and scene_4, outside the current region, 4.
  3. region_relation selects maps by their relation to the current region: overlaps keeps all but scene_4, contains only scene_1, which covers the region, and is_contained only scene_2, which lies inside it. Combined with -r, the selected maps are counted in their own regions.

Use a dataset of another mapset

t.rast.univar reads a dataset of another mapset. The example creates the mapset analysis and switches to it; the dataset temperature stays in the mapset PERMANENT and is named with its mapset. The region of the new mapset is set to the one of the maps. In the second block, g.mapsets shows that PERMANENT is in the search path of the new mapset, so the name temperature without a mapset finds the same dataset.

g.mapset -c mapset=analysis
g.region n=2 s=0 e=3 w=0 res=1
