DESCRIPTION

t.rast.univar calculates univariate statistics of each raster map registered in a space time raster dataset and prints one line of statistics per map, ordered by start time. It runs r.univar for every map, so the statistics are those of r.univar: they are taken from the cells of the current computational region and count only cells with a value (non-null cells). See the introduction to temporal data processing for space time datasets. Space time 3D raster datasets have their own tool, t.rast3d.univar, space time vector datasets t.vect.univar.

The option input names the space time raster dataset. Each line of the output starts with four columns that name the map:

  • id, the name of the map with its mapset, such as precipitation_monthly_2020_01@t_rast_univar;
  • semantic_label, the semantic label of the map, empty if it has none;
  • start and end, the start and end time of the map; the end of a map registered as a time instance is None.

The statistics follow:

  • non_null_cells and null_cells: the number of cells with and without a value;
  • min, max and range, the smallest and the largest value and their difference;
  • mean and mean_of_abs, the mean of the values and the mean of their absolute values;
  • stddev and variance: the variance is the sum of the squared deviations from the mean divided by the number of non-null cells (the population variance), the standard deviation is its square root;
  • coeff_var, the coefficient of variation in percent, 100 times the standard deviation divided by the mean. It grows without bound when the mean approaches 0, and it is negative for a negative mean;
  • sum and sum_abs, the sum of the values and of their absolute values.

The flag -e adds the extended statistics first_quartile, median, third_quartile and the 90th percentile percentile_90. r.univar finds a percentile p in the sorted values of the n non-null cells: it takes the value at position n * p / 100 - 0.5 with the fractional part dropped, counting from 0, so the percentile 0 is the minimum. The quartiles follow the same rule with p = 25 and p = 75. The median is the middle value, or the mean of the two middle values when n is even, so it can differ from the 50th percentile. The option percentile replaces the 90th percentile by one or more percentiles from 0 to 100, separated by commas; it requires -e. Each percentile gets a column of its own, named after it, with an underscore for a decimal point: percentile=97.5 gives percentile_97_5.

Three ways select the maps of the dataset, and they can be combined:

  • the option where takes an SQL condition on the registered maps, for instance on start_time or name;
  • a semantic label after the name of the dataset, input=name.label, keeps only the maps with this label;
  • the option region_relation keeps the maps that have a spatial relation with the current computational region: overlaps keeps the maps that share at least a part of the region, contains the maps that cover the whole region, and is_contained the maps that lie inside the region. A map with the extent of the region both contains it and is contained in it. The option only selects maps; it does not change the cells the statistics are taken from.

Without the flag -r, the statistics of every map are taken in the current computational region: cells of the map outside the region are not counted, and cells of the region outside the map are null cells. With -r, the statistics of each map are taken in the region of that map, so every cell of the map is counted, whatever the current region. This holds together with zones as well; the zone map is then read in the region of each map, too.

The option zones names an integer (CELL) raster map whose categories divide the region into zones. t.rast.univar then prints one line per map and zone, with the columns zone (the category) and label (the category label) after the four columns of the map. A zone without any cell in the region gets no line. zones takes a single raster map, not a space time dataset; the same zones apply to every map.

The option nprocs sets the number of maps that are processed at the same time. Its default is the variable NPROCS of the session, if it is set with g.gisenv, and 0 otherwise. 0 uses all CPU cores, a negative number leaves that many cores unused. The output is the same, in the same order, for any value.

The option format chooses the form of the output:

  • plain (the default) separates the columns with a vertical bar |;
  • csv separates them with a comma, or with another single character given in separator;
  • json prints a list with one object per map, or with zones one per map and zone. The keys are the column names, except where they follow r.univar: n instead of non_null_cells, zone_label instead of label, the additional key cells for the number of all cells, and no sum_abs. With -e, the percentiles are the list percentiles of objects with the keys percentile and value, instead of the columns percentile_90 and so on. A value that does not exist, such as the semantic label of a map without one, is null.

The option separator sets the separator of the formats plain and csv. The flag -u leaves out the line with the column names. The format json always names the values and accepts neither separator nor -u.

The option output writes the statistics to a file instead of the standard output; output=- is the standard output. An existing file is replaced only with --overwrite.

NOTES

The current computational region decides which cells are counted, unless -r is given. A map that does not reach into the region has only null cells there; its min, max and all further statistics are nan in the formats plain and csv and null in the format json. The raster mask is respected: cells outside the mask are null cells. Region and mask are the same for all maps, so maps with different extents can have different numbers of non-null cells, as the example with the scenes below shows.

In a dataset with relative time, start and end are numbers of the time unit of the dataset, printed without the unit: a map registered from 0 to 6 hours shows 0 and 6, as the first example shows.

t.rast.univar only reads, so it works on a dataset of another mapset as well. The name with the mapset (input=precipitation_monthly@t_rast_univar) selects it; a name without a mapset is searched in the mapsets of the search path (see g.mapsets). The example at the end shows this.

If no map is selected, for instance because the condition in where matches none, t.rast.univar prints nothing in the formats plain and csv, not even the line with the column names. The format json prints an empty list [].

The option zones takes a map of type CELL; t.rast.univar stops with the error "Zoning raster must be of type CELL" for a floating point map.

The format csv refuses a separator of more than one character, the format json refuses separator and -u. percentile without -e is refused by the parser.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_univar and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset, except the last, which creates a second mapset with the same region. The examples that show how the statistics, the selection and the regions work use maps with small constant values, so that the results can be checked by hand.

Statistics of each map of a dataset

The dataset precipitation_monthly holds twelve maps of the monthly precipitation sum in 2020, in whole millimeters. They are generated, not measured: the monthly normals of the 136 climate stations in the vector map precip_30ynormals are interpolated with v.surf.idw for each month and multiplied by an assumed factor for a wet year (1.2 in January, 1.7 in February and so on), so the pattern changes from month to month. Each map is an interval of one month, and cells outside North Carolina are null. Whole millimeters are integers, so the sums, the means and the standard deviations below are the same on every system.

The first command selects the maps of the first quarter to keep the output short. t.rast.univar processes two maps at the same time here (nprocs); the output does not depend on it.

The second block makes the dataset runoff with relative time: two model steps of 6 hours each, with the constant values 1 and 2 in every cell of the region. Their start and end are numbers of hours, printed without the unit.

Command line:

g.mapset -c mapset=t_rast_univar
g.region raster=elev_state_500m res=1000 -a
month=1
for entry in jan:1.2 feb:1.7 mar:0.9 apr:1.3 may:1.6 jun:0.9 \
    jul:1.1 aug:1.5 sep:0.8 oct:1.0 nov:1.6 dec:0.9; do
    name=$(printf %02d $month)
    v.surf.idw input=precip_30ynormals column=${entry%:*} \
        output=precipitation_normal_$name npoints=12 power=2
    r.mapcalc expression="precipitation_monthly_2020_$name = if(isnull(elev_state_500m), null(), round(${entry#*:} * precipitation_normal_$name))"
    month=$((month + 1))
done
t.create output=precipitation_monthly title="Precipitation" \
    description="Monthly precipitation sum 2020 in mm"
t.register -i input=precipitation_monthly \
    maps=$(g.list type=raster pattern="precipitation_monthly_*" mapset=. separator=comma) \
    start=2020-01-01 increment="1 month"
t.rast.univar input=precipitation_monthly nprocs=2 \
    where="start_time < '2020-04-01'"

Maps with extents of their own

Satellite scenes rarely share one extent. The dataset scenes holds four maps with constant values on extents of their own. The current region is the square of 4 km by 4 km with 16 cells whose south-west corner is at easting 400000 and northing 100000; the extents of the scenes are given in km from this corner:
  • scene_1 covers the square from (-1, -1) to (5, 5) and so the whole region;
  • scene_2 lies inside the region, from (1, 1) to (3, 3);
  • scene_3 reaches from (2, 2) to (6, 6) and shares 4 cells with the region;
  • scene_4 lies outside, from (10, 10) to (12, 12).

The commands print the columns id, non_null_cells and null_cells only: on the command line, cut keeps the first, fifth and sixth column; in Python, the function print_cells() reads them from the JSON output, where n is the number of non-null cells.

  1. By default, the cells are counted in the current region: scene_1 has 16 non-null cells there, scene_2 and scene_3 have 4, and scene_4 none.
  2. With -r, each map is counted in its own region: scene_1 has 36 cells, scene_3 16, and scene_4, outside the current region, 4.
  3. region_relation selects maps by their relation to the current region: overlaps keeps all but scene_4, contains only scene_1, which covers the region, and is_contained only scene_2, which lies inside it. Combined with -r, the selected maps are counted in their own regions.
  4. -r works with zones as well. The zone map sides covers all four scenes and holds 1 west of the easting 402000 (2 km from the corner) and 2 east of it. In its own region, scene_1 has 18 cells in each zone and scene_2 2; scene_3 and scene_4 lie east of it and get a line for zone 2 only, because a zone without any cell in the region of a map gets no line. The commands print id, zone and non_null_cells.
