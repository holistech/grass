DESCRIPTION

t.rast.list lists the raster maps that are registered in a space time raster dataset, with the metadata that the temporal database holds for each map. It reads the temporal database; the maps themselves are not opened. The listing is the usual step after t.info has shown the dataset as a whole and before a tool such as t.rast.univar or the map algebra works on its maps. See the introduction to temporal data processing for space time datasets. Space time 3D raster datasets have their own tool, t.rast3d.list, space time vector datasets t.vect.list, and t.list lists the datasets themselves.

Select the maps

The option input names the space time raster dataset. A semantic label after the name, input=name.label, keeps only the maps with this label; the name and the label are separated by a single dot. Labels are given to maps by r.semantic.label or when the maps are registered with t.register.

The option where takes an SQL condition on the columns of the registered maps, such as max > 5, name = 'temperature_1' or start_time >= '2026-03-02'. Times are compared as text, so a time with a clock part needs the whole text: start_time = '2026-03-02' selects nothing, because the stored value is 2026-03-02 00:00:00. Use >= and < for a day, or name for a single map. The function strftime() of SQLite selects recurring times, such as one day of the month or one month of the year. A condition with a syntax error stops with an error that starts with "Invalid where condition". With the methods delta, deltagaps and gran, the condition selects the maps before the lengths and distances are counted, so the distances start at 0 with the first selected map.

Columns and order

The option columns chooses the columns that are printed for each map, separated by commas. The columns are:
  • id, the name of the map with its mapset, such as temperature_1@PERMANENT; name and mapset, the two parts of it;
  • semantic_label, the semantic label of the map, None for a map without one;
  • temporal_type, absolute or relative;
  • start_time and end_time, the time of the map. The end time of a map registered as a time instant is None. With relative time, they are numbers in the unit of the dataset, printed without the unit;
  • creator and creation_time, the user who created the entry of the map in the temporal database and the time of its creation;
  • north, south, west and east, the spatial extent of the map; nsres and ewres, its cell sizes; cols, rows and number_of_cells, its size in cells;
  • min and max, the smallest and the largest value of the map, as stored in the temporal database;
  • interval_length and distance_from_begin, the length of the time interval of the map and the distance of its start from the start of the first listed map. They exist for the methods delta, deltagaps and gran only (see below). With absolute time they are numbers of days, with relative time numbers of the time unit of the dataset.

The option order sorts the maps by one or more columns, separated by commas; the possible columns are those of the list above up to max. The default is start_time. The order is ascending, and the option takes names of columns only, no sort direction. The option works with the method list only.

Methods

The option method chooses what is listed. The default is list.
  • list prints one line per registered map with the columns of columns. Without columns, these are name, mapset, start_time and end_time; with format=line, the column id. It supports all columns except interval_length and distance_from_begin, and it is the only method that order applies to.
  • delta prints the maps ordered by start time with the length of their intervals and their distance from the first map. Without columns, the columns are id, name, mapset, start_time, end_time, interval_length and distance_from_begin. The length of a time instant is None. delta supports only these columns.
  • deltagaps is delta with a line for every temporal gap between two maps. A gap line has None as id, name and mapset; its times are the end of the map before and the start of the map after the gap, and its length is the length of the gap. Maps that follow each other directly leave no gap.
  • gran samples the maps by a granule and prints one line per granule, with the columns of delta. The times and the length are those of the granule, not of the map, so a map that is longer than the granule is listed once for each granule it covers. A granule without a map has None as id, name and mapset. When more than one map meets a granule, the line names the map with the earliest start of the first of these groups that is not empty: maps that are equal to the granule, maps that contain it, maps that start inside it and end after it, maps that start before it and end inside it, and maps that lie inside it. gran refuses a dataset without maps.
  • cols and comma are the old names of the formats plain and line. cols is the same as list, and comma is list with format=line. Prefer the option format.

The option granule is the granule of the method gran. For absolute time it is a text with a number and a time unit, such as "2 months". For relative time, leave it out (see the notes). Without it, the granularity of the dataset is used. The first granule starts with the first map; each later start is counted in whole granules from this start. A step of months or years that ends behind the last day of a shorter month ends on that day: with a granule of one month and a first map from 31 January, the granules start on 31 January, 28 February, 31 March and 30 April. The other methods ignore granule.

Output

The option format chooses the form of the output:
  • plain (the default) prints one line per map with the columns separated by a vertical bar |, and the column names as the first line;
  • line prints the values of one column in one line, separated by commas. It takes one column only; the default column is id, so the line is a list of maps that other tools accept as input;
  • csv prints comma separated values, with the column names as the first line. Text is enclosed in double quotes and numbers are not. A missing value (None) is an empty text;
  • json prints an object with the key data, a list with one object per map, and the key metadata with the list column_names. A missing value is null, numbers are numbers, and times with absolute time are text;
  • yaml prints the same structure as YAML. It needs the PyYAML package.

The flag -u suppresses the line with the column names in the formats plain and csv. The formats json and yaml always name the columns and refuse -u.

The option separator replaces the separator of the formats plain, csv and line. It is a single character or a name such as pipe, comma or tab. The format csv accepts one character only, and json and yaml refuse separator. The option output writes the listing to a file instead of the standard output.

NOTES

If no map is listed, the result depends on the method and the format. With the method list and the formats plain and line, t.rast.list stops with the error "Nothing found in the database for space time dataset <name@mapset> (type: strds)", followed by "Dataset is empty" for a dataset without maps and by "Dataset is empty or where clause is too constrained or incorrect" when where is given. With the format json, data is an empty list. The methods delta and deltagaps print the line with the column names only, both for a dataset without maps and when where selects nothing. The method gran does the same when where selects nothing in a dataset that has a granularity, but stops for a dataset without maps with the error "Dataset is empty". A dataset with a single map that is a time instant has no granularity, and gran without granule stops for it with the error "Wrong granularity: "None"", whatever where selects. Give a granule, such as "1 day", or use delta.

A map without a start time is listed by delta and deltagaps with None in all time columns, and t.rast.list warns about it. The distances count from the first map that has a start time.

The first example shows the format of a dataset with absolute time, the dataset model in the fifth example the format of one with relative time: the times are numbers of the time unit of the dataset, printed without the unit. The method gran works with relative time without granule. Given a granule for a dataset with relative time, it fails: a number ends with a Python error (TypeError) and a text with a unit such as "6 hours" with the error "Wrong granularity". Leave granule out; the granularity of the dataset is used.

The option output takes the name of a file. The name - is not the standard output here: it writes a file with this name, as the last block of the "Choose the output format" example shows. To print the listing, leave out output; to keep it in a file, give a file name other than -.

t.rast.list only reads, so it works on a dataset of another mapset as well. The name with the mapset (input=temperature@PERMANENT) selects it; a name without a mapset is searched in the mapsets of the search path (see g.mapsets). The last example shows this.

Combinations that cannot work are refused with a message that names the options: order with delta, deltagaps or gran; a column of the temporal database with these methods and interval_length or distance_from_begin with list; more than one column with format=line; -u or separator with json or yaml; a separator of more than one character with csv. A granule of absolute time without a time unit ("2") or with an unknown unit ("3 foo") is refused with the error "Wrong granularity".

The dataset rain has two daily maps, registered with a start and an end: rain_1 for 1 June 2026 and rain_3 for 3 June, so 2 June is a gap. The method delta prints the length of each map and its distance from the first map in days; it skips the gap. The method deltagaps adds a line for the gap with None as id, name and mapset, and its length. The CSV form of this table shows None as an empty text.

The dataset model has relative time: three model steps of 6 hours. Its times, lengths and distances are numbers of hours, printed without the unit.

Sample the maps by a granule

The dataset monthly has four maps that start on the last day of a month and end on the last day of the next one, from 31 January. The first block lists them. The method gran with a granule of one month prints one line per month granule: the granules start on 31 January, 28 February, 31 March and 30 April, as each start is counted in months from 31 January and cut to the last day of a shorter month. With a granule of two months, each line covers two maps and names the first of them. The last block samples the relative dataset model of the previous example without a granule, so it uses the granularity of the dataset, 6 hours.

Command line:

for month in 1 2 3 4; do
    r.mapcalc expression="month_$month = $month"
done
t.create output=monthly title="Monthly" description="Monthly maps"
t.register -i input=monthly maps=month_1,month_2,month_3,month_4 \
    start=2026-01-31 increment="1 month"

Use a dataset of another mapset

t.rast.list reads a dataset of another mapset. The example creates the mapset other and switches to it; the dataset temperature stays in the mapset PERMANENT and is named with its mapset. In the second block, g.mapsets shows that PERMANENT is in the search path of the new mapset, so the name temperature without a mapset finds the same dataset.

Command line:

g.mapset -c mapset=other
t.rast.list input=temperature@PERMANENT columns=id,start_time
