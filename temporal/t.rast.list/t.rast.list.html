DESCRIPTION

t.rast.list lists the raster maps that are registered in a space time raster dataset, with the metadata that the temporal database holds for each map. It reads the temporal database; the maps themselves are not opened. The listing is the usual step after t.info has shown the dataset as a whole and before a tool such as t.rast.univar or the map algebra works on its maps. See the introduction to temporal data processing for space time datasets. Space time 3D raster datasets have their own tool, t.rast3d.list, space time vector datasets t.vect.list, and t.list lists the datasets themselves.

Select the maps

The option input names the space time raster dataset. A semantic label after the name, input=name.label, keeps only the maps with this label; the name and the label are separated by a single dot. A dataset whose whole name is name.label is found first, before the text after the dot is read as a label; this concerns only datasets of earlier releases, which could have a dot in their name. Labels are given to maps by r.semantic.label or when the maps are registered with t.register.

The option where takes an SQL condition on the columns of the registered maps, such as max > 5, name = 'temperature_2026_03_01' or start_time >= '2026-03-02'. Times are compared as text, so a time with a clock part needs the whole text: start_time = '2026-03-02' selects nothing, because the stored value is 2026-03-02 00:00:00. Use >= and < for a day, or name for a single map. The function strftime() of SQLite selects recurring times, such as one day of the month or one month of the year. A condition with a syntax error stops with an error that starts with "Invalid where condition". With the methods delta, deltagaps and gran, the condition selects the maps before the lengths and distances are counted, so the distances start at 0 with the first selected map.

Columns and order

The option columns chooses the columns that are printed for each map, separated by commas. The columns are:
  • id, the name of the map with its mapset, such as temperature_2026_03_01@t_rast_list; name and mapset, the two parts of it;
  • semantic_label, the semantic label of the map, None for a map without one. A temporal database of version 2 has no semantic labels: asking for the column stops the run with an error that tells to run t.upgrade first;
  • temporal_type, absolute or relative;
  • start_time and end_time, the time of the map. The end time of a map registered as a time instant is None. With relative time, they are numbers in the unit of the dataset, printed without the unit;
  • creator and creation_time, the user who created the entry of the map in the temporal database and the time of its creation;
  • north, south, west and east, the spatial extent of the map; nsres and ewres, its cell sizes; cols, rows and number_of_cells, its size in cells;
  • min and max, the smallest and the largest value of the map, as stored in the temporal database;
  • interval_length and distance_from_begin, the length of the time interval of the map and the distance of its start from the start of the first listed map. They exist for the methods delta, deltagaps and gran only (see below). With absolute time they are numbers of days, with relative time numbers of the time unit of the dataset.

The option order sorts the maps by one or more columns, separated by commas; the possible columns are those of the list above up to max. The default is start_time. The order is ascending, and the option takes names of columns only, no sort direction. The option works with the method list only.

Methods

The option method chooses what is listed. The default is list.
  • list prints one line per registered map with the columns of columns. Without columns, these are name, mapset, start_time and end_time; with format=line, the column id. It supports all columns except interval_length and distance_from_begin, and it is the only method that order applies to.
  • delta prints the maps ordered by start time with the length of their intervals and their distance from the first map. Without columns, the columns are id, name, mapset, start_time, end_time, interval_length and distance_from_begin. The length of a time instant is None. delta supports only these columns.
  • deltagaps is delta with a line for every temporal gap. A gap is time that no map covers. A gap line has None as id, name and mapset; its times are the latest end of the maps before the gap and the start of the map after it, and its length is the length of the gap. Maps that follow each other directly leave no gap, and neither does a map that ends inside a longer one: of maps from 1 to 11 January, 3 to 5 January and 8 to 13 January, the first covers 5 to 8 January.
  • gran samples the maps by a granule and prints one line per granule, with the columns of delta. The times and the length are those of the granule, not of the map, so a map that is longer than the granule is listed once for each granule it covers. A granule without a map has None as id, name and mapset. When more than one map meets a granule, the line names the map with the earliest start of the first of these groups that is not empty: maps that are equal to the granule, maps that contain it, maps that start inside it and end after it, maps that start before it and end inside it, and maps that lie inside it. gran refuses a dataset without maps.
  • cols and comma are the old names of the formats plain and line. cols is the same as list, and comma is list with format=line. Prefer the option format.

The option granule is the granule of the method gran. For absolute time it is a text with a number and a time unit, such as "2 months". For relative time it is a whole number of at least 1 in the time unit of the dataset, also followed by this unit: 12, "12 hours" and "12 hour" are the same granule of a dataset in hours. Another unit, such as "1 day" for a dataset in hours, is refused with the error "Invalid granule". Without granule, the granularity of the dataset is used. The first granule starts with the first map, and the granules reach the latest end of the maps, also when a shorter map starts last. Each later start is counted in whole granules from the start of the dataset when the first selected map lies whole granules after it, otherwise from the first selected map; this matters when where selects later maps only. A step of months or years that ends behind the last day of a shorter month ends on that day: with a granule of one month and a first map from 31 January, the granules start on 31 January, 28 February, 31 March and 30 April. Such a series has the granularity one month (see t.info), so gran without granule samples it by months as well. The other methods ignore granule.

Output

The option format chooses the form of the output:
  • plain (the default) prints one line per map with the columns separated by a vertical bar |, and the column names as the first line;
  • line prints the values of one column in one line, separated by commas. It takes one column only; the default column is id, so the line is a list of maps that other tools accept as input;
  • csv prints comma separated values, with the column names as the first line. Text is enclosed in double quotes and numbers are not. A missing value (None) is an empty text;
  • json prints an object with the key data, a list with one object per map, and the key metadata with the list column_names. A missing value is null, numbers are numbers, and times with absolute time are text;
  • yaml prints the same structure as YAML. It needs the PyYAML package.

The flag -u suppresses the line with the column names in the formats plain and csv. The formats json and yaml always name the columns and refuse -u.

The option separator replaces the separator of the formats plain, csv and line. It is a single character or a name such as pipe, comma or tab. The format csv accepts one character only, and json and yaml refuse separator. The option output writes the listing to a file instead of the standard output.

NOTES

If no map is listed, the result depends on the method and the format. With the method list and the formats plain and line, t.rast.list stops with the error "Nothing found in the database for space time dataset <name@mapset> (type: strds)", followed by "Dataset is empty" for a dataset without maps and by "Dataset is empty or where clause is too constrained or incorrect" when where is given. With the format json, data is an empty list. The methods delta and deltagaps print the line with the column names only, both for a dataset without maps and when where selects nothing. The method gran does the same when where selects nothing in a dataset that has a granularity, but stops for a dataset without maps with the error "Dataset is empty". A dataset with a single map that is a time instant has no granularity, and gran without granule stops for it with the error that the dataset has no granularity, whatever where selects. Give a granule, such as "1 day", or use delta.

A map without a start time is listed by delta and deltagaps with None in all time columns, and t.rast.list warns about it. The distances count from the first map that has a start time.

The first example shows the format of a dataset with absolute time, the dataset model in the fifth example the format of one with relative time: the times are numbers of the time unit of the dataset, printed without the unit. The method gran works with relative time with and without granule, as the example "Sample the maps by a granule" shows.

The option output takes the name of a file; the name - is the standard output, as the last block of the "Choose the output format" example shows.

t.rast.list only reads, so it works on a dataset of another mapset as well. The name with the mapset (input=temperature@t_rast_list) selects it; a name without a mapset is searched in the mapsets of the search path (see g.mapsets). The last example shows this.

Combinations that cannot work are refused with a message that names the options: order with delta, deltagaps or gran; a column of the temporal database with these methods and interval_length or distance_from_begin with list; more than one column with format=line; -u or separator with json or yaml; a separator of more than one character with csv. A granule of absolute time without a time unit ("2") or with an unknown unit ("3 foo") is refused with the error "Wrong granularity".

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_list and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region. t.rast.list reads the temporal database only, so the maps hold small integer values in two halves: the first 167 rows, counted from the north, hold the low value of the map, the remaining rows the high value, and the smallest and the largest value of a map are these two values.

List the maps of a dataset

The dataset temperature has four maps of daily mean air temperature over North Carolina for the days from 1 to 4 March 2026. The northern half of each map holds the low value and the southern half the high value, in degrees Celsius: 1 and 3, 7 and 9, 4 and 6, 10 and 12. The smallest and largest value of temperature_2026_03_01 are therefore 1 and 3, and the third map is colder than the second one.

The first block lists the maps with the default columns. The second block adds the flag -u, which suppresses the line with the column names. The third block names the columns, among them the smallest and largest value of each map. The fourth block lists all columns of the first map except creator and creation_time, which differ from user to user and from day to day. The map has no semantic label, and its extent is the computational region of 839 by 335 cells of 1000 m.

Select and sort the maps

The maps of temperature are sorted by start time. The option order sorts by another column; the first block sorts by max, so the colder third map comes before the second one.

The option where selects the maps. The second block selects the maps that start from 2 March on and before 4 March, so the second and the third map. The third block combines a condition on the smallest value with order. The fourth block uses strftime() to select the maps that start on the 1st or the 4th day of the month, a recurring selection that works the same way for one month of every year.

The last block shows a trap: a time compared with = must be the whole text 2026-03-02 00:00:00, and the short form selects no map. The format json shows the empty result, data is an empty list; the formats plain and line stop with an error here.

Intervals, distances and gaps

The dataset rain has two daily maps, registered with a start and an end: rain_2026_06_01 for 1 June 2026 and rain_2026_06_03 for 3 June, so 2 June is a gap. The method delta prints the length of each map and its distance from the first map in days; it skips the gap. The method deltagaps adds a line for the gap with None as id, name and mapset, and its length. The CSV form of this table shows None as an empty text.

The dataset model has relative time: three model steps of 6 hours. Its times, lengths and distances are numbers of hours, printed without the unit.

Command line:

r.mapcalc expression="rain_2026_06_01 = 4"
r.mapcalc expression="rain_2026_06_03 = 2"
t.create output=rain title="Rain" \
    description="Daily rain in mm with a gap"

t.register input=rain maps=rain_2026_06_03 start=2026-06-03 end=2026-06-04

Sample the maps by a granule

The dataset monthly has four maps that start on the last day of a month and end on the last day of the next one, from 31 January. The first block lists them. The method gran with a granule of one month prints one line per month granule: the granules start on 31 January, 28 February, 31 March and 30 April, as each start is counted in months from 31 January and cut to the last day of a shorter month. With a granule of two months, each line covers two maps and names the first of them. Without a granule, gran takes the granularity of the dataset, one month, and prints the same lines as with "1 month". The last blocks sample the relative dataset model of the previous example: without a granule by the granularity of the dataset, 6 hours, and with the granule 12, a number of hours; "12 hours" is the same granule.

Use a dataset of another mapset

t.rast.list reads a dataset of another mapset. The example creates the mapset t_rast_list_2 and switches to it; the dataset temperature stays in the mapset t_rast_list, which is not in the search path of the new mapset, and is named with its mapset. In the second block, g.mapsets adds t_rast_list to the search path of the new mapset and prints the search path, because a name without a mapset is searched only there (see Datasets of other mapsets); the name temperature then finds the same dataset.

Command line:

g.mapset -c mapset=t_rast_list_2
g.region raster=elev_state_500m res=1000 -a
t.rast.list input=temperature@t_rast_list columns=id,start_time
