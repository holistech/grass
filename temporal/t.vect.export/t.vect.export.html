DESCRIPTION

t.vect.export writes the maps of a space time vector dataset and a description of their times into one tar archive. The archive moves a dataset to another project or computer: t.vect.import reads it back and registers the maps in a new dataset. See the introduction to temporal data processing for space time datasets. The tool for space time raster datasets is t.rast.export.

The option input names the space time vector dataset, and output the archive that is written. The tool uses the name of output as it is and adds no suffix, so the name should say what the archive is, such as wind.tar.bz2. An existing archive is refused unless the flag --overwrite is given.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2026-03-02', and exports only the maps it selects. Without where, all maps are exported. The maps are written in the order of their start time. A selection without a map is not an error (see the notes).

Export format

The option format chooses how each vector map is stored in the archive:
  • GML, the default, writes the files name.xml and name.xsd with v.out.ogr;
  • GPKG writes a GeoPackage file name.gpkg with v.out.ogr;
  • pack writes the file name.pack with v.pack, the GRASS format that v.unpack reads. The .pack file is a tar archive of its own that is not compressed again.

v.out.ogr writes one layer per file, v.pack all layers of a map (see the notes).

Archive and compression

The option compression compresses the archive: bzip2 (the default), gzip, or no for a plain tar archive. A tool such as tar -tf or the Python module tarfile recognises the compression by itself.

The option directory names the working directory, by default /tmp. t.vect.export exports the maps into a temporary subdirectory of it, packs them there, moves the archive to the path given by output and removes the subdirectory. The archive is therefore not written to directory, and a relative output is taken from the current directory.

Files in the archive

The archive holds the files of the maps, in the order of their start time, and then five text files:
  • list.txt has one line for each map, with the fields name, start time and end time, separated by |. The start and end time are in ISO format with absolute time and numbers with relative time. A map that is a time instance has the end time of its start time. In the pack format the name is name:layer, with one line for each registered layer of a vector map;
  • proj.txt is the output of g.proj with -p format=proj4, the coordinate reference system of the project;
  • init.txt has one key=value line for each of the following: stds_type, format, temporal_type, semantic_type, relative_time_unit (relative time only), number_of_maps and the extent north, south, east, west. number_of_maps counts the exported maps, and the extent is that of the exported maps, not of the region. A selection without a map (see the notes) writes the extent of the whole dataset instead;
  • readme.txt describes the files of the archive;
  • metadata.txt is the output of t.info for the dataset.

NOTES

The export reads the maps from the mapsets they were registered from, also if a map of the same name exists in the current mapset. The maps of a dataset may come from several mapsets. If maps of one name from different mapsets are exported together, each of them is named name@mapset in the archive, in its file names and in list.txt, where the pack format writes name:layer@mapset. A map whose name no other mapset of the selection shares keeps its name, so an archive without such maps has the form of older versions. The last example shows this. t.vect.import imports dup@other as dup_other.

The GML and GPKG formats hold one layer per map. A selection that contains several layers of one vector map is refused before anything is written; use format=pack for such a map, or select one layer with where. The same holds for a map that the selection names several times with the same layer, for example registered as name and as name:1; select it once with where. The fifth example shows the refusal.

With relative time, list.txt holds the numbers of the start and end, and init.txt the unit as relative_time_unit.

A where condition that selects no map gives the warning "The selection contains no map" and an archive without maps, with number_of_maps=0 in init.txt. A condition with a syntax error stops the tool with an error that starts with "Invalid where condition".

The tool checks the directories before it makes anything. It stops with "Directory ... not found" or "... is not writable" for directory, and with "Output directory ... not found" for the directory of output; both must exist and be writable. A map that can no longer be exported, for example because it was removed, stops the tool with "Unable to export vector map <name@mapset> as GML with v.out.ogr" (GPKG for the format GPKG; the pack format ends the message with "with v.pack" instead); no archive is left, and the temporary subdirectory is removed in every case.

Choose the compression

Each block exports wind with one value of compression and prints the first two bytes of the archive as hexadecimal numbers: 1f8b for gzip and 425a ("BZ") for bzip2. A plain tar archive has no such mark; its first bytes are the start of the first file name, 2e2f for the characters "./". tar -tf and tarfile read all three the same way.

Command line:

for method in no gzip bzip2; do
    t.vect.export input=wind output=wind_$method.tar compression=$method
    od -An -tx1 -N2 wind_$method.tar | tr -d ' '
    tar -tf wind_$method.tar | sed -n 1p
done

The dataset pair registers dup@PERMANENT for 1 March and dup@other and solo@other for 2 March. The mapset other is added to the search path, so that the maps can be registered.
