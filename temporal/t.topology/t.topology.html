DESCRIPTION

t.topology reports the temporal topology of a space time dataset (STRDS, STR3DS or STVDS; see the introduction to temporal data processing): whether the maps follow each other without overlap, how many maps are time points or intervals, how many gaps lie between them, and which temporal relation holds between which maps. It tells whether a dataset has a valid topology and where it has not. The dataset is read only; t.topology changes nothing.

The option input names the dataset and type its type: strds (the default), str3ds or stvds. A dataset is found by its type and name, so a name that belongs to a dataset of another type is not found. The option where is an SQL condition on the table of the registered maps, for example start_time >= '2026-06-02' or name != 'c'; t.topology then looks at the selected maps only. It uses the time of the maps and of the dataset in absolute and in relative time alike.

Without a flag t.topology prints a summary in three parts. The first part, Basic information, shows the same lines as the basic information of t.info. The second part, Temporal topology, has these lines:

  • Is subset of dataset is True if where is given and False otherwise, also if the condition selects all maps.
  • Temporal topology is is valid if no two of the maps are equal, overlap, or lie in each other. A pair that touches (Follows, Precedes) or has a gap between them is allowed, as are time points. It is invalid if a pair of maps breaks the rule; the next part tells which relations. No maps break no rule, so the topology of an empty selection is valid.
  • Number of points counts the maps that have a start time only and Number of intervals those that have a start and an end time. Invalid time stamps counts the maps without a start time.
  • Number of gaps counts the neighbours in the order of the start times of which the later one starts after the earlier one has ended.
  • Granularity is the time step of the maps, for example 1 day. In relative time it is a number without a unit. It is None if there are no maps.

The third part, Topological relations, counts the pairs of maps by their temporal relation. Each pair counts twice, once for each map as the point of view: a pair that touches counts as one Follows and one Precedes, a pair of maps with the same times as two Equal. A pair that does not touch and does not overlap, because there is a gap, is not counted. The counts are:

  • Equal: the maps have the same start and end time.
  • Follows and Precedes: the end of one map is the start of the other.
  • Overlaps and Overlapped: the maps share a part of their time, but neither lies in the other.
  • During and Contains: one map lies in the other.
  • Starts and Started: the maps start together and the first ends earlier; Finishes and Finished: the maps end together and the first starts later. A pair of this kind is counted as During and Contains, too.

Without maps the part has no count lines.

The flag -m prints, instead of the summary, an entry for each selected map in the order of the start times, with the basic information, the time, the spatial extent and the metadata of the map. Its section Temporal Topology has a line for the next and the previous map in time (Next, Previous) and one line for each temporal relation that holds for the map, with the identifiers of the other maps. A relation line reads from the map to the maps it names: Overlaps: b in the entry of the map a says that a overlaps b. Only maps of the selection are named. The flag -s does the same and adds the spatial relations of the map to the other maps: Equivalent, Cover, Covered, Overlap, In, Contain and Meet. With -s a map is listed with another one only if the two maps are related in time and in space; a map that has no spatial relation to a map is not listed with its temporal relation either. The spatial relations of a STRDS are computed from the 2D extent of its maps (west, east, south, north), those of a STR3DS and a STVDS from the 3D extent (with bottom and top). -s prints the same as -m and -s together. Both flags print no summary.

NOTES

A map that has an end time before its start time cannot be registered, but a database that was edited by hand can hold one. t.topology warns about each such map with its identifier and treats it as a map without time: it has no relations, the other maps are related as if it were not there, and the granularity leaves it out. A map without a start time comes last in the listing of -m and -s. t.topology ends without an error in both cases.

An empty dataset or a where condition that selects no map is not an error. The summary shows the topology as valid, zero counts, the granularity None and no count lines for the relations.

A where condition with a syntax error stops t.topology with the error Invalid where condition <...> and the message of the database.

The times in where are compared as text in absolute time: start_time >= '2026-06-02' selects as expected, whereas start_time = '2026-06-02' selects nothing, because the stored value is 2026-06-02 00:00:00. Select a single map by name = '...'.

A dataset that does not exist stops t.topology with an error such as Space time dataset <nope> of type <strds> not found.

Datasets of relative time and of the other types work in the same way; the last example shows a relative time dataset and a vector dataset. A dataset of another mapset of the search path is found by its name, and name@mapset names it explicitly.

Include the spatial relations

The dataset scenes holds three maps of one day each, one after the other: big covers 0 to 4 in both directions, small lies inside it, and far lies at 4 to 8 and has no common area with small. The maps get the extent of the region that is current when they are created. The first block lists the temporal relations with -m: big precedes small, which precedes far. The second block adds the spatial ones with -s: big contains small and small is in big. far and small are related in time but disjoint in space, so the listing of -s has no Follows line for far and no Precedes line naming far for small; only the chain of Next and Previous stays.

Command line:

g.region n=4 s=0 e=4 w=0 res=1
r.mapcalc expression="big = 1"
g.region n=2 s=1 e=3 w=1 res=1
r.mapcalc expression="small = 1"
g.region n=8 s=4 e=8 w=4 res=1

t.register -i input=scenes maps=big,small,far start=2026-06-01 increment="1 day"
