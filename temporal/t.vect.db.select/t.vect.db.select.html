DESCRIPTION

t.vect.db.select prints the attribute tables of the vector maps that are registered in a space time vector dataset. It runs v.db.select on each map, in the order of the start times of the maps, and puts the start and end time of the map in front of every row. Use it to see the attributes of a whole time series at once, or to find the rows of all maps that meet one condition. See the introduction to temporal data processing for space time datasets. t.vect.list lists the maps themselves, and t.vect.univar calculates statistics of their attributes.

The option input names the space time vector dataset. It is searched in the mapsets of the search path, so a dataset of another mapset can be named with or without its mapset; the last example shows both forms. The maps are read from their own mapsets.

Select maps and rows

The option t_where selects maps of the dataset. It takes an SQL condition on the columns of the registered maps, the columns that t.vect.list offers, such as start_time >= '2026-03-02' or name = 'gauges_2'. Without t_where, all maps are used. The option where selects rows. It takes an SQL condition on the columns of the attribute table, such as speed > 22, and is applied to the table of each selected map. Both options leave out the word where, and they can be combined: a row is printed if its map meets t_where and the row meets where.

The option layer (default 1) is the layer whose table is printed. A map that is registered in the dataset with a layer, as name:2, always uses that layer, and the option layer applies to the maps registered without one, unless an earlier map was registered with a layer; see the notes. The layer example shows both.

Select columns

The option columns takes the names of the table columns to print, separated by commas, in the order in which they are given. Without columns, all columns of the table are printed in the order of the table. The names are compared without regard to case, as the database does. Besides plain names, columns takes the star and SQL expressions such as speed * 2, which v.db.select evaluates for each row.

Output

Every row starts with two columns, start_time and end_time, the times of the map that the row comes from; the other columns are those of the attribute table. A map registered as a time instant has no end time: the column is empty in the formats plain and csv and null in json. With relative time, the times are numbers in the unit of the dataset.

The option format chooses the form of the output:

  • plain (the default) prints one header line with the column names and then one line per row. The columns are separated by |.
  • csv prints the same lines, separated by a comma. Text values are put in double quotes.
  • json prints a single list that holds one object per row, with the keys start_time and end_time first and then the columns. Numbers stay numbers and text values are strings.

The option separator replaces the separator of the columns in plain and csv. It takes a character or a name such as comma, as the example shows. In csv the separator must be a single character. json does not take a separator.

Several maps

The header line is printed before the rows of the first map. When the next map has other columns, the header is printed again before its rows, so each block of lines has the header that belongs to it. Maps with the same columns share one header. A map without a row that meets where adds no line, except a header if its columns differ. The format json has no headers. Its list holds the rows of all maps.

NOTES

All maps are checked before the first line is printed, for their attribute table and for the columns named in columns. If a map has no attribute table in the layer used for it, or lacks such a column, the module ends with an error that lists the maps and prints nothing. The star and SQL expressions in columns are not checked; v.db.select evaluates them in the table of each map. A column of where is not checked in advance. An error in where ends the module with the message of v.db.select, for example "incomplete input", and a column that the table of a later map lacks stops the module at that map, after the lines of the earlier maps have been printed.

If t_where selects no map, the module prints a warning and ends successfully: the output is empty, or [] for the JSON format. An error in t_where ends the module with the message "Invalid t_where condition".

A separator longer than one character with the format csv, and any separator with the format json, are refused.

A map is read with the layer it is registered with. A map that is registered without a layer takes the layer of the last selected map before it, in the order of the start times, that is registered with one, and the option layer only if there is none. The order of registration does not matter, and a map that t_where leaves out passes on nothing. The layer example shows the case, which is easy to miss: register such maps with the layer they need, as name:1, or keep them in a dataset of their own.

The dataset both registers the two layers of plots_1 as plots_1:1 and plots_1:2. The third block prints both, and a layer option does not change this: the registered layer wins.

features = "VERTI:\nP 1 2\n {k} 1\n 1 1\n 2 1\nP 1 2\n {k} 2\n 1 2\n 2 2\n"
for k in (1, 2):
    tools.v_edit(map=f"plots_{k}", tool="create")
    tools.v_edit(map=f"plots_{k}", tool="add", input=StringIO(features.format(k=k)))
    tools.v_db_addtable(map=f"plots_{k}", columns="count integer")
    tools.v_db_addtable(
        map=f"plots_{k}", layer=2, table=f"plots_{k}_b", columns="count integer"
    )
    sql = f"UPDATE plots_{k} SET count = cat;\n"
    sql += f"UPDATE plots_{k}_b SET count = 100 + cat;\n"
    tools.db_execute(input=StringIO(sql))

Print from a dataset of another mapset

The dataset gauges stays in the mapset PERMANENT. The first block creates the mapset other, switches to it and prints the dataset by its name alone, which is found in the search path. The second block names the mapset. Both print the same rows.

Command line:

g.mapset -c mapset=other
t.vect.db.select input=gauges columns=cat,speed where="cat = 1"
