DESCRIPTION

t.vect.what.strds reads the values of the maps of a space time raster dataset (STRDS) at the points of the maps of a space time vector dataset (STVDS) and stores them as columns in the attribute tables of the vector maps. Use it to attach a time series of raster values, such as temperature or precipitation, to monitoring stations or other sample points. Each vector map of the STVDS has a time interval, which this manual calls its window. For each vector map, the tool collects the raster maps of the STRDS that are related to its window in time, optionally combines them to one map, and lets v.what.rast write the raster values at the points into the table. See the introduction to temporal data processing for space time datasets. t.vect.observe.strds does the sampling into new vector maps instead of existing ones, t.vect.list lists the vector maps of the dataset, and v.db.select prints their tables.

Datasets and region

The options input (the STVDS) and strds (the STRDS) are required. Both datasets must have the same temporal type, absolute or relative. Every vector map of input must have a time interval; a map with a time instant stops the tool. The tool changes the tables of the vector maps, so the maps must be in the current mapset, and each registered layer must have an attribute table. The STRDS may be in another mapset (strds=levels@PERMANENT), but the vector maps of input must be in the current mapset; the seventh example shows both. Points outside the current region get no value, as v.what.rast skips them; the second example shows it.

Select the raster maps of a window

The option sampling is a list of temporal relations. A raster map is taken for a vector map if it has one of the listed relations to its window. The default is start. The relations describe the raster map in terms of the window:
  • start: the raster map starts inside the window, at or after its start and before its end. Its end does not matter, so the map may end after the window, and a map that equals the window is taken too.
  • during: the raster map lies within the window and is not equal to it. It may share the start or the end of the window.
  • overlap: the raster map starts before the window and ends inside it, or starts inside the window and ends after it.
  • contain: the raster map covers the whole window and is longer than it.
  • equal: the raster map has the start and the end of the window.
  • follows: the raster map starts when the window ends.
  • precedes: the raster map ends when the window starts.

So start selects more than its name suggests: it takes a map that during rejects because it is equal to the window or because it ends after the window, and it takes nothing that starts before the window, however long it lasts. The fourth example runs every relation on the same windows. If a window has no raster map, the vector map is left as it is, without a new column. The tool takes the maps of a window in the order of their start time.

The relations apply only to a STRDS whose maps are all intervals. If the STRDS has time instants, or instants and intervals, sampling has no effect: the tool always takes the raster maps that start inside the window, as start does, even with contain, which no instant can satisfy. The fourth example shows it.

Choose the columns

Without column, each raster map found for a vector map gets a column named after it, with dots replaced by underscores (level_2), in the table of the layer of the vector map. The column type is INT for an integer raster map and DOUBLE PRECISION for any other. The value of a point is the value of the cell below it.

The option column names one column instead, the same in every vector map. It holds the values of one raster map for each vector map: the first map of the window in time order, or the aggregate if method is given and the window has several maps.

The option where is an SQL condition on the attribute table of the vector maps. Only the points that satisfy it get a value; the column of the other points stays empty (NULL). The tool tries the condition on the table of each layer before it writes the first value, and stops if it fails.

The option t_where is an SQL condition on the vector maps of input, using the columns of the temporal database such as name, start_time and end_time (see t.vect.list). The tool changes only the vector maps that match. SQLite compares times as text: start_time >= '2026-02-01' selects as expected, but an equality with a date without a time of day finds nothing, as the stored value reads 2026-02-01 00:00:00.

Aggregate the raster maps of a window

With method other than disabled (the default), the tool combines the raster maps of a window to one map with r.series and reads that map. It does so only for a window with more than one raster map. A window with a single map is treated as if method were disabled: the values of the map go to the column named after it (or to column). With several maps and without column, the aggregate goes to the column <strds>_<method>, built from the name of the STRDS without the mapset, for example levels_average. Every character outside A-Za-z0-9_ is replaced by an underscore, and a name that would start with a digit gets the prefix c_, because v.what.rast cannot write such a column. If the aggregate has no value at all, the tool adds no column. The temporary raster map is removed after it has been read.

For a window with two raster maps, here level_2 and level_3, whose value at one point is 211 and 311 (the first point of the first example), the methods give:

  • average 261, median 261, mode 211 (the first of the sorted values with the highest count), minimum 211, maximum 311, sum 522;
  • count 2 and diversity 2 (the number of maps and the number of different values), range 100 (maximum minus minimum);
  • variance 2500 and stddev 50: population values, the sum of the squared deviations divided by the number of maps, not by that number minus 1;
  • min_raster 0 and max_raster 1: the position of the map with the smallest or largest value in the time-ordered list, counted from 0;
  • slope 100, offset 211 and detcoeff 1: slope, intercept and coefficient of determination of the regression of the values over their position 0, 1 in the list;
  • quart1 236, quart3 286 and perc90 301: quantiles interpolated between the sorted values by the rule of Hyndman and Fan, type 7, at position q * (n - 1);
  • quantile 211: the tool has no option for the quantile, so this is the smallest value;
  • skewness 0 and kurtosis -2: the skewness and the excess kurtosis of the two values.

NOTES

Before the first value is written, the module checks the target columns of all vector maps and layers. If one of them already exists, a layer to be written has no attribute table, a vector map belongs to another mapset, or the same layer of one map is registered under two ids (for example c and c:1) and both would write the column option's column, the module stops with an error and changes nothing. Without column the same layer under two ids is refused only if both intervals reach one raster map, as they would write its column twice, and is otherwise allowed; two different layers of one map (c:1 and c:2) are allowed with column, as each has its own table. With the --overwrite flag, the existing columns are kept and their values are written again, so a second run does not add a second column; the fifth example shows it. An existing column keeps its type: values of a floating-point raster map written into an integer column lose their fractional part, and v.what.rast warns about it. To get a column of the new type, drop the column with v.db.dropcolumn first. A column name that differs from an existing column only in upper and lower case (K for k) is refused, with and without --overwrite, before anything is written.

The tool stops with an error if a required option is missing, if method or sampling has a value outside the lists above, if a dataset does not exist, if the two datasets differ in their temporal type ("Input and aggregation dataset must have the same temporal type"), if a map of the STVDS has a time instant ("All registered maps of the space time vector dataset must have time intervals"), and if the STVDS is empty or t_where selects no map ("is empty"). A where or t_where with a syntax error is reported as a message (Invalid where condition <...> for vector map <...> and Invalid t_where condition <...>), not as a traceback.

Relative time works as absolute time does; the sixth example shows it. The relations of sampling then compare the start and end numbers of the maps. The tool neither converts nor checks the units: use the same unit in both datasets. With a STRDS in hours and a vector map from 0 to 2 days, the tool compares 0 to 2 with the hours and takes the maps of the first two hours only, not those of 48 hours; the last block of the sixth example shows it.

With method=quantile the tool gives the smallest value, as it has no option for the quantile that r.series would need.

Sample the raster maps of each interval

The dataset levels holds six raster maps, level_1 to level_6, one for each month from January to June 2026. The region has two rows and two columns of size 1, and the value of level_k in the cell of row r and column c is 100 * k + 10 * r + c. The dataset stations holds three vector maps with the same four points, one at the centre of each cell, with the column height 1 to 4: the points cat 1 and 2 lie in the first row, 3 and 4 in the second. stations_1 has the interval January, stations_2 February and March, and stations_3 April.

t.vect.what.strds uses the default sampling, start. For each vector map it takes the raster maps that start inside its interval: level_1 for stations_1, level_2 and level_3 for stations_2, and level_4 for stations_3. Each vector map gets one column per raster map, named after it. The last two commands print the tables of stations_1 and stations_2. The point cat 3, in the second row and first column, reads 121 in level_1, 221 in level_2 and 321 in level_3.

Choose the raster maps by their relation to the interval

The loop runs every value of sampling on four vector maps with the same points and these windows (all in 2026): a from 15 February to 15 April, b from 10 to 20 March, c from 1 March to 1 April and d from 1 March to 10 April. The raster maps are the monthly maps level_1 to level_6, so level_3 lasts from 1 March to 1 April, level_2 from 1 February to 1 March and level_4 from 1 April to 1 May. For each relation the loop makes a dataset windows_<relation> with four copies of a template map, runs the tool, and prints the raster columns of each copy.

Compare the rows of a window in the output:

  • start: level_3 and level_4 for a and d, because both start inside these windows, though level_4 ends after them; level_3 alone for c, which it equals; nothing for b, because level_3 starts before it.
  • during: level_3 for a and for d, which shares its start with level_3; nothing for c, which equals level_3.
  • overlap: level_2 and level_4 for a, level_4 for d.
  • contain: level_3 for b, which lies inside it.
  • equal: level_3 for c.
  • follows: level_4 for c, which ends when level_4 starts.
  • precedes: level_2 for c and d, which start when level_2 ends.

The last block uses a dataset readings of two time instants, 5 and 25 March, and a window from 1 March to 1 April. No instant can contain a window, but with sampling=contain the tool writes both columns: a STRDS with time instants is always sampled as with start.

Command line:

0.5,1.5,1
1.5,1.5,2
0.5,0.5,3

for s in start during overlap contain equal follows precedes; do
    t.create type=stvds output=windows_$s title="Windows" \
        description="Sampling $s"
    for w in a b c d; do

        c=$(db.columns table=${s}_$w | awk '/^level_/' | paste -sd, -)
        echo "${s}_$w: ${c:--}"
    done
done

Select vector maps by time and write the values again

t_where restricts the tool to the vector maps whose temporal metadata match. Here it takes the maps that start on or after 1 February, so stations_2 and stations_3 get the column late and stations_1 does not. The loop prints the columns named late, with - where there is none.

The second call repeats the first one with --overwrite. The columns exist now, and the flag lets the tool write them again instead of stopping. The call changes what is read: method=maximum takes the larger of the two maps of stations_2, level_3, and where limits the new values to the points with a height of at most 2. The points 1 and 2 of stations_2 read 311 and 312 from level_3; the points 3 and 4 keep the values 221 and 222 of the first call.

Command line:

t.vect.what.strds input=stations strds=levels column=late \
    t_where="start_time >= '2026-02-01'"

    echo "$m: ${c:--}"
done

Relative time

The dataset steps has three raster maps for the hours 0 to 1, 1 to 2 and 2 to 3, and probes two vector maps with the intervals 0 to 2 and 2 to 3, both in hours. Both datasets have relative time. probe_1 has step_1 and step_2 in its interval, so method=average stores their mean, 111 and 211 for the first point, 161, in the column steps_average. probe_2 has only step_3, which is stored under its own name, 311 for the first point.

The last block shows that the tool does not look at the unit. The vector map probe_days has the interval 0 to 2 days, while steps counts hours. The tool compares the numbers: it takes step_1 and step_2, which start at 0 and 1, but not step_3, which starts at 2, although 2 days are 48 hours and cover all three maps. Use the same unit in both datasets.

Command line:

for k in 1 2 3; do
    r.mapcalc expression="step_$k = 100 * $k + 10 * row() + col()"
done
t.create output=steps temporaltype=relative title="Steps" \
    description="Three hourly maps"
t.register -i input=steps maps=step_1,step_2,step_3 \
    start=0 increment=1 unit=hours
g.copy vector=window,probe_1
g.copy vector=window,probe_2
t.create type=stvds temporaltype=relative output=probes title="Probes" \
    description="Two intervals"
t.register type=vector input=probes maps=probe_1 start=0 end=2 unit=hours
t.register type=vector input=probes maps=probe_2 start=2 end=3 unit=hours
t.vect.what.strds input=probes strds=steps method=average
v.db.select map=probe_1

Datasets of another mapset

The example creates the mapset analysis and switches to it, where the region is its own and is set again. The dataset levels stays in PERMANENT, and strds=levels@PERMANENT names it with its mapset. The vector map remote and its dataset belong to analysis, so the tool writes the columns level_2 and level_3 into the table of remote in the current mapset. The second block asks for the dataset stations in PERMANENT as input. The tool refuses it before it writes anything, because it would have to change the tables of vector maps of another mapset, and the block prints the message.

    description="One interval in the new mapset"
