DESCRIPTION

t.vect.extract selects maps of a space time vector dataset and registers them in a new space time vector dataset. On the way, it can extract the features that meet an SQL condition on their attribute table from each selected map into a new vector map. Use it to cut a time window out of a dataset, or to keep the features of every map that meet the same condition. See the introduction to temporal data processing for space time datasets. t.vect.list lists the maps of the result. The tool works like t.rast.extract, on space time vector datasets (STVDS) and vector maps instead of space time raster datasets and raster maps, with v.extract in place of r.mapcalc.

The option input names the space time vector dataset, the option output the new one. The new dataset takes the temporal type and the semantic type of the input dataset. The output always belongs to the current mapset. An existing output dataset is refused unless the flag --overwrite is given; then it is replaced.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, the columns that t.vect.list offers, such as start_time >= '2026-03-03', which selects the maps that start on 3 March or later. Without where, all maps are selected.

Register or extract

Without expression, t.vect.extract creates no map. It registers the selected maps themselves in the new dataset, so a map is then part of two datasets and the data are not duplicated.

With expression, the tool runs v.extract once for each selected map and registers the new maps, with the start and end time of the map they come from, in the new dataset. The expression is an SQL condition without the word where, such as speed > 22. It is not a map algebra expression, as in t.rast.extract: v.extract applies it to the attribute table of the map and copies the features that meet it, with their table rows, into the new map. The new maps belong to the current mapset. The expression needs the option basename.

The options layer and type tell v.extract where to look. The option layer (default 1) is the layer whose table the expression reads, for the maps that are registered without a layer. A map registered as name:2 (name and layer 2) is extracted from layer 2, as the layer example shows. The option type (default point,line,boundary,centroid,area) lists the feature types that are copied; any other feature of the map is left out.

The new maps are named after basename, followed by an underscore and a suffix that the option suffix chooses.

  • gran (the default) takes the start time of the map, cut to the unit of the granularity of the input dataset: year and month for a granularity of three months, year, month and day for a granularity of one day (2026_03_01). A dataset of a single time instant has no granularity; gran then takes the full start time, as time does.
  • time takes the full start time: 2026_03_01T00_00_00.
  • num numbers the selected maps from 1 in the order of their start time and map id, with five digits (00001); the number counts also the maps that come out empty. num%03 gives three digits (001).
  • With relative time, a start time is a number without a calendar date. Every suffix then gives the number, as num does.

Two layers of one vector map, registered as name:1 and name:2 for the same time, get the same name from the suffix. The layer is then appended to both names: bx_2026_03_01_1 and bx_2026_03_01_2. Two different maps of one time with the same layer also get the same name. The first of them, in the order of start time and map id, keeps the name; the second and every further map get the number _2, _3 and so on after it. A number that another new map has as its name is skipped.

A new map without any feature is empty, for example when no feature meets the expression. By default it is not registered in the new dataset and the map is removed after the run. The flag -n registers the empty maps and keeps them. An expression therefore selects maps by their contents as well.

The option nprocs sets the number of v.extract processes that run at the same time. The default is 1. The parser advises to use more than one only with a database backend that supports concurrent writing; the default backend is SQLite.

NOTES

If where selects no map, or the input dataset has none, t.vect.extract warns "Nothing found in the database for space time dataset" and makes no output dataset; for a where that selects nothing, the message adds that "Dataset is empty or where clause is too constrained or incorrect". A condition with a syntax error stops with the error "Invalid where condition".

The tool stops with an error if expression is given without basename ("You need to specify the base name of new created maps"), if the input dataset does not exist, if the output dataset exists and --overwrite is not given, and if suffix is not gran, time, num or num%NN ("Invalid suffix"). A dot in the name of the output dataset is refused: "a dot is not allowed". An expression that v.extract does not accept stops with "Error in computation process"; the maps that the run has made are removed. If a new map is already in the temporal database and --overwrite is not given, the tool stops before it extracts anything, with "Map ... is already in temporal database, use overwrite flag to overwrite", and makes no dataset.

The last example shows that a dataset of another mapset works as input when an expression is given. Without an expression, such a dataset is refused, and the empty output dataset that the refusal leaves behind has to be removed with t.remove. Add an expression that every feature meets, such as level > 0 there, to copy the maps instead.

Select maps by time

The dataset gauges has four point maps of wind speed for the days from 1 to 4 March 2026. Map gauges_k has three points at (k, 1), (k, 2) and (k, 3) with the speeds 10 * k + 1, 10 * k + 2 and 10 * k + 3, so the speeds are 11 to 13, 21 to 23, 31 to 33 and 41 to 43.

The first block extracts the maps from 3 March on into the dataset later. There is no expression, so no map is made: the second block lists the vector maps of the mapset, and they are still the four maps of gauges. The dataset later lists two of them, with three points each. The third block shows what the new dataset takes from the input: the temporal type and the semantic type, the start and end time and the number of maps and points that follow from the maps it holds.

Choose the layer

The dataset plots has two maps for 1 and 2 March 2026. Each has two points with the categories 1 and 2 in layer 1 and in layer 2. The table of layer 1 has the column count with the values 1 and 2, the table of layer 2 the values 101 and 102. The maps are registered without a layer.

The first block runs the condition count > 100 with the default layer 1, which finds nothing; the flag -n keeps the empty maps, so that the result can be listed. The second block sets layer to 2: each new map has the two points whose count is above 100.

The third block registers the two layers of plots_1 as plots_1:1 and plots_1:2 in the dataset both, both for 1 March. Each registered map reads the layer it is registered with, so the condition count > 0 is met by the points of both layers. The two new maps would get the same name from the time; the layer is appended to tell them apart. The mapset has the two maps bx_2026_03_01_1 and bx_2026_03_01_2.

Extract from a dataset with relative time

The dataset model has two maps of six hours each, from 0 to 6 and from 6 to 12 hours. Map run_1 has two points with the levels 1 and 3, map run_2 the levels 2 and 4. In a dataset with relative time a start time is a number, so the names of the new maps carry the number of the map instead of a date. The first block keeps the levels above 3. The number counts all selected maps, also the empty one: the first map has no such point and is left out, so the remaining map is m_00002. The new dataset has the times and the unit of the input. The second block takes time as the suffix; with relative time it gives the number as well.

    columns="x double precision, y double precision, level double precision" <<EOF

Extract from a dataset of another mapset

The dataset model stays in the mapset PERMANENT. The first block creates the mapset other, switches to it and extracts with an expression. The new dataset model_copy and its maps copy_00001 and copy_00002 belong to other. The id column shows the mapset.

The second block shows what happens without an expression. The call is refused, so the block prints refused. The refusal leaves the empty dataset model_copy_empty behind. number_of_maps=None shows that it has no maps, and t.remove removes it.

Command line:

g.mapset -c mapset=other
t.vect.extract input=model@PERMANENT output=model_copy basename=copy \
    expression="level > 0" suffix=num
t.vect.list input=model_copy columns=id,start_time,points

t.info -g type=stvds input=model_copy_empty | grep -E "^(id|number_of_maps)="
