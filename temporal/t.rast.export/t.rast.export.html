DESCRIPTION

t.rast.export writes the maps of a space time raster dataset and a description of their times into one tar archive. The archive moves a dataset to another project or computer: t.rast.import reads it back and registers the maps in a new dataset. See the introduction to temporal data processing for space time datasets. The tool for space time vector datasets is t.vect.export.

The option input names the space time raster dataset, and output the archive that is written. The tool uses the name of output as it is and adds no suffix, so the name should say what the archive is, such as temperature.tar.bz2. An existing archive is refused unless the flag --overwrite is given.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2026-03-03', and exports only the maps it selects. Without where, all maps are exported. The maps are written in the order of their start time; the order of maps with the same start time is not defined. A selection without a map is not an error (see the notes).

Export format

The option format chooses how each raster map is stored in the archive:
  • GTiff, the default, writes a GeoTIFF file name.tif with r.out.gdal and the color table of the map as the rules file name.color with r.colors.out;
  • AAIGrid writes an Arc/Info ASCII Grid file name.asc with r.out.gdal and the rules file name.color;
  • pack writes the file name.pack with r.pack, the GRASS format that r.unpack reads. There is no .color file. The .pack file is a tar archive of its own that is not compressed again.

The GeoTIFF and ASCII grid files cover the current computational region, as r.out.gdal does, and a pack file holds the whole map (see the last example for the region).

Options of GeoTIFF and ASCII grid files

The following options are passed on to r.out.gdal. They are skipped with a warning for the pack format, which has no use for them.
  • type sets the data type of the files: Byte, Int16, UInt16, Int32, UInt32, Float32, Float64, CInt16, CInt32, CFloat32 or CFloat64. It is used for GTiff only and skipped with a warning for AAIGrid and pack. Without type, a map of floating point cells gets the type that r.out.gdal chooses; for a map of integer cells the tool chooses the type (see nodata).
  • nodata sets the value that marks the cells without data in the files. Without nodata, a GeoTIFF file of an integer map without type gets the value maximum + 1 of the map, and the smallest of the types Byte, UInt16, UInt32 and Int32 that holds the values of the map and this value: a map of the values up to 350 and NULL becomes a UInt16 file with the nodata value 351. For a map of integer cells with nodata and without type, the tool takes the smallest of the types Byte, UInt16, Int16, UInt32 and Int32 that holds the values of the map and the nodata value: a map of the same values with nodata=-77 becomes an Int16 file. nodata also applies to AAIGrid: it is the value of the cells without data in the header and in the rows of the file.
  • createopt passes creation options to the GDAL driver, written as NAME=VALUE and separated by commas, such as COMPRESS=DEFLATE for GeoTIFF. AAIGrid takes createopt without a warning.
  • metaopt writes metadata to the files, written as TAG=VALUE and separated by commas. It works for GTiff only: r.out.gdal writes the metadata of an ASCII grid into a side file that the archive does not hold, so t.rast.export skips metaopt with a warning for AAIGrid and pack.

Archive and compression

The option compression compresses the archive: bzip2 (the default), gzip, or no for a plain tar archive. A tool such as tar -tf or the Python module tarfile recognises the compression by itself.

The option directory names the working directory, by default the current directory. t.rast.export exports the maps into a temporary subdirectory of it, packs them there, moves the archive to the path given by output and removes the subdirectory. The archive is therefore not written to directory, and a relative output is taken from the current directory.

Files in the archive

The archive holds the files of the maps, in the order of their start time, and then five text files:
  • list.txt has one line for each map, with the fields name, start time, end time and a fourth field that is None for a map without a semantic label, separated by |. Start and end time are in ISO format with absolute time and numbers with relative time;
  • proj.txt is the output of g.proj with -p format=proj4, the coordinate reference system of the project;
  • init.txt has one key=value line for each of the following: stds_type, format, temporal_type, semantic_type, relative_time_unit (relative time only), number_of_maps and the extent north, south, east, west. number_of_maps counts the exported maps, and the extent is that of the exported maps, not of the region;
  • readme.txt describes the files of the archive;
  • metadata.txt is the output of t.info for the dataset.

NOTES

The export reads the maps from the mapsets they were registered from, also if a map of the same name exists in the current mapset. The maps of a dataset may come from several mapsets. If maps of one name from different mapsets are exported together, each of them is named name@mapset in the archive, in list.txt and in its file names, for example dup@other.tif and dup@other.color. A map whose name no other mapset of the selection shares keeps its name, so an archive without such maps has the form of older versions. t.rast.import imports dup@other as dup_other.

With relative time, list.txt holds the numbers of the start and end, and init.txt the unit as relative_time_unit.

A where condition that selects no map gives the warning "The selection contains no map" and an archive without maps, with number_of_maps=0 in init.txt. A condition with a syntax error stops the tool with an error that starts with "Invalid where condition".

The tool checks the directories before it makes anything. It stops with "Directory ... not found" or "... is not writable" for directory, and with "Output directory ... not found" for the directory of output; both must exist and be writable. A map that can no longer be exported, for example because it was removed, stops the tool with "Unable to export raster map name@mapset"; no archive is left, and the temporary subdirectory is removed in every case.

For a map of integer cells, a nodata value that no integer type holds, such as nan, leaves the choice of the type to r.out.gdal, which refuses it for the type it picks; the tool then stops with "Unable to export raster map".

A dataset of another mapset (input=name@mapset) is exported like one of the current mapset; the tool reads its maps from their own mapset.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast_export and sets the computational region to North Carolina with cells of 1 km, then narrows it to a part of the coast near Wilmington; the later examples work in this mapset and region.

Export a dataset as a GeoTIFF archive

The dataset precipitation_monthly has twelve maps of the monthly precipitation sum in 2020, in whole millimeters. Each map is an interval of one month. The maps are generated, not measured: v.surf.idw interpolates the monthly means of the 136 climate stations in precip_30ynormals (columns jan to dec), and an assumed factor between 0.8 and 1.7 for each month turns them into the sums of a wet year. Cells outside North Carolina are NULL.

The first block creates the dataset and then narrows the region to eight by four cells on the coast near Wilmington. GeoTIFF and ASCII grid files cover the current region, so the archives stay small. The second block exports the dataset with the default format and compression: a GeoTIFF file and a color rules file for each of the twelve maps, packed into a bzip2 compressed archive. tar -tf lists 29 entries, of which the block shows the first four and the last five. The maps come first in the order of their start time, then the five text files. The third block shows the first three lines of list.txt and all of init.txt. The extent in init.txt is that of the maps, North Carolina, not that of the narrowed region.

Choose the compression

The loop exports the maps of the first quarter three times into the archive all.tar, which --overwrite replaces each time. It prints the compression, what the first two bytes of the file say about it and the number of files in the archive. A gzip file starts with the bytes 1f8b and a bzip2 file with 425a (the letters BZ); a plain tar archive has neither. All three hold the same 11 files, the two files of three maps and the five text files, and tar reads them without being told the compression.

Command line:

for compression in no gzip bzip2; do
    t.rast.export input=precipitation_monthly output=all.tar \
        compression=$compression where="start_time < '2020-04-01'" --overwrite
    magic=$(od -An -tx1 -N2 all.tar | tr -d ' ')
    case $magic in
        1f8b) kind=gzip ;;
        425a) kind=bzip2 ;;
        *) kind="plain tar" ;;
    esac
    echo "$compression: $kind, $(tar -tf all.tar | wc -l) files"
done

no: plain tar, 11 files
gzip: gzip, 11 files
bzip2: bzip2, 11 files

Set the data type and the nodata value

The three blocks export the map of November, whose cells hold up to 350 mm over the whole of North Carolina and are NULL over the sea. Each block reads the output of gdalinfo -json for the GeoTIFF file and prints its data type and nodata value. The first block exports without options. The map has integer cells, so the tool takes the largest value of the whole map plus one as the nodata value, 351, and UInt16 as the smallest type that holds 350 and 351; a Byte holds only up to 255. The 8 by 4 cells of the region hold at most 132 mm, but the maximum of the whole map counts.

The second block adds nodata=-77. Neither Byte nor UInt16 can hold -77, so the tool takes Int16. The third block sets the type itself and passes a creation option and a metadata tag to the GeoTIFF driver: the file is compressed with DEFLATE and carries the tag TAG=hello; this block also prints the compression and the tag.

t.rast.export input=precipitation_monthly output=november_default.tar \

def gdal_info(archive, member):
    with tarfile.open(archive) as tar:

    result = subprocess.run(
