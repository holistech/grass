DESCRIPTION

t.rast3d.extract selects maps of a space time 3D raster dataset and registers them in a new space time 3D raster dataset. On the way, it can compute a new 3D raster map from each selected map with an r3.mapcalc expression. Use it to cut a time window out of a dataset, to drop the maps whose values do not matter, or to derive a dataset by map algebra when the same expression applies to every map. See the introduction to temporal data processing for space time datasets. t.rast3d.mapcalc computes from more than one dataset, and t.rast3d.list lists the maps of the result. The tool works like t.rast.extract, on space time 3D raster datasets (STR3DS) and 3D raster maps instead of space time raster datasets and raster maps.

The option input names the space time 3D raster dataset, the option output the new one. The new dataset takes the temporal type and the semantic type of the input dataset. The output always belongs to the current mapset. An existing output dataset is refused unless the flag --overwrite is given; then it is replaced.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2020-06-01', which selects the maps that start on 1 June 2020 or later. Without where, all maps are selected.

Register or compute

Without expression, t.rast3d.extract creates no map. It registers the selected maps themselves in the new dataset, so a map is then part of two datasets and the data are not duplicated.

With expression, the tool runs r3.mapcalc once for each selected map and registers the new maps, with the start and end time of the map they come from, in the new dataset. The expression is the right side of an r3.mapcalc expression, without the map = of a full one. The name of the input dataset stands for the selected map of each step, so 2 * temperature_profile doubles the map of every step of the dataset temperature_profile. Any other 3D raster map can be used in the expression by name. The new maps belong to the current mapset. The expression needs the option basename.

The new maps are named after basename, followed by an underscore and a suffix that the option suffix chooses.

  • gran (the default) takes the start time of the map, cut to the unit of the granularity of the input dataset: year and month for a granularity of three months, year, month and day for a granularity of one day (2026_03_01). A monthly series from the last day of a month (January 31, February 28) has the granularity of one month and gets year and month (2026_01). A dataset of a single time instant has no granularity; gran then takes the full start time, as time does.
  • time takes the full start time: 2026_03_01T00_00_00.
  • num numbers the selected maps from 1 in the order of their start time and map id, with five digits (00001); the number counts also the maps that come out empty. num%03 gives three digits (001).
  • With relative time, a start time is a number without a calendar date. Every suffix then gives the number, as num does.

Two different maps of one time, such as two maps of January 2001, get the same name from the suffix. The first of them, in the order of start time and map id, keeps the name; the second and every further map get the number _2, _3 and so on after it. A number that another new map has as its name is skipped.

A new map that has no valid cell, that is, no minimum and no maximum, is empty. By default it is not registered in the new dataset and the map is removed after the run. The flag -n registers the empty maps and keeps them. An expression such as if(temperature_profile > 20, temperature_profile, null()) therefore selects maps by their values as well.

The option nprocs sets the number of r3.mapcalc processes that run at the same time. The default is 1. The result does not depend on it.

NOTES

If where selects no map, or the input dataset has none, t.rast3d.extract warns "Nothing found in the database for space time dataset" and makes no output dataset; for a where that selects nothing, the message adds that "Dataset is empty or where clause is too constrained or incorrect". A condition with a syntax error stops with the error "Invalid where condition".

The tool stops with an error if expression is given without basename ("You need to specify the base name of new created maps"), if the input dataset does not exist, if the output dataset exists and --overwrite is not given, and if suffix is not gran, time, num or num%NN ("Invalid suffix"). A dot in the name of the output dataset is refused: "a dot is not allowed". An expression that r3.mapcalc does not accept stops with "Error in computation process". If a new map is already in the temporal database and --overwrite is not given, the tool stops before it computes anything, with "Map ... is already in temporal database, use overwrite flag to overwrite", and makes no dataset.

The last example shows that a dataset of another mapset works as input when an expression is given. Without an expression, such a dataset is refused, and the empty output dataset that the refusal leaves behind has to be removed with t.remove. Add an expression such as the name of the input dataset to copy the maps instead.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_rast3d_extract and sets the computational region to North Carolina with cells of 1 km, in the plane and in the vertical (the option res3), and three layers of 1000 m from 0 to 3000 m; the later examples work in this mapset and region, except the last, which creates a second mapset with the same region. The examples about names, relative time and other mapsets use 3D maps with small constant values, so that the results can be checked by hand.

Select maps by time

The dataset temperature_profile has twelve 3D raster maps of the monthly mean air temperature in 2020, in degrees Celsius rounded to tenths. They are generated from the height z() of the cell: 16.5 degrees at sea level and the northing 160 km, an annual cycle of plus and minus 10.5 degrees with its maximum in July, 6.5 degrees less for every 1000 m of height, and 1 degree more for every 100 km to the south. Each map is an interval of one month.

The first block creates the maps and the dataset. The second block extracts the summer months, June to August, into the dataset summer. There is no expression, so no map is made: the third block lists the 3D raster maps of the mapset, and they are still the twelve maps of temperature_profile. The dataset summer lists three of them. The fourth block shows what the new dataset takes from the input: the temporal type and the semantic type, and the start and end time that follow from the maps it holds.

Command line:

g.mapset -c mapset=t_rast3d_extract
g.region raster=elev_state_500m res=1000 res3=1000 t=3000 b=0 tbres=1000 -a
for month in $(seq 12); do
    echo "temperature_profile_2020_$(printf %02d $month) = round((16.5" \
        "+ 10.5 * cos(30 * ($month - 7.2)) - 0.0065 * z()" \
        "- 0.00001 * (y() - 160000)) * 10) / 10.0"
done | r3.mapcalc file=-
t.create type=str3ds output=temperature_profile title="Air temperature" \
    description="Monthly mean air temperature 2020 in degree Celsius, 0 to 3000 m"
t.register -i type=raster_3d input=temperature_profile \
    maps=$(g.list type=raster_3d pattern="temperature_profile_*" mapset=. separator=comma) \
    start=2020-01-01 increment="1 month"

t.rast3d.extract input=temperature_profile output=summer \
    where="start_time >= '2020-06-01' and start_time < '2020-09-01'"
t.rast3d.list input=summer

Compute new maps from the selected maps

The first block converts the maps of the first quarter to degrees Fahrenheit. The expression names the dataset, which stands for the map of each step. The new maps are named fahrenheit, an underscore and the month of the map (the granularity of temperature_profile is one month), and each has the time of its source map. The result is rounded to tenths, so that the values are the same on every system. nprocs lets two r3.mapcalc processes run at the same time; the result is the same as with one process.

The second block shows that the expression may use any 3D raster map. The map correction is 1.5 everywhere, as a correction of a sensor that reads 1.5 degrees too low; where selects the first two months, and the new maps hold the values of their source maps plus 1.5.

Command line:

t.rast3d.extract input=temperature_profile output=fahrenheit \
    basename=fahrenheit where="start_time < '2020-04-01'" \
    expression="round((temperature_profile * 1.8 + 32) * 10) / 10.0" nprocs=2
t.rast3d.list input=fahrenheit columns=name,start_time,min,max

Select maps by their values

Name the new maps

The option suffix chooses the end of the names. Each of the first three blocks copies the maps of the first quarter of temperature_profile with the expression temperature_profile and lists the names: time gives the full start time, num a number of five digits and num%03 a number of three digits.

Extract from a dataset with relative time

Extract from a dataset of another mapset

The dataset model stays in the mapset t_rast3d_extract. The first block creates the mapset t_rast3d_extract_2, sets the same region, and extracts with an expression from model@t_rast3d_extract, which the name with its mapset selects. The name model in the expression stands for the maps of the dataset, though it has no mapset, and the output dataset model_copy and its maps copy_00001 and copy_00002 belong to t_rast3d_extract_2. The id column shows the mapset.

The second block shows what happens without an expression. The call is refused, so the block prints refused. The refusal leaves the empty dataset model_copy_empty behind. number_of_maps=None shows that it has no maps, and t.remove removes it.

Command line:

g.mapset -c mapset=t_rast3d_extract_2
g.region raster=elev_state_500m res=1000 res3=1000 t=3000 b=0 tbres=1000 -a
t.rast3d.extract input=model@t_rast3d_extract output=model_copy \
    basename=copy expression="model" suffix=num
t.rast3d.list input=model_copy columns=id,start_time,min

id|start_time|min
copy_00001@t_rast3d_extract_2|0|1.0
copy_00002@t_rast3d_extract_2|6|2.0
