DESCRIPTION

t.rast3d.extract selects maps of a space time 3D raster dataset and registers them in a new space time 3D raster dataset. On the way, it can compute a new 3D raster map from each selected map with an r3.mapcalc expression. Use it to cut a time window out of a dataset, to drop the maps whose values do not matter, or to derive a dataset by map algebra when the same expression applies to every map. See the introduction to temporal data processing for space time datasets. t.rast3d.mapcalc computes from more than one dataset, and t.rast3d.list lists the maps of the result. The tool works like t.rast.extract, on space time 3D raster datasets (STR3DS) and 3D raster maps instead of space time raster datasets and raster maps.

The option input names the space time 3D raster dataset, the option output the new one. The new dataset takes the temporal type and the semantic type of the input dataset. The output always belongs to the current mapset. An existing output dataset is refused unless the flag --overwrite is given; then it is replaced.

Select the maps

The option where takes an SQL condition on the columns of the registered maps, such as start_time >= '2026-03-03', which selects the maps that start on 3 March or later. Without where, all maps are selected.

Register or compute

Without expression, t.rast3d.extract creates no map. It registers the selected maps themselves in the new dataset, so a map is then part of two datasets and the data are not duplicated.

With expression, the tool runs r3.mapcalc once for each selected map and registers the new maps, with the start and end time of the map they come from, in the new dataset. The expression is the right side of an r3.mapcalc expression, without the map = of a full one. The name of the input dataset stands for the selected map of each step, so 2 * soil doubles the map of every step of the dataset soil. Any other 3D raster map can be used in the expression by name. The new maps belong to the current mapset. The expression needs the option basename.

The new maps are named after basename, followed by an underscore and a suffix that the option suffix chooses.

  • gran (the default) takes the start time of the map, cut to the unit of the granularity of the input dataset: year and month for a granularity of three months, year, month and day for a granularity of one day (2026_03_01). A dataset of a single time instant has no granularity; gran then takes the full start time, as time does.
  • time takes the full start time: 2026_03_01T00_00_00.
  • num numbers the selected maps from 1 in the order of their start time and map id, with five digits (00001); the number counts also the maps that come out empty. num%03 gives three digits (001).
  • With relative time, a start time is a number without a calendar date. Every suffix then gives the number, as num does.
Two different maps of one time, such as two maps of January 2001, get the same name from the suffix. The first of them, in the order of start time and map id, keeps the name; the second and every further map get the number _2, _3 and so on after it. A number that another new map has as its name is skipped.

A new map that has no valid cell, that is, no minimum and no maximum, is empty. By default it is not registered in the new dataset and the map is removed after the run. The flag -n registers the empty maps and keeps them. An expression such as if(soil > 6, soil, null()) therefore selects maps by their values as well.

The option nprocs sets the number of r3.mapcalc processes that run at the same time. The default is 1. The result does not depend on it.

NOTES

If where selects no map, or the input dataset has none, t.rast3d.extract warns "Nothing found in the database for space time dataset" and makes no output dataset; for a where that selects nothing, the message adds that "Dataset is empty or where clause is too constrained or incorrect". A condition with a syntax error stops with the error "Invalid where condition".

The tool stops with an error if expression is given without basename ("You need to specify the base name of new created maps"), if the input dataset does not exist, if the output dataset exists and --overwrite is not given, and if suffix is not gran, time, num or num%NN ("Invalid suffix"). A dot in the name of the output dataset is refused: "a dot is not allowed". An expression that r3.mapcalc does not accept stops with "Error in computation process". If a new map is already in the temporal database and --overwrite is not given, the tool stops before it computes anything, with "Map ... is already in temporal database, use overwrite flag to overwrite", and makes no dataset.

The last example shows that a dataset of another mapset works as input when an expression is given. Without an expression, such a dataset is refused, and the empty output dataset that the refusal leaves behind has to be removed with t.remove. Add an expression such as the name of the input dataset to copy the maps instead.

EXAMPLES

Select maps by time

The dataset soil has four 3D raster maps of daily mean soil temperature for the days from 1 to 4 March 2026. The region has two rows, two columns and three layers. The values of a map are the layer number plus the offset 0, 6, 3 and 9, so the smallest and largest values of the maps are 1 to 3, 7 to 9, 4 to 6 and 10 to 12.

The first block extracts the maps from 3 March on into the dataset later. There is no expression, so no map is made: the second block lists the 3D raster maps of the mapset, and they are still the four maps of soil. The dataset later lists two of them. The third block shows what the new dataset takes from the input: the temporal type and the semantic type, and the start and end time that follow from the maps it holds.

Command line:

g.region n=2 s=0 e=2 w=0 t=3 b=0 res=1 res3=1 tbres=1
r3.mapcalc expression="soil_1 = depth()"
r3.mapcalc expression="soil_2 = depth() + 6"
r3.mapcalc expression="soil_3 = depth() + 3"
r3.mapcalc expression="soil_4 = depth() + 9"
t.create type=str3ds output=soil title="Soil temperature" \
    description="Daily mean soil temperature"
t.register -i type=raster_3d input=soil \
    maps=soil_1,soil_2,soil_3,soil_4 start=2026-03-01 increment="1 day"
t.rast3d.extract input=soil output=later \
    where="start_time >= '2026-03-03'"
t.rast3d.list input=later

Compute new maps from the selected maps

The first block doubles the maps of soil. The expression 2 * soil names the dataset, which stands for the map of each step. The new maps are named doubled, an underscore and the day of the map (the granularity of soil is one day), and each has the time of its source map. nprocs lets two r3.mapcalc processes run at the same time; the result is the same as with one process. The values are twice those of the source maps: 2 to 6 for the first day, 14 to 18 for the second.

The second block shows that the expression may use any 3D raster map. The map bias is 10 everywhere; where selects the first two days, and the new maps hold the values of their source maps plus 10.

Command line:

t.rast3d.extract input=soil output=doubled basename=doubled \
    expression="2 * soil" nprocs=2
t.rast3d.list input=doubled columns=name,start_time,min,max

name|start_time|min|max
doubled_2026_03_01|2026-03-01 00:00:00|2.0|6.0
doubled_2026_03_02|2026-03-02 00:00:00|14.0|18.0
doubled_2026_03_03|2026-03-03 00:00:00|8.0|12.0
doubled_2026_03_04|2026-03-04 00:00:00|20.0|24.0

r3.mapcalc expression="bias = 10"
t.rast3d.extract input=soil output=biased basename=biased \

Select maps by their values

An expression that sets cells to null selects maps. The first block takes the maps from 2 March on, three maps, and keeps the values above 6. Of the three, only the maps with values from 7 to 9 and from 10 to 12 keep cells; the map with the values 4 to 6 has none left, so it is empty. The empty map is not registered in warm, and the second block shows that it is removed: only two maps are left in the mapset.

The third block runs the same call with the flag -n. The dataset warm_all registers the empty map as well, with None as its smallest and largest value, and the mapset keeps all three maps.

t.rast3d.extract input=soil output=warm basename=warm \

Extract from a dataset with relative time

The dataset model has two maps of six hours each, from 0 to 6 and from 6 to 12 hours, with the values 1 and 2. In a dataset with relative time a start time is a number, so the names of the new maps carry the number of the map instead of a date. The first block keeps the values above 1. The number counts all selected maps, also the empty one: the first map is empty and left out, so the remaining map is m_00002. The new dataset has the times and the unit of the input. The second block takes time as the suffix; with relative time it gives the number as well.

Command line:

r3.mapcalc expression="step_1 = 1"
r3.mapcalc expression="step_2 = 2"
t.create type=str3ds output=model temporaltype=relative title="Model" \
    description="Model output per step"
t.register -i type=raster_3d input=model maps=step_1,step_2 start=0 \
    increment=6 unit=hours
t.rast3d.extract input=model output=model_high basename=m \
    expression="if(model > 1, model, null())"
t.rast3d.list input=model_high columns=name,start_time,end_time,min
t.info -g type=str3ds input=model_high | grep -E "^(temporal_type|unit)="

Extract from a dataset of another mapset

The dataset model stays in the mapset PERMANENT. The first block creates the mapset other, switches to it and extracts with an expression. The name model in the expression stands for the maps of the dataset, though it has no mapset, and the output dataset model_copy and its maps copy_00001 and copy_00002 belong to other. The id column shows the mapset.

The second block shows what happens without an expression. The call is refused, so the block prints refused. The refusal leaves the empty dataset model_copy_empty behind. number_of_maps=None shows that it has no maps, and t.remove removes it.

Command line:

g.mapset -c mapset=other
t.rast3d.extract input=model@PERMANENT output=model_copy basename=copy \
    expression="model" suffix=num
t.rast3d.list input=model_copy columns=id,start_time,min

id|start_time|min
copy_00001@other|0|1.0
copy_00002@other|6|2.0

if t.rast3d.extract input=model@PERMANENT output=model_copy_empty \
    2>/dev/null; then echo extracted; else echo refused; fi
t.info -g type=str3ds input=model_copy_empty | grep -E "^(id|number_of_maps)="
t.remove -f type=str3ds inputs=model_copy_empty

id=model_copy_empty@other
