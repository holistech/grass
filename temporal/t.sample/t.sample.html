DESCRIPTION

t.sample shows how the maps of one or more space time datasets lie in time to the maps of another space time dataset, the sampler. It reads the temporal topology of the datasets and prints one row for each map of the sampler and for each gap between two maps of the sampler. A row lists the maps of every input dataset that stand in the chosen temporal relations to that sampler map. The types of the datasets can differ: a vector dataset can be sampled by a raster dataset, and a raster dataset by a 3D raster dataset. See the introduction to temporal data processing for an overview, t.topology for the temporal topology of one dataset and t.rast.list for the method deltagaps, which lists the gaps of a dataset in the same way.

Datasets

The option inputs names the datasets to be sampled, separated by commas, and is required. The option sample names the sampler and is required. All inputs are of the type given by intype, the sampler is of the type given by samtype: strds (the default of both), str3ds or stvds. A name without @mapset means the current mapset. The temporal type, absolute or relative, must be the same for the sampler and for each input, and the maps of the sampler must be intervals. If they are not, the dataset is not sampled, see the NOTES.

The sampler divides the time into granules: each of its maps is a granule, and a hole between two maps is a granule of its own, a gap. Two maps that touch, where the end of one is the start of the next, leave no gap. A granule includes its start and excludes its end. The sampler should have a valid topology: the tool does not check it, and if sampler maps start at the same time, the rows follow the order of their start and end times.

Relations

The option method selects the temporal relations between a granule and the maps of an input. The default is during,overlap,contain,equal. It takes the following values:
  • during: the map is longer than the granule and the granule lies inside it; the two may share the start or the end
  • overlap: the map reaches over one border of the granule
  • contain: the map lies inside the granule, also a time instance; a map that shares the start or the end of the granule counts as well
  • equal: the map has the start and the end of the granule
  • start: the maps of contain, the maps that begin before the granule and end inside it or at its end, and the maps longer than the granule that begin with it; the maps equal to the granule are never listed
  • follows: the map ends where the granule starts
  • precedes: the map starts where the granule ends, also a time instance

Other values are rejected by the parser, among them the inverse relations overlaps and overlapped. Several values are separated by commas. The maps of a cell are listed relation by relation: first those of during, equal, follows and precedes, in the order in which the list names them, then those of the groups start, overlap and contain in this order, whatever the order of the list. A map that stands in two selected relations is listed once. The maps of one of the plain relations follow their start times, and maps that start together follow their ids. A group is made of several relations, which follow one another, so a map need not be listed by its start time: in the call with start of the third example, wide_s stands before wide_e, although it starts later.

Output

t.sample prints a table to standard output. The columns are separated by the character of the option separator, which is the pipe | by default; the names space and tab are accepted as well. A comma cannot be used, as it separates the map ids inside a cell: with a comma the columns are separated by |, a pipe with a space on each side. The flag -c prints the names of the columns as first row, with the ids of the datasets for the first columns. The columns are:
  • the sampler map of the granule, as name@mapset; a gap has no map, and the cell shows None
  • one column for each input dataset, in the order of inputs: the ids of the maps related to the granule, separated by commas, or None if there are none; a map of a vector dataset registered with a layer shows as name:layer@mapset
  • start_time and end_time: the start and the end of the granule; relative time is printed as the stored numbers, without a unit
  • interval_length: the length of the granule, end_time minus start_time; absolute time gives days, as a fraction if the granule is shorter than a day (0.25 for six hours), relative time gives a number of the unit of the datasets
  • distance_from_begin: the distance of the start of the granule from the start of the first granule, in the same unit as interval_length

The flag -s adds a spatial check: a map stays in a cell only if its spatial extent touches the extent of the granule, where a shared edge or corner counts. For 3D datasets only the north-south and east-west extent is compared, not bottom and top. A gap has no extent of its own and is given the extent (0, 0, 0, 0): with -s it relates only to maps whose extent touches the origin. Without -s the spatial extent plays no role.

NOTES

The tool checks every dataset before it prints anything. A dataset that is not found, an unknown name or a name of another type than intype or samtype, ends the tool with the error Dataset <name@mapset> not found in temporal database and return code 1; the name in the message always has the mapset.

The two other refusals print an error and no failure code. If the sampler has time instances instead of intervals, the tool prints The temporal map type of the sample dataset must be interval, nothing else, and returns 0. If an input has another temporal type than the sampler, absolute or relative, the tool prints The space time datasets must be of the same temporal type, leaves that input out of the rows and samples the others. With -c the header still names the left-out input, so the header has one column more than the rows.

Maps outside the time of the sampler get no row of their own. With the default method a map before the first granule, or starting at or after the end of the last one, appears in no cell.

EXAMPLES

The examples run in the North Carolina sample dataset nc_spm_08_grass7 from the GRASS sample data. The first example creates the mapset t_sample and sets the computational region to North Carolina with cells of 1 km; the later examples work in this mapset and region. Most examples are about time, not about maps: their maps hold small constant values, and the dates are the point. The last two examples sample series of maps over North Carolina and use the extents of the maps.

Sample time instances with intervals

Six maps are time instances on June 1 to 6, 2026. The sampler periods has three intervals: June 1 to 3, June 5 to 7 and June 7 to 9. With the flag -c the first row names the columns. The first period holds the readings of June 1 and 2. The reading of June 3 is not in it, as the end of a granule is excluded: it belongs to the gap from June 3 to 5, a row without a sampler map, with the reading of June 4. The second period holds the readings of June 5 and 6. The third period starts where the second one ends, so there is no gap row between them, and it holds no reading: its cell shows None. The length of each granule is 2.0 days, and the distance from the start of the first granule grows by 2.0 days from row to row.

Choose the temporal relations of intervals

A granule from June 10 to June 20, in the dataset windows_june, is sampled with the dataset shapes. The maps wide, wide_s and wide_e are longer than the granule, wide_s shares its start and wide_e its end, early and late reach over its start and its end, inside lies in it, same has its start and end and before ends long before it. The first call uses the default method: the plain values during and equal come first, then the groups overlap and contain, so the maps come in the order wide, wide_e, wide_s, same, early, late, inside; the maps of during follow their start times. The other calls select one relation each. before is related by none of them. start lists early, which begins before the granule and ends inside it, wide_e, which begins before it and ends with it, wide_s, which is longer and begins with it, and inside. It does not list wide, late and same: the value start never lists a map equal to the granule. The last call names overlap before start, yet the maps of start come first and late, which only overlap selects, comes last.

Maps next to the granule

The relations follows and precedes select the neighbours of a granule in time. The dataset spans from the previous example has maps June 1 to 3, June 3 to 5 and June 5 to 7, and the sampler is periods again. With follows a cell lists the span that ends where the granule starts: span_1 ends on June 3 where the gap starts, span_2 where period_2 starts and span_3 where period_3 starts. Daily precipitation in the months of a temperature series

A common use of the tool is to find out which maps of a fine series fall into each granule of a coarse one. The sampler temperature_monthly has the monthly mean air temperature of June, July and August 2020 in degree Celsius, one map for each month. The input precipitation_daily has five daily precipitation sums in mm, from July 30 to August 3, 2020. The table has one row for each month. June has no daily map and shows None; July lists its two days and August its three, so the series is split at the month boundary. Both series are generated: the temperature falls with the height from elev_state_500m, and the precipitation is the height factor 1 + elev_state_500m / 1000 times a fixed amount for each day (8, 0, 14, 21 and 3 mm at sea level), not a measurement. The last two columns give the length of each month in days and the distance of its start from June 1.

Command line:

for month in 6 7 8; do
    echo "temperature_monthly_2020_$(printf %02d $month) = round((16.5" \
        "+ 10.5 * cos(30 * ($month - 7.2)) - 0.0065 * elev_state_500m" \
        "- 0.00001 * (y() - 160000)) * 10) / 10.0"
done | r.mapcalc file=-
t.create output=temperature_monthly title="Air temperature" \
    description="Monthly mean air temperature June to August 2020 in degree Celsius"
t.register -i input=temperature_monthly \
    maps=temperature_monthly_2020_06,temperature_monthly_2020_07,temperature_monthly_2020_08 \
    start=2020-06-01 increment="1 month"
for entry in 07_30:8 07_31:0 08_01:14 08_02:21 08_03:3; do
    r.mapcalc expression="precipitation_daily_2020_${entry%:*} = round(${entry#*:} * (1 + elev_state_500m / 1000.0))"
done
t.create output=precipitation_daily title="Precipitation" \
    description="Daily precipitation sum July 30 to August 3, 2020 in mm"
t.register -i input=precipitation_daily \
    maps=precipitation_daily_2020_07_30,precipitation_daily_2020_07_31,precipitation_daily_2020_08_01,precipitation_daily_2020_08_02,precipitation_daily_2020_08_03 \
    start=2020-07-30 increment="1 day"
t.sample -c inputs=precipitation_daily sample=temperature_monthly

Keep only maps that touch the granule in space

The flag -s drops maps whose spatial extent is apart from the extent of the granule. The sampler plots has one granule of eight days with the map plot, which covers a square of 4 km by 4 km, from 200000 to 204000 in both directions (meters). The scenes are time instances inside this granule: scene_1 covers the area from 199000 to 205000, scene_2 lies inside it, from 201000 to 203000, scene_3 from 204000 to 206000 touches the granule in the corner (204000, 204000) and scene_4 from 210000 to 212000 is far away. Without -s the cell lists all four scenes. With -s the scene scene_4 is dropped and the scene that touches the corner stays.

Command line:

g.region s=200000 n=204000 w=200000 e=204000 res=1000
r.mapcalc expression="plot = 1"
for scene in "scene_1 199000 205000 10" "scene_2 201000 203000 20" \
    "scene_3 204000 206000 30" "scene_4 210000 212000 40"; do
    set -- $scene
    g.region s=$2 n=$3 w=$2 e=$3 res=1
    r.mapcalc expression="$1 = $4"
done

t.register input=plots maps=plot start=2026-06-01 end=2026-06-09
